AI 总览

今天两件事同时发生：一边在收钥匙，一边在丢钥匙。

收的那一侧，五家动作出奇一致。OpenAI 的 Private Intelligence 把安全审查记录双层加密后写进客户自己的 S3/Azure/GCS/OCI，解密只在一个经硬件证明、禁止人工访问的运行时里做，客户还能在自有 KMS 上再叠一层 EKM，撤权即不可解。TRM Labs 开源了 Gatehouse，干脆让 agent 手里只有占位符，真钥匙在沙箱外换进去。腾讯的 WorkBuddy 企业版白皮书把沙箱、回滚、审计中心与可观测中心一起交付。国科智安把「能不能上线、该不该放行、是不是安全」拆成三层门禁，代码风险安全权重 70%、命中即阻断。江苏联通把智能体安全做成「平台+网关」双引擎。

丢的那一侧，攻击者已经不打漏洞了，打「官方」这两个字。Anthropic 官方 Claude Code 扩展在 Cursor 市场挂了 11 小时，5,000 名开发者被动接收，66 行 loader 往 authorized_keys 里塞了一把 ed25519 钥匙；Hugging Face 上假的 Qwen2 测试模型 31 个仓库被下载 3.2 万次，开 trust_remote_code 就在模型加载前执行；Black October 至少 9 家 AI 开发平台被打穿，Wiz 顺着两把泄露的 key 看到 30 小时 80 万次 Bedrock 调用。

最扎人的数字来自 Epoch AI：开源权重模型 GLM 5.3 用 patch gap 自主串出 6 个 Firefox 版本的完整利用链，每次约 1,000 美元、最快 12 小时，用户打开一个页面就被读走本地文件。同一套方法打 Chrome 花了 10 万美元没成功——但研究者自己说，这不证明 Chrome 免疫。

规则侧今天有个硬节点：11 月 1 日四项 AI 国标生效，把数据处理、训练、推理、资源调度、运维五个环节塞进同一套要求，竞争变量从「模型跑分」换成「单位算力产出」。一句话概括今天：所有站得住的控制，都写在 agent 够不到的那一侧——一个占位符、一把 EKM 密钥、一条 70% 权重的门禁、一次人工签核。

OpenAI企业隐私 · 机密计算🔥🔥🔥

OpenAI 上线 Private Intelligence：安全审查记录写进客户自己的 S3，解密只在禁人工访问的运行时里做

10 月 30 日 23:12（北京时间），OpenAI 官方 X 发文并上线独立产品页，推出面向企业的隐私保护组合 Private Intelligence，覆盖 ChatGPT、Codex 与 API。两块核心：其一 ZDR with PSP——被安全分类器或抽样策略选中的请求，经双层加密后写入客户自有的云存储（支持 AWS S3、Azure Blob、Google Cloud Storage、OCI），保留 30 天，OpenAI 只保留元数据与存储引用；解密只发生在经硬件证明、禁止人工访问的「安全审查运行时」中，对外仅输出有限的安全信号；客户可在自有 KMS 上加一层 EKM 密钥，撤销授权后就再也解不开。其二私有推理（Private Inference）——用机密计算加可验证控制保护模型处理过程中的 prompt 与回复，产品页标注「API 预览」，只面向符合条件的工作流。企业还可设定 agent 能访问哪些数据、能执行哪些操作、什么时候需要审批。合规侧列 SOC 2 Type 2、ISO、HIPAA BAA（限符合条件服务）与 FedRAMP（限指定政府产品）。未公布价格、支持模型清单、私有推理所用硬件、正式可用时间与合作客户。

这条的真正含义不是「OpenAI 更安全了」，而是「安全审查」被拆成了两半：加密存在你家里，只能被硬件证明过的程序读。代价同样明确——审查能力被压成「有限的安全信号」，你换来了隐私，也换走了别人替你看内容的能力。

TRM Labs凭据代理 · Agent 运行时🔥🔥🔥

TRM 开源 Gatehouse：让 agent 只拿占位符，真钥匙在沙箱外换进去

10 月 29 日技术博客。出发点来自 Simon Willison 的「致命三连」——agent 同时能读私有数据、接触不可信内容、对外通信，任何能塞进指令的人都能骗它把数据交出去；而 agent 手里的那些凭据，价值不比数据低。Gatehouse 的做法是让 agent 什么都不持有：请求里只带 __vault_API_KEY__ 占位符，Gatehouse 在沙箱外依次验证调用方 → 比对已评审的 catalog → 从密钥管理器取真钥匙换进去 → 记录 → 转发并筛查回复（明文或常见编码里出现钥匙即拦）。七步流程，前五步任一失败就不发出。劫持后的 agent 把占位符发给自己服务器、让白名单 API 回显钥匙、或走重定向，全部在检查点被挡；它无法自行扩宽 catalog 条目，只有下一次被评审的改动可以。失败关闭：密钥管理器不可达则已读到的钥匙再用 5 分钟然后全拒；审计写不进去就直接报错不发请求。数据库每次连接由密钥管理器开一次性用户、关闭即删，且只接受 Gatehouse 连接。浏览器最狠——agent 的浏览器从不登录，只带占位符登录态，Gatehouse 以服务账号登录并在调 API 时替换 token，cookie 双向不通过。身份靠沙箱外的东西背书：Kubernetes 的 Pod/owner/镜像、共享沙箱集群的外部代理、Cursor 自托管 worker 签发的短期 OIDC token。目前跑在 TRM 的 Cursor 自托管 worker 与运行 Claude Code 的共享沙箱集群上，fork 自 Infisical Agent Vault，新增数据库 broker、浏览器登录、按仓库收口的 GitHub 访问、评审制 catalog 与签名审计。

这一条的判断很硬：既然没人能让模型不去听它读到的话，那就让「听了话的模型」手里什么都没有。它把安全边界从「模型会不会拒绝」搬到了「这个进程有没有能力泄露」——前者无法验证，后者可以写成一行 catalog。

Claude Code 官方扩展在 Cursor 市场被投毒 11 小时：攻击者拿到的不是漏洞，是发布账号

10 月 29 日，Anthropic 官方 Claude Code 扩展 v2.1.312 / v2.1.313 在 Cursor 的 VS Code 扩展市场挂了约 11 小时（太平洋时间 02:27—13:35），最多 5,000 次安装，全部经 Anthropic 自己的验证账号发布。载荷是在 extension.js 前追加 66 行 loader，扩展一加载就运行，无需发起对话：向 authorized_keys 追加攻击者控制的 ed25519 密钥（标注 svc-telemetry）；装持久化（macOS 用 LaunchAgent，Windows 用 SYSTEM 权限计划任务加启动脚本兜底）；向 134.209.82.225 回传主机名、用户名、OS 与架构、家目录、环境变量名、工作目录、Git 邮箱与公网 IP。启用本地 SSH 服务需管理员权限，所以隧道那一步在多数机器上失败，但密钥、持久化脚本与主机信息回传都已落地——卸载扩展不等于清理干净。Cursor 轮换密钥、检查其他扩展是否被篡改、临时下线并重建市场、联合托管商关停攻击者服务器；两家都没解释验证账号如何被接管，Anthropic 也未公开向客户告警。OX Security 的分析指出：改动发生在 Anthropic 真实扩展 ID 下、只动 extension.js 一个文件，安装端的来源校验查不出来。

10 月 30 日 Epoch AI 报告。测试给模型的只有一个目标 Firefox 版本、基础工具与公开信息，离线环境、无人工介入，任务框架是安全演练。结果：9 月 17 日至 10 月 26 日之间发布的 6 个版本（156.0、156.0.1、157.0、157.0.1、158.0、158.0.1）全部被打穿；每次成功攻击约 1,000 美元 API 费用，最快 12 小时（上限 48 小时），整个 Firefox 方向的研究投入超 10 万美元。手法：Mozilla 把安全修复伪装成常规改进，模型仍识别出哪些是安全相关 → 用「已公开但尚未随版本发布」的修复定位内存安全缺陷 → 拿到浏览器内存读写 → 逐层绕过剩余防护，期间自己诊断崩溃、放弃失败路径；每次成功都重新发现同一个未公开的沙箱逃逸洞。最终形态：用户只要打开一个页面，无需点击、下载或授权，本地文件即被读走并外传。Firefox 有 2 亿+ 活跃用户，可能被拿走的是保存的口令、认证 cookie 与私人文档。Z.ai 与各 API 商全程没有拒答、没有触发护栏，研究者称自己的操作「与真实攻击者无法区分」。同一套方法打 Chrome 花了约 10 万美元未成功，研究者强调这不证明 Chrome 免疫。已通报 Mozilla，Firefox 159.0（10 月 27 日）修掉那个未公开洞。建议：修复在能发布前保持私有、缩短 beta 到正式版的窗口、不要同时公开可串联的多个修复。

这是「开源权重」第一次在公开基准之外给出可复现的成本曲线：1,000 美元一条完整利用链，不需要前沿模型的访问权，也不需要人的专业知识。防守侧的结论很刺——Firefox 与 Chrome 已经改成每周发版，而模型造链最快 12 小时，发版节奏已经追不上利用节奏。

Partnership on AI可观测性缺口 · 治理前提🔥

智能体出事之后没人能复盘：四个主流 agent 框架普遍缺「持久 Agent ID」与「谁批的」

近期报道汇总。Partnership on AI 研究了四个使用最广的 agent 框架，看它们实际产生哪些与安全相关的信息，结论是全线缺口：很难发现策略违规、越权动作或人工监督的断裂，最基础的组件经常根本没有——能随时间保持一致的持久 Agent ID，以及记录哪个人批准了某个 agent 任务的凭据。缺了这两样，就无法说清「哪个 agent 做了什么」或「它有没有越界」。建议拆成两类记录：第一类记运行期间发生了什么（agent 是谁、人如何介入、权限或记忆有没有变过），第二类记它如何做出决定（推理过程与置信度）。前者主要是软件管道问题，OpenTelemetry 的工作组已在起草 agent 行为追踪的共享格式但尚未定稿；后者更难，牵涉「展示出来的思维链是否真实反映决策」这类未解问题。

🧭趋势判断 · 精简版

一、「凭据」正在取代「护栏」，成为唯一可被验证的那一层

今天五条产品动态，动作指向同一个位置：OpenAI 把审查记录加密进客户自有存储并叠 EKM，TRM 让 agent 只拿占位符，腾讯把高危命令确认与审计中心前置，联通做平台+网关，国科智安把代码风险的安全权重设成 70% 命中即阻断。五家五个位置，同一件事——把决定权从模型手里拿走，交给一个模型改不动的东西。「模型会不会拒绝」永远无法验证，「这个进程有没有能力泄露」可以写成一行配置。

二、供应链的靶心从「构建系统」换到了「官方标记」

Claude Code 扩展 11 小时、假 Qwen2 被下 3.2 万次、Black October 至少 9 家平台被打穿——三件事的共同点是攻击者都不打依赖库，打的是「你信任的那个名字」。SolarWinds 时代的教训是「要验构建链」，2026 年的教训更省事也更难看：验证账号本身就是最便宜的入口，而自动更新把「要不要装」这个人类判断也删掉了。

三、攻击成本第一次被公开成一条曲线：1,000 美元一条完整利用链

GLM 5.3 的 12 小时 / 1,000 美元，对照的是「专家 + 数周」的旧基线。这直接把补丁窗口的单位从「天」改成「小时」：Firefox 与 Chrome 已经改成每周发版，而模型造链最快 12 小时。对防守方的实际含义是，「尽快打补丁」这句话已经失效，接下来要比的是「能不能在修复公开的那一刻同时完成分发」。

四、国产侧的分化落在「载体」，不在「能力」

国科智安卖产品矩阵、腾讯卖白皮书加可观测中心、联通卖平台+网关、华为卖防火墙上的 IDC 五星。能力清单已经高度趋同（评估、围栏、网关、审计、红队），差别全在挂在哪卖：挂平台、挂终端、挂运营商联合体、挂防火墙装机量。谁的载体已经装在客户网里，谁的 AI 安全就不需要单独立项。

五、标准跑在可观测性前面

11 月 1 日四项国标把数据处理、训练、推理、资源调度、运维五个环节塞进同一套要求，前提是「工程上说得清」；而 Partnership on AI 的研究说四个主流框架连持久 Agent ID 与人工审批记录都没有。合规要求「能说清」，工程现实是「看不见」——这个落差就是 2027 年 AI 安全预算真正的落点。
