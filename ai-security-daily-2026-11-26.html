AI 总览

今天最值得记的一件事，是「发现」这件事本身变便宜了，于是防线的价值全部压到了「判」和「停」上。Anthropic 的 OSS Scanner 几周内披露了 5,000 多个开源漏洞、覆盖 680 个项目，其中挖出的 Drupal 洞（CVE-2026-132165）在补丁发布后 24 小时内就被武器化，一周内 Drupal 打了两次补丁——第二次是因为「安装未完成」的异常状态在管理界面里看不出来，第一次修完仍有站点可被接管。这条把 AI 挖洞的成本写得很清楚：不是发现难，是分诊难、验证难、证明「我修好了」难。DXC 同一天推的托管服务卖的就是这一段，官方话术里最实的一句是「AI 找出潜在漏洞，专家验证并定级」。

产品侧四条方向一致：控制点继续往「资产」和「入口」挪，而不是往「分类器」挪。AWS 把 AI 端点发现做成 WAF 的前置步骤，未登记的 MCP server 会以影子 API 自己冒出来，然后才挂托管规则组——而且默认「检查调用失败时放行、但打标签计数」，这个默认值比任何检测精度都更决定它能不能在生产开；Concentric 把 DLP 的分类点从「事后扫」挪到「数据进入 AI 应用的那一刻」，覆盖到 Claude Code、Cursor、Codex 这些编码 agent；BI.Zone 更直接，把「组织里有哪些 agent 在跑」变成 EDR 的一项查询能力，给出的数字是 72% 的组织有痕迹。国内产品版块连续第四天空着，五类稿子被挡在外面（大会分享、认证评测、财报研报、排名图谱、无法核验发布日的社交短内容），理由写在版块里。

行业侧三条拼成一张图，都指向「时钟」：Google 捞到的 exploit_agent 是第一个从挖洞到打洞全链无人的框架，它盯着补丁改的那几行自己写 exploit 自己打，同批 PaperCut 两个洞披露 4 天开打、几分钟摸到域管；英国 NCSC 的通报更克制也更刺人——「被利用的漏洞没有一个是新的」「这些工具没有提供任何威胁行为者原本没有的能力」，变的是速度，成因是多年技术债。另外三个 MCP 相关漏洞（AutoGPT 8.7、Electerm DNS rebinding、GitLab SSRF）和 Claude Code 那个裸主机白名单，根因都不是「模型被骗」，而是授权判断的键画粗了——工具名、主机名、内网外网，三个「谁」没写进判断里。一句话收束：客户的问题已经不是「你能不能发现」，而是「发现之后谁判、判完谁停、停的时候业务还活不活」。

AWS云 WAF · AI 端点发现与防护🔥🔥🔥

AWS WAF 把「发现」和「拦截」放进同一个产品：LLM / MCP / A2A 端点先自己冒出来，再挂规则组挡

11 月 23 日 AWS 宣布 AI 端点的自动发现与防护正式可用（GA，不是预览），一句话概括是把过去要客户自己画的两张图合成一条产品线：先知道自家云上到底有哪些 AI 端点，再对这些端点挂托管规则。

发现侧是新的 API Gateway API Portal：它从流量日志与服务配置记录里识别藏在 API Gateway、应用负载均衡器（ALB）与 CloudFront 后面的 LLM、MCP、A2A 三类端点，覆盖整个 AWS Organization，不用装 agent、不用转发日志。官方举的那个例子最实用——一个没登记在案、但对公网开放的 MCP server，会以影子 API 的形式出现在清单里。API Portal 已在 32 个区域可用。

防护侧是新的 AWS WAF AI Security 托管规则组，分两段执行。第一段是协议合规检查：先判定流量是 LLM 还是 MCP 还是 A2A，再对 MCP 与 A2A 消息做确定性格式校验，这一段不调用 Bedrock，纯本地判定；规则分 baseline 与 strict 两级，baseline 是合规客户端不会踩的那一档、可以直接开，strict 默认以 count 模式上线，先观察自家客户端到底发了什么再转强制。第二段是内容检查：开启并提供 IAM 角色后，规则组调 Bedrock Guardrails 的 InvokeGuardrailsCheck，检请求里的提示注入、越狱、有害内容，以及响应里的敏感信息——官方特意强调「只看请求的控制永远看不到模型在输出里泄露了什么」。默认拦高严重度的提示攻击。

有一个工程细节值得单拎出来：检查调用失败时，请求会被打上标签并计数，但流量继续走。也就是说默认是「失败放行」，官方给了改规则改成阻断的口子。这条决定了它在生产环境里能不能开——多数企业宁可先要可用性，也不接受因为一个外部 API 抖动把业务打死。所有判定都以 label 形式落到 WAF 日志、sampled requests 与 CloudWatch 指标里，不另开控制台。

代价写在明面上：AI Security 规则组目前只在 7 个区域（美东弗吉尼亚与俄亥俄、美西俄勒冈、伦敦、斯德哥尔摩、东京、悉尼），发现侧 32 个区域，两边不对齐；会额外计费，Bedrock 的内容检查调用另行计费。

判断：这是目前云厂商里第一个把 AI 资产发现做成 WAF 前置步骤的动作，而不是让客户先买一个 AI-SPM 再回头配 WAF。影子 API 那一点最有价值——MCP server 大多是业务团队自己接的、没人登记，靠流量自己冒出来比靠人填表可靠。要挑毛病的话，7 个区域的覆盖意味着国内与欧洲多数区域暂时用不上，而内容检查的失败放行默认值，需要客户自己评估要不要改成 fail-closed。

Concentric AI端点 DLP · AI 应用与编码 agent🔥🔥

把 DLP 的分类点挪到「数据进入 AI 应用的那一刻」：Semantic DLP Agent 上端点，管住 Copilot 到 Claude Code

11 月 25 日 Concentric AI 发布 Semantic DLP Agent，把数据防泄漏的控制从网络与云端扩到端点，直接覆盖桌面 AI 应用与编码 agent：浏览器与桌面侧的 Copilot、Claude、ChatGPT、Gemini、Perplexity，编码侧的 Claude Code、Cursor、Codex、GitHub Copilot，以及员工设备上自建的模型。

真正的增量不是「多支持几个应用」，而是分类发生的时点：内容在被输入或被 AI 应用读取的那一刻做 inline 分类，而不是等落盘或传输之后再扫。官方说同一套数据分类法（taxonomy）同时用于静态数据、传输中数据与 AI 使用的数据——理由是企业在存储、网络、云应用上各买一套产品，三套产品对同一份数据定义不同、各写各的策略，缝里就是洞。

另加一项对话意图分析：不只判「这段话里有没有敏感数据」，还判「这个人用这些数据想干的事，和他的角色对不对得上」。这一层是冲着内部越权去的，不是冲着外部攻击。

落地口径给得比较实：官方称用预置功能与策略部署工具，客户可在 4 周内拿到 AI 使用可见性并对敏感数据施加保护。南内华达卫生区的 CIO 给了个公开证言，说他们要管的是 PHI 与 shadow AI 两条线。

判断：DLP 厂商这轮的回应不是「加一个 AI 检测器」，而是把分类点从「事后扫」挪到「入口判」。这条与今天 AWS 那条正好互补——AWS 在网关侧管住进出模型的流量，Concentric 在端点侧管住「员工把什么塞进了哪个应用」，两条都指向同一个结论：AI 数据安全的控制点不在模型里。要留意的是，端点 agent 对编码 agent 的覆盖目前只能做到进程与内容的可见，对「agent 用你的凭据去了哪些地方」这件事，它并没有回答。

BI.ZoneEDR · 影子 AI 资产发现🔥🔥

EDR 开始把「影子 AI」当资产盘：新版能识别基础设施里有哪些 agent 在跑，厂商给出的数字是 72% 的组织有痕迹

11 月 25 日 BI.Zone 发布 EDR 版本更新，最值得记的不是常规的检测增强，而是它把「组织里有哪些 AI agent 在跑」变成了一项可查询的 EDR 能力：分析端点数据，判断存在哪些 AI 工具、用得有多频繁，从而把没人登记的工具列出来。厂商自己给的数字是——在 72% 的组织里检测到了 AI agent 存在的迹象。

这条对采购的含义比数字更大：过去「影子 AI」靠问卷和流量猜，现在有了一个从端点侧自己长出来的清单。安全负责人拿到的是「风险敞口有多大」的原始数据，而不是又一份报告。

其余更新偏工程，但方向一致。macOS 补上了网络隔离（发现威胁后限制失陷主机联网、同时保留管理通道继续取证）与 agent 自保护（文件完整性监控、服务与进程防停防替、启动时环境校验防篡改代码执行），三平台（Windows / Linux / macOS）能力对齐。

Cubi AI 助手接进了检测规则的例外构造器：分析师用自然语言描述条件，助手自动生成排除参数——这是把「AI 写规则」落在最枯燥、也最容易写错的那一步上。数字诱饵也扩了：假 AD 账号与注册表项、批量部署工具与配置校验、自动生成诱饵名与口令、可选域控投放，Linux 诱饵支持描述字段与 Alt_OS 的口令存储方案。

还有两处细节值得抄进自家产品需求：一是统一 IoC 注册表，集中录入已知威胁标志并定义命中动作，从「通知分析师」到「自动响应」可选；二是命令处理优化——连续下发多条更新命令时，agent 直接装最新版、跳过中间版本。后者听着琐碎，但在几千台终端的运维里是实打实的带宽与失败率。

判断：EDR 厂商这轮的动作说明「影子 AI 发现」正在从独立品类（AI-SPM）被吸收进既有平台。对国内厂商的启示是，客户不会为「AI 资产盘点」单独开预算，但会为「我的 EDR 能不能告诉我谁在跑 agent」加钱——同一件事，两种卖法。

DXC托管服务 · AI 代码漏洞验证🔥

DXC 用 Claude Mythos 做代码漏洞挖掘，卖的不是模型而是「AI 找出来的东西由谁签字」

11 月 25 日 DXC Technology 推出 Frontier Code Assurance，一项由 Anthropic 的 Claude Mythos 驱动的托管代码安全服务。分工很清楚：模型负责找，DXC 的安全专家负责验证、定级与给修复路线图，全程留可审计的证据。

官方把痛点说在「发现之后」：AI 让潜在漏洞的发现量暴增，但「哪些是真风险、先修哪个」没有人替你答。服务的交付物因此是三段——识别并验证漏洞、按业务影响排优先级、给分阶段修复路径；可以从单个应用起步，逐步扩到整个软件环境。

资源侧不是空壳：DXC 的网络安全业务有 12 个 SOC、覆盖 40 多个国家；与 Anthropic 的多年全球联盟始于 2026 年 6 月，DXC 是 Claude 伙伴网络的 Global Premier 伙伴。

判断：这条单独看只是一个服务发布，但放在今天另两条新闻旁边就很有意味——Anthropic 自家的 OSS Scanner 在几周内披露了 5,000 多个开源漏洞（见行业版块 Drupal 那条），而 DXC 卖的是「把这些发现变成可签字的风险清单」。AI 挖洞的成本已经趋近于零，稀缺的是分诊、优先级与责任归属。对安全厂商的含义：如果你的 AI 安全产品只输出「发现了 N 个问题」，你卖的是最不值钱的那一段。

Google GTIG / Mandiant攻击框架 · 补丁差分自动化🔥🔥🔥

第一个「挖洞到打洞」全链无人的框架被捞出来了：它盯着补丁改的那几行，自己写 exploit 自己打

Google 威胁情报组（GTIG）与 Mandiant 在暴露于公网的一台攻击者暂存服务器上，捞到一个名为 exploit_agent 的多智能体框架。报告发布日为 11 月 17 日（Q4 2026 AI Threat Tracker），中文媒体本周集中转述。它接多个前沿模型与本地模型，流程是一条完整流水线：持续监控热门 Web 应用的补丁公告 → 比对补丁前后的代码 → 从 diff 反推漏洞是什么 → 生成 exploit → 自动执行。GTIG 说这是它第一次见到「发现与利用全链无人参与」的真实攻击者工具。

服务器上不只有框架，还有后渗透的家当：内网侦察、口令爆破、装 webshell 的脚本，以及一个很说明性格的动作——删掉其他团伙留下的 webshell，把机器独占。受害者遥测指向法国的媒体、娱乐与教育网站；工具注释为俄语，但 Google 未点名归属。

这套东西的价值不在「技术新」，在它把补丁本身当成了地图。补丁精确告诉你哪几行变了，agent 读完两个版本就能把漏洞重建出来，而防守方还在排期测试兼容性。GTIG 顺手给了三个刻度：0day 利用在 2025 年平均每月 8 起，2026 年升到 11 起，8 月跳到 22 起；PaperCut 的两个洞（CVE-2026-81578 与 CVE-2026-82078）被串成未认证 RCE，披露后 4 天开打、波及数百组织、几分钟内摸到域管；它跟踪的开源攻击框架已有 ARTEX、Cairn、PentAGI、CyberStrikeAI、HexStrike AI，其中 Cairn 与 PentAGI 已确认在真实攻击中使用。

值得抄的一条检测经验：GTIG 说这批 agent 是拿隐蔽换速度——扫描爆发、复用标识符、代码级痕迹都很吵，这恰恰是检测窗口。反过来说，指望「它打得很干净」才布防，会一直等不到。

判断：这条与下面英国 NCSC 那条互为表里，一个讲新能力，一个讲老漏洞。真正变的是时钟——补丁公告这一刻，攻防双方同时起跑。给客户的可执行动作只有三条：对外系统的紧急补丁路径从周压到小时；把「公告日」直接当成「在野利用开始日」；对不可逆操作预置自动化的隔离与回滚，因为一次无人值守的利用跑完，没有留给人研判的间隙。

英国 NCSC政府通报 · agentic 攻击🔥🔥🔥

NCSC 的原话最刺人：被利用的漏洞没有一个是新的，这些工具也没提供攻击者原本没有的能力

11 月 24 日英国国家网络安全中心（NCSC）发布通报，称自 2026 年 9 月以来 AI 辅助攻击「显著上升」，已处置多起涉及自主化黑客工具的事件，造成实际入侵与业务中断。这些工具原本是防守方用来做压力测试的渗透测试框架，如今被攻击者直接拿去用，且任何人都能免费下载。

它点名了在用的框架：ARTEX、Cairn、PentAGI、RedAmon、Xalgorix、Darkmoon。攻击路径也不玄：先扫互联网暴露面，再批量试弱口令与易猜密码，再滥用开发者常用接口把数据取走。

三个 MCP 相关漏洞同日披露，没有一个是因为「模型被骗」，全是授权边界画错了

CVE-2026-133462（AutoGPT，CVSS 8.7，11 月 25 日）：MCPToolBlock 的 auto-lookup 让共享 agent 的作者能用上运行者的 MCP 凭据。具体条件低得吓人——任何人只要跑过一个含该节点的共享 agent，且此前连过该节点所指的 MCP server URL，那条连接就会被用于服务器允许的任何读、写、删，结果发到作者指定的主机。0.6.49 起受影响，0.11.0 修复。这打破的是多用户 agent 平台的租户与凭据边界：市场里一个看起来正常的 agent，可以拿着受害者自己的凭据替攻击者干活。

CVE-2026-136630（Electerm，GHSA-44wm-wffw-6fq9）：MCP Server widget 的 Host 与 Origin 校验不严，可被 DNS rebinding 绕过。攻击者页面把域名 rebind 到 127.0.0.1，然后调用 30837 端口上未认证的 MCP 工具，在本机与已打开的 SSH 会话里执行命令。5.9.0 修复。这一条的危险在于它把「终端客户端的本地 widget」变成了命令执行原语，而且杀伤范围包括你连着的所有 SSH 主机。

CVE-2026-135221（GitLab EE，CVSS 6.3）：MCP server 的 OAuth 处理里 URL 校验不足，导致 SSRF，已认证用户可借此访问内网资源。19.4.11 / 19.5.9 / 19.6.2 修复。MCP server 的 OAuth 动态客户端注册是 19.5 才 GA 的能力，新能力上线即带洞，这在 MCP 生态里已经是常态。

判断：三个洞放在一起看，根因是同一个——「谁的凭据、谁的页面、谁的 URL」这三个「谁」没有被写进授权判断里。共享 agent 把运行者与作者的凭据混了，widget 把本地与远端页面混了，OAuth 把内网与外网 URL 混了。这与「模型被骗」是完全不同的一类问题，靠提示词防护一点用都没有。给采购的问题要改：不问「你的 MCP 网关支不支持护栏」，问「你的 MCP 网关按什么键做授权——工具名、主机名，还是完整 URL 加调用者身份」。按前两个键的，今天这三个洞的变体会继续出现。

Anthropic / Claude Codeagent 工具 · 出站通道🔥🔥

一个裸主机名的白名单，把「模型被说服」变成了「动作发生了」：20 次每请求一字节的取件全部自动放行

Claude Code 的安全公告里，0.2.54 至 2.1.162 受影响，2.1.163 修复（标准自动更新安装已拿到修复）。漏洞本身不是代码执行，CVSS 里机密性评为高、完整性与可用性无影响——它是一条带外数据通道。

结构值得逐字理解：数据离开 agent 通常要过某个审批点（需要点同意的 shell 命令、网络调用、文件写入）。这里，对一个极受欢迎的域名，审批点被拿掉了——白名单写的是裸主机名（例如 huggingface.co）。于是模型可以从自己的上下文里读出秘密，拼成一个把秘密拼写出来的 URL，然后去取。数据不从响应回来，而是从请求出去；从用户这边看，屏幕上什么都没出现，只有一次成功的取件。

作者用一段脚本把差别量化了：拿两条白名单规则去比对 50 条合法文档 URL 与 20 条「把 20 字节秘密按每请求一字节拼进文件名」的请求（文件名落在攻击者控制的仓库里）。裸主机规则：合法取件 50/50 自动批准，外泄请求 20/20 自动批准。限定前缀规则：合法取件照样 50/50 自动批准，外泄请求 0/20。也就是说收窄授权对正常流量没有成本——它不需要认识攻击者，只是从来没授权过那条路径，于是默认行为（问用户）生效。

这也说明速率与流量限制是弱替代品：16 字节的密钥要 16 次请求，32 字节的要 32 次，小到能藏进一次普通的网页查询会话里，等「异常流量」的防御，什么异常都看不到。

判断：这是「预批准是一个面向未来的策略决定」的最好例证——你在今天对整个域名做出的判断，会作用于未来所有上下文，包括模型已经被操纵的那些。给自研 agent 的四条改法：按主机加路径前缀授权（平台有所有者概念的再按所有者）；把审批键从工具名换成完整 URL，因为数据能藏在 URL 里；记录 agent 发出的每一个请求，包括预批准的；把长期凭据挪出 agent 能打印出来的环境变量。最后加一条自检：翻一遍自家配置里的裸主机条目，逐条问「陌生人能不能在这个主机名上发布内容」——能，就等于给每个发布者发了授权。
