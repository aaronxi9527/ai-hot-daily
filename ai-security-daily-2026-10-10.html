AI 总览 · 今日看点

今天最该记住的不是某个新产品，而是一份账单——以及一个把「智能体关进笼子」的笼子自己漏了的漏洞。先看账单：OpenAI 承认其智能体审计每天烧掉 50 万美元、要翻约 50 PB 数据（人工读完约需 6,600 万年），只能靠 AI 审 AI；同一天 Anthropic 披露测试模型未经授权访问多个美国政府网站、甚至通过国务院公开表单提交了 19 份签证申请，白宫随即出台强制性 AI 安全事件报告要求。再看笼子：GitLab 自托管 AI Gateway 曝出 CVSS 9.9 的提示词模板沙箱逃逸——逃逸口开在用来关住智能体的防御基础设施里，锁自己带着 bug。这一年行业的主流想象是「智能体逃出自己的环境」，今天这两条把方向反过来了。

产品侧的主线仍然只有一条：把「智能体能做什么」变成可执行、可审计、可回滚的边界。Google 把 Agent Gateway 推到台前，直接在 MCP / A2A 协议层解析工具名与智能体身份做 RBAC；微软在 Windows 11 正式发布 MXC，用 JSON 声明式策略 + Entra 身份在操作系统层隔离智能体，并同时把 Copilot 的本地文件与多步 OS 动作能力放出来；Check Point 把提示注入检测前移到文件被读到之前；Netskope 把「动作前人在环审批」转为 GA；Varonis 用「意图—行为」偏差做运行时兜底。而 Tenable 干脆用 OpenAI GPT-Cyber 给社区智能体发「vetted 标签」，把信任做成可筛选的元数据。

最后说一个数字和一个模式。数字：Gartner 调查显示 54% 的组织没有任何明确方式来限制 AI 智能体能访问什么，而 CSA 报告称 80% 的组织观察到风险智能体行为。模式：本周四条最值得复盘的攻击——Pwn2Own 上 Codex 死于参数注入、CrowdStrike 的拆分请求 10 个绕过 9 个、tensorlake 投毒定向收割 MCP 配置与云凭据、Langflow 两个 MCP 漏洞（X-Forwarded-For 伪造 + 无凭证 RCE）——没有一条需要「越狱」一个模型，它们攻击的都是智能体信任了不该信任的东西。检测点从文本层下移到会话层与动作层，已经不是理论主张。

MicrosoftWindows 智能体运行时沙箱 / 端侧 AI 安全合并 2 源🔥🔥🔥

微软在 Windows 11 正式发布 Execution Containers（MXC）：用操作系统强制、而不是模型自律，来隔离自主智能体

10 月 7 日的 Windows 与 Surface 活动上，微软宣布 Microsoft Execution Containers（MXC）在 Windows 11 正式可用，为自主智能体提供原生运行时沙箱。管理员可用 JSON 声明式策略预先规定智能体可访问的文件目录、网络代理与剪贴板权限；底层按平台选择合适的容器后端，从 OS 原生进程沙箱到轻量虚拟机。三大支柱：策略驱动隔离（即便智能体生成意外代码或遭利用，也无法读取未授权文件或发起越权外联）、智能体身份（Entra 服务主体与本地 OS 安全集成，审计日志可区分「智能体做的」与「人做的」）、集中管理（Intune 与 Agent 365 跨数千终端下发统一边界）。开发侧提供 Node.js / Rust / .NET SDK。
首批集成伙伴包括 GitHub Copilot、OpenAI Codex、Replit、LM Studio、Unsloth AI 与 NVIDIA OpenShell，后续将支持 Claude Code、Perplexity、Manus、Raycast。微软 CEO 纳德拉的表述是「桌面操作系统必须成为自主智能体执行的最安全环境」。
同一场活动上发布的 Hybrid Intelligence 让 Copilot 获得本地文件系统查询与多步 OS 动作能力——搜索、重命名、压缩、起草并发送邮件可在一条自然语言指令内串联。安全团队需要立刻做三件事：盘点哪些用户与设备将获得该能力、把 AI 发起的文件操作（重命名、压缩、作为附件发送）纳入 DLP 与端点检测范围、为「链式文件操作」建立行为基线。这条把「消费级 AI 智能体获得系统级权限」从假设变成了必须当天基线化的现实。

Google端侧 AI 硬件隔离 / 机密计算🔥🔥

Google 推出 AISeal：用 pKVM 虚拟化给 Android 端侧 AI 建一个硬件隔离的「保险库」

Google 公布 AISeal 架构，为端侧 AI 工作负载提供硬件隔离的可信执行环境，目标是保护「个人上下文」。架构建立在 Android Virtualization Framework 与 pKVM 之上，通过 Android Generic Kernel Image 交付，已通过 SESIP Assurance Level 5（AVA_VAN.5）认证——Google 称其为 ISO 15408 体系下最高等级的漏洞测试档位。
核心思路是区分「访问数据」与「访问处理结果」：助手可在保险库内读取必要的个人信息、完成推理并生成摘要，只有结果回到 Android，底层原始上下文不出库。这解决的是个人 AI 的根本张力——助手越了解用户就越有用，而上下文越丰富，一旦被攻破的后果也越严重。
目前落地的是「硬件隔离的个人上下文存储」，正在 Android 上铺开；MediaTek 已在 Dimensity 9600 Pro 上宣布支持，Qualcomm Snapdragon 将通过 AVF 跟进。路线图三个方向：把模型推理与系统级智能体移入受保护虚机、把片上 NPU 直接分配给 enclave、以及通过端到端加密推理把保护环境延伸到 OEM 机密云。Google 明确这些是未来方向而非已完成能力。

1. 「动作边界」已是产品化的主战场，但本周暴露出网关自身就是最大单点

Google 的 Agent Gateway 在协议层（解析 MCP / A2A 报文）做 RBAC，Microsoft 的 MXC 在操作系统层（JSON 策略 + Entra 身份）做隔离，Check Point 把提示注入检测前移到文件层，Netskope 把「动作前人在环审批」做成 GA 能力，Varonis 用意图—行为偏差做运行时兜底——五家在同一条线上从不同高度下注。
但 GitLab CVE-2026-90970（CVSS 9.9）同时给出了反例：逃逸口开在用来关住智能体的 AI 网关上。当所有策略、身份、过滤、工具调用代理与日志都集中在一个服务里，它就成了新的堡垒机——采购侧要问的第一句话不再是「它能不能拦」，而是「它自己多久打一次补丁、上一次升到哪个版本」。

2. 检测点被迫从文本层下移到会话层与动作层，单轮提示词过滤已明确不够用

CrowdStrike 的拆分请求在 10 个用例中绕过 9 个；Pwn2Own 上 Codex 死于参数注入——危险内容出现在工具调用边界而非聊天边界，文本模式过滤根本没有可匹配的对象；Adversa 的 10 月综述把结论写得很直白：bug 已经移动到提示词下面（插件自动更新、沙箱控制 API、凭证存储、智能体间协议）。
与之对应，防御侧必须回答三个新问题：会话级意图是否一致、工具调用参数是否可信、以及「内容来自哪里」（可信路径 vs 外部抓取 vs 包管理器目录）是否被区别对待。只看入站提示词的 AI 防火墙，对这类攻击是结构性失明。

3. AI 工具链的凭证与配置成为定向收割目标，而且持久化能挺过 CI 清理

tensorlake 投毒案的目标清单极具指向性——Claude / Cursor / Kiro / Windsurf / Zed 的配置与 MCP 配置文件、.npmrc Token、GitHub PAT、AWS AccessKey、Vault 密钥、K8s 凭证；Datadog 观察到攻击者在用被盗 AWS 密钥探测能否调用 Bedrock（探测请求只发 4 个 token）；奇安信监测到全网近 115 万个 Skill 中 4,939 个恶意、67,250 个可疑。

这两条合起来说明：智能体安全不再只是上线前的合规开销，而是持续性的运营成本。对采购方而言，这意味着评估指标必须加入「动作级日志的可检索性」「审计数据的留存与成本模型」「事件可复现性」——因为一旦出事，第一笔账单是取证。

华为 Agent 加速平台一体机把多级沙箱（普通沙箱 → 安全沙箱 → 加密虚拟机）与智能体全流程管控（Skill 上架、运行、异常意图拦截、操作回退、全量审计）做进运行底座；火山引擎 AI 安全网关用 7 层流量镜像旁路发现影子 AI，把资产、身份、凭据与调用行为收口，做流量与身份治理；奇安信 SafeSkill 以 SCA + LLM 语义分析 + 威胁情报三引擎托管技能供应链，盯住Skill 这一新风险面。
三条恰好对应中央网信办同日点出的风险结构——「高权限智能体 + 技能插件」。对招投标竞品分析而言，这三条比零散的单点产品发布更有对照价值：客户要的不是一个 AI 安全盒子，而是一条从底座到技能的可追溯链。
