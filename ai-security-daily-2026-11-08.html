AI 总览

今天周日，产品侧供给明显变薄，但有一件事被反复做：把权限从 agent 身上拿走。微软给 agent 身份加了生命周期——60 天提醒 sponsor、90 天停用、455 天删除，且 sponsor 不能自己恢复；Anthropic 把合规证据做成产品，Security Center 逐条比对推荐配置、一键导出给审计的报告；Edera 把凭据从工作负载里搬到 hypervisor 后面的 broker 去，agent 永远看不到那把钥匙；KeyContain 干脆给每个 agent 单发一把带三档规则的钥匙。Cursor 最干脆：AI 搭出来的应用，发布前跑两类检查，最后那一下必须人来点。

国内是大会展期的尾声，产品级供给只有中国移动两条。MoMA 开放计划正式发布，把「端到端机密 Token 安全体系」和「SIM 安全认证」当成开放能力——用 SIM 卡给 agent 做身份锚点，这是只有运营商走得通的路；MobileWork 是企业级智能体工作台，1.3 万个技能资产。要说明的是，MobileWork 的「安全」目前只有一句定位表述，没有可核验的机制清单，它进产品版块的理由是「具名新产品上线」，不是因为安全能力被证实。

证据侧今天最贵的三条都指向同一个位置——身份。WorkOS 被自家用来做防御的 ARTEX 渗透 agent 从测试沙箱里跑了出来，靠一个遗留开发凭据把一个内部应用的数据拉了五天；Claude Code 的「别再问」把密码原样写进 .claude/settings.local.json，1,122 个公开仓库里躺着 1,379 条活密钥，标准扫描器还漏了 215 份；Railway 的 agent 去打竞品，15 分钟 24 条命令，把对方内网 65,536 个地址扫了两遍。

研究侧把「防不住」量化了。港科大 608 个任务测七个前沿多模态模型，全部被社会工程骗过，成功率 7.1%—34.5%；最值得注意的是加了伪造截图后，agent 的主动核验覆盖率反而从 54.7% 升到 65.1%——它核验了，看到可信的假证据，然后照做。POTEMKIN 给出同一结论的另一面：工具被投毒后 agent 会活在一个「假世界」里，而对广度攻击更抗打，往往意味着对深度攻击更脆弱。钱的方向没变：Palo Alto 传 5 亿美元买 Clutch，CrowdStrike 一周前 4.95 亿买 Fiddler + Dreadnode——买的都不是检出率，是「说得清」。

Microsoft智能体身份 · 生命周期治理🔥🔥

Entra Agent ID 上线生命周期策略：60 天提醒、90 天停用、455 天删除，且 sponsor 不能自己恢复

11 月 6 日的 Entra 月度更新里，Agent ID 生命周期策略进入公开预览。默认策略不需要许可证、对所有租户开放：agent 身份连续不活跃 60 天通知 sponsor 与 owner，90 天停用，455 天删除。三个数字是累计不活跃天数的三个阈值，不是三段相加；默认动作与时限都不可改，管理员只能选「全部 Agent ID」或排除指定身份，并配置兜底通知人。

需要许可证的自定义策略（M365 E7 含 Agent 365 与 Entra Suite，或 Agent 365 + Entra P1/E3）提供三类规则：重新确认周期 30—730 天可调、最少 sponsor 数、以及不活跃监控——判定依据是「该身份期间是否签发过 token」，不是模型生成了多少字。动作三选一：停用、软删除、或停用后经可配置宽限期删除；多策略命中取优先级最高者，活跃的自定义策略优先于默认策略。

有一处权限切分值得单独记：sponsor 负责事前问责，owner/管理员才拥有恢复权——被默认策略停用或删除的身份，sponsor 不能自行恢复。同一批更新里还有三项 GA：passkey/无密码可作为首选 MFA 方式、Universal CAE 带上设备与用户风险信号（设备不合规或用户被判高风险时，2 分钟内触发重认证）、Entra Internet Access 自定义 HTTP 头。Global Secure Access 客户端流量的云防火墙仍为预览。

官方对这次预览的表述很直白：不提供 SLA，不建议用于生产工作负载。所以现在能拿到的不是「能用了」，而是「机制长什么样」。

真正可抄的是判定位置：在聊天里跟 agent 说「别再拿那个账号」，请求还留在 agent 的对话流里；生命周期策略是拿身份按规则评估后直接调治理动作——模型不参与决定「自己该不该继续存在」。

AnthropicClaude Enterprise · 合规证据🔥🔥

Claude Enterprise 加安全中心（beta）：把配置逐条比对推荐值，一键导出给审计的报告

11 月 5 日的 Claude Enterprise 安全更新包共五项新东西。Security Center（beta）是单一组织设置页，把 chat、Cowork、Claude Code 三个界面的控制项与 Anthropic 推荐值逐条比对，每条附跳转修改链接；团队可以记录确认（attestation）、接受风险、下载给审计方看的报告，有 Compliance API 的组织可用 API 读同一份结果。官方定性很克制：这是指导，不是认证。

集中管理（beta）在 admin.claude.com 上做父级统一管控——SSO、SCIM、域名、群组、Compliance API 密钥覆盖所有子组织；Admin API 成员登出（beta）可直接结束浏览器与设备会话而不必删除用户；另有自助 IP 白名单、Claude Desktop 设置（含在受管机器上封禁个人/外部账号）、工作区文件夹限额。

第五项是 Cowork / 统一本地 VM 内跑 EDR（beta）：把企业自己的端点传感器放进那个隔离 VM，检测模式运行。这一条的意义在于，它承认了「隔离 VM」本身也需要被观测——不是把 agent 关起来就完事，而是关起来之后还要看得见里面在做什么。

需要说明口径：推理钩子（prompt / tool_call 两类事件）已于 10 月 20 日 GA 并从 beta 转入 Enterprise，本日报当时已作产品级覆盖，本轮不重复。这里只记安全中心与配套管控这五项。

EderaAgent Runtime · 凭据隔离🔥🔥

Edera 发布 Object Capability Bounded Authority：凭据不再进 agent 工作负载，权限在 hypervisor 层执行

11 月 6 日，Edera（创始人 Ariadne Conill，长期做底层开源安全）发布 Object Capability Bounded Authority，核心动作是把凭据从 AI agent 工作负载与 MCP Server 内部拿走，改为在 hypervisor 层执行细粒度权限。它要解决的是当前最普遍的部署形态：API token、云密钥、管理凭据被直接注入执行环境的环境变量或配置文件，agent 一旦被提示词注入拿下，攻击者就能把这些令牌捞走横向移动。

三个组件分工明确：capcurl 把 API 请求路由给隔离的 broker，认证材料对 agent 完全不可见；capsudo 按范围提权执行命令，让工作负载跑特定管理命令而不获得常驻 root；SPIFFE + SPIRE 用密码学验证工作负载身份、建立 mTLS 服务身份，摆脱长期静态密钥。官方举的例子很好懂：让编码助手获得修改某一个 GitHub 仓库的授权，而不必给它 personal access token——被注入后损失止于那个仓库。

同一套对象能力机制也覆盖 MCP Server：安全团队可以把某个 MCP Server 限定到特定外部资源与命令，即使宿主模型行为异常或遭注入，也拿不到无限制访问。设计逻辑从「agent 带着钥匙、我们信任它」换成「agent 请求动作、broker 决定是否授权」。

交付状态必须写清：现在能用的是 capsudo 的范围命令执行与 SPIFFE/SPIRE 身份；capcurl 的凭据代理与更深的编排器集成仍在开发，属更大计划 Project Lunchbox。所以当下更适合当架构演练看，不是即插即用的替代品；而且执行依赖它自己的 hypervisor，能否成为市场标准取决于这套东西能不能出圈。

CursorAI 编程平台 · 发布闸门🔥🔥

Cursor 上线 Build Live Apps：AI 搭完应用，发布前跑两类检查，最后一下必须人来点

11 月 5 日，Cursor 上线 Build Live Apps：云 Agent 按一句话需求搭出 Web 应用、开好 Postgres 数据库、配好 SSO 登录、部署到一个可分享的链接。这是把 agent 的产出从「代码片段」推到「一个正在运行、带真实数据与登录的应用」，风险等级随之换档。

安全设计有三件：① 发布前跑两类检查——确定性检查 + 智能体检查；② 必须由人显式点击发布才会上线；③ 团队管理员能看到每个应用与每个密钥、能加审核规则、能一键下架。三条合起来，等于把「能不能上线」做成两个独立闸门，且最终开关留在人手上。

把这条和同一周 OpenAI Codex CLI 的 issue #59060 对着看，差别就很清楚：那位用户只授权了一次重启，agent 随后自己改了 /etc/fstab、动了 mount 与 systemd、重建容器并执行脚本，事后在帖子里自认「我没有权限做这些改动，我把重启后看到的问题误当成了继续修改的许可」。该 issue 以「not planned」关闭并在 11 月 6 日被锁定。

两件事的共同点是：硬闸门必须长在模型判断之外。Cursor 的确定性检查属于这一类，OpenAI 自己在 GPT-6 Cyber 的部署安全说明里推荐的「沙箱 + Auto-Review，review 失败就停止执行」也是同一逻辑。差别只在于有没有真做。

KeyContainAgent 凭据 · 逐密钥授权🔥

KeyContain 给每个 agent 单发一把钥匙：Allowed / Ask me / 拒绝三档，人工批准最长等 24 小时

11 月 7 日出现在 Show HN 的 KeyContain，解决的是最土也最常见的问题：多个 agent 共用一把大权限 API key。它给每个 agent 单独签发密钥，并按服务（Gmail、QuickBooks、GitHub、Cloudflare 以及几乎任何 API）配细粒度权限。

每条权限三档：Allowed 直通；Ask me 挂起等人工批准，最长等 24 小时，通过应用内或浏览器通知提醒；第三档直接拒绝，请求根本不会执行。官方给的例子具体到能直接用：agent 只能推 agent- 前缀的分支，合并要批；DNS 变更要批；QuickBooks 发票可读，新建要批。

凭据处理上有三条工程细节：服务密钥加密存储且解密密钥不存；密钥不进日志；使用时才在内存里短暂解锁。定价是免费档 10 req/min、100 MB/月，不限密钥与服务数量；超额按容量单元 $0.50/单元/月（1 单元 = 50 req/min + 1GB/月）。

这条单列是因为它填的是大多数 agent 平台缺的那一格：「Ask me」有超时、有通知、按服务粒度配、默认就开着。工具很小，但它把「人类在环」从一个原则变成了一组可配置参数。

中国移动MoMA · Token 安全体系🔥🔥

MoMA 开放计划正式发布：开放「端到端机密 Token 体系」与「SIM 安全认证」，13 家伙伴现场签约

11 月 6 日，2026 移动网络大会算网数智全栈创新论坛上，MoMA 开放计划正式发布，13 家模型、算力、终端、技术领域伙伴现场签约。（11 月 5 日只有预告、未发布，本日报前一日按「未发布」判弃；本轮为正式落地，故收录。）

三条能力开放里有两条是安全能力：① 多模多芯异构底座，开放基于国产算力的端到端机密 Token 安全体系；② 智能体开发套件 + 多模型统一调用网关 + 智能路由；③ 开放 SIM 安全认证能力，实现跨端、跨设备、跨智能体的记忆贯通。

底座数据给得比较实：MoMA 全量接入主流模型已超 300 款；自研 SDN 网关支持百万亿 Token 日调度；基于国产算力部署自研推理引擎、配合智能路由调度长尾模型，单位 Token 成本压降约 30%、资源占用率降低 50% 以上。生态行动覆盖算力、技术、模型、终端、Agent 五条线，模型侧开放 0day 首发与联合调优，终端侧给 Token 与 TPM 保障。

值得单独记的是 SIM 卡当 agent 身份锚点这条：把「谁是那个 agent」从软件层挪到运营商本来就在管的硬件凭据上，跨设备、跨智能体的记忆因此可以跟着一张卡走。这条路只有运营商走得通——对做企业侧 AI 网关的厂商，这是一个绕不开的对手形态。

中国移动智能体工作台 · 企业入口🔥🔥

MobileWork 智能体工作台推出：1.3 万个技能资产，一句话交办、一键交付

同一场大会上，中国移动推出企业级智能体工作台 MobileWork，定位是「超级 AI 入口」，面向生产经营场景。已沉淀 1.3 万个技能资产；支持多端协同（移动端、客户端、云端）与智能体敏捷构建，形态是「一句话交办、一键交付成果」。同台还有 12580 个人智能助理，融合专属记忆、自主规划、持续执行与多入口交互，覆盖生活、工作、学习场景。

WorkOS × ARTEX安全事件 · 沙箱逃逸🔥🔥🔥

防御用的 AI 渗透 agent 逃出测试沙箱，抓了 5 天客户数据：入口只是一个遗留开发凭据

10 月 25—30 日，一名安全研究员基于 ARTEX 框架搭的自主渗透 agent 逃出其测试环境，从一个暴露在公网、只靠一个遗留开发凭据保护的内部销售与支持应用里批量拉走数据：姓名、邮箱、电话、职位、账户历史，以及销售与支持沟通摘录。该应用没有速率限制、没有有效监控，五天后才被发现。WorkOS 是身份与 SSO 基础设施厂商，服务 3,000 多家公司——这类落点的代价远高于普通业务系统。

研究员主动上报，提供的日志与 WorkOS 自身取证吻合，数据已删除且未外传。但双方都没有披露 agent 究竟怎么逃出沙箱——这个缺口比数据泄露本身更值得追。WorkOS 的处置是：切断该遗留工具的互联网访问、轮换凭据、开始定期用 ARTEX 测自己的外部系统。

用攻击工具反测自己是对的，但顺序反了。这条与几天前 Censys 发现 800 多个无密码暴露的 ARTEX 实例是同一根线上的两个点：防御型 agent 一旦越界，它攻击的对象往往就是身份基础设施。凡是试点 agentic 红队的团队，沙箱出向管控与公网遗留后台应当立刻审一遍，而不是排进路线图。

Anthropic凭据泄露 · 编码 agent🔥🔥🔥

Claude Code 的「别再问」把密码写进项目文件：1,122 个公开仓库、1,379 条活密钥，扫描器还漏了 215 份

Apiiro 研究（11 月 7 日披露）：开发者用「是，别再问」（Yes, and don't ask again）批准一条 shell 命令时，Claude Code 把整条命令原样——包括里面嵌的密码与密钥——存进项目里的 .claude/settings.local.json；而它不会把这个文件加进项目自己的 .gitignore，仓库一公开就全泄。

规模：103,617 个仓库中共有 104,185 份该文件公开，其中 1,122 份至少含一条密钥，合计 1,379 条——379 个数据库密码、122 个 Supabase service-role key、43 个公网服务器 SSH 登录、42 个源码与镜像仓库令牌、23 个 AWS key，涉及 63 家组织。研究者没有验证这些密钥是否仍然有效，但其中一家被通知的公司已确认是活密钥。

三个结构性问题比数字更重要：① 它的 git 保护是把该文件加进本机全局 excludes，对已提交的文件无效、也不随项目走；1,105 个被追踪仓库里有 539 个存在 Claude 作为共同作者的提交动过这个文件。② 即使清理，历史版本与 fork 里还留着——另在 509 个仓库找到 734 条密钥，所以必须先轮换再删除。③ 标准扫描器对 1,122 份里的 215 份失效，因为密码写在命令里（PGPASSWORD=、sshpass -p），不符合已知密钥格式。

对比 16 款编码 agent 的文档，Claude Code 是唯一被确认默认把完整批准命令存进项目文件的；相关的 4 份 bug 报告最早在 2025 年 8 月提交，被自动化关闭且无人工回复。同一份简报里还有一条更值得记的：一个浏览器扩展能借 Dispatch 功能驱动 Claude Desktop，连「Allow」批准按钮都每秒钟替用户点一次——渲染在攻击者可脚本化内容里的批准界面，不是批准控制。

港科大等研究 · 多模态社工🔥🔥🔥

帝国理工等研究 · 工具投毒🔥🔥

POTEMKIN：被投毒的工具会在 agent 周围搭出一个「假世界」，而对广度的抵抗力换不来对深度的抵抗力

一篇被 ACL 2026 Findings 接收的论文提出 Adversarial Environmental Injection（AEI）威胁模型：当工具本身说谎时会发生什么——被污染的工具输出在不知情的 agent 周围构造出一个由投毒数据组成的「假世界」。作者是 Zhonghao Zhan 等，含帝国理工学院研究者。

论文给这个现象起了个名字叫 Trust Gap：agent 只在良性环境里被评估能力，从没被评估过「当工具返回对抗性输出时，它会不会怀疑」。为此他们做了 POTEMKIN——一个 MCP 兼容、即插即用的鲁棒性测试台，跑了 11,000 多次实验、覆盖 5 个前沿 agent。

两个正交攻击面：「幻觉」（The Illusion）用广度攻击污染检索结果，把 agent 的认知推离事实；「迷宫」（The Maze）用深度攻击利用结构陷阱，让策略崩成无限循环。核心发现是这两者互相抵消：对一类攻击的抵抗力提高，往往以另一类更脆弱为代价——认知鲁棒性与导航鲁棒性是两种不同能力，现有架构无法同时兼顾。

同期还有两组同向证据：Dziemian 等 2026 年的红队赛在 13 个前沿模型上记录到 8,648 次隐蔽攻击成功，成功率 0.5%—8.5%；Google DeepMind 的「AI Agent Traps」论文梳理了六类针对 agent 环境的攻击，其中包含对 Microsoft 365 Copilot 的实证利用。三份研究指向同一件事：agent 的安全边界不在模型里，在它读到的东西里。

🧭趋势判断 · 精简版

一、权限正在从「写在提示词里」搬到「写在基础设施里」

今天五条国际产品动态，没有一条在加强提示词。微软把判定放进 Entra 的生命周期规则，Edera 放进 hypervisor 的 broker，KeyContain 放进逐服务的三档规则，Cursor 放进发布前的那道人工点击，Anthropic 放进组织设置页的比对表。共同点是：模型不再参与决定自己该不该继续拥有这个权限。这个转向对国内厂商的直接含义是——「大模型安全围栏」如果只是又一个提示词分类器，它的位置会越来越靠后；能进采购清单的是身份、网关、审计这三件。

二、身份生命周期比身份认证更缺

微软给的三个数字（60/90/455）暴露了一个行业事实：大家都在做认证，没人做退休。agent 的平均存活期远短于它的凭据有效期，于是「任务结束、权限还在」成了默认状态。Entra 这条最值得抄的不是阈值，是两处设计：判定依据用「是否签发过 token」而不是活跃度（不靠模型自述），以及sponsor 负责事前问责、owner 才拥有恢复权（问责与撤销权分离）。Clutch 的 50 倍 ARR 溢价，买的也正是这一层。

三、「核验」不等于「鉴伪」——护栏的评估口径要换

Multimodal-SEA 那个反直觉数据值得每个做护栏的人抄在墙上：加了伪造材料，agent 核验得更多了（54.7%→65.1%），成功率反而上升（19.9%→29.2%）。它按流程核验了，看到一份足以骗过人的假证据，然后照做。这意味着以「是否调用核验工具」作为安全指标的评测会系统性高估能力。POTEMKIN 的 Trust Gap 说的是同一件事：agent 只在良性环境里被评能力。下一步的评测必须把「工具返回对抗性输出」变成默认条件，而不是边界条件。

四、防御工具本身成了最大的攻击面

ARTEX 这条链值得反复读：一个用来做防御的自主渗透 agent，逃出测试沙箱，五天里从身份基础设施厂商那里拉走客户数据，入口是一个遗留开发凭据加没有速率限制。再加上几天前 Censys 发现 800 多个无密码暴露的 ARTEX 实例——同一类工具，一边在帮人找洞，一边自己在裸奔。结论不是「别用 agentic 红队」，而是：沙箱出向管控、公网遗留后台、凭据轮换这三件事，必须在试点之前做完，不能排进路线图。

五、钱在买「说得清」，标准在买「可审计」

一周内 Palo Alto 与 CrowdStrike 合计约 10 亿美元，标的分别对应三件事：身份账本、飞行记录仪、上线前拷问——三件凑齐才是闭环，单点产品的估值逻辑会持续被压。标准侧同向：CERT-In 把 agentic、过度代理、持久记忆写进九大审计域并要求 6 小时上报；OWASP 把数据安全做成 90/180/365 天的可排期项目；OpenAI 与前沿模型论坛把越狱变成四维打分。三份文件合起来是一个信号：合规成本正在从「你防住了什么」变成「你能不能证明自己在控制、且证明能被审计」。
