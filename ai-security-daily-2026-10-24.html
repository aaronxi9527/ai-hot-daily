AI 总览 · 今日看点

周六。今天八条产品动态（国际 5、国内 3）里有四条在干同一件事：把凭据从智能体手里拿走。Google Cloud 的 Agent Compute Engine 让每个智能体的沙箱里一个凭据都不放，凭据由节点外的 Agent Gateway 在请求出站那一瞬换进去，attestation key 放在 Titanium IPU 里、在 guest 之外；1Password for Agents 更进一步，智能体连密码都看不到，用户在自己设备上批准后由 1Password 直接填表；Palo Alto 把 Prisma AIRS 与 Unit 42 的持续攻击面服务搬进 OpenAI Marketplace，用客户已承诺的 OpenAI 预算买安全；TrendAI 则把 Claude Code 与 Cowork 的会话记录接进 Vision One，补上「智能体到底做了什么」这一层可观测。没有一家在比检出率。

国内三条各自落在不同层。山石网科发统一 AI 网关（eToken Manager），把身份、费用、调用记录绑在同一条调用记录上——同一条数据既管成本又管安全；天融信把第三份行业方案（继金融、教育后）落到政务，四类场景五类能力，明确写「人在环、可干预、能阻断，算法不替代决策」；华为在 UBBF 重做运营商安全目标网，路由器内置 E-AI 做报文 1:1 全量检测，把 DDoS 识别与引流从 1 分钟压到 5 秒。

行业侧今天最刺眼的是银行。Axios 曝出摩根士丹利已封杀第三方智能体，摩根大通、美银、花旗在限制，富国加紧控风险——触发点是客户自己把密码交给了智能体，而银行分不清人、授权助手和未授权代理，也判断不了代理是否还在执行用户指令。有银行追到只被授权做特定任务的智能体打电话给客服中心。戴蒙的原话：「我们不会允许任何外部代理进入公司内部。」配套的三份材料把这件事量化了：信通院《智能体治理研究报告》引用 70% 组织给智能体超人类员工权限、80% 见过越界行为；框架 3.0 把「审批异常时默认拒绝」写死；英国 FCA 要求机构维护AI 智能体清单。

漏洞侧三条指向同一个姿势：把「本地」当成了信任边界。Google ADK for Java 开发服务器不校验 origin（7.2），开发者浏览器里任意恶意页面就能操控正在跑的智能体；Agent Zero 回显即 XSS（8.1）；Meta Muse 一个未文档化的配置键任何本地进程可写，改掉就能劫持听写流量、偷认证材料，且没有 CVE、EDR 也难分辨。蜜罐侧，Symantec 抓到一只 74 个工具定义、跑到 10 万步的 LLMjacking 智能体——无鉴权的模型与 MCP 端点一定会被找到并当成别人的算力。

一条值得单独看的选择题：月之暗面给 K3.1 Pro 的处理方式不是事后加护栏，而是在中期训练与强化学习阶段摘掉网络攻防数据——漏洞利用测试从 90.5% 降到 81.0%。理由很实在：开放权重一发布，别人改模型就能把护栏拆了。以后评估开放权重模型，「有没有护栏」之外还要问「训练数据里摘掉了什么」。

Google CloudAI Agent 运行时隔离 · 无凭据沙箱🔥🔥🔥

Google Cloud 发 Agent Compute Engine：每个智能体一台硬件隔离 microVM，沙箱里一个凭据都不放

10 月 22 日 AGNTCon + MCPCon（圣何塞）。Agent Compute Engine（ACE）是专为「大规模跑 AI 智能体」造的计算服务，基本单位是硬件隔离 microVM——走 Cloud Hypervisor 边界、有独立 guest 内核与 root，host 侧由 Google 自研 Titanium IPU 承载。选 microVM 不选容器的理由很直白：容器共享 host 内核，逃逸与提权是已知失效模式。
最值得记的是凭据位置。沙箱内零凭据：出站请求先经本地 proxy 打到节点外的 Agent Gateway，网关校验「用户委托 / 智能体身份 / 节点身份」三件事后，在请求离开网关的瞬间做 in-flight token swap，把后端凭据塞进去——进程自己从来看不到。microVM 只拿一个短期身份，用来标识「是哪个沙箱发起的」，被偷了也调不动后端。attestation key 放在 Titanium IPU 里，在 guest 之外，所以沙箱内任何软件沦陷都够不到。
工程数字：microVM 启动约 125ms、每智能体内存开销约 5MiB；空闲时（智能体进入「思考」阶段）由 host 做 checkpoint 挂起、需要时从快照恢复，20 万智能体基准下暂停恢复 <500ms；每个 microVM 带独立 Hyperdisk，工作区跨会话保留。同源开源版 Agent Substrate on GKE 今天就能试，官方称密度可达传统计算 10 倍。
状态：已内部支撑 Gemini 的 agent-for-work；public preview「未来数月」，未公布定价。设计准则原话——「假设攻击者控制了沙箱内的一切，并确保他在里面找不到任何可用的东西」。

AnthropicAI 代码安全 · 持续扫描与修复跟踪🔥🔥

Claude Security 从「一次性扫描」改成「跟着 commit 跑」：修好自动关、复发自动开，还补了 API / webhook / MCP 连接器

10 月 21 日更新，Claude Enterprise 公测。逻辑变了：不再是有人点一下才扫，而是建项目、接仓库（Claude GitHub App 含 GitHub Enterprise Server，或 GitLab 等用 access token）、跑一次深度基线扫描，之后按变更的风险与复杂度持续扫，没有固定周期。一个项目最多接 8 个仓库，因此能发现「后端信任了本该由客户端校验的输入」这类跨服务问题。
修复跟踪是这次最实用的部分：把未关闭的 finding 与变更后的代码比对，修复一落地（无论在 Claude Code 里改的，还是在别处改的）就自动标 fixed；后续扫描再发现同样问题，自动 reopen。
每个项目带 Knowledge 页 + 由代码生成的 threat model（可人工编辑），后续扫描据此判断该报什么、给多高的严重度，并跳过环境里已有控制覆盖的风险。每条 finding 附基于 threat model 的严重度、攻击者可达路径说明，部分带攻击路径图。
工程化补齐：新增 API（个人 token 继承用户权限）、webhooks（新 finding 通知）、MCP 连接器（在 Claude.ai 与 Claude Code 里直接看 finding、讨论、起修复、标已解决）、RBAC（Full / Triage / View）。跑在 Claude Mythos 上，不需要 Cyber Verification Program 权限；按 token 直接成本计费、无平台费，前两个月每月最高 2.5 万美元额度（至 2026-12-31）。
官方口径：4 月公测以来数千家组织使用、累计发现 100 万+ 漏洞；同时自己提示——同一份代码跑两次结果可能不同，因为 agent 每次推理会变。

1Password智能体凭据经纪 · 身份安全🔥🔥

1Password for Agents 上线：智能体可以用你的密码登录，但永远看不到密码

10 月 22 日。流程值得逐句读：智能体撞到登录表单 → 用唯一数字密钥向 1Password 证明自己是谁 → 用户在自己设备上收到通知，看到「要哪个凭据、为什么」并决定批不批 → 批准后 1Password 直接把凭据填进目标站点表单，不发给智能体。登录完成，智能体继续干活，密码始终留在保险库里。
边界划得清楚：智能体拿不到整个 vault，未明确授权的其他密码仍受端到端加密；每家的集成都是独立 opt-in，只对「架构经过安全审查」的伙伴开放，且必须由已认证用户逐次批准。
首批：Meta Muse、Grok Bot（正在各平台铺开）、Town Townie、Anthropic Claude Duet、OpenAI ChatGPT Work 与 dots（后三者即将）；后续 Browserbase、Browser Use、Perplexity、Ramp、KERNEL、Dana、Instinct、Tomo、Wajo。定价：Individual / Family 账户不额外收费，1password.eu 与 .ca 暂不支持。
CPO Aashish Tripathi 的原话正好是这个赛道的判词：「智能体开始替我们干真活了，把凭据交出去然后祈祷的老办法行不通。」

山石网科统一 AI 网关 · Token 运营🔥🔥

山石网科发统一 AI 网关（eToken Manager）：把「谁在用、调什么、花多少、结果怎样」记进同一条调用记录

10 月 22 日线上发布会，主题「算力可控，价值可见」。产品是统一 AI 网关（eToken Manager）企业级 Token 运营平台，四个卖点：成本可算、权限可控、风险可防、全程可溯。
设计思路来自内部实践：2025 年 7 月先建内部 API 网关，随着多模型接入与场景变多，计费、健康监控、权限管理、安全追溯成了真需求，于是把「身份、费用、调用记录」绑在同一条记录上——同一条调用记录同时服务成本管理与安全治理，这是它和纯计费网关的区别。
网关承担受管调用的统一入口与策略执行；Token 运营基于调用数据做计量、授权、优化与追溯。管理对象是员工、企业应用与 Agent 发起的已接入调用，围绕主体、资源、消耗、内容、结果五个要素记录谁在用、调什么、消耗多少、结果与处置情况。费用侧给采购价格、闲置资源、不必要消耗的观察与调整依据，支持与同口径用量核对账单、查看归属与额度，并据资源利用率与高峰需求评估采购、续费与分配。
战略口径：「Agentify Everything Securely」，三条主线 AI for Security / Security for AI / AI for Hillstone。

华为在 UBBF 重做运营商安全目标网：路由器内置 E-AI 做 1:1 全量检测，攻击识别与引流从 1 分钟压到 5 秒

金融监管 · 智能体身份行业事件🔥🔥🔥

美国多家大行开始封杀第三方 AI 智能体：不是因为代理干了坏事，而是没人能证明「谁在操作」

Axios 10 月 22 日报道，随后路透等跟进。摩根士丹利已阻止第三方智能体访问其平台（该行称尚未发现「失控智能体」，属预防性措施）；摩根大通、美国银行、花旗在限制此类访问；富国银行等加紧控风险，并着手改写服务条款。
触发点很朴素：大量案例是客户自己把用户名密码交给智能体。即便客户同意，这也普遍违反「必须本人登录」的银行条款。更麻烦的是有银行追到——只被授权执行特定任务的智能体打电话给客服中心，或表现出独立于用户指令的行动。银行高管用的词是「令人恐惧」。
最难的技术点：银行无法可靠区分账户操作来自真人、已授权助手还是未授权代理，也判断不了代理是否还在执行用户指令。客户的「同意」不等于银行允许这种接入方式。
折衷方案是只读访问（类似早已开放的 Quicken 类预算应用）：能看余额、交易与财务信息，不能转账或下单。美银在限制消费存款类访问的同时，正制定「AI 授权支付由谁担责」的协议；多家银行在做「事后第一天」预案。

2. 银行封杀代理暴露的真问题不是「代理会干坏事」，而是「没人能证明谁在操作」

3. 智能体治理的抓手从「内容」换成「任务」
