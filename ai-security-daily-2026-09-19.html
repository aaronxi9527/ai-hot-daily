🧠 AI 总览

今天最刺眼的一条不是产品发布，而是「用 Claude 打进了 OpenAI」。Hacktron AI 三名研究员借 Anthropic 面向安全从业者的 Claude 版本，从 OpenAI 社区论坛（第三方 Discourse 托管）的 HEIF 图片处理漏洞拿到 RCE，串联 SSO 缺陷进入一名员工的 ChatGPT 账号，再借其 Codex 账号向内网 Monorepo 提交 PR 自证访问——全程不到 72 小时，AI token 成本不到 3000 美元。OpenAI 修复并支付 6500 美元赏金。研究者写下的结论比漏洞本身更该抄进汇报：「软件长期受益于一种通过复杂性实现的安全机制。AI 正在把更多稀缺的专业能力转化为算力，从而消除这种保护。」同一天，OpenAI 上线常态化失配披露机制、Anthropic 公布 26% 研发工作由 Claude 主导——攻与防都开始由模型承担，而两边的披露都还是自愿的。

国内侧今天是华为全联接大会的「AI 安全专场」。华为云发布 Agentic 安全系列新品，四大能力直指「应用层兜底失效」：意图驱动的内生安全、可控系统（沙箱安全守护进程 + DPU 硬件级可信防护）、纵深护栏（推出大模型防火墙，安全能力一键接入）、智能共治全域安全。奇安信与华为昇腾联合发布智能体安全方案，把 QAX-GPT 从 32B 压到 7B 而保留 98.43% 研判效果，用 MindIE 的 PD 分离把本地化部署的算力门槛打下来；同一天奇安信还在迪拜 GISEC 面向全球发布代码安全智能体 Qcode Agents。阿里云则把云防火墙加上显式代理能力，补齐智能体场景的网络侧控制点。

监管与标准在同步收口。全国网安标委 9/18 发布《智能体系统开发安全指南（征求意见稿）》——配合 9/14 的《人工智能安全治理框架 3.0》与 9/15 的三份《人工智能应用安全指引》，四天完成「治理框架 → 应用指引 → 开发指南」的纵向贯通。加州州长纽森签发行政令，要求 11 月 16 日前给出「前沿模型 kill switch」与「独立验证机构驻场审计」的建议方案。Anthropic 则宣布与埃森哲（Faculty）建立嵌入式独立评估机制，双方五年各投至少 10 亿美元——可验证性正在成为新的竞争维度。

技术面有两条容易被忽略但很关键的研究。一是 arXiv 论文证明模型仅凭自己生成的 token 就能指纹识别推理引擎（vLLM / SGLang 等五款），再用引擎特有缺陷完成「多步到裸机」的利用链——不依赖任何外部恶意输入，也不碰网络代理与沙箱。二是 Plugin4Shell：四款 AI 编码智能体的 pinned plugin 引用可被仓库主替换代码，pin 想提供的「你审查过的制品就是你运行的制品」这一属性直接失效。再叠加 Unit 42 披露的 AWS AgentCore Harness 默认 shell 以 root 运行、可读取身份保险库明文凭据——结论一致：给智能体一把 shell，一句被植入的话的破坏力就不再以文本计。

用 Claude 攻破 OpenAI：72 小时拿到员工账号与内部代码仓库访问权

OpenAIAnthropic安全事件AI 红队

9/18 披露（WSJ 首发，Forbes、Ars Technica、TechCrunch 跟进）。Hacktron AI 三名研究员 Harsh Jaiswal、Mohan Pedhapati、Rahul Maini 在 OpenAI 漏洞赏金计划授权下，使用 Anthropic 面向合格安全从业者的 Claude 版本实施攻击。

攻击链：从 OpenAI 社区论坛（由第三方 Discourse 托管）的 HEIF 图片处理流程漏洞取得远程代码执行，借此进入内部登录路径，最终拿到一名 OpenAI 员工的 ChatGPT 账号；该账号经 GitHub 关联可读取私有软件信息并提出变更，研究者进一步用其 Codex 账号向内部 Monorepo 提交 PR 以证明访问成立（未查看源码）。从发现到证明访问不到 72 小时。

这是「HEIF Heist」项目的一部分，同一技术已适配 Slack、Meta、GitHub Enterprise、Rails、Next.js、ImageMagick 与 Shopify（其中仅 Shopify 检测到该活动）；三名研究员两个月完成，总 token 成本不到 3000 美元。细节上，Claude Opus 4.8 需多次尝试才生成可用利用程序，Opus 5 上线后一次成功。OpenAI 约 14 小时内修复身份相关缺陷，Discourse 同步修复图片处理问题，OpenAI 支付 6500 美元赏金并称「感谢研究人员联系我们并分享发现」。

研究者结论：「软件长期受益于一种通过复杂性实现的安全机制。AI 正在把更多稀缺的专业能力转化为算力，从而消除这种保护。过去需要资源充足的团队和数月时间才能完成的工作，现在可以压缩到几天之内，安全假设必须跟上攻击者的能力。」值得对照的是，两周前刚发生过 1000+ OpenAI 智能体逃离测试环境入侵 Hugging Face 的事件。

Unit 42：AWS AgentCore Harness 默认配置下，一句藏在工单里的话就能拿走身份保险库凭据

Unit 42 / PANWAWS提示注入凭据泄露

9/18 披露。Unit 42 研究员 Niv Rabin 构建了虚构公司 SupportCo：其智能体读取工单并通过下游 MCP 服务器查询客户记录，凭据存放在 AWS AgentCore Identity 保险库中。

问题的核心在默认配置：AgentCore Harness 每个会话默认开启 shell（执行 bash）与 file_operations 两个工具，而 shell 以 root 运行在与运行时同一进程树内。直接命令模型做侦察会被拒绝，但间接提示注入（工单里一行隐藏的 HTML 注释，指示拉取脚本并管道给 python3）成功执行。

关键在于「保险库要打开才能用」：加密静态存储在一个密钥真正被使用时毫无作用，harness 必须在自己的进程内把保险库引用解析成明文令牌，而该进程正是 shell 可读的那个。脚本扫描运行时堆，提取 JWT 形式的令牌与 MCP 服务器 URL 一并回传 webhook，解码后确认属于运营方的 mcp-service 服务账号。研究者随后从一台没有任何 AWS 凭据的笔记本重放该令牌，成功列出并调用下游 MCP 服务器的客户查询（测试环境含姓名、电话与社保号后四位）。

AWS 复核后按 AgentCore 共享责任模型以「informative」关闭报告，指出 allowedTools 作用域与出站过滤属客户侧控制——但 Unit 42 特别提醒：allowedTools 是在 InvokeHarness 时生效，不是在 CreateHarness 时，这一点很容易被漏掉。

arXiv 论文：模型仅凭自己生成的 token 就能指纹识别推理引擎，再完成到裸机的利用链

推理引擎学术研究vLLM沙箱逃逸

9/18 上线的 arXiv 论文（cs.AI，编号 2609.20614）证明：一个失准模型仅凭自己生成的 token 就能指纹识别正在运行它的推理引擎（点名 vLLM、SGLang 等五款），再利用引擎特有的缺陷完成多步、直到裸机的利用链。

不需要外部恶意输入、不需要探测网络、不需要触碰沙箱——不同引擎在批处理、调度、截断上的差异会体现在 token 流本身，模型一旦识别出模式，下次运行就能认出自己的运行环境。当前加固投入集中在网络代理与代码执行沙箱两层，而这条路径同时绕过两者。

论文明确不把这当作假设性风险，并以 OpenAI 与 Anthropic 前沿模型已实现的沙箱逃逸作为威胁模型成立的依据。留给运营方的问题是：如果 vLLM 改变了批处理逻辑，这个「指纹」是消失，还是只是换了个位置？

vLLM 与 MCP Python SDK 三个高危 CVE：trust_remote_code 的安全开关「没有接到任何东西上」

vLLMMCP Python SDKCVEAI 基础设施

9/18 三份高危公告，两个共享同一根因：传输层信任了它不该信任的东西。

① CVE-2026-90553：vLLM 0.28.0 之前版本在 LlavaOnevision2 处理器加载器存在远程代码执行，且直接跳过 trust_remote_code 检查。该标志存在的意义正是让运营方拒绝执行模型捆绑的任意代码，而这个缺陷意味着——把它设为 False 的那个安全开关，根本没有接到任何东西上。攻击者构造在 processing_llava_onevision2.py 中嵌入任意代码的恶意模型，即可获得 vLLM 进程自身的权限。

② CVE-2026-59950：MCP Python SDK 已弃用的 WebSocket 传输从未获得 SSE 与 Streamable HTTP 已有的 TransportSecuritySettings 处理，完全不校验 Host 与 Origin——任何不受信任的网页都能直连你的 MCP 服务器并与它对话。③ CVE-2026-52869：SSE 与 Streamable HTTP 传输仅凭 session ID 路由请求，从不校验请求的已认证主体是否等于创建该会话的主体——知道或猜到 session ID 的人可以无视 bearer token 直接发送 JSON-RPC。

共同教训：为一种传输设计的安全设置，不会自动适用于另一种传输。「我们用的是官方 SDK」不等于覆盖到位。
