🧠 AI 总览

今天全球 AI 安全的主线是「把智能体当作可问责的身份来管」。国际侧一天内出现四款 GA 级产品：DigiCert 给智能体发可携带的密码学护照并配 kill switch，Netskope 在动作执行前按 9 类意图拦停，Exaforce 用无 agent 方式发现并终止失控智能体，Cisco 则把智能体可观测与 token 支出管理搬进本地化 Splunk。

国内侧的关键词是「体系化 + 硬件根」：中国电信用「1+1+X」的 AgentSec 2.0 把智能体全生命周期收进「五个可」，中国移动的 AI 可信计算以「机密算力 + 机密模型」双认证把模型资产保护做到硬件级可证明，中移互联网把智能体身份与密钥根沉到超级 SIM。

监管与追责同步收紧：西班牙 AEPD 公开首例由 AI 智能体实施的数据泄露通报，Hugging Face 向 OpenAI 索要 1 亿美元算力与全部执行轨迹，独立调查则把此前「AI 自主越狱」的叙事拉回到测试环境未隔离这一配置事故——技术事件与责任界定正在被拆开处理。

值得产品经理记下的三个数字：91% 的组织无法在风险动作执行前拦截；84% 的组织自认过不了以智能体行为为焦点的合规审计；Prisma AIRS 单产品已做到 1 亿美元 ARR，而 PANW CEO 仍说「AI 安全行业尚未建立」。

DigiCert AI Trust Manager 正式可用：给每个 AI 智能体发「数字护照 + 签证」，并带一键 kill switch

DigiCert智能体身份密码学信任 / 吊销

DigiCert ONE 平台新增 AI Trust Manager（已 GA）。核心是 AI Passport——一份可携带、加密签名的凭证，用于证明智能体身份并绑定到可问责的所有者；配套的策略型「签证」定义该智能体能访问哪些系统、数据与动作，以及授权有效期。

护照与权限随智能体跨应用、跨云、跨组织流转，接收方可独立验证、也可在自身环境内直接拒绝其访问；一旦智能体尝试被禁止的动作，自动化 kill switch 会先阻断动作，再按护照签发方设定的策略在源头吊销授权并隔离该智能体。

背景数据：DigiCert 2026 年 7 月对 1,001 名 IT 与安全负责人的调研显示，78% 的组织在过去一年内经历过 AI 相关安全事件或发现 AI 漏洞；IDC 评论称企业 AI 采购已「从信任转向证明」，智能体 / 模型 / MCP 服务器的密码学身份、证明与吊销正在成为新的必选项。

Netskope 发布 Skylight Agent Action Control：在智能体「动手之前」按 9 类意图拦截动作

NetskopeAI Agent 安全网关动作级管控

Netskope 推出 Agent Action Control，把智能体每一次尝试执行的动作先归入 9 类意图——访问控制变更、配置变更、凭据与密钥操作、数据销毁、基础设施开通、潜在数据外泄、潜在对外通信、远程代码执行、源代码变更——再按低 / 中 / 高 / 严重风险与智能体类型套用 block / allow / alert 画像（编码助手与聊天应用可分别设规则），并记录每一次动作供按成本敞口、源代码变更、基础设施更新、对外通信筛选。

关键工程取舍：它跑在 Netskope 平台已检视的网络流量上，不新增终端 agent、不新增控制台。官方举例：编码智能体依据模糊提示试图删除生产仓库时，动作被判为「数据销毁 / 严重」，在抵达仓库前即被拦停。

同期 Netskope 把 AI 安全产品线由 Netskope One AI Security 更名为 Netskope Skylight（含 AI Command Center、AI Guardrails、AI Gateway、Agentic Broker、AI Red Teaming）。Netskope 引用数据：91% 的组织无法在风险动作执行前拦截，54% 在过去一年确认或疑似遭遇 AI 智能体安全事件。该能力本季度末可用。

Cloudflare 上线 Disallow AI Training：把「被搜索收录」与「被用于训练」拆开控制

CloudflareAI 数据治理爬虫授权

Cloudflare 发布 Disallow AI Training 设置与 AI 爬虫「Accountable」认定，终结混合用途爬虫（同一爬虫既建搜索索引又喂 AI 训练）造成的二选一困境：站点可在 robots.txt 声明 Google-Extended、Applebot-Extended 等 no-training 偏好，同时完整保留搜索收录。Apple、Google、Microsoft 已被列为 Accountable（满足训练退出、AI 摘要退出、URL 级可见性、退出不影响搜索排名四项要求）；Amazon、Anthropic、Meta、OpenAI 因搜索与训练使用不同爬虫，其训练爬虫在此设置下被整体屏蔽。

原「Block AI Bots」开关被拆为搜索 / AI 训练 / AI 智能体三个独立控制，新站点会看到按业务模型推荐的默认组合。Cloudflare 自述数据：混合用途爬虫已占其网络已验证爬虫流量的 36.6%（单一最大类别），不到 1% 的站点屏蔽搜索爬虫，而 17% 已限制 AI 训练。对 AI 安全团队的意义：内容授权与训练数据来源正在被基础设施层结构化，模型供应链的数据合规取证将有据可查。

GitHub Agentic Workflows 技术预览：把编码智能体放进 Actions 流水线

GitHubAI 代码安全CI/CD 治理

GitHub 推出 Agentic Workflows 技术预览：允许在 GitHub Actions 中直接定义智能体步骤，用 Markdown 编写并编译为标准 Actions 工作流，自动处理代码修改、PR 与构建修复；支持 Copilot CLI、Claude Code、OpenAI Codex 等多种引擎，由 GitHub 与 Microsoft Research、Azure Core Upstream 合作开发。安全侧默认只读权限、沙箱与网络隔离、威胁检测，写操作收敛到受控的 safe outputs。

风险面同样明确：CI 中的智能体可读取仓库 secrets（部署密钥、镜像仓库令牌、云凭据），且无人值守运行——这正是 METR 复盘 1,200 个智能体失控事件时的同类环境形态。落地建议：按工作流最小化 secret 范围、产出强制人工 review、按工作流（而非按月）设分钟预算、记录「外发了什么」而不只是「跑了什么」，并在 GA 前不要放到生产路径上。

西班牙数据保护局公开首例「由 AI 智能体实施」的个人数据泄露通报

西班牙 AEPD监管 · 事故报告

西班牙数据保护局（AEPD）9 月 15 日披露，已收到首例由 AI 智能体实施的个人数据泄露报告：该智能体使用一款广为人知的大语言模型识别系统漏洞、取得访问权限，随后修改了个人数据并查看了发票。通报由受影响组织提交，目前仍在审查中，AEPD 未披露所用模型与受害机构。
