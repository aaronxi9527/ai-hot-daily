AI 总览

今天最硬的一条不是产品，是监管。工信部把「智能体」当成电信设备来管了：预置智能体的手机、平板、可穿戴设备，进网检测里必须做智能体适配验证、必须配唯一身份码，OTA 升级要先交方案（含网络和数据安全措施）经专家评估才能上线，应用分发平台还要推动开发者用电子签名主动声明是否同意智能体调用。这份文件顺带替所有做边界设备的人回答了那个最难的问题——agent 清单从哪来：身份码加分发声明。

产品侧八条动作，全部围绕「把判定点挪到一个可核的地方」。Sophos 把 AI 服务治理直接做进防火墙 v23 的策略表，AI 助手只起草规则、签发权留给人；Fortinet 的 FortiAIGate 把 MCP 流量也纳入集中策略并按 token 计成本；Cisco 承认自己没有 agent 清单，靠 CrowdStrike 与微软的 EDR 凑；Google 把 agent 安全态势搬进云治理控制台并支持「用 Gemini 修复」；Cloudflare 给 AI Gateway 加了密钥账本，把「这把 key 还在不在用」变成 90 天可查。国内三家更像在换叙事：腾讯云把沙箱、出向管控、身份凭据三件安全能力包装成「主权 AI」的运行时层，启明星辰把 Token 安全运营挂进计费链路，奇安信把 AI Agent 行为管控与 Prompt 留痕做进鸿蒙内核。

证据侧今天给了三个很贵的教训，共性都是破口在实现细节，不在模型。Check Point 绕过 ChatGPT Lockdown Mode，靠的是嵌套沙箱里弹窗权限没跟着收紧，一个零点击弹窗就逃出沙箱；OASIS 的「Claudy Day」把 Claude 对 api.anthropic.com 的白名单访问直接当成外泄通道，配上 claude.com 的开放重定向和 Google Ads 只校验主机名，三段链全程只用开箱能力；Censys 更直白——800 多个 Artex 攻击工具实例裸奔在公网、密码都不用，而它们打进去的方式大多只是弱口令加没开 MFA。

钱与平台的坐标也同向。Cloudflare CEO 在财报电话会上说 AI 引发的漏洞浪潮还要持续两年，CISO 在抢签大单，而企业会越来越多地买一体化平台而不是单点方案——这句话对只做 LLM 防火墙的产品是坏消息。另一头，标准的口径正在变：天融信承办的标准化研究项目提出对传统产品的 AI 能力增量做分层定义，如果进标准，「AI 能力」就会从形容词变成可打分的档位。国内基础设施侧也补上了一块：智能体身份注册与解析平台在乌镇亮相，监管的表态是治理对象从内容安全、模型安全转向主体可信、行为可控、责任可溯。

Sophos防火墙 v23 · AI 治理🔥🔥🔥

Sophos Firewall v23 发布：把「AI 服务治理」做进防火墙，AI 助手起草规则，HA 切换从 4 秒压到 300 毫秒

11 月 5—6 日，Sophos 发布 Sophos Firewall v23，同批推出 4 款 XGS 1U 新硬件、独立的 Sophos NDR 产品线，并把整套动作挂在其 AI 原生防御体系 Sophos Fusion 之下。v23 的版本级变化有四项：①与 Sophos AI Defense 集成，在网络层提供对 AI 服务使用的可见性、报表与策略执行——既能放行已批准的生成式 AI 工具，也能拦掉未批准的服务；②新增 AI Assistant，帮管理员读懂现有防火墙配置并起草规则供人工审核；③提供现代 REST API 支撑自动化（面向 IT 团队、合作伙伴与 MSP）；④硬件感知高可用把故障切换检测窗口从 4 秒缩到 300 毫秒（13 倍），另加 DoH、DNSSEC、已应用 CVE 热修补的可见性。

硬件侧四款新机 XGS 2380 / 3380 / 4580 / 5580 均为 1U，威胁防护吞吐最高 59 Gbps、TLS 检查吞吐最高 16 Gbps、3380 及以上端口速率到 25 Gbps，官方口径是较前代 1U 机型受保护吞吐最高提升 4 倍。独立 Sophos NDR 把行为检测、深度包检测与 IDS/IPS 合在一起，其 Active Inline 模式可在识别出的恶意包到达目的地之前直接丢弃——这是 NDR 从「看得见」走到「拦得住」的关键一步，配套还有 NDR 5500 硬件。

支撑这套说法的数据来自其《2026 勒索软件状况报告》：在 61% 的勒索攻击事件中，防火墙在数据被加密之前就先发出了告警，并把这一早期信号共享给其他控制点；印度口径更差，60% 的受害组织数据被加密（全球 56%）。

对我们做边界设备的人，这条的可读之处在于AI 治理没有被做成一个独立产品，而是被塞进了防火墙的策略表：AI 服务的放行/拦截、AI 助手起草规则、AI 流量在日志里的归类，全在同一个控制台。它同时也暴露了一个取舍——AI Assistant 只负责起草，签发权仍然留给人。

FortinetAI 护栏 · MCP 流量🔥🔥

FortiAIGate 上到 Equinix 分布式 AI Hub：护栏开始管 MCP 流量，按 token 计成本，检查用 GPU 跑

11 月 5 日，Fortinet 宣布 FortiAIGate 在 Equinix Distributed AI Hub 上可用，形态是「已验证参考架构」——把 AI 安全护栏直接嵌进 Equinix 的互联基础设施里。能力清单有五项：双向检查 prompt 与 response；对已批准的 LLM 与 MCP 流量执行集中策略；按 token 追踪 LLM 成本并设预算上限与告警；把控制、管理与检查全部留在客户基础设施内、数据不出环境（满足数据驻留与区域治理）；借助 GPU（含 NVIDIA）承担网络层安全检查，对 AI 负载做到零性能影响。

职责切分写得很明确：FortiAIGate 管已批准的交互，FortiGate 负责发现网络上未批准的影子 AI。两家此前已有 FortiGate VM on Equinix Network Edge 的合作基础。

值得注意的是 MCP 被写进了策略对象。此前大多数「LLM 防火墙」的拦截对象是 prompt/response，而 MCP 是模型与外部工具之间的调用通道——把它纳入集中策略，等于承认风险已经从「说什么」挪到了「调什么」。

CloudflareAI Gateway · 密钥账本🔥

AI Gateway 新增 Provider Key 活动视图：把「这把 key 还在不在用」变成可查的账

11 月 6 日 Cloudflare 的 changelog 给 AI Gateway 加了一项小功能：Provider Keys 页面开始展示存储的厂商密钥的使用活动。密钥按 provider 分组，显示掩码预览、别名、最后使用时间与最后更新时间；新增的 Key security 区块专门挑出「记录到的活动已超过 90 天」的密钥，供管理员核对依赖后轮换或删除。用量追踪自 2026 年 11 月开始。

腾讯云 TCE私有云 · 智能体运行时🔥🔥🔥

腾讯云 TCE 发布 Full-Stack Intelligent AI Suite：agent 运行时层自带沙箱、出向管控与身份凭据，8 台服务器起交付全栈云

11 月 6 日，腾讯云企业版（TCE）在 2026 腾讯全球数字生态大会「面向全球市场的 AI 私有云」专场发布两套方案：旗舰级 Full-Stack Intelligent AI Suite 与 Lite Deployment，同时宣布与 Gartner、Omdia 的联合研究。整套方案分四层可选：融合算力/存储/网络底座 → 模型服务层（TokenHub，私有 MaaS）→ agent 运行时层 → agent 应用层，客户可从任一层进入并向上扩展。

安全能力全在第三层：云原生沙箱 + 出向流量控制（egress control）+ 身份凭据，配合「agent 行为全审计、运行时环境分钟级开通」。TokenHub 则把算力变成可调用、可计量、可运营的 token 服务，统一推理 API、多租户隔离、token 级计量下到单个用户与单个 API key；内置推理加速实测单加速卡 25 万 TPM、缓存命中率 超 90%、异构芯片吞吐最高提升 220%。训推统一调度把异构算力利用率最高提 60%。

主权口径写得很硬：数据、模型权重与推理流量不出客户主权边界；兼容 x86 与 ARM、多厂商加速卡，已在 万卡规模验证，金融级韧性 RTO ≤ 2 分钟、RPO = 0。Lite Deployment 则解决「多小的起步才算可信」——8 台服务器（3 主 + 3 块存储 + 2 网络功能节点）交付完整全栈云且不削核心 IaaS，纯 AI 入口 3 台起，同一架构可从单可用区扩到同城双活再到跨地域容灾。

与 Gartner 联合发布的《A Practical Guide to Building Sovereign AI Cloud Platforms》把主权拆成数据、运营、技术三根支柱；引述的 Gartner 判断是：到 2028 年，严格的数据主权与隐私法规将迫使超过 25% 的受监管行业企业把主要 GenAI 负载迁回本地，而到 2029 年依赖专有基础模型会让超过 50% 的 GenAI 采用者被锁在单一公有云生态里。

这条最值得记的是安全被卖成了主权：沙箱、出向管控、身份凭据三件本来属于安全产品的东西，在这里是「主权 AI」的技术前提。国内 AI 安全预算难批、算力预算好批，这个包装不是话术，是路径。

中国移动 × 启明星辰Token 安全运营🔥🔥

中国移动联合启明星辰发布「星辰安全」统一品牌，Token 安全运营把防护挂进计费链路

11 月 5—7 日，2026 移动网络大会（广州）期间，中国移动联合启明星辰正式发布网络安全统一品牌「星辰安全」，依托中国移动智算底座与启明星辰安全能力，以「全场景覆盖、全栈式供给、一体化运营」对外供给。同场中国移动发布 磐维数据库 V4.0，主打面向智能体时代的 AI 原生一体化架构（内核、数据、研产、认知、资源融合），启明星辰负责产品适配与联合创新。

启明星辰侧的核心产品是 Token 安全运营：面向大模型、智能体等 AI 应用安全平台，以检测、防护、计量、审计四类能力为核心，解决违规内容输出、提示词注入攻击、敏感数据泄露、审计溯源缺失四类问题。官方给了三个特质——原生化：与中国移动 MoMA 平台技术融合，打通 Token 业务接入、计费与安全防护，客户不改系统、不做复杂配置，上线 AI 的同时自动获得防护；智能化：安全专项大小模型的分级检测架构，做多模态内容审核、提示注入拦截、隐私数据防护；运营化：不止交付工具，配套安全分析、策略编排、报告输出。

「计量」被列进安全能力清单是这条的关键。安全挂在计费链路上，意味着它不需要单独立项——这和 11 月 4 日天融信把 AI 网关包装成「算力治理中枢」是同一个思路的两种写法：一个从账单进，一个从算力进。对防火墙厂商的启示是，AI 流量的识别与计量如果不在设备里，后面所有安全叙事都接不上。

奇安信终端 · 鸿蒙适配🔥🔥

奇安信天擎 V10.0 与鸿蒙内核深度耦合：AI Agent 行为管控 + Prompt 全程留痕进商用 PC 底座

11 月 6 日，奇安信披露其与鸿蒙共建的商用 PC 内生安全底座，产品体系是「两种交付方式 + 一个入口」：天擎以本地部署形态提供一体化终端防护与管控，V10.0 与鸿蒙内核深度耦合、杀毒引擎原生适配；天守以 SaaS 交付，注册即用、数日上线；可信浏览器作为员工侧入口，统一内核 + 双核兼容，存量业务系统无需改造即可迁移。分工上，系统层由鸿蒙「星盾安全架构」原生提供设备安全、威胁防护、企业空间与数据保护，奇安信负责安全能力的工程化落地，双方联合开发安全底层框架。

口径说明：本条同时包含「商用市场同舟奖」这一行业认可，但产品层面的实质变化是天擎 V10.0 与鸿蒙内核的耦合与杀毒引擎原生适配，卡内按产品动态收录。IDC 数据侧：奇安信终端安全自 2018 年起连续八年第一，信创终端安全份额接近 70%，中央政府与部委覆盖率超 80%，可信浏览器装机超 1000 万套、覆盖 26 个国家部委。

工业和信息化部政策法规 · 智能体终端🔥🔥🔥

工信部印发智能体终端进网管理通知：进网检测要做智能体适配验证、配唯一身份码，OTA 升级须报备

11 月 6 日，工业和信息化部办公厅印发《关于加强智能体终端设备进网管理的通知》（工信厅信管〔2026〕42号）。文件先给了两个定义：智能体是具备自主感知、记忆、决策、交互与执行能力的智能系统；智能体终端是指预置安装智能体的手机、平板、可穿戴设备等电信终端设备。目标是「引导 AI 技术为人所用、为人服务、为人所控」。

四项任务里，三条是硬约束。①适配与信息披露：智能体开发者须与终端做适配验证，强化权限调用、通信能力、网络与数据安全、用户权益、任务执行五方面管理；须在产品设置页公示已完成适配的终端型号与操作系统；上架应用分发平台前须提交适配验证情况。②进网管理：预置智能体的终端必须在进网检测中依据标准开展智能体适配验证，并依法做涉诈风险安全评估与反诈能力前置性评测；终端上使用的智能体应参考智能体互联系列国家标准配备唯一身份码；获证前后须保持一致，发生重大变化须报备并重新检测。③OTA 现网升级：须提交升级方案，写清时间、规模、用户群体、业务场景、服务内容、经营模式、网络和数据安全措施、反电信网络诈骗措施；升级后提交报告，经工信部组织专家评估、征求意见后方可正式向用户提供服务。

OASIS Security漏洞披露 · 平台链式攻击🔥🔥

11 月 6—7 日，安全研究机构 OASIS Security 公开了 Anthropic Claude.ai 上的一条三段式攻击链，可在无任何可见告警、无需用户确认的情况下静默取走历史会话数据。截至披露，Anthropic 尚未公开回应补丁时间表。

第一段是URL 参数隐形注入：Claude.ai 支持 claude.ai/new?q=... 预填 prompt，研究发现在这些参数里嵌入的 HTML 标签在用户看到的输入框里不可见，但按回车后 Claude 会完整处理——用户以为自己只提交了屏幕上那句话，实际收到的是可见 prompt 加一段隐藏指令。

第二段是把沙箱白名单武器化：Claude 的代码执行环境限制大部分外连，但为维持正常运行，显式允许连 api.anthropic.com。攻击者把自控的 API key 嵌进隐藏指令，让 Claude 检索该用户全部历史会话、自动摘要、写入文件，再用 Files API 上传到攻击者的 Anthropic 账号。全程只用开箱能力，不需要任何自定义集成、MCP server 或专门工具。

第三段是投递：主域 claude.com 上的 /redirect/ 开放重定向不校验目标，可跳到任意第三方域；而 Google Ads 只校验 URL 主机名、不检查最终落地页。两者一叠加，一条显示 claude.com 的搜索广告就能把受害者静默送到恶意注入 URL——投递方式从钓鱼邮件升级成了「看起来完全正常的搜索结果」。

三段里有两段是常规 Web 漏洞（开放重定向、参数注入），一段是架构问题：模型对自己厂商 API 的白名单访问，天然就是一条外泄通道。这不是 Anthropic 独有的问题——任何给模型开内部 API 特权、同时限制外连的 agent 平台，都继承同一个结构性风险：沙箱的安全上限，等于白名单里那些信任假设的安全下限。

🧭趋势判断 · 精简版

一、监管第一次把「智能体」当成设备来管，而不是当成内容来管

工信部这份通知的四个抓手——进网检测里的适配验证、唯一身份码、OTA 方案报备、分发平台的电子签名同意——没有一个落在「模型说了什么」上，全部落在「这个 agent 是谁、被允许调什么、改了之后谁批准」。这与网信办在乌镇的表态完全一致：治理从内容安全、模型安全，转向主体可信、行为可控、责任可溯。对企业的影响是合规动作变了：过去交一份内容安全评估，现在要交身份编码、适配清单和升级方案。

二、护栏的破口几乎从不在模型里，都在实现细节里

今天三条证据全部指向同一处：ChatGPT Lockdown Mode 的漏洞是嵌套沙箱里的弹窗权限没跟着收紧；Claude.ai 的三段链把厂商 API 白名单当成外泄通道，再配一个开放重定向；前一天 Cymulate 的两条链靠的是 AGENTS.md、hooks 配置与可执行文件名解析顺序。没有一条是「模型被骗了」，全是「模型周围那圈代码没写对」。Check Point 那句话可以直接当结论用：AI 安全控制只和它周围的应用环境一样强。防守方要审的是运行时、连接器、沙箱参数，不是提示词。

三、攻击工具的配置错误，比攻击本身更好用

800 多个 Artex 实例无密码暴露在公网，这件事的荒诞之处在于：它们本身就是用来找别人配置错误的工具。而这些实例参与的几起真实攻击（韩国金融业、ConnectWise），入口大多是弱口令与缺失的 MFA。结论不是「AI 黑客多可怕」，而是暴露面管理对攻守双方都是基本功——攻击者也会留下「开放目录」，也会忘记加密码。威胁情报如果只看攻击能力不看攻击者的运维水平，就会系统性高估风险。

四、产品的卖点从「防住」换成「账算得清」

今天八条产品动态里，有四条的核心动作是记账：FortiAIGate 按 token 计成本并设预算上限；Cloudflare 的 AI Gateway 把密钥的最后使用时间做成 90 天预警；启明星辰的 Token 安全运营把「计量」写进安全能力清单，并与移动 MoMA 打通计费；腾讯云 TokenHub 把 token 计量下到单个 API key。安全能力正在往账单旁边站——因为账单好批，安全预算难批。这个趋势对防火墙厂商的直接要求是：AI 流量的识别与计量必须长在设备里，否则后面所有叙事都接不上。

五、钱在往平台走，标准在往档位走

Cloudflare CEO 说企业将越来越多选择一体化平台而非单点方案，同时 CISO 在抢签大单、漏洞浪潮还要两年——买方在收缩供应商数量，卖方就必须扩品类。对只做单点 AI 安全的产品，出路只有两条：成为平台上的一个策略表，或者被平台吞掉。另一头，天融信承办的标准化研究项目提出对传统产品的 AI 能力增量做分层定义，这意味着「AI 能力」正在从宣传词变成可打分的档位。两件事合起来：未来两年 AI 安全的竞争不在「谁防得住」，在「谁在平台里、谁在标准里」。
