AI 总览 · 今日看点

周一。今天最值得记的不是某条新闻，而是三件事同时被证伪。

第一件：「身份」被证伪为「安全」。ID-JAG 这份被六家厂商拿去跑生产的智能体身份标准，停在 -04 版、11 月 22 日到期、连工作组最后征集意见都没排期；另一边 Sierra × Meta 的 PAP 草案拿到 43 家签署方，却被摩根大通与至少四家美国大行直接阻断——理由不是技术，是「认证解决不了责任」。同一天 IDC × GuidePoint 给出比例：非人类身份已达人类的 75:1，19% 的确认事件以它为初始入口，与钓鱼、被盗凭据并列。身份是入场券，从来不是票价。

第二件：「校验」被证伪为「覆盖」。NVD 在 136 毫秒内连发两条智能体 CVE——LobsterAI 的 AES-GCM 用得完全正确，密码却是公开仓库里的 lobsterai-APP，导出按钮根本不收用户输入；Omnigent 的上传校验只看了外层包，没往里看嵌套的子智能体。同一天那篇扫了 21,097 个 MCP Server 的论文把这件事做成统计：787 个（16.4%）声明自己不是文件系统，实际能读宿主机文件，150 个动态确认可利用，产出 13 份公告——包括 Anthropic 官方 Git MCP Server 的两个 CVE。更该警惕的是节奏：两个补丁都比 CVE 编号早数周，只订 CVE 情报的人在关键窗口里是失明的。

第三件：「加一层检测」被证伪为「降一层风险」。《From Detection to Decision》算得很清楚——要把漏检压到 1%，每个被测系统都得把 91.8% 以上的输入升级出去；《Language Is a Security Surface》证明同一动作只因指令语言不同，守护模型判断就不一样；HNSW 拓扑投毒在检索层做到 72% 命中 / 31.29% 攻击成功，现有防御全线失效。检测层自己就是攻击面。

产品侧今天 4 条国际 + 1 条国内，全部可追溯到具名产品：Descope 把 MCP 原生授权下沉到网关层并双向处理 ID-JAG；HOL Guard 把「智能体插件」当需要签名的软件包来管（六种包格式 + SARIF + AI BOM）；Cloudflare 把 Verified Bots 从一次性身份核验改成持续行为问责；ADTL 用会话级污点标签卡住「读公开页 → 外发私有库」；国内是 HKGAI（中国香港）开放 Agent Workshop API，把出站管控写进 gVisor 沙箱运行时。国内安全厂商侧今日无新的具名产品发布，按「宁缺毋滥」如实呈现，没有用行业内容填充。

唯一的好消息在订单侧：绿盟上半年 AI 安全订单 1.17 亿元、运营商签单同比 +300%；天融信 AI 安全防护收入同比 +130%。赛道正在从「发产品」进入「交订单」，观察指标该换了。

DescopeNHI 身份 · MCP 原生授权🔥🔥🔥

Descope 发布 Agentic Identity Hub 3.0：把 MCP 原生授权直接下沉到网关层，同时签发与校验 ID-JAG

10 月 15 日发布。Descope 称这是首家把 MCP 原生授权放进网关层的非人类身份（NHI）厂商——不是再做一个控制台，而是让网关自己成为授权点。核心能力是双向的：既签发 ID-JAG，也校验 ID-JAG，因此智能体能跨不同身份提供商取访问令牌，不必为每一条连接弹一次同意屏。这一点是它与 Okta Agent SSO 的实质差别——后者主要解决签发侧与生态分发。
配套的 Agentic Governance Suite 把入职流程做成四步：request → justify → approve → review，结果是每个智能体都留下书面用途、可问责的责任人、最小权限范围三项记录。客户端认证侧支持 SPIFFE 工作负载身份 + 双向 TLS，比 Okta 当前姿态更靠前。
厂商自述数据：已保护数百万个智能体、1,000+ 个 MCP Server，含 Claude 与 ChatGPT 应用商店上的服务器。这些是厂商口径，未经独立复核。
值得记的背景：ID-JAG 目前仍只是 -04 版 Internet-Draft，而 Descope 已经把它做成生产件——标准还没定稿，产品已经上线，这本身是今天最值得留意的一条结构性事实。

HOL Guard智能体运行时防护 · 开源🔥🔥

HOL Guard 开源「智能体杀毒软件」：在命令执行前审，把 shell、文件、包安装与 MCP 调用一起纳入策略

Apache-2.0，GitHub 约 933 stars，今日仍在更新。定位很直白——本地优先的智能体安全层，在动作发生之前审查：shell 命令、文件访问、包安装、MCP 工具调用、插件 / skill / 智能体配置变更、以及提示词与工具返回内容里的注入。判定结果三档：放行 / 阻断 / 转人工审批，审批走本地审批中心，每个决定落成本地收据（receipts）。
接入方式是原生 hook + 受管 MCP 代理 + 启动集成，适配 Codex、Claude Code、Cursor、Gemini CLI 等多种智能体；不需要账号即可本地跑，可选 Guard Cloud 做团队策略与机队管理。
第二个包 plugin-scanner 更值得注意：它把「发布前扫描」做成 CI 门禁，覆盖 六种包格式（Codex、Claude Code、DeepSeek Harness、Gemini CLI、Kimi Code、OpenCode），检查 manifest、硬编码密钥、MCP transport 与命令配置、GitHub Actions 权限、lockfile，输出 text / JSON / Markdown / SARIF，并配一个 GitHub Action 强制卡住不合规提交；同时可导出 AI BOM（hol-guard abom）。
把「智能体插件」当成需要签名的软件包来管，是这条最值得抄的地方——供应链安全的那套动作，正在被搬到 skill 与 MCP 上。

Cloudflare机器人治理 · 持续行为评估🔥🔥

Cloudflare 把 Verified Bots 从「一次性身份校验」改成「持续问责」：验证过不等于一直守规矩

10 月 16 日发布。原先的 Verified Bots 是一次性身份核验——签名对、在目录里，就打上「已验证」。新机制改成持续评估，三个判据：① 是否准确自报身份（请求用 Web Bot Auth 签名，且在 BotBase 目录中登记）；② 是否只做它声称要做的事；③ 是否遵守站点偏好——robots.txt、HTTP 429 退避、不把源站压垮。
Cloudflare 自己点出了动机：一个已知的机器人照样可能无视站点偏好或压垮源站，而且往往是配置错误而非恶意。也就是说「身份」回答不了「行为」，而 AI 爬虫与智能体正在让这个缺口变成常态。
落地节奏：目前 Cloudflare 内部先用，积累观察历史、校准「观察 → 处置建议」的映射；之后向所有客户开放，并允许客户自选信任阈值决定已验证机器人流量怎么处理；评估结果计划发布到 Cloudflare Radar。公告未给出 GA 日期、阈值配置项、评分方法与 Radar 上线时间——这三点都还是空白。
来源：Xcademia 解析 · Minoworks 周报
ADTLMCP 数据流标签 · 开源网关🔥

ADTL v0.4 发布：给每条工具返回打「完整性 × 机密性」双标签，用会话级污点阻断「读公开页 → 外发私有库」

开源 MCP 网关，作者自述为实验性项目，明确「别放在重要环境前面」。思路是把信息流控制搬到 MCP 层：每个工具返回结果都打两个标签——完整性（trusted / unknown / untrusted）与机密性（public / private / secret）；会话维护一个只收紧、不放松的标签：读过一条不可信 issue，整个会话就是 untrusted，直到结束；读过一份私有文件，就是 private。
每次工具调用前，用会话标签 × 工具出站能力做策略判断。示例规则两条就够：session.integrity: untrusted 且工具可写公开渠道 → ask；session.confidentiality: private/secret 且工具可外发 → block。
这条设计正好卡住 2025 年 Invariant Labs 演示过的 GitHub MCP 攻击链：公开 issue 藏指令 → 智能体读私有库 → 用评论外发。在 ADTL 下第三步无论模型怎么想都会被拦——不依赖模型「注意到」攻击。
v0.3.1 补了一个关键洞：Claude Code 自带的 WebFetch / Bash / Read 不经过 MCP，所以加了 Claude Code hook，让这些内置工具也污染会话标签。标签格式沿用 MCP 的 draft trust-annotations，检查逻辑走 SEP-2624 拦截器草案——没有另造格式，这点克制值得肯定。

HKGAI · 中国香港智能体运行时 · 内核级沙箱🔥🔥

HKGAI 开放 Agent Workshop API：gVisor 内核级隔离 + runsc 出站管控，单会话可挂 10 个 MCP Server

10 月 16 日，香港生成式人工智能研发中心（HKGAI，2023 年 10 月由香港特区政府 AIR@InnoHK 资助成立、香港科技大学主导）宣布 HKGAI Agent Workshop 的 API 正式开放，把智能体能力封装成标准化的「能力平台」。
安全设计是这条的重点，也是它被收进产品版块的原因：内核级沙盒隔离，明确支持 gVisor 核心级隔离 与 runsc 出站管控；每个会话配一台独立的云端电脑，权限与数据双重隔离。换句话说，出站流量是在沙箱运行时层被管住，而不是靠应用层白名单——这是与多数「智能体平台」最实质的差别。
稳定性指标：Agent 可在独立云沙箱内连续运行数十小时，单轮执行过百次工具调用；具备自动容灾（网络或服务器故障时切备用接口）与断线续传（文件与进度保留、故障后自动接棒）；流式调度支持10 路并行读、写入串行以保证一致性。
扩展协议原生支持 MCP 与 Agent Skills：每个会话最多挂载 10 个 MCP Server、单个 Server 最多 256 个工具，按需加载不占模型记忆空间。成本侧用多级渐进式上下文压缩，同时保留 URL、文件路径、ID 等关键信息。
主任郭毅可（香港科技大学首席副校长）的定位是「从技术研发走向能力赋能与生态构建」。对国内同行值得记的一点：把「出站管控」写进沙箱运行时，正在成为智能体平台的安全基线，而不是可选加分项。

IETF · OAuth WG标准进程 · 智能体身份🔥🔥🔥

ID-JAG 草案 36 天后到期，且没有排期工作组最后征集意见——六家厂商已在草案上跑生产

截至 10 月 17 日，智能体身份领域最接近统一标准的那份文件，距离到期只剩 36 天。ID-JAG（Identity Assertion JWT Authorization Grant）是 OAuth 工作组的一份 Internet-Draft，当前为 -04 版，2026 年 11 月 22 日到期；作者是 Okta 的 Aaron Parecki、Karl McGuinness 与 Ping Identity 的 Brian Campbell。它要解决的问题很具体：让一个应用在用户授权下取得另一个应用 API 的访问权，由双方都信任的 IdP 居中背书——下游授权服务器不需要再弹一次用户同意，不需要静态 API Key，签发的是短时效、带范围、可审计的令牌。这正是智能体经济规模化所需的那块砖。
但制度侧几乎停摆：IESG 状态是「I-D Exists」，没有排定 Working Group Last Call，没有 telechat 日期，没有指派区域总监。OAuth WG 2025 年 9 月采纳，一年后仍停在 -04；Parecki 本人说距成为 RFC「还要一段时间」。
商业侧没有等：Okta 把 ID-JAG 做成 Cross-App Access 商业产品，Agent SSO 于 2026 年 8 月 GA，覆盖 2 万+ 客户、生态 25+ 伙伴（含 Anthropic、Cloudflare、Keycloak、WorkOS）；MCP 已把 XAA 采纳为 Enterprise-Managed Authorization 扩展（2026 年 6 月起 stable）；Descope 10 月 15 日在其 Agentic Identity Hub 3.0 里同时做了签发与校验。
两边的风险都要说清：若 IETF 最终要求的方向与厂商已交付的实现冲突，这批厂商要返工；若草案直接失效且无继任者，正式锚点消失，实现分叉概率上升。给建设方的建议只有一句——锚定「模式」而不是锚定草案版本号。
两个数字放在一起看更刺眼：Gartner 预计 2028 年 Fortune 500 企业平均要管 15 万个智能体，而只有 13% 的组织对自身 AI 治理有信心。

LobsterAI / OmnigentCVE · 补丁先于公告🔥🔥🔥

NVD 在 136 毫秒内连发两个智能体 CVE：一个把导出密钥的密码写在公开仓库里，一个只查了外层没查子智能体

10 月 18 日 12:17:14 UTC，NVD 相隔 136 毫秒发布两条 CVE（.167Z 与 .303Z），都来自 VulnCheck，都是 AI 智能体软件，都是 vulnStatus: Received。两个产品、两种语言、两个 CWE，失效模式却是同一个：校验只覆盖了「被检查的那部分输入」，而漏洞在没人检查的那部分。
CVE-2026-112014 · LobsterAI（netease-youdao/LobsterAI，约 6,100 stars，基于 OpenClaw 的桌面级智能体）：「导出 Providers」功能把所有第三方 provider 的 API Key 写进 JSON 备份，用 AES-GCM 加密、PBKDF2 派生密钥——密码学本身没错，错在密码是 lobsterai-APP，就写在公开仓库的 src/renderer/constants/app.ts 里；导出按钮的 handler 根本不接收用户输入的密码，直接用这个常量。盐每次随机但嵌在文件里，所以任何人拿到一份默认流程导出的备份，都能用公开密码重新派生出同一把钥匙，解出全部 provider 密钥。CVSS 4.0 6.8（中危）、CWE-321 硬编码加密密钥、AV:L——攻击向量定为本地，因为密文得先流到攻击者手里（共享备份、同步网盘、邮件或工单附件、误公开）。
CVE-2026-112015 · Omnigent：智能体编排框架的上传校验只检查了提交包的工作目录，从未往里看嵌套的子智能体。
第三个细节比漏洞本身更值得警惕：两个补丁都早于 CVE 编号数周——LobsterAI 10 月 13 日修、16 日发版；Omnigent 9 月 15 日合入并当日发版。也就是说，只盯 CVE 情报源的人，在补丁与 diff 已经公开的那段时间里是完全失明的。这个「patch-before-advisory」模式本月已连续出现，正在变成常态而非例外。
来源：AL-ICE 技术复盘
学术 · arXivMCP 能力洗白 · 大规模实测🔥🔥🔥

扫描 21,097 个 MCP Server：787 个「声明不是文件系统」却具备文件系统能力，150 个动态确认可利用，13 份公告含两个 CVE

论文《My Credentials, Please: Detecting Filesystem Capability Laundering in MCP Servers at Scale》，10 月 15 日。提出一个准确的名字——「文件系统能力洗白」（filesystem capability laundering）：工具声明的范围与实际能读的路径不一致，靠精心构造的参数让工具越界读宿主机文件。
规模：扫了 9 个注册表、21,097 个 MCP Server；其中 4,806 个进入人工筛查，787 个（16.4%）被归类为「非文件系统」却实际具备文件系统能力；最终动态确认 150 个实例可利用，产出 13 份安全公告——其中包括 Anthropic 官方 Git MCP Server 的两个 CVE。
这条的价值不在比例，而在它产出了真实 CVE：说明这不是理论风险，而是「你正在用的第三方 MCP Server 里，每六个就有一个在权限声明上说了谎」。
同批值得一起读的两篇：《From Detection to Decision》（10 月 14 日）证明提示词注入检测器一旦从「二分类」变成真实生产问题「放行 / 阻断 / 升级」，要把漏检率压到 1%，每一个被测系统都得把超过 91.8% 的输入升级出去，误报随之暴涨——单一检测分数不足以支撑决策，必须显式定义升级策略；《Poisoning the Neighborhood》（10 月 15 日）则打 HNSW 近似索引的结构，用 Hub / Satellite 文档占住语义区域，在 200 万文档的 Wikipedia 语料上做到 72% 检索命中、31.29% 攻击成功，现有投毒防御全部失效。三篇合起来是一条完整的坏消息：工具在骗你、检测器分不清、检索层能被结构性污染。
来源：AI Security Digest（10/11–10/18）
OpenCode / Anomaly Innovations第三方密钥托管 · 供应链🔥🔥🔥

OpenCode Console 遭入侵：约 1.4% 用户受影响，OpenAI / Anthropic / Google 密钥可能泄露，有开发者一夜被刷 1,700 美元

10 月 17 日 OpenCode 向用户发邮件：一套正在退役的旧控制台系统遭到未授权访问，存储在该工作区的第三方模型服务密钥（OpenAI、Anthropic、Google）可能已经泄露。公司在 X 上把事件描述为「large scale distillation attack」，影响约 1.4% 的 Console 用户，且只涉及主动接入了外部 provider 的那部分账号，已逐一邮件通知；截至发稿事件仍在进行中，未公布密钥是怎么被拿到的、被拿走了多少、攻击者是谁。
后果已经在发生：有开发者称 Anthropic 账户被未授权使用、金额约 400 美元；另一人称一个早已遗忘的密钥一夜之间产生超过 1,700 美元费用。Anthropic 的 Lydia Hallie 表示已吊销其认为受影响的 Claude 密钥，OpenCode 正与三家厂商联合处置。
根因是产品设计，不是运维失误：OpenCode Console 的文档写得很清楚——「平台存储凭据并通过网关代发，成员无需看到 provider 密钥」。这对团队很方便，代价是一个第三方替你保管着带账单的长效密钥。只用开源 CLI、把密钥放在自己环境变量里的人不受影响。

🧭趋势判断 · 精简版

1. 身份层正在「先商业化、后标准化」，而标准侧已经开始倒计时

ID-JAG 停在 -04 版、11 月 22 日到期、没有 WGLC 排期；同一时间 Okta 的 Agent SSO 已覆盖 2 万+ 客户、MCP 把 XAA 定为 Enterprise-Managed Authorization、Descope 在 10 月 15 日把签发与校验都做进网关。另一条腿更乱：Sierra × Meta 的 PAP 拿到 43 家签署方，却被摩根大通等大行以「认证不等于责任」为由阻断。结论不是「标准会赢」，而是未来 12 个月里，谁的产品先落地，谁就在事实上写标准；而采购方要防的正是把某个草案版本号写进架构图。

2. 「校验只覆盖被检查的那部分」是本周所有漏洞的共同结构

LobsterAI 的密码学没错、错在密码是公开仓库里的常量；Omnigent 查了外层包、没查嵌套子智能体；Coder 的调试端口只监听了 127.0.0.1，却忘了同一台机器上有个会发 HTTP 请求的智能体；MCP 那篇论文更彻底——787 个服务器声明自己不是文件系统，实际能读宿主机文件。四件事同一个教训：安全假设的有效范围，永远等于「你实际检查过的那部分输入」。而补丁先于 CVE 数周发布，意味着只订阅 CVE 情报的团队在关键窗口里是失明的。

3. 检测器本身正在被证伪：从「给个分」到「必须定义升级策略」

《From Detection to Decision》把话说死了——要把漏检压到 1%，每个被测系统都得把 91.8% 以上的输入升级出去；《Language Is a Security Surface》补了另一刀：同一个动作，只因指令写的语言不同，小型守护模型判断就不一样；HNSW 拓扑投毒则在检索层做到 72% 命中、31.29% 攻击成功，现有投毒防御全线失效。三篇合起来推翻了一个默认假设：「加一层检测」不等于「降一层风险」，检测层自己就是攻击面。

4. 治理缺口已经从「技术问题」变成「流程位置问题」，而且被量化了

IDC × GuidePoint：NHI 与人类 75:1、19% 的确认事件以 NHI 为初始入口、近 80% 自称看得全但 40%+ 承认清单有缺口、只有 18% 对智能体做了 JIT 最小权限 + 自动纠正；Gartner：54% 的组织对「怎么限制智能体访问」根本没有方法。这两个数字解释了一个悖论——工具不缺，缺的是「谁在什么时点有权说不」这个流程位。Aembit、Opsin、Descope 这批产品卖的都是同一个位置：在智能体与资源之间插一个必须表态的点。

5. 国内进入「订单验证期」，观察指标从发布会换成签单结构

绿盟 2026H1 AI 安全订单 1.17 亿元、运营商签单 同比 +300%；天融信 AI 安全防护收入 同比 +130%、AI 赋能安全直接收入 超 8,000 万元；中信证券判断「从主题催化进入订单兑现期」。同期亚信安全拟更名「亚信智能科技集团」，八成收入已来自数智业务——两条路径并存：一条把 AI 安全做成可计量科目，一条把它当入口。值得盯的新变量是运营商成为最快落地行业：当词元被当商品经营，智能体调用链的安全账本就成了必需品而不是选配。
