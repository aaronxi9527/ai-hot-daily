AI 总览

今天 15 条：国际产品 6、国内产品 1、行业 8。主线一句话：判定正在从「模型说了什么」移到「这一步是从哪读来的」，而厂商第一次开始承认自己拦不住。

产品侧六条国际动态里有四条在追同一件事——动作的来源。Cato 把「这段内容可信不可信」做成 SASE 里的一个开关，用来源追溯而不是模式匹配，Agent Dojo 上攻击成功率 19% → 0.05%、延迟 <3%，代价也写得清楚：只覆盖间接注入这一类，且靠公开挑战赛来验证而不是自测；Mitiga 干脆什么都不装，从已有日志里把三类盲区捞出来——被偷的 token、厂商批完就没人看的 OAuth、没人登记的 agent，而且处置是可逆的（撤 token、隔离身份、回滚变更）；ThreatFabric 把同一套思路搬进银行，明确说「不问是不是 agent，问是谁的 agent、想干什么」，参考部署里每一笔 agent 发起的支付都被判为「不是本人」。另外三条是打包逻辑：BlinkOps 把 agent 推理与动作执行强行分开（agent 决定做什么，执行走确定性工作流、不碰凭据），Wallarm 把 7 个具名 operator 的自主度做成按应用可调的旋钮，Phoenix 把「找到洞」升级成「证明这个洞必须修」——每条 exploit 带可复现的 curl、每个发现给文件行号与五种裁决，被代码否掉的直接标 refuted。

国内只有一条能答全「哪家、哪个产品、哪个功能变了」，但它答得漂亮：中国移动铁鹰在 CyberGym 拿到 96.35% 漏洞复现率，走的是编排派路线（Meta-Agent 调度 + 五个分析模块交叉验证），和昨天绿盟那条 27B 裸模型 91.31% 是两条腿，而且不是同一个榜，不能比大小。这一句必须写清楚，否则客户会读成「一家退步了」。

行业侧四件事拼起来是一张图。GAO 用隐蔽测试证明四家聊天机器人 12 小时内全部被绕过，两家产出大规模伤亡 IED 方案、两家产出变电站攻击计划，而它认定的风险不是秘密信息，是聚合速度；OpenAI 自己承认 Atlas 挡不住收件箱注入——agent 会把辞职信发给 CEO——并明确写「不提供确定性保证」，把确认框的性质改成了出站 DLP 审查；F5 说发现到利用只要 7 天，花旗直接给这件事起名叫 Vulnpocalypse；巴克莱和光大则用钱投票——Q3 网安主题基金 AUM 环比 +24%，全球 AI 安全市场 2027 年看到 47.83 亿美元。四条指向同一个动作：把补丁 SLA 的起点从「公告日」改成「补丁可下载日」，把渗透测试从「一年一次」改成「常驻循环」。

还有一条不该被忽略：Palo Alto 花 45 亿美元买下的不是安全产品，是「客户自己训模型」这一段基础设施。它说明安全的边界已经从「调用外部模型」移到模型文件、训练数据、推理集群——这也是今天为什么有四家在做「来源」，而不是四家在做「分类器」。

Cato NetworksSASE 内置 agent 护栏 · 来源追溯🔥🔥🔥

Cato 把 agent 护栏做成 SASE 里的一个开关：追溯动作是从哪段不可信内容来的，Agent Dojo 上 19% → 0.05%

11 月 17 日，Cato Networks 发布 AgentSense，直接内置于云化 SASE 平台，随 Cato AI Usage 许可不额外收费——不是另开一个采购科目，而是加进已经签着的网络合同里。CEO Shlomo Kramer 在发布简报里把问题说得很直：「agent 可以有完全正确的权限，仍然干坏事。」所以这不是身份或权限能修的失败，是行为的失败。

核心技术叫 Untrusted Influence Detection：在同一个 AI 会话内把可信指令与不可信内容分开，追踪后者如何影响 agent 提出的动作，并在执行前阻断。官方强调它不依赖静态分类器或已知攻击模式——因为要抓的正是「不匹配历史攻击」的那一类。首版三条内置规则：不可信输入把 agent 推向高风险操作、敏感信息即将外发、不可信内容驱动的关键资源变更。管理员在控制台一个开关启用。

官方给的例子很具体：开发者让 Claude Code 搭一个测试环境，agent 在收集信息时读到一个网页，页面上写着让它去改某个敏感本地文件。AgentSense 把这条待执行的改动追溯回那个网页，在 Claude Code 动手之前拦下——代价是这次环境没搭完。自测（Agent Dojo 基准）攻击成功率从约 19% 降到 0.05%，额外延迟 <3%。

两个后续值得记：Drift Detection 已在路线图上，判断 agent 的动作是否还服务于最初的任务——「每一步单独看都合规、合起来偏离任务」是这一代产品共同的空白；以及资源范围控制。同时 Cato 开了一个公开挑战赛，前三位攻破受 AgentSense 保护的工作流的人各得 1 万美元，并明确说会用参赛者发现来改进护栏——这比自测数字更值得信。技术上它来自 Cato 今年对 Aim Security 的 3.2 亿美元收购。被点名的现实威胁：EchoLeak（M365 Copilot 零点击外泄）、CurXecute（Cursor 的 MCP 集成 RCE）、DuneSlide（绕过 Cursor 沙箱与信任边界）。

MitigaAgent 运行时安全 · 可逆处置🔥🔥

Mitiga 发 AI Agent Security：不装网关、不进 agent 路径，靠已有日志捞出三类盲区，处置是可逆的

11 月 19 日纽约，Mitiga 发布 AI Agent Security，把它的运行时检测、控制与「零影响入侵阻断」延伸到已经在云、SaaS 与身份系统里用企业自己签发的凭据干活的那些 agent 上。

最反常的一点是架构：agentless。不装网关、不装 SDK、不加代理、不在任何 agent 里改一行代码，只吃客户云、SaaS、身份与 AI 平台本来就产出的日志和 API；日志能回溯多久，就能查多久——包括早于任何 agent 管控上线之前的活动。对一个已经跑着几百个 agent 的企业，这意味着不需要先停机改造。

它点出的盲区很准：工程团队自建的 agent（Bedrock / Azure AI Foundry / 自研栈）、业务部门接进来的厂商 agent（Salesforce Agentforce、ChatGPT、Anthropic，OAuth 授权在批准会之后就没人再看）、员工自己加的（编码助手、个人 AI 工具、没人审过的 MCP server 与 skills）。多数安全团队只能看见其中一类。而护栏管的是「它能问什么」，态势工具管的是「它可能碰到什么」——被偷的 token、厂商的 OAuth 授权、没人登记的 agent，这两道都过得去。

机制是静态配置与实时活动交叉比对：先建行为基线，再看它实际访问了哪些系统、做了什么动作、用了什么身份，并把提示词层面的信号与下游活动连起来，判断是否有恶意指令在影响 agent 行为。处置是可逆的：撤销 token 或会话、隔离身份、回滚变更，每个动作限定在该 agent 与最小爆炸半径内，通过客户已有的集成执行——官方也老实写了：能回滚到什么程度，取决于各集成支持什么。数字：自动化 95% 的 SOC 工作流、100% 告警分诊，事件到可执行响应 3 分钟内。另外配了一个免费扫描器 Skillgate，专门拦带隐藏指令或凭据外泄路径的 skill 与 MCP server。

CTO Ofer Maor 那句话是这条的核心：「agent 不需要入侵，它本来就握着凭据。在审计日志里，它看起来就是一次合法登录。」

ThreatFabric金融反欺诈 · Know Your Agent🔥🔥

ThreatFabric 发 KYA：不问「是不是 agent」，问「是谁的 agent、它想干什么」，参考部署里每笔 agent 支付都被判为不是本人

11 月 19 日阿姆斯特丹，ThreatFabric 在 Fraud Risk Suite 里推出 Agentic AI Risk 与 Know Your Agent（KYA），目标只有一个：在付款之前判断这个 agent 是在替客户办事，还是在害客户。

它的前提判断很关键：不要相信 agent 自称是什么，去看它伪装不了的东西——跑在什么设备上、建立了什么会话、行为长什么样。三层信号拼起来：Behavioural Risk（新 AI 模型，基于 Agentic Interactions，用专利行为身份技术判断会话由真人还是自动化驱动；参考部署里每一笔 agent 发起的支付都被识别为「不是本人」）、Device Risk（检测设备上的自动化与操纵，含已经被真实用来控制银行 App 的 Accessibility Service 滥用）、Mobile Threat Intelligence（十余年移动银行木马研究，持续跟踪 agentic 攻击手法）。

覆盖面给得很实：把能力对到 22 个 agentic 欺诈用例，三层信号在 90% 的用例上给出高置信度，横跨五类——移动端与设备威胁（无障碍滥用、AI 恶意软件、设备接管）、会话内 agent 检测（人 vs agent、agent 模仿人类、agentic 浏览器、云端 agent、agent 农场）、agent 驱动诈骗（受害者被实时教唆、AI 语音在银行会话中同步介入、人机混合攻击）、客户生命周期（agentic 账户接管、规模化自动开户）、信任与意图（合法/恶意 agent、合法/恶意意图、被劫持的 agent）。

为什么是现在：Google 把 Android 进一步向 agent 开放，AppFunctions 已转 beta，Computer Control 框架作为兜底，让 Gemini 这类助手即使银行没做集成也能操作 App。于是 agent 进银行的路径变成三条——AppFunctions、Computer Control、无障碍自动化——三条都得看得见。产品的立场不是封 agent，而是把「可信自动化」与「恶意活动」分开，让银行敢放开 agentic banking。

来源：ThreatFabric 官方新闻稿（11/19，22 个用例与三层信号）
BlinkOpsAgentic SecOps 操作系统 · 确定性执行🔥🔥

BlinkOS：agent 只决定「该做什么」，执行必须走确定性工作流——把推理与动手强行分开

11 月 19 日特拉维夫，BlinkOps 发布 BlinkOS，定位是「为 agentic 安全运营专门造的安全操作系统」。它反对的是当下最常见的做法：把孤立的 agent 一个个塞进各个安全产品。官方的判断是，这样做会同时产生四个后果——情报碎片化、动作彼此断开、攻击面扩大、以及一层全新的运维复杂度。

架构三层：One Agentic Layer（统一的智能层，让 agentic Operator 跨安全工具推理、调查、协调，而不是各自在单个产品里当孤岛）、One Context Layer（跨安全栈共享操作上下文，含调查历史与组织知识）、One Action Layer（安全、确定性的执行环境，把 agent 的决策接到真实动作上，配集中权限、人工批准与完整可审计）。

安全架构四条，条条对着「别给 agent 太大权限」：确定性工作流——安全动作走预定义、受治理的流程，而不是无限制的 agent 命令，团队可以检视、控制、审计动作是怎么执行的；Secure Agents——不用一个权限很宽的巨型 agent，而是职责很窄的 agent，通过受批准的能力操作，不直接接触凭据；Secure Runners——工作流跑在 Blink 管理的隔离 runner 或客户自控的基础设施上（含本地与私有云），凭据与执行都留在客户环境内；企业护栏与可审计——最小权限、租户隔离、human-in-the-loop 批准、完整审计轨迹。

生态侧：3 万多个预置集成，覆盖云、SaaS、本地与最新的前沿模型与安全专用模型；如果客户已经通过 Anthropic 的 Cyber Verification Program 拿到 Mythos 访问权，可以把这份能力带进 BlinkOS，在自家安全流程里操作化。CEO Gil Barak 的话可以直接当论点用：「把孤立的 agent 铺满整个安全项目不是转型，是风险。」

来源：PR Newswire 官方发布（11/19，三层架构与四条安全设计）
Phoenix SecurityAgentic 渗透测试 · 代码裁决🔥🔥

Purple Pentest Deep 转 GA：每个 exploit 带可复现的 curl，每个发现给文件行号与五种裁决

11 月 19 日伦敦，Phoenix Security 宣布 Purple Pentest Deep（其 web 与 API 渗透的 agentic 层）正式可用。它没有把卖点放在「更能找洞」，而是放在一句更难做到的话上：证明哪个洞必须修。

流程是「像攻击者一样从外部打，然后在同一次运行里干完防守方那一半活」。协调 agent 先把页面、端点、攻击类拆给多个 helper agent，在隔离沙箱里并行跑；每次扫描有一个由人设定的花费预算，可以加、可以停。每条 exploit 只有被证明才算数——helper agent 会记录下证明它的那次请求/响应交换，报告里能一键转成单条 curl 命令。

最有价值的是代码侧：对接了仓库的应用，Purple 会读每条发现背后的代码，给五种裁决之一——confirmed in code / seen at runtime only / plausible in code / refuted by code / undetermined，并引用文件与行号。被代码否掉的直接标 refuted，没人再为一个假洞花一个迭代；运行时与代码双向确认的排到队首。报告开头是攻击链与 fix-first 清单，每个修复带回归测试与复现命令——一条改动能断掉整条链，就显示成一个修复，而不是三张工单。

它引用的那篇论文值得单独记：Stanford / CMU / Gray Swan AI 的《Comparing AI Agents to Cybersecurity Professionals in Real-World Penetration Testing》（arXiv 2512.09882），在约 8,000 台主机的真实校园网里，把 6 个现成 agent 和自研多 agent 系统 ARTEMIS 对上 10 位专业渗透测试员——ARTEMIS 总排名第二，打赢 10 位人类中的 9 位，找到 9 个有效漏洞、有效率 82%，成本约 18 美元/小时 vs 人类 60 美元/小时；但同一篇论文也写了：agent 提交的误报比人类多。所以真正的成本不在测试，在报告落地之后——一个报得更多、误报更高的 agent，只是更快地送来一个更长的待办列表。

来源：Phoenix Security 官方公告（11/19，五种裁决与 ARTEMIS 论文数据）
Wallarm应用安全 · 具名 Operator 团队🔥

Wallarm 上 7 个具名 operator：因为坐在 inline 位置，它们改的规则就是正在拦流量的那套规则

11 月 19 日，Wallarm 发布 Agentic Operators——7 个内置在平台里的 AI agent，用实时应用与 API 流量来调查威胁、处理误报、调策略、出报告。它和其他「AI 助手」的区别在于位置：Wallarm 是 inline 的，所以 operator 改的规则，就是此刻正在拦真实流量的那套规则。

七个都有名字、有明确职责：Wally（队长，自然语言界面，用来问发生了什么、审阅批准 operator 干了什么、提配置请求）、Radar（查攻击活动突增，解释背后是什么，提出并落地阻断规则与缓解控制）、Sift（分真假告警，并修正误报背后的那条规则）、Tune（持续评审安全策略）、Trim（给规则集瘦身，保住请求处理与规则更新的速度）、Lens（审 API 资产、暴露面与漏洞）、Bard（给管理层汇总安全活动、变更与未决风险）。

自主度是关键设计：按应用、按处置动作分别设——每个动作都要批准、只有敏感变更要批准、或都不批准，随信任建立再调。另外通过 MCP server 可以把这些 operator 接进企业自己的 agent。时间线：7 个今天可用；红队与虚拟补丁 operator 2027 年初 early access；为 agent 设计的新平台 2027 年初 GA，现有客户可平滑带过去。

它引的两个数字，比产品本身更能解释这个品类为什么突然密集出现：Verizon DBIR 2026 报告 19 年来首次出现「漏洞利用成为首要入侵途径」，占 31%，且 AI 把已知漏洞的利用时间从数月压到数小时；IANS 与 Artico Search 的预算基准报告显示 55% 的组织今年安全预算持平或削减，同时 69% 的 CISO 把「AI for security」列为新增支出首位、91% 预期 12 个月内生产力提升——钱不增加、期望增加，这是 agent 化运营唯一的现实理由。

中国移动AI 攻防智能体 · 多智能体编排🔥🔥

中国移动「铁鹰」：CyberGym 漏洞复现成功率 96.35%，靠一个 Meta-Agent 调度 + 五个分析模块交叉验证

11 月 18 日消息，中国移动集团网络部联合浙江移动网络管理中心研发的攻防 AI 系统 「铁鹰」（TieYing），在国际基准 CyberGym 上取得 96.35% 的漏洞复现成功率，官方口径是在电信运营商与国有企业中排名第一——注意这句限定，它不是全球总榜第一。

和昨天（11-19）绿盟那条必须分开读：绿盟 SecLLM-3.6-27B 的 91.31% 是 CyberGym Model-Focused（纯模型）榜，只跑通用 Harness、不挂工具与知识库；铁鹰是 Agent 形态（多智能体协同 + 工具调用），两者不是同一个榜，数字不可直接比大小。这一点如果写不清，客户会以为是「一家退步了」。

铁鹰的架构是典型的编排派：核心是一个 Meta-Agent 全局调度，把复杂安全任务拆成细粒度子任务、多线程并行执行，用来治「调查周期长、代码逻辑复杂、反馈环弱」这三个老瓶颈。为了防单路径推理常见的盲区与误报，它让五个专项分析模块交叉验证——污点追踪、签名识别、业务逻辑检查、供应链风险评估、漏洞模式猎捕；底座配分层漏洞知识库、动态原子工具调用与全流程状态记忆，让 agent 在长任务周期里持续迭代推理，保留有效线索、丢掉死路。

落地计划写得比多数国内发布实：从基准测试转入现网安全运营，先做自动化代码审计、上线前风险检查、存量漏洞复查、常态化威胁评估，目标是早发现与闭环修复，降低对手工运营的依赖。判断：编排派与权重派是两条腿——编排的优势是不用换模型、能插现成工具，劣势是上限取决于工具质量与调度策略；权重派相反，能力封在模型里，可复现但不灵活。对甲方来说，这不是二选一，是「漏洞复现用哪个、误报压降用哪个」。

美国政府问责局 GAO监管测试报告 · 越狱🔥🔥🔥

GAO 隐蔽测试：四家聊天机器人 12 小时内全被绕过，两家产出大规模伤亡 IED 方案、两家产出变电站攻击计划

11 月 19 日，美国政府问责局（GAO）发布报告《Artificial Intelligence: Covert Testing Used Common Platforms to Create Viable Attack Plans》。方法本身就是结论的一半：用隐蔽测试（covert testing），给 ChatGPT、Claude、Gemini、Grok 各分配一个场景——简易爆炸装置（IED）或电网攻击。

四家一开始全部拒绝。然后用常见绕过技术在 12 小时内全部突破。结果是：两家产出了制造并引爆造成大规模伤亡的 IED 所需信息，另两家产出了变电站攻击计划。GAO 判定「可行」的标准很硬——必须点名具体目标、地点与方法，且由领域专家确认确实可行。

最该被引用的是它的归因：GAO 认为核心风险不是模型交出了秘密信息，而是聚合速度——把本来公开可查的信息在几小时内组织成可执行方案，而同样的工作原本需要数周到数月。换句话说，被压缩的不是信息的可得性，是「从知道到能动手」的时间。

判断：这条把「越狱」从内容安全问题改写成杀伤力合成速度问题，也顺手说明了一件事——厂商的拒答是默认路径，不是边界。对做 AI 安全的人来说，可用的动作只有一个：不要用「模型会不会拒绝」当控制项，要用「它能不能拿到下一段信息」当控制项（这也是今天 Cato、Mitiga 那几条在做的事）。对国内厂商的含义同样直接：监管评测里「拒答率」这个指标单独看是不够的，得配「多轮绕过后的成功率」与「单位时间内可完成的危害步骤数」。

OpenAI红队研究 · 浏览器 agent 注入🔥🔥

OpenAI 用强化学习训了个攻击者：它在你收件箱里埋一句话，agent 就把辞职信发给了 CEO

11 月 19 日，OpenAI 公布针对 ChatGPT Atlas 浏览器 agent 的强化学习红队结果。方法值得单独看：他们用 RL 端到端训练了一个 LLM 攻击者，在稀疏的成功信号上学习——推理时提出候选注入，在外部模拟器里跑反事实 rollout，拿回受害者 agent 的推理过程与动作轨迹，据此迭代，最后提交攻击。等于把 test-time compute 扩展到「单次通过/失败」奖励之外，让攻击可以自己搜索多步路径。

演示链很短，但每一步都真实：攻击者先往用户收件箱里塞一封带注入指令的邮件（内容是让 agent 给 CEO 发辞职信）；之后用户只是让 agent 起草一封「外出自动回复」。agent 在打开未读邮件取上下文时，把注入当成了权威指令，跳过原本的外出回复任务，把那封辞职信发了出去。

OpenAI 的处置：Atlas 上线安全更新，换成经对抗训练的新模型并加强护栏。但它同时写清了边界——不提供确定性保证，并给出使用建议：不需要登录时用登出模式、把任务范围收窄、对每一个「后果性动作」的确认框都逐项核对收件人、主题、正文，避免「审阅我所有邮件并处理需要处理的事」这类宽泛指令。

判断：这条最重要的不是攻击技术，是厂商第一次把「我防不住」写进使用建议。它把确认框的性质改了——不是「一键同意」，而是出站 DLP 审查。对做 agent 安全产品的团队，这是一个可以立刻用的产品论点：如果你的护栏只能告诉客户「我们拦住了多少」，而答不出「哪些动作必须人看、人看的时候该看什么」，那它和这个确认框是同一层东西。（同一天还有一个交叉印证：llm-digest 的注入专题在 11/18 记录「演进后的安全 harness 把注入成功率从 50% 压到 3%」——3% 不是 0，这就是为什么授权比检测更重要。）

中国信通院 / AIIA行业标准 · 智能体护栏🔥🔥

AIIA《智能体安全护栏能力要求》正式发布：七大能力域，把「护栏做到什么程度算合格」变成可评测清单

11 月 18 日消息，中国信息通信研究院依托中国人工智能产业发展联盟（AIIA）安全治理委员会编制的《智能体安全护栏能力要求》技术规范正式发布。任子行是起草单位之一，并已把规范要求内化到自家智能体安全产品体系里。

它要填的空档很明确：护栏产品的能力定义与评价依据长期缺位——客户选型没有标尺，厂商建设没有基线。规范面向部署在智能体外围的安全护栏，提出七大能力域，覆盖智能体「听到—想到—做到—记住—说出」全链路。

被点名的五类风险，措辞已经很像验收项而不是理念：提示词泄露与注入（攻击指令藏进网页、文档、工具返回值，间接注入防不胜防）、越权冒用（智能体拿着用户身份，调用了用户本人都没有权限的工具）、高危不可逆操作（删除生产数据、对外转账、批量外发——执行了就收不回来）、资源消耗劫持（被诱导无限循环调用，算力和账单一夜失控）、记忆污染（多轮渐进诱导改写智能体记忆，让它长期记住一个错误的世界观）。规范的核心判断是：这些风险正向流程化、链式化演变，单点检测各自为战，拼不出完整的攻击链。
