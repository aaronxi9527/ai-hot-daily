AI 总览 · 今日看点

今天的主线是「智能体身份与治理层被批量产品化」。10 月 6 日至 7 日两天里，RSA、AppViewX、SailPoint、AIBound、Anaconda 五家几乎同时把「发现影子智能体 → 给智能体发身份 → 运行时一键终止 → 把策略塞进智能体内部」做成了可售卖的模块，HTB 甚至专门做了测评「安全智能体能不能胜任岗位」的平台。而另一边，AWS 的智能体编排平台 Loom 爆出 CVSS 10.0 的未认证超管接管漏洞，OX Security 又审计出 15,465 个公开 MCP 服务器「零审核、2.3% 悬空域名可被 12 美元劫持」。

RSA智能体身份安全 / AI·MCP 网关🔥🔥🔥

RSA 发布 Agent ID：给每个智能体发身份、配责任人，高风险动作必须「人线下签字」

10 月 7 日，在荷兰 World Summit AI 上，RSA 发布 RSA Agent ID——面向政府、金融等高合规行业的智能体身份安全平台，由三个可独立部署、也可互联的模块组成：
① Discover——跨身份、云、终端与网关源发现已知与影子智能体及 MCP 服务器，把每一个注册为一等身份，绑定具名责任人、风险等级与生命周期状态，并挂接到企业已有的身份提供方；
② Secure——在 AI/MCP Gateway 上对每次调用执行策略，网关可按个选择 RSA 托管或客户自建；高风险动作要求具名、已认证的操作员用抗钓鱼凭证线下批准，智能体退役即吊销访问；
③ Govern——像治理人一样治理智能体：持续认证、基于风险的访问复核、生命周期自动化。
支撑它的两个数字很扎眼：Gartner 预计到 2028 年，一家典型的全球 500 强企业将运行约 15 万个 AI 智能体（2025 年不足 15 个），而仅 13% 的组织认为自身的智能体治理到位；IBM 发现涉「影子 AI」的事件平均比常规事件多花 67 万美元。
主权设计上，租户数据留在所选区域（美 / 欧），执行证据在网关侧生成并流入 SIEM；2027 年计划推出全气隙自管版本。

Hack The BoxAI 安全智能体测评平台🔥🔥

Hack The Box 推出 AI Range 企业版：首个专门度量「安全智能体能不能胜任岗位」的平台

10 月 7 日，Hack The Box（HTB）推出 AI Range Enterprise Edition，官方称是业界首个用于测试与度量 AI 安全智能体效能的平台。企业可以用它评估自己的智能体能否胜任被指派的网络安全角色，再决定如何在团队里投放智能体。
核心是两套方法论：Agentic Worker Competence——在真实条件下证明某个智能体能否把某个岗位做到标准；Agentic Operator Competence Scoring——用实操安全场景评估 AI 辅助工作背后的判断力。
输出物包括角色化评分、单环境的通过 / 不通过结论，以及随时间变化的性能视图；当模型、软件、数据集与运行条件变化后可重复测评，从而看出能力是提升、下降还是原地踏步。
AI Range 于 2025 年 12 月首发，此后已被 AI 实验室、政府客户与超大规模云厂商压测过。HTB 创始人 Haris Pylarinos 的说法是：既要确认智能体能干这份活，也要确认有人有专业能力去指挥、验证并在必要时接手。

AWS智能体编排平台漏洞 / 未认证提权合并 3 源🔥🔥🔥

AWS 智能体编排平台 Loom 爆 CVSS 10.0 漏洞：未配身份提供方时，任何人都是超级管理员

10 月 2 日，AWS 安全公告 2026-124-AWS 披露 AWS Labs 开源智能体编排平台 Loom 的三个漏洞；10 月 4 日，CVE-2026-103956 的公开 PoC 已出现在 GitHub。
CVE-2026-103956（CVSS 3.1 与 v4.0 均为 10.0，Critical）：认证依赖里存在硬编码兜底身份（t-admin / g-admins-super），在未配置身份提供方的部署中，任何能访问应用 API 的网络客户端都能直接拿到智能体控制面的超级管理员权限——可注册恶意工具服务器、读取已存的集成凭证、改写托管智能体角色挂载的 IAM 策略，从而把应用层缺陷放大成 AWS 账户级风险。已在 1.6.1 修复。
CVE-2026-103957（配置恶意 OAuth2 发现文档，把客户端密钥或其他用户访问令牌投递到攻击者端点）与 CVE-2026-103958（MCP 工具服务器 / A2A 远程智能体连接处理的 SSRF，可读取容器的凭证分发端点）需持有 mcp:write / a2a:write 的已认证用户，均在 1.7.0 修复。
同批还修补了 Amazon SageMaker Unified Studio 的 CVE-2026-104019：Studio Space 启动脚本存在 OS 命令注入，可在他人的 Space 中执行任意命令，并在启用可信身份传播时窃取对方的临时执行角色凭证。
官方口径是协调披露、未见在野利用（EPSS 30 天内利用概率 0.3%–0.5%）。但补丁不等于恢复完整：OAuth2 客户端密钥、在流通的访问令牌与平台托管的 IAM 会话凭证都必须轮换，并回溯 CloudTrail 查异常 IAM 策略变更。

OX SecurityMCP 供应链审计 / 行业研究合并 3 源🔥🔥🔥

OX Security 审计 15,465 个公开 MCP 服务器：零审核流程，2.3% 悬空域名花 12 美元就能劫持

10 月初，OX Security 对 5 个注册表中 15,465 个公开索引的 MCP 服务器（去重后 5,095 个唯一主机名）做了安全分析，结论是：没有任何 MCP 市场设有安全护栏或审核流程——任何人可发布，发布与消费之间没有审核层，而且仓库里可见的代码未必等于远端实际执行的代码。
三个关键数字：15.6% 的主机名解析到美国境外（含中国 19 个、俄罗斯 18 个）；0.45% 通过 ngrok 之类的消费级隧道跑在个人机器与家庭网络上；2.3% 的主机名已不再解析，其中 6 个挂在可花 4–12 美元买下的过期域名上——攻击者注册后即继承该服务器既有身份，并自动接收所有仍配置调用它的智能体流量，无需任何漏洞利用。
报告里最刺眼的对照是：2012 年 Google 的 Bouncer 至少还尝试对 Android 应用做自动审核，而 2026 年的 MCP 市场连等价物都没有。攻击链被完整映射为「恶意服务器上架 → 智能体信任关系被利用 → 横向移动到云工作负载 → 数据外泄至境外司法辖区」。

📈 趋势判断 · 精简版

1. 智能体治理正在从「讲理念」变成「装模块」

48 小时内，RSA 的 Discover/Secure/Govern、AppViewX 的 Guardian Agent + MCP Gateway + Kill Switch、SailPoint 的 Autonomous Agents + A-ISPM、AIBound 的 AgentHarness、Anaconda 的集群协调，五家给出了几乎互补的拼图。共同点是把「发现影子智能体」放在第一位——你管不了一个你不知道存在的智能体。

2. 但基础设施层的默认值仍在裸奔

AWS Loom 的 t-admin / g-admins-super 硬编码兜底、15,465 个零审核的 MCP 服务器、2.3% 可被 12 美元劫持的悬空域名、Copilot CLI 的模型级行为差异——治理工具在应用层越做越厚，而编排层、协议层与市场层的默认配置没有同步收紧。缺的从来不是新功能，是把 fail-closed 变成默认。

3. 「模型差异」成为新的评估盲区

同一个 Copilot CLI，换一个底层模型就从「约半数中招」变成「完全拒绝」；Security-One 在不同注入数据集上从 99.83% 掉到 78.33%。采购与合规若只做一次性评测，测的可能根本不是上线时生效的那套组合——这要求评测从「选型时做一次」变成「随模型版本持续做」。

4. 责任落点继续向「开发方 / 运营方」收拢

LASST 起诉 OpenAI、共和党州检察长联盟要求保全记录、保险公司计提索赔并讨论高管个人责任、FTC 明确拒绝把智能体当作独立法律主体——四件事指向同一句话：智能体不担责，造它和用它的人担责。合同、保险与内部责任划分需要按这个前提重写。

5. 开源权重被重新定义为防御资产

Mistral 把「闭源模型会在关键时刻拒绝合法的漏洞研究」当成 ML4 的核心卖点，Visa 开源部分 AI 网络防御系统，加拿大明确允许联邦部门用防御性 AI 工具查漏洞——一年前还被当作风险源的开源权重，现在被摆到了防御侧。「谁来保证防御方不被自家的安全过滤器拦住」，正在成为一条独立的采购问题。
