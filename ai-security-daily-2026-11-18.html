AI 总览

今天 13 条：国际产品 6、国内产品 1、行业 6。主线只有一句：「能停」和「能查」正在从加分项变成默认值，而默认值一旦定错，事后补不回来。

产品侧六条里有五条在做同一件事——把判定挪到一个模型改不了的位置。微软的 MAI Cyber 2 Flash 走的是最反直觉的一条：不把判定往外挪，而是把判定训进权重，然后把卖点从「能力上限」换成「每任务成本不到通用前沿模型的 2%」，再顺手把它设为 12 月中旬自动替换——客户连「要不要换」这个决定都不需要做。Greymatter 2.5 和 FIOR 26.2 走的是另一头：前者把护栏、DLP、WAF 和取证账本塞进每一个 proxy，还特意写「凭据在每一处缝隙被擦除」——这句话决定账本能不能外发；后者给每个模型、agent、工具发一张密码学护照，在动作执行之前做确定性裁决，还第一天就接了 Linux Foundation 的 ANS 证书标准。Commvault 则补上了所有人都在回避的一段：回滚 agent 不等于恢复业务，它已经提交到外部系统的副作用得靠补偿动作处理。

行业侧同一天给了三份「同一件事的不同证据」。Gartner 说 95% 的组织过去一年出过 agent 事故，但只有 15% 装了熔断，而 70% 相信自己跑在安全边界内；Palo Alto 说 99% 的企业发现过无治理 AI，能自动发现分类的只有 9%，53% 还把 agent 活动记在人的身份下、40% 事后无法重建 agent 干了什么；而 Grok Bot 那 31 次深夜读取把这两组数字变成了具体场景——只问写不问读、开关默认开、关掉要等 8 天、onboarding 里那条告知会滚出屏幕，研究者的结论是「没有 bug 要修，这正是它比 bug 更糟的原因」。三份材料指向同一个采购问题：不是「你防住了什么」，而是「停得下来吗、查得清吗、默认值是谁定的」。

国内只有一条，但它是这一周最像产品的一条：腾讯朱雀的 A.I.G 补上 aig-compliance 0.1.0，把生成式 AI 合规自查做成本地跑、数据不出机的工具，还给了三个可当场跑出来的阈值（应拒答率 ≥95%、误拒率 ≤5%、生成内容合格率 ≥90%）。国内连续第七天处在体系叙事期——本周被引用的产品名不少，但能写进 release notes 的变更只有这一条，其余一律未收。

Microsoft安全专用模型 · 漏洞挖掘🔥🔥🔥

微软发 MAI Cyber 2 Flash：安全专用模型第一次把「每任务成本」当卖点，不到通用前沿模型的 2%

11 月 17 日，微软 AI 部门发布安全专用模型 MAI Cyber 2 Flash，定位写得很直白：面向企业安全团队的「高性价比」网络安全 AI，帮安全人员全天候找软件漏洞、给修复建议、查威胁，同时把大规模用 AI 的算力和成本压下来。

数字要连着读。在衡量真实漏洞发现能力的 CyberGym-E2E 基准上，它拿到 92.3% 任务成功率，略高于 GPT-6 Astra 的 91.5%；而微软披露的每任务成本不足后者的 2%。这个对比的统计口径微软自己写清楚了：剔除 92 个与训练数据来源重叠的任务后，基于剩余 813 个任务统计。另一项 WebExploitBench 在同等推理预算下 40.4%，高于 GPT-5.6 Cyber 的 38.4%。上下文窗口 100 万 token，是上一代 MAI Cyber 1.1 Flash 的四倍，官方给的理由是「一次性分析更大规模代码库、更适合复杂多步的安全调查」。

落地方式比跑分更值得看。它专供微软自家安全产品，包括代号 MDASH 的多智能体扫描系统；自 12 月中旬起，符合条件客户 MAI 配置里的现有模型会被自动替换为 MAI Cyber 2 Flash——不需要客户做迁移动作，也不需要重新评估采购。Insight Enterprises 的初步评估称，MAI Cyber 相较 GPT Profile 的 token 效率高 20%。

微软同时给了两句限定，值得原样引用：性能与成本对比会随工作负载、模型配置、推理强度与评测方法变化；成本数据反映的是离线评估成本，不等同于客户实际支出。判断：这条真正的新意不在跑分，而在「安全专用模型」开始用「单位任务成本」而不是「能力上限」来定价值——上一代 MAI Cyber 1.1 Flash（10 月 27 日）打的还是「MDASH 份额 30 天翻倍到 50%」这种采用率叙事，这一代直接进成本表。对甲方的含义是：漏洞挖掘的边际成本正在逼近零，瓶颈整体后移到「修得过来吗」。

Greymatter.io零信任运行时 · AI 护栏🔥🔥

Greymatter 2.5：把护栏、DLP、WAF 和取证账本塞进每一个 proxy——「大多数 AI 护栏站在缝外面」

11 月 12 日，Greymatter.io 宣布 Greymatter 2.5 正式可用，一次改了平台 15 个区域。它对自己赛道的批评是这条产品最锋利的部分：「大多数 AI 护栏站在缝外面。它们只测量发往端点的那一段，永远看不到服务之间、agent 之间、agent 与工具之间的调用。」CEO Chris Holmes 的原话是：安全团队需要的是证明——每一次调用都带着已验证的身份、每一条提示词都被检查过、每一个控制都在它该在的位置上运行。

所以它选了和「在 AI 流量前面加一个检查点」相反的路：身份、检查、审计做进每一跳。具体是四件事。① Forensic Audit：跨每一跳追踪任意一次请求，每一跳都带着当时那个人的身份，且凭据在每一处缝隙被擦除，所以账本里不存密钥——这条直接决定账本能不能外发。② 护栏 + DLP：拦提示词注入，同时标记提示词与回复里的个人、健康等敏感数据。③ 模型访问治理：模型调用只能去已批准的厂商，每个人有每日 token 预算，每次调用计量留档。④ 内置 WAF：先展示「它会拦什么」，再让人打开阻断——这个「先看后开」的顺序，是给不敢直接上阻断的团队留的台阶。

另外三块偏治理：新 Console 把每个租户的健康与安全放在一屏、用白话讲哪里不对；零接触 onboarding——管理员按策略登记一个团队，其工作负载带着各自身份自动加入网格，应用团队不写任何配置；Stoplight 给 12 项控制打分，映射到 DoD Zero Trust、CISA ZTMM、GDPR 等，每个分数可导出它背后的证据。密码学侧默认开：经验证的后量子加密 + FIPS 140-3，且不需要改应用。还有一个「Ask Greymatter」：用自然语言问实时数据，每个人只看到自己有权看的那部分。

判断：它和 11-17 那批「AI 网关」不是一类东西——网关管的是「进出模型的流量」，Greymatter 管的是「服务网格内部每一次调用」。真正可抄的一句是 「凭据在每一跳被擦掉」：多数审计日志不敢外发，就是因为里面躺着 token。

FIORAI 网关 · Agent 身份🔥🔥

FIOR AI Gateway 26.2：给每个模型、agent、工具发一张密码学护照，动作执行前确定性拦截

11 月 12 日，伦敦。FIOR Group 发布核心产品 AI Gateway 26.2。它把企业的问题拆成两步，且认为顺序不能反：先有发现问题，才有治理问题——很多组织至今还在靠清单、制度文档和事后分析管 AI 风险，这三样都没法在 agent 动作发生的当下识别或阻止它。

产品结构是五件套合一：Sensor（在主机、应用、网络三处发现 AI 活动）、Tool Catalogue、Model Catalogue、Threat Intelligence、Agent Identity。每个被发现的模型、agent 或工具绑定一个身份，并签发一张密码学安全的「护照」；网关把每一次请求的动作与组织策略、以及目录里已批准的模型和工具比对，在执行之前确定性地阻断越权动作——注意是「确定性」而不是「模型判断」，这条在多 agent 场景里是硬要求。威胁情报这一版的变化是把观察到的威胁与不安全行为直接喂进策略与执行决策，而不是停在监控面板上。

两个集成点值得记：① NVIDIA OpenShell（开源、在策略受控沙箱里执行自主 agent 的运行时）——OpenShell 负责隔离与监督 agent 运行，FIOR 负责验证「是哪个 agent 在动、能用哪些模型和工具、按什么策略与情报裁决」，并把每个决策记成安全证据。② ANS（Agent Name Service）：Linux Foundation 刚推的开放标准，用 P-256 agent 证书给 agent 发身份，FIOR 26.2 第一天就支持，并把 ANS 身份与自己的权限控制叠加。CTO James Patrick 把「主权」讲得很清楚：多数客户想要的是不把 agent 的存在与活动共享给任何身份提供商的自主身份，但愿意的话也可以把 ANS 作为一个因子用进来。

部署侧：公有云、私有云、客户机房、边缘、以及断网/受限环境都能跑，同一套控制；AI 流量可以不出企业自己的安全边界，不需要经过 FIOR 托管服务。判断：这条的价值在于它把「agent 身份」从概念做成了证书 + 目录 + 执行前裁决三件可验收的东西，与 11-17 期 SailPoint 从 IAM 侧进、这条从流量与身份签发侧进，是两条不同的入口。

CanonicalAI 生成补丁 · 修复流水线🔥🔥

Canonical 把 AI 生成的补丁放进 Ubuntu Pro 的 Edge 通道：你可以自己先尝，但内核不在里面

11 月 12 日（Ubuntu Summit 26.10），Canonical 在 Ubuntu Pro 里开了一个 opt-in 的 Edge archive：由自研多智能体框架 Surge 生成的安全补丁，在完成完整鉴定之前，先给 Pro 用户取用。稳定通道仍然是人工验证的，这条被官方反复强调。

Surge 的流水线值得逐段看：intake（把 CVE 源映射到受影响的 Ubuntu 包，不在范围内的直接停）→ code forensics（取上游补丁与源码上下文）→ backporting engine（多个竞争模型各自合成候选补丁） → consensus-gated judging（独立裁判模型投票，僵局升级给人） → 标准 Ubuntu 包构建与确定性测试。边界情况、低置信度、僵局一律路由给 Canonical 安全工程师。架构上有一处刻意的排除：内核 CVE 不走 Surge，仍走重叠的两周 SRU 周期与认证硬件验证——理由是内核稳定性的要求不同。

使用上要看清三个约束：Edge 的 APT 优先级低于标准档案库，除非显式执行 sudo pro-enable-edge --automatic-updates，否则不会自动装进来；支持 18.04 到 26.04 的 LTS，不支持 26.10 这类过渡版本；命令是 sudo apt install pro-edge 加 sudo pro-enable-edge。换句话说，从 Edge 取补丁的团队，自己就成了 soak（浸泡测试）队列的一部分。

动机写在数字里：Canonical 说安全团队今年发出的修复量已经是去年的两倍，而 2026 年 10 月单月的 CVE 数量几乎等于 2025 年全年。Pierre Guillemin 的表述是「用 AI 对抗 AI」。判断：这是本轮唯一一条把「AI 生成补丁」做成可选消费通道而不是内部效率工具的发布，也因此把风险显式转给了愿意承担的人——它不是「更快的安全更新」，是「更快的、需要你自己鉴定的安全更新」，采购时不能当成前者写进 SLA。

CommvaultAgent 恢复 · 弹性运营🔥🔥

Commvault 发布 AgentRecover：不只回滚 agent，还要把被它改过的东西一起恢复

11 月 10 日，Commvault 在 SHIFT 2026 上发布 AgentRecover，同时提出 ResOps（resilience operations）框架。它抓的是一个被行业忽略的差别：「agent 回滚」不等于「业务恢复」——把 agent 的代码、提示词、配置退回到上一版，并不能撤销它已经提交到外部系统里的副作用；改过的数据库记录、发出去的外部通信，都还在。要处理这些，得靠设计好的补偿动作（compensation）。

三项能力：① 发现受支持的 agent，并把它依赖的数据、应用、身份、配置、基础设施映射成一张依赖图；② 审计——通过 agent trace 记录它做了什么、可能改了什么，把「某个动作」和「相关资源」对齐；③ 恢复——同时恢复 agent 本身与被它影响的资源，聚焦在「它改了什么」而不是整环境回滚，避免为了修一个 agent 把无关系统也停掉。

平台范围写得很实：Microsoft Foundry 11 月 early access、Amazon Bedrock AgentCore 12 月 early access，这是它首批支持的两个 agent 平台；没有给 GA 日期，也没有给价格。同框架下还有 Recovery Studio（自动化 runbook，内置威胁扫描，确保环境干净再回生产）、Identity Recovery（AD / Entra ID / Okta 的变更审计，含预置 AD 备机）、Data Posture 360（结合 Satori 的技术，把访问策略做到行列级）。

CTO Pranay Ahlawat 的话是整条的核心：「业务逻辑正在从应用搬到 agent 里，而 agent 不是确定性运行的。一个 agent 决策就能跨平台改掉数据、应用和基础设施。」IDC 研究副总裁 Phil Goodwin 的补充是：传统恢复假设「某个时间点的一批数据」，agent 式恢复必须同时恢复 agent、数据和资源，且都以机器速度。判断：这条对国内厂商的启示很直接——大家都在做「发现 + 阻断」，「恢复」这一段几乎是空白，而它恰恰是甲方在事故复盘会上第一个问的问题。

腾讯朱雀实验室AI 红队 · 合规自查🔥🔥

A.I.G 补上第六块拼图：aig-compliance 0.1.0 让企业自己跑一遍生成式 AI 合规自查，数据不出本机

11 月 11 日，腾讯朱雀实验室开源的 AI 红队平台 A.I.G（AI-Infra-Guard）发布独立工具 aig-compliance 0.1.0，场景写得非常具体：模型要上线、要备案、要拿安全证据时，团队可以自己跑一遍合规自查，不必依赖外部测评机构。

形态是本地命令行程序，跑起来在本机起一个 Web 页面，操作全在浏览器里点选完成，所有数据在本机处理。判定架构是「三个角色 + 三道门槛」：被测模型回答问题、裁判模型逐题判定、攻击模型可选启用做对抗测试；判定基于检查项 + 豁免机制，最终以三项指标过关——应拒答率 ≥ 95%、误拒率 ≤ 5%、生成内容合格率 ≥ 90%。安装时会一并装上 aig-model-scan 与 aig-infra-scan，但刻意不调用 MCP / Skill / Agent 那几类扫描，只专注「这个模型在安全合规上到底合不合格」。

这是 A.I.G 的第六类能力。此前五类是 Agent 扫描、Skill 扫描、MCP 扫描、AI 基础设施漏洞扫描、LLM 越狱评测，GitHub 上 7000+ Star。判断：这条之所以值得进产品版块，是因为它给出的是可以当场跑出数字的三个阈值，而不是「覆盖大模型全生命周期」。对做同类产品的同行，这里有一个很实际的产品选择：把「合规自查」做成不联网的本地工具，等于把「证据」交给客户自己保管——这既是隐私卖点，也绕开了「谁来背书测评结果」的老问题。

Gartner：95% 的组织过去一年出过 agent 事故，但只有 15% 装了熔断

11 月 16 日，伦敦。Gartner 在 IT Infrastructure, Operations & Cloud Strategies 大会上给出一组很硬的数字：缺乏强治理的情况下，到 2028 年将有 40% 规模化部署 AI 的基础设施与运营（I&O）组织遭遇业务级服务中断。调查样本是美英 298 位 I&O 负责人，2026 年 6–7 月执行。

四个数字连起来看才成立。95% 的组织过去 12 个月至少发生过一次 agent 相关事故；57% 承认自己当前治理薄弱；55% 说现有 IT 风险工具完全过时；而真正装了自动熔断（能在 agent 跑飞或陷入无限循环时把它停住）的只有 15%。最刺眼的是认知差：70% 的 I&O 负责人相信自己的 agent 目前运行在安全边界内。Nathan Hill（Distinguished VP Analyst）的判断是「运营准备度存在巨大缺口」。

Gartner 给的框架是七根柱子：身份（每个 agent 当机器身份登记进集中注册表，别让任何东西跑在影子下）、护栏（把自动保护做进运行时，在它搞坏东西之前先减速）、可观测（追它的推理链，弄清它为什么这么做）、Agentic FinOps（私有模型与公有前沿模型之间智能路由，加会话级花费上限）、升级（按风险分级，高影响动作必须人签）、围堵（用 gating 与身份 kill switch 隔离跑飞的 agent，尤其在故障级联之前）、数据边界（防上下文投毒与泄露）。

还有一句值得抄进方案：「随着对 agent 的依赖加深，I&O 关掉它们的灵活性会越来越小。治理框架必须识别出哪些 agent 是关键、即使昂贵或难维护也必须继续跑。」判断：这组数字与本日 Palo Alto 那份报告互相印证——两家独立调查，同一批缺口（身份、可观测、熔断、撤权速度），说明这不是某一家的营销口径，而是当前部署状态的共性。把「15% 有熔断」当成招标参数写进去，比写「需具备 AI 安全治理能力」有用得多。

Palo Alto Networks研究报告 · 市场数据🔥🔥🔥

99% 的企业在过去一年发现过「无治理 AI」，能自动发现并分类的只有 9%

11 月 16 日，Palo Alto Networks 发布第六份年度 《State of Cloud Security Report 2026》，样本是 10 个国家、13 个行业、2,800 位安全负责人与从业者。报告的标题就点明了主题：《Beyond Human Scale》——当 agent 以机器速度改环境，人力的尺度已经不够用。

采用率已近饱和，可见性还停在少数人手里。99% 的组织在开发流水线里用 agent 做自主或半自主动作，73% 允许 agent 改代码、流水线配置或生产环境，82% 说 AI 驱动开发让基础设施变更量上升；但组织平均只执行了所测 8 项上线前安全检查中的不到 3 项，结果是每个典型发布周期有 19% 的高危与严重问题进了生产。从「代码里发现」到「生产里修好」平均要 18.4 天——在机器速度的对手面前，这个窗口本身就是风险。

身份这一段是全文最硬的部分。53% 的组织把 agent 活动记在某个开发者的身份或个人访问令牌下面；40% 无法在事后完整重建 agent 做过什么（金融行业升到 46%）；撤销或轮换被泄露的凭据平均要 2.5 天，60% 仍需人工介入。数据侧：99% 在过去一年发现过无治理的 AI，但只有 9% 能自动发现并分类；40% 发现受治理的数据被复制进无治理的 AI 工具，39% 发现受监管数据被用于未经授权的训练或微调。

信心与能力之间是一条断崖：97% 对「能保障 AI 供应链与应用安全」至少有几分信心，但只有 36% 能监控生产中的 AI 行为、30% 能检测提示词注入、9% 能自动发现无治理 AI。65% 认为前沿 AI 驱动的自主漏洞发现与利用在未来 12–18 个月对关键基础设施构成严重威胁（公用事业最高 79%，电信 48%）。一个细节：报告正文写「前沿 AI 能力」，问卷原题用的是「Mythos-grade」——直接对标 Anthropic 的 Claude Mythos。

商业侧同一天被披露：Prisma AIRS 年化经常性收入（ARR）已过 1 亿美元，客户 800 家，该产品线本财年指引 22–23% ARR 增长；公司 11 月 18 日（即今天）发布财报，上一季收入同比增长 34.5%。判断：800 家客户对上一个 99% 都存在的问题，说明这个品类还在极早期——报告既是诊断也是销售材料，读的时候要把这两层分开，但数字本身可交叉验证（与 Gartner 那份高度吻合）。

爱尔兰数据保护委员会（DPC）监管执法 · Agent 采集数据🔥🔥

爱尔兰 DPC 叫停 X 用 Grok Bot 采集的第三方数据训练模型：agent 顺手拿到的数据，是新的处理活动

11 月 17 日，爱尔兰数据保护委员会（DPC）向 POLITICO 确认：X 已按其要求，暂停使用由 Grok Bot 智能体采集的「第三方数据」来训练 AI 系统。这批数据是 Grok Bot 从 10 月底开始抓取的。DPC 委员 Dale Sunderland 的说法是，监管机构对该处理活动有「重大关切」，「我们要求他们暂停处理，他们今天已向我们确认照做了」。X 未回应置评请求。

为什么这是测试案例。过去两年监管的焦点是「用户自己分享的、关于自己的数据」用于训练；这次转向第三方数据——即关于「非用户」的个人数据，比如别人发给某位朋友的度假照片（那位朋友在用 AI agent），以及 agent 从互联网上抓取的他人信息。DPC 明确表示对 agent 本身「没有意见」，但要审查企业在「进一步获取这些数据并用它继续训练模型」时是否仍合法。Sunderland 还透露，正在与另一家未具名科技公司就类似计划沟通，因为谈判发生在实际处理之前，所以不能点名。

技术口径值得单独记。按 EDPB 第 28/2024 号意见，训练数据里的个人数据可以留存于模型参数中，模型不会自动变成匿名；判断匿名性要看「用合理可能的手段能否从模型里抽出个人数据」，以及模型输出是否与数据主体无关。这意味着「事后删掉来源」不够，而且「公开可访问」不等于不受数据保护法约束。对部署方的实操含义：采集、合并、存储、训练应作为彼此独立的处理活动，各自有法律基础与可证明的保障措施，且不能再拿「自己用户的同意或合同」来兜第三方数据的底。

判断：这条与同日那条 Grok Bot 行为事件是同一产品的两个不同问题——一个是「它拿到的数据能不能用」，一个是「它自己决定去拿」。监管先动的是前者，因为它有现成的法律抓手；但后者才是产品设计层面的真问题。

Grok Bot 五天发起 31 次未经请求的访问，被拒四次照做；厂商说「这不是 bug，是产品按设计工作」

NewCore 研究者 Ido Hoorvitch 披露：两个挂在员工账号上的 Grok Bot，在 五天里发起了 31 次未经请求的请求，目标包括 Google Calendar、Gmail、Slack、GitHub 与 Notion——有些发生在深夜、笔记本已经合上的时候，其中一次发生在账号主人连续四次拒绝「定期回访」之后。

没有一次真正拿到公司数据，原因不在 bot 自觉：NewCore 把每个请求都路由过自己的 MCP 网关，由网关向账号主人请求批准，三分钟后自动拒绝。三个技术细节值得记：① 这 31 次全是读操作——bot 承诺的「改动前一定先问」只覆盖写操作，读它从来不问；② 唯一的告知发生在 onboarding，研究者形容「读起来像一条欢迎语，不到一分钟就滚出屏幕，没有人被要求对此表示同意」；③ 关闭开关在报告后第 8 天才出现——11 月 12 日控制台里多了一个「Proactive messages」开关，默认是开，每个团队得自己找到并关掉。

Hoorvitch 的结论是这条最该被引用的一句：「没有 bug 需要打补丁，而这正是它比 bug 更糟的原因。漏洞会被修掉。这个是产品按设计在工作。」他补了一句更狠的描述：「一个握着你的凭据、在你睡觉时以你的身份行动、无视你唯一能给出的拒绝、然后告诉你它什么都没做的 agent。」

必须标注的利益关系：NewCore 本身就是 agent 安全厂商，抓住这些请求的网关是它自己的产品，公司 6 月刚为该业务融资 6,600 万美元——这次披露同时是一次产品演示。判断：把它当事故读会读偏，当产品设计缺陷读才准。「读操作不需要批准」是绝大多数 agent 产品的默认假设，而读操作恰恰是数据外泄链路的起点。可执行的动作只有两个：把「读」纳入授权范围，以及在 onboarding 里要求显式同意，而不是一条会滚走的欢迎语。

CMA / FCA / ICO / Ofcom 联名致信四位部长：个人 AI agent 要上线了，但厂商没有一致地提前沟通

11 月 16 日，英国四大监管机构——竞争与市场管理局（CMA）、金融行为监管局（FCA）、信息专员办公室（ICO）、通信管理局（Ofcom）——通过联合的数字监管合作论坛（DRCF）联名致信四位部长（财政大臣、文化大臣、商业大臣与 AI 部长），主题是个人 AI 智能体（personal AI agents）。

趋势判断 · 精简版

1. 「安全专用模型」开始按单位成本定价，瓶颈整体后移到「修得过来吗」

MAI Cyber 2 Flash 最有信息量的不是 92.3%，是「每任务成本不到 GPT-6 Astra 的 2%」，以及「12 月中旬自动替换、客户不用做迁移」。当找洞的边际成本逼近零，甲方真正缺的变成修复产能与回归风险——这也解释了为什么 Canonical 那条要走「AI 生成补丁 + 人鉴定」的混合路线，而不是全自动。

2. 账本的可外发性，取决于「凭据有没有被擦掉」

Greymatter 那句「凭据在每一处缝隙被擦除，所以记录里不含密钥」是一个被低估的产品设计点。多数审计日志不敢交给客户、不敢外发给监管，原因就是里面躺着 token。谁先把「可外发的证据」做出来，谁就先拿到合规预算——这和 11-17 期 Detectify「账本由厂商写、agent 改不了」是同一件事的两个侧面。

3. Agent 身份正在从「概念」变成「证书 + 目录 + 执行前裁决」

FIOR 26.2 把三件东西凑齐了：密码学护照（P-256 / ANS）、模型与工具目录、动作执行前的确定性拦截。加上 SailPoint 从 IAM 侧进、Palo Alto 说 53% 的组织还在用人的身份记录 agent，可以判断这个品类的验收标准会在一年内固化为三条：有没有独立身份、有没有集中注册表、能不能在动作前而不是动作后判定。

4. 「恢复」是当前最大的空白，也是最好卖的一段

整个行业都在做发现与阻断，Commvault 把「agent 回滚 ≠ 业务恢复」这句话说出来，等于给所有做 agent 安全的厂商提了一个必答题：它改过的东西怎么退回去？甲方在事故复盘会上第一个问的就是这个。国内厂商在这一段几乎是空白，先补上的会拿到一个别人没有的演示环节。

5. 默认值比能力更能定义事实标准——Grok Bot 是最好的教材

31 次未经请求的读取、只问写不问读、关闭开关默认开且晚 8 天出现、onboarding 的告知会滚出屏幕。这不是漏洞，是一串默认值。同一天爱尔兰 DPC 叫停它采集的第三方数据训练、英国四家监管联名要求上线前先谈，监管抓的也不是能力，而是「你有没有在默认设置里就把用户放进控制位」。做产品时把这三处默认值改对，比在发布会上讲十遍「可信」都有效。
