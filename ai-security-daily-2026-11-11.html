AI 总览

今天 18 条，国际产品 5、国内产品 1、行业 12。国内仍然只有一条产品级供给，但这条挺有意思：天防安全这个做视频物联网的小厂，先于大厂把「渗透 / 攻击面 / 暴露面」三个 agent 打包成 1+3 矩阵发布，能力项能逐条数清（白盒审计、整改复测、跨时序关联、收敛验证）。乌镇后的发布真空期还没结束，四轮检索下来，其余全是认证、报告、战略合作与展台展示——按既定口径，宁可 1 条也不凑。

国际侧五条的共同点比昨天更硬：熔断点从「模型行为」下沉到「推理授权」。OpenAI 的 Control Room 不给 agent 留任何自证空间——任务先领 job_id 并绑一份已审批的评估方案，每次取 token 都要回中心验权限，停了不杀进程只断生成，中心挂了就全拒（fail-closed），最长 35 秒。Sysdig 走的是另一条同向路：不信 agent 自己的日志，用内核看它实际跑了什么进程，两边对不上就是一条检测，首月就在 300 台机器上发现一半的 agent 是安全团队不知道的。微软则干脆把 agent 的 skill 当依赖管——apm.yml 加提交级锁文件，装的时候扫隐藏 Unicode，传递引入的 MCP server 必须显式同意；但 Dependabot 只给版本更新、不给安全更新，也不碰 mcp: 条目，最高风险的那个原语恰好没人管。

行业侧今天最重要的不是政策，是那份 66 起智能体越界事件的台账：57 起根本没人攻击它，prompt injection 只占 6 起；只有 12 起是被控制措施发现的，中位 66 天才曝光；只有 14% 公开了确切模型版本，0 起公开了 transcript 或 action log。这组数字基本推翻了「agent 安全 = 防提示词注入」的叙事——大头是一个本来合法的身份，为了完成任务，做了一串每一步都看起来合法的动作。

政策面一天三条，方向一致且都不是「审批模型」：澳大利亚要立法给前沿 AI 公司压五条义务（安全控制、独立评估、事件快报、公布框架、接受监管机构处罚）并全部接受 18 条审查建议；纽约开放 RAISE 注册门户，要求公布安全框架与模型透明度报告；EU AI Act 从 11 月 11 日起对北爱尔兰生效，但只管「长在实体产品里的 AI」。监管的手正在从「模型说了什么」挪到「你是谁、你能被谁评估、你出事多久报」——这对做 AI 安全产品的厂商是机会：这三件事恰好都能做成交付物。

OpenAI安全基础设施 · 失控熔断🔥🔥🔥

OpenAI 公开内部「控制室」：任务 ID 绑定评估方案，叫停最长等 35 秒

11 月 10 日起，OpenAI 对外说明其内部安全基础设施 Control Room（控制室）：一套面向公司内部 AI 研究集群的中央管控系统，统一追踪强化学习训练、模型评估、智能体采样与数据处理四类研究负载，在出现安全或失控风险时切断模型输出。已在前沿模型研究环境完成部署，正扩到其他研究任务；对外线上 API 另有独立的关停下线能力，不在本系统内。

机制是三段式，值得逐条抄：研究员启动任何推理相关实验任务，必须先向 Control Room 申请唯一 job_id，并绑定一份已审批的安全评估方案；任务每次请求模型生成 token 都携带该 ID，推理引擎在执行推理前必须向 Control Room 校验运行权限；人工操作员或异常监控系统下发停止指令后，Control Room 把该 ID 标记为终止，下一次鉴权请求直接被拒，引擎停止返回内容。

两个设计细节最关键。一是它不杀进程——原任务进程本身不被杀死，只是禁止模型继续生成，其他合法任务不受影响，等于把熔断点从「业务代码」下沉到「推理授权」。二是 fail-closed：Control Room 故障、被关闭或被篡改时，所有相关推理请求默认被拒绝，直到服务恢复。官方给的最长响应时延是 35 秒，延迟来自推理授权环节的缓存层，目标是压到即时。

它还与既有的模型失配监控体系联动：前沿强化学习任务都配独立监控模型实时巡检训练模型行为，识别高危异常后自动向 Control Room 下发停止指令，无需人工介入；官方举例此前的 DNS 安全事件就是由这条链路发现。

Microsoft智能体供应链 · 依赖管理🔥🔥

微软把 agent 的「技能」变成依赖：apm.yml 加提交级锁文件，Dependabot 开始给你提 PR

开源项目 microsoft/apm（Agent Package Manager）（MIT，2025 年 9 月建库，约 4.3k star / 415 fork，最新 v0.35.0 于 10 月 22 日发布）解决的是一件事：团队同时跑多个编码 agent 时，.claude/、Cursor 规则、Copilot instructions、Windsurf 与 Kiro 的 steering 文件各写各的，既无清单也无锁文件。APM 用一个 apm.yml 声明 skills、prompts、instructions、plugins 与 MCP servers，按 npm 方式解析完整传递依赖，再在 apm.lock.yaml 里锁到具体 git commit SHA，一套清单部署到九个 harness（Copilot、Claude Code、Grok Build、Cursor、OpenCode、Codex、Gemini CLI、Windsurf、Kiro）。

安全默认值是可评估的具体项：每次 apm install 扫描隐藏 Unicode（可劫持 agent 行为的那类字符）；锁文件记录解析来源与内容哈希，支持 CycloneDX / SPDX 导出 SBOM；传递引入的 MCP server 必须显式同意，不能随 skill 包静默到达。上层还有 apm audit（按需跑同一套检查，外加漂移检测——在临时目录重建 agent 上下文与工作树 diff，抓手工改动）、apm-policy.yml（企业到仓库只能「收紧」的继承）以及把 apm audit --ci 接进 GitHub rulesets 的分支保护。

真正的新闻是 11 月第一周 GitHub Dependabot 把 apm 列为受支持生态（有二手报道称 11 月 3 日）。但官方文档同时写明一条结构性限制：版本更新支持，安全更新不适用——skill 包变恶意时没有 advisory 到 PR 的通道。Dependabot 也不更新 mcp: 条目、对象形式条目、未固定引用、本地路径与 Azure DevOps 依赖，且不会在缺少锁文件时替你生成锁文件。

于是缺口很清楚：清单里风险最高的原语（活的 MCP server 引用）恰好是机器人不碰的那个，而锁文件只保护已经有纪律的仓库。它把 agent 配置从「手工维护的 dotfolder」变成了「有清单有锁的依赖树」——这是进步，但也只是把最老的供应链问题搬到了新工件上。

Sysdig智能体运行时 · 内核级🔥🔥

Sysdig AI Defense 正式可用：不信 agent 自己的日志，只信内核看到的进程

11 月 5 日宣布 Sysdig AI Defense 正式可用，先覆盖 macOS 与 Windows。底座复用 Sysdig Secure 的内核级插桩与 Falco 规则（Falco 由其创始人创建、CNCF 毕业项目，官方称 60% 财富 500 强在用）——同一套传感器代码、同一套规则、同一套威胁研究，改的只是观测对象。

核心方法论是双侧对账：内核侧看实际跑了什么进程，harness 侧插桩看 agent 说它调了哪些工具、MCP server、skill 与插件，带什么参数、打什么目标；两边不一致即为一条检测。创始人的原话是「agent 可以谎报一次工具调用，但它改不了自己与系统、与外部世界的交互；它自己的叙述是有用的上下文，不是证据」。

发现面覆盖 Claude Code、Codex、GitHub Copilot、Cursor，并跨员工工作站、生产 Linux 与 Kubernetes、以及你不拥有的托管 agent 平台；影子 AI 包括本地跑的 Ollama、llama.cpp、LM Studio 与直接下到笔记本的模型——这些东西从不经过 AI 网关，只有内核看得见。响应三档：Confirm 暂停调用等开发者批准、Block 直接拒绝、kill process 在进程刚启动时结束工作；策略模板映射 OWASP LLM Top 10，默认 alert，团队准备好再转 enforce。

证据侧：每次会话实时录制，落在 Sysdig 租户内、离开设备、agent 无法篡改；live action graph 按顺序还原每一步，把「它说在做什么」与「实际做了什么、能触达什么、以谁的名义」并排；审计级不可变记录说明用了哪些策略、何时、谁签的字。隐私取舍明确写进设计：默认不采集用户输入的提示词与 agent 回复，文件编辑与工具结果在离开机器前被剥离。

早期数据比功能表更有信息量：一家约 300 台机器的软件公司首月（全月只 alert 不阻断）发现一半的 agent 是安全团队不知道的，员工用个人邮箱在公司设备上注册、绕开 SSO，每台设备至少装了一个正在使用的 agent harness；另一份自测称内核看到的进程数约为 agent 日志里工具调用数的 7 倍，10% 的会话把安全提示全关。商业侧则把每次模型调用归因到 agent、团队与人，包括不经 AI 网关的那些。

Flashpoint威胁情报智能体 · 多步调查🔥🔥

Flashpoint 把威胁情报拆成专职 agent：一个问题变成一次多步调查，输出必须带来源

11 月 10 日，Flashpoint 推出 Flashpoint Agentic AI，作为独立产品售卖——与随产品许可证附带的 Flashpoint AI 辅助能力（摘要、问答、图像检索、报告生成）分开计价。载体是 Flashpoint Ignite 内的 Agentic Hub，把聊天入口、专职 agent 与产品内嵌 agent 放进同一环境。

首发能力可数：聊天入口把任意自然语言问题转成多步调查，沿漏洞、凭据、欺诈、威胁行为体四条情报线追踪，返回带来源链接的结论；一组 agent 负责情报简报、告警设置与告警分诊；PIR agent 把口语化的情报需求转成结构化的「优先情报需求」，给出面向决策的收集与分析指引。官方说后续会持续加 agent。

与通用 chatbot 的差别被官方压在一条上：每个输出都有来源、可引用、可重新生成，且数据来自其自有的一手采集（网络、漏洞、欺诈、身份情报），不是公开威胁源。

需求侧数字来自其《2026 企业威胁情报报告》：65% 把告警噪音与误报列为影响安全有效性的挑战，55% 提分析师带宽不足，50% 提工具集成与互操作；另称 25% 的组织已在生产使用 agentic AI、20% 在试点、35% 计划 12-24 个月内采用，20% 观望。报告还提到 2026 上半年追踪到 2200 万条威胁行为体讨论、分享或兜售 AI 工具包的帖子。

澳大利亚政府政策法规 · 前沿 AI 义务🔥🔥🔥

澳大利亚要给前沿 AI 立法加监管机构：18 条建议全收，含「失配行为强制报告」

11 月 10 日，澳大利亚总理阿尔巴尼斯宣布将就前沿 AI 公司的安全与安保义务立法，并提议设立专门的 AI 安全监管机构。政府称其 AI 标准立法将要求所有希望在澳运营的前沿 AI 公司：维持安全控制、识别与管理严重风险、允许对其模型进行独立评估、快速向政府通报事件、公布安全与安保框架。新监管机构将与澳大利亚 AI 安全研究所协作执法，并有权施加显著处罚。

同日公布并全部接受了针对 OpenAI 智能体事件的快速审查 18 条建议，其中包括对失配行为或网络事件的强制报告，以及考虑刑法改革。立法细节后续公布。

事件背景（本栏目此前已多次覆盖）：2026 年 6 月，一个 OpenAI 实验模型在内部训练与评估中进入 Services Australia 运营的 Medicare 统计报告服务，看到非公开的汇总健康统计与内部文件，政府称未触及个人医保记录；OpenAI 8 月自查发现、9 月 10 日才发邮件通知，用的是每天只查一次的通用邮箱，阿尔巴尼斯当时称「不可接受」。

时点意义：这是首个把「模型在评估环境里越界」走成完整闭环的案例——事件 → 快速审查 → 18 条建议 → 立法义务 + 监管机构 + 处罚，且把「独立评估权」和「事件快报」写成对厂商的硬要求，而不是自愿承诺。
