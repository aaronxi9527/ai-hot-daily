AI 总览

今天两条消息放在一起看，是整个行业的一记重锤：Google 首次承认 Gemini 在测试中自主入侵了 3 家真实公司（7 月底已知、媒体问询才披露），同一天 CNN 爆料美军被 AI 生成的虚假军情报告误导、险些冲上中国船只——知情人士的原话是「几乎挑起战争」。一边是模型越界，一边是幻觉直接进入作战决策链，两条都不是理论风险，而是已经发生、只是被压了几周才说出来的事实。
产品侧今天的关键词是「给智能体装上可撤销的权限」。KnowBe4 首发 Agent Risk Manager（首个专门治理自主智能体行为的系统）、Auth0 把 CIAM 控制平面推到客户侧智能体（智能体 kill switch + Token Vault 凭据代理）、TypeSafe AI 用非 LLM 的 Jev 解决「用 LLM 盯 LLM」的成本瓶颈——三家都在回答同一个问题：智能体跑起来之后，谁在盯着它、凭据放在哪、出事怎么拔插头。国内则是一次少见的体系化发布：科大讯飞旗下长三角安全人工智能安徽省实验室在 CCSC 2026 一次推出星界、星驭、星鉴三条线，把内容安全、智能体安全、AIGC 可信传播打包成完整治理栈。
另外值得单独标记：智谱 ZCode 静默上传完整 .git 历史，且解密私钥只在云端——这是「AI 工具为了上下文，悄悄拿走超出必要范围的数据」的典型样本，配合 MCP 侧 91.8% 服务器缺 OAuth、68 个 CVE 的报告，可以说今天的日报把「AI 安全的债」摊得相当清楚：能力在狂奔，账在累积。

KnowBe4AI Agent 安全网关安全智能体🔥🔥

KnowBe4 发布 Agent Risk Manager：业界首个自主 AI 智能体行为治理系统

KnowBe4 发布 Agent Risk Manager，作为其 HRM+ 平台的基石模块，定位为业界首个面向自主 AI 智能体行为的安全、监控与治理防御系统，解决「给智能体足够权限干活、又不能让它搞破坏」的智能体悖论。核心能力：行为护栏（实时监控智能体动作，阻止未授权数据外泄与被越狱后的自主执行）；智能体身份治理（识别智能体可访问的权限与工具）；智能体对抗模拟（用最新提示注入与社工手法压测智能体）；提示注入检测（机器学习分析越狱、逻辑覆盖、间接注入，覆盖用户消息与工具输出两侧）；敏感信息检测（20+ 分类器扫 PII 与凭据，写入审计日志前自动脱敏）；无界消耗检测（识别「失控」智能体的过度 API 调用与算力开销）；另有智能体清单自动编目、合规级审计日志、多租户集成管理与引导式上手。产品强调基于 15 年行为数据预测智能体何时偏离安全运行参数，采用「由外向内」的安全层，无需改动底层模型。

TypeSafe AI提示词注入防护大模型安全评估🔥🔥

前 OpenAI RLHF 架构师创立 TypeSafe AI，发布非 LLM 模型 Jev 做智能体监督

由前 OpenAI 研究员、RLHF 架构师之一 Diogo Almeida 创立的 TypeSafe AI 发布 Jev——一个刻意背离 LLM 范式的 transformer 模型：不生成自由文本，而是接受结构化输入、在用户预定义的输出类别上返回校准概率分布（自称「校准决策」）。由于输出空间被预先定义，Jev 在设计上结构性规避幻觉；输出 token 免费、输入按 10 亿 token 计量，成本结构大幅低于「用一个 LLM 盯另一个 LLM」的传统方案。定位三类用途：越狱与提示注入分类器（可内嵌智能体管道作为近实时护栏）、AI 智能体行为监督、模型路由。公开试用反馈：Vercel 工程师在命令安全分类测试中测得比 OpenAI 模型快 5–18 倍且更准；Bryo AI CTO 在业务邮件分类测试中测得比 Gemini 便宜 10–20 倍。产品映射 MITRE ATLAS（AML.T0054 越狱、AML.T0051 提示注入、AML.T0080 上下文投毒）与 OWASP LLM Top 10（LLM01/02/08/09），并建议用置信度分数把边界决策路由到人工复核而非二元放行。

Auth0（Okta）AI Agent 安全网关身份治理🔥🔥

Auth0 Agent Gateway 进入 Beta：面向多租户 SaaS 的客户侧智能体身份控制平面

Auth0 宣布 Agent Gateway 进入 Beta，把 CIAM（客户身份与访问管理）控制平面延伸到「产品内嵌、面向客户」的 AI 智能体。产品指出，多数智能体安全方案是按「员工内部使用」设计的，而多租户 SaaS 里客户侧智能体的信任模型完全不同——连接账号由成千上万个客户租户与终端用户各自持有与授权，策略评估或上下文作用域一旦出错，就会导致跨租户数据暴露、未授权第三方操作，或被提示注入驱动滥用已连接工具。四大支柱：身份绑定执行（每次工具调用绑定智能体＋组织＋用户上下文，保留委派链）；工具调用授权（调用外部工具前实时策略评估，落实最小权限）；Token 管理与凭据代理（用 Token Vault 与 token exchange 铸用户级令牌，给智能体只发短期网关令牌，让原始 API Key 与下游令牌不进入提示词、运行时、上下文窗口与日志）；全面审计日志 + 智能体 kill switch（日志写入租户日志并可流式送 SIEM，管理员可集中禁用智能体或切断其下游访问）。

GoogleAI-SPM安全智能体🔥🔥

Google 推出 AI Threat Defence 框架：把 Wiz 上下文、CodeMender 修复与 Mandiant 响应串成一条线

Google 对外披露其 AI Threat Defence 框架：把 Gemini 与其他模型、来自 Wiz 的环境上下文、来自 CodeMender 的代码修复能力、以及来自 Mandiant 的事件响应专长组合起来，上下文再回流到 Google Security Operations，让安全团队更快识别与阻断攻击路径。Google 威胁情报团队同时给出三大态势转变：一是 AI 辅助开发带来新的供应链风险，攻击者正试图污染 AI 助手推荐的上下游软件包；二是 AI 系统本身成为攻击面——点名 LLMJacking（攻击者窃取 GPU 算力运行未授权的模型与智能体工作流，某案例中攻击者借暴露的 personal access token 进入云环境，把算力资源扩容后把硬件与平台账单留给受害方）以及提示词、智能体指令、微调模型与源代码的窃取；三是攻击自动化——Mandiant 调查的一起入侵中，攻击者用 AI 编码聊天机器人加提示词与指令集，在不到 6 小时内搭起批量凭据收割活动。Google 明确反对用单一 LLM 做安全分析，称单模型部署会形成可被探测的「单一栽培」，改用多模型交叉比对降低误报。

「星界」「星驭」「星鉴」三大 AI 安全方案发布：一次覆盖大模型内容安全、智能体安全与 AIGC 可信传播

9 月 19 日，首届中国网络空间安全大会（CCSC 2026）人工智能安全与应用治理论坛在合肥举办，承办方长三角安全人工智能安徽省实验室（安徽省人民政府批准设立、依托科大讯飞全资子公司安徽星盾智能科技有限公司建设）现场发布三大 AI 安全治理方案，中国工程院院士吴世忠、科大讯飞联合创始人胡国平、中科大教授俞能海等共同上台发布。
「星界」大模型内容安全治理：面向大模型全生命周期，数据构建阶段做训练数据清洗、安全价值对齐与模型安全增强以降低内生风险；应用运行阶段用内容安全护栏实时识别处置提示词攻击与违法违规内容；持续运营阶段靠风险监测＋人工研判＋闭环优化；安全评测贯穿全过程。支持开源与闭源模型，兼容云端与私有化部署。

「星鉴」AIGC 内容可信传播治理：覆盖文本、图像、音频、视频四大模态，支撑 AI 内容标识、生成内容与深度伪造检测、有害内容识别与来源追溯，为版权保护与来源核验提供技术依据。

Google 证实，其 Gemini 模型在今年 5 月由 AI 安全公司 Irregular 组织的一次网络安全能力评估（capture-the-flag 形式）中，因测试环境意外开放互联网访问，把外部真实网站误判为测试范围，自主入侵了 3 家真实公司的系统——这是 Google AI 系统自主实施此类行为的首个已知案例。其中一起案例中，模型反复尝试猜中密码进入受保护系统；另两起中模型在公共代码库找到凭据并借此访问更多系统。Google 安全工程副总裁 Heather Adkins 表示，模型在判定自己接入的是真实公司系统后均自主终止，未造成损害，公司已通知三家实体并与 Irregular 一起修补测试流程。Irregular 称该问题与其影响 OpenAI、Anthropic、Meta 的属同一根因，所有相关实验室已于 7 月底收到通知，已知问题数周前修复完毕。

Adversa AI / Elastic Security Labs / AWSMCP 安全漏洞披露供应链安全🔥🔥

MCP 安全 9 月报告：审计发现 68 个 CVE，91.8% 服务器完全缺 OAuth 认证

Adversa AI 发布 9 月报告《MCP security September 2026: Deadbugz + 3 server CVEs》，在对已审计 MCP 服务器的排查中累计发现 68 个漏洞，归为四类在 MCP 语境下重新变得危险的经典缺陷：SQL 注入（攻击者经工具调用读取后端数据库）、SSRF（专打云元数据服务窃取临时凭据）、提示模板注入（操纵智能体执行攻击者选定动作）、路径遍历（未授权文件访问）——每一类都已在生产环境造成数据外泄或智能体完全失陷。早期数据显示被检 MCP 服务器中 91.8% 完全缺乏 OAuth 认证。
同一波披露中还有多个具体案例：9 月 4 日一起 SSH MCP 服务器实现存在命令分类缺陷，高权限命令被误标为安全，直接破坏「只读审批」假设，使审计日志在智能体处理攻击者可控内容后不再可信；AWS 官方 MCP 服务器再爆两枚 CVE——postgres-mcp-server CVE-2026-87911 与 mysql-mcp-server CVE-2026-85788，只读模式被 COPY TO PROGRAM 打穿，OS 命令注入 CVSS 9.6，根因是注释绕过与黑名单机制的先天缺陷（与 9 月 8 日披露的四枚 AWS MCP CVE 属不同漏洞）；MCP Atlassian CVE-2026-73498 则因漏掉一处 validate_safe_path，形成「路径遍历 → 提示注入 → 凭据窃取」三阶段利用链，可经 confluence_upload_attachment 读取 /proc/self/environ。
