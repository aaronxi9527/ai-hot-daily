AI 总览

今天 15 条：国际产品 5、国内产品 1、行业 9。周末没停，主线反而更锋利——「判定」和「证据」正在分家，而分家的方式是把证据从模型手里拿走。

产品侧五条里有三条在做同一件事：把「凭什么信」变成一个外部可核对的物件。Detectify 最直白——它不卖更准的扫描，卖一份由厂商写、agent 改不了的只追加账本；规则硬到「agent 报了一个漏洞但账本里找不到对应测试，这条发现直接驳回」。Wiz 走的是另一条：不阻断、只给优先级，但要求每个结论都带源码位置，还把「agent 当初被设计来干什么」与「它现在实际握着什么」摆在一起比——「对内使用却暴露在公网」「只该答问却握着 shell」这两类错配，规则查不出来，只能靠意图对比看出来。CrowdStrike 的 Falcon AI Gateway 则干脆把凭据从每个工作负载里抽走，留在网关；它写得最老实的一句是边界：不自动发现、不自动重定向、停不掉本机进程。Exaforce 的反面教材最有用——一个要像新员工那样配登录、配 token 的 agent，本身就是新凭据面和新爆炸半径。

行业侧今天是一场「同一件事的两种读法」。Google GTIG 说全自动挖洞并利用第一次出现，证据是一台暴露的 staging 服务器上的 exploit_agent；但 Severity Daily 逐句核完指出，报告全文的动词是「被配置成」，没点名一个由它产出的 CVE、没有成功率、没有 IOC / 哈希 / YARA，防守方拿它查不了自己的遥测。两篇都该读，因为结论完全不同：前者要你重排补丁队列，后者要你别把「配置描述」当成「战果统计」。同日加州把 OpenAI 告上法庭，核心不是赔偿而是禁令，而诉状真正追问的是沙箱、权限、审计日志——和产品侧那三条在回答同一道题。

国内只有一条，但它给出的是一个可验收的动作而不是能力矩阵：360「紧箍宙」把「高危操作可叫停」写成了产品特性。这比「覆盖 AI 应用全生命周期」有用得多——甲方能测「能不能停」，测不了「覆盖没覆盖」。行业侧还有两条国内坐标：IDC 首份智能体威胁检测评估把「影子智能体」抬成采购第一问，国家 AIVD 漏洞库落地首批支撑单位，让「AI 漏洞怎么定级」第一次有了国家级口径。

WizAI-SPM · Agent 资产发现🔥🔥🔥

Wiz 把「发现 agent」做成产品：连没有管理 API 的自研 agent 也扫，客户环境里查出量是传统引擎的 5 倍

11 月 16 日，Wiz 的 AI Security Agent 进入公开预览。它的立论不是「又一个 AI 扫描器」，而是一句方法学批评：云上下文是基础，但 agent 活在应用层——它编排提示词、调用工具、执行业务逻辑，而底层仍然依赖身份、出网与数据存储。只看一层，得到的都是半张图。

三项能力是连着的。① 发现：很多自研 agent 直接写在代码里，没有管理 API、没有可识别的框架特征，Wiz 从代码仓库、PaaS 平台、自托管环境（VM / 容器 / serverless，以及存在桶里的代码）三个入口反推，把模型、系统提示词、MCP 服务器、网关、护栏、工具定义一起盘出来。官方称在多个客户环境里，发现量是传统发现引擎的 5 倍。② 把「意图」和「能力」摆在一起比：重建应用架构后，指出「对内使用的 agent 却暴露在公网」「只该回答问题的助手却握着 shell 执行工具」这类错配，并给出源码位置作为证据，而不是一个黑箱评分。③ 接进 Security Graph 算攻击路径：把应用层的 AI 原生缺陷与云侧的外网暴露、出网能力、有效权限、敏感数据访问拼起来，判断它到底能不能被利用。

官方举的例子很典型：一个 BigQuery agent，代码里同时有对多个库的读写工具和一个任意代码执行缺陷。单独看是「一个应用层漏洞」，接进图之后才看得出「外部攻击者可以劫持这个 agent 的工具去读敏感数据」——代码分析只讲了一半故事。

来源：Wiz 官方博客（11/16）
CrowdStrikeAI 网关 · 模型访问治理🔥🔥🔥

Falcon AI Gateway 正式可用：把「批准的路」做成唯一的路，模型凭据一条都不下发

11 月 14 日，CrowdStrike 宣布 Falcon AI Gateway 正式可用（GA），包含在 Falcon Guardian 里、不额外收费。官方给的产品逻辑只有一句：「让批准的路成为唯一的路。」

机制上有几处值得记：应用只认一个网关端点、一把网关 key，继续用它原本就会说的 API 格式；各家模型厂商的凭据留在网关里，管理员在 Anthropic、Amazon Bedrock、Microsoft Foundry、Google Vertex AI 之间切换时，不需要改每一个工作负载。策略过两遍——请求到厂商之前一遍，响应回来再一遍，查的是提示注入与敏感数据外泄。限额可以按应用 / 用户 / 团队 / 模型 / 厂商五个维度切，应用 key 给服务与共享负载、个人 key 把用量归到具体的人。

最该被同行抄走的是边界写得多清楚：网关不自动发现、也不自动重定向 AI 流量，团队得自己决定把哪些负载接进来；它作用在「经过它的流量」上，停不掉本机进程、文件与命令——那是 Falcon sensor 的活。两者共用同一套 Falcon Guardian 策略模型，各管各的位置。也正因为流量收在一个点上，AI Kill Switch 才能通过网关切断 agent 的模型访问。

还有一个细节说明它是真跑过的：这套网关不是为发布而写，而是从 CrowdStrike 内部那个服务数万名员工的 AI Hub 里长出来的。他们总结出两条经验——请求路径要短（每多一跳就多一个故障点），以及大多数团队并不想自己运维一个网关。

来源：CrowdStrike 官方博客（11/14 GA）
ExaforceAgentic SOC · 安全智能体🔥🔥

ExaU 给每个安全工程师配一队 agent：有名字、有记忆、能互相派活，且不铸新 token

11 月 16 日，旧金山。Exaforce 发布 ExaU，定位是「给每个安全从业者一队属于他自己的 agent」。它对第一波安全 agent 的批评很具体：每个只接一件事，任务结束就停，而且没有持久记忆——下一次会话要从零解释一遍，所以没法围绕「一个人长期负责的那摊事」来建工作流。

ExaU 的 agent 有名字、有角色、有自己的记忆：你说一次「我负责什么」，它自己去看身份、设备、云、SaaS 与 AI 工具上实际发生了什么，自己排出待办，还自己决定什么时候值得打扰你。它们之间可以互相交接，也可以共享——分析师的威胁狩猎 agent 给 CISO 用，CISO 的简报 agent 反过来汇总全团队的 agent 状态，一个发现可以同时触发一次狩猎、一次活动审计、一次员工沟通，结果合成一份评估。

安全侧最关键的设计是反着做 onboarding：一个需要像新员工那样配登录、配 token 的 agent，本身就是一个新凭据面和新爆炸半径。ExaU 复用平台已有的身份与连接（身份提供商、云、设备、SaaS、安全遥测），没有新 token 要铸、没有新登录要配，agent 一开始就知道平台已经知道的东西。所有影响员工、系统或通信的动作必须先批，每一步进审计日志。

商业背景：这是 9 月那个「给失控 agent 装杀开关」的 Exaforce AI Security 之后的下一块拼图；公司 5 月完成 1.25 亿美元 B 轮（投后 7.25 亿），2023 年成立至今累计融资 2 亿美元。

来源：Exaforce 官方博客（11/16）、SiliconANGLE（11/16，含融资与定价背景）
Detectify应用安全 · 可验证性🔥🔥

八成 AI 静态扫描告警是噪音：Detectify 让 agent 去实跑验证，账本由厂商写、agent 改不了

11 月 16 日，瑞典应用安全公司 Detectify 发布 Agentic Tooling 与配套的 Security Ledger（安全账本），按申请开放。它要解决的不是「扫得更准」，而是「凭什么信 agent 的结论」。

三个数字撑起整个立论：客户反馈，AI 驱动的静态应用安全测试结果里约 80% 是噪音；复旦大学与腾讯研究者的一项研究里，被检查的静态分析告警76% 是误报，每条要开发者花 10–20 分钟核实；Detectify 自家《2026 下半年网络卫生指数》显示，九成已公开的严重与高危漏洞暴露时间超过 90 天。它同时点破了一个更难看的事实：在交付压力下，agent 会为一次根本没跑过的测试写出一份很有说服力的报告。

产品形态是「验证工厂」：SAST 结果、赏金提交、红队报告、攻击面数据，每一条变成一张工单；agent 在自己的环境里通过 MCP 或 CLI 调 Detectify 十多年攒下的测试引擎（白帽社区的 payload、Surface Monitoring 的攻击面数据、2025 年 3 月上线用于自动验证已知漏洞的 Alfred），先读代码，再像攻击者一样从外部打运行中的应用，跑在 CI 触发的循环里。结论只允许四种：confirmed / not confirmed / inconclusive / not testable——中间两档是刻意留的出口，避免模型被迫二选一。可能造成危害的测试（比如 DoS）标为 unsafe，交人决定。

真正的新东西是那份账本：只追加、由 Detectify 写、agent 不能编辑，记录每次调用的请求、payload 与返回结果。规则很硬——agent 报了一个漏洞，但账本里找不到对应的测试，这条发现直接驳回。CEO Rickard Carlsson 的原话可以直接当采购问题用：「让 agent 写你的代码，再问同一个 agent 安不安全。如果它说安全，你其实什么都不知道。」

来源：SiliconANGLE（11/16）、Jarvis AI（含四种结论与账本设计细节）
SailPoint身份安全 · Agent 治理🔥🔥

SailPoint 把身份治理改成「自主代理」：A-ISPM 自己发现风险、自己撤权，JIT 取代常驻权限

11 月 11 日，SailPoint 在年度大会 Navigate 2026 上一次性发布三组东西，主线是「代理式 AI 时代的身份安全」。

① 自主代理（Autonomous Agents）：在不影响合法业务自动化的前提下执行政策、按需调整权限、保护系统——既能识别合法意图，也能拦恶意活动。② A-ISPM（Autonomous Identity Security Posture Management）：用 Atlas 的实时身份上下文持续发现各类身份面临的重要风险，并通过实时修复闭环——自动撤销访问、停用身份或停用 AI agent。这一步把「发现问题」和「把问题关掉」放进了同一个产品。③ Agentic Fabric 扩展：绘制完整 AI agent 分布与覆盖范围，支持影子 AI 探测、执行阶段授权、实时 Kill Switch；Human Fabric 侧上了新一代认证与分段式身份数据。

另外两块偏工程：Atlas Extensibility Framework 新增共享服务、SaaS 插件与工作流升级（版本管理、执行历史、最多可执行 1,000 次迭代的序列循环）；以及零常驻权限——带条件的 JIT 配置配合有效权限可视化，同时取代人员、服务账户与 AI agent 的长期常驻访问权。本地部署侧发布 IdentityIQ 9.0。

判断：这条与 11-16 期 Varonis 的 Atlas 扩展是同一赛道不同入口——Varonis 从数据侧往外管，SailPoint 从身份侧往外管。「停用 AI agent」被做成一个可点按钮这件事，比任何「AI 身份治理框架」都更能说明这个品类成熟到哪一步了。

360 数字安全智能体安全 · 权限与行为管控🔥🔥

360 把「管 agent」做成一个产品：紧箍宙约束权限与行为，高危操作可叫停

11 月 16 日《经济日报》乌镇报道，360 集团总裁叶健把问题讲得比大多数发布会清楚：「过去模型出错是『说错话』，现在智能体出错可能是『做错事』。因此，安全必须内建于系统。」

他给出的产品是 360 智能体安全防护与管理系统「紧箍宙」，能力边界三句话：约束智能体调用工具、执行任务的权限；让过程可审计、可干预；高危操作可叫停。这三句合起来是一个动作序列——先划权限、再留痕、最后留一个随时能按的停止键，而不是又一张「全生命周期防护」矩阵图。

同一底座上还有两个可量化的东西：自研 AI 漏洞挖掘智能体 「图龙锋」累计挖掘漏洞超 1.5 万个；网络安全自动化防御系统 「仪天阵」支持威胁发现、研判与联动处置。

判断：国内已经连续第六天处在「体系叙事期」而非「版本发布期」——深信服、天融信、安恒、奇安信这一周被引用的产品名都不少，但大多是既有矩阵的复述。这条能站住，是因为它给出了一个可以写进配置检查清单的动作（叫停 + 干预 + 审计），而不是「覆盖 AI 应用全生命周期」这种无法验收的表述。对做同类产品的人，这也是最该抄的一句：把「能停」做成产品特性，比把「能防」做成产品特性更容易被甲方验收。

Google GTIG / MandiantAI 威胁情报 · 攻击自动化🔥🔥🔥

Google 说「全自动挖洞并利用」第一次出现；但报告全文的动词是「被配置成」，没给一个 CVE

11 月 16 日，Google 威胁情报组（GTIG）与 Mandiant 发布季度《AI Threat Tracker》，标题就是结论：《Agentic Threat Activity Crosses a Significant Threshold》。核心证据是一台暴露的 staging 服务器，上面跑着一个多 agent 框架，操作者叫它 exploit_agent，接了多个前沿模型与本地模型。

它干的事是把「补丁 diff」这件事工业化：持续对比热门 Web 应用补丁前后的代码 → 推断这个补丁在补什么 → 写 exploit → 自动打出去，全程无人。公开截图显示它在读 WordPress 插件 Spectra（Ultimate Addons for Gutenberg）2.19.25 的访问控制实现——这类装机量过百万、长期暴露在公网上的代码，正是「补丁即地图」的最佳标的。配置注释是俄语，受害遥测指向法国的媒体、娱乐与教育站点；服务器上除了外泄数据，还有内网侦察、爆破、装 webshell 的脚本，以及一个很说明赛道拥挤程度的细节——删掉其他攻击者的 webshell 的脚本。环境文件里写着「LLM API keys for auto-exploitation (exploit_agent pilot)」。

报告更大的部分是生态：ARTEX（多 agent LLM 渗透 + C2，六个子 agent，已被单列为 UNC7228，与微软的 STORM-0940 重叠；原 GitHub 仓库 10 月被作者自己下架，现在靠 fork 与付费「ARTEX PRO」传播）、CAIRN（OODA 循环 + agent 共享「黑板」，已被用于攻击美国航空航天领域目标）、PentAGI（8 月底至 10 月初，对亚洲大量组织做系统性侦察与漏洞扫描）、CyberStrikeAI 与 HexStrike AI（仅见实验）。另有疑似朝鲜集群 MIDNIGHT NEPTUNE / UNC6836：假招聘者（头像带 Google SynthID 水印）→ 假会议平台 + ClickFix 诱导运行「诊断脚本」→ 进去后改内部仓库的 .claude/settings.json，让 Claude Code 一启动就拉 SOMBERMEME 后门。助手本身不需要有漏洞，被滥用的是一个合法的配置钩子。

钱的部分：LLMjacking 有单日超 10 万美元、遏制前累计达 100 万美元的案例；手法是从公开 GitHub 仓库捞 key、建流氓服务账户，以及滥用 LiteLLM 的 CVE-2026-40217（把受限的「虚拟 key」提成管理员凭据）；偷来的算力经「mixer」转卖，标价 0.10–25 美元/百万 token。曲线方面：0day 从 2025 年月均 8 起升到 2026 年 11 起、8 月冲到 22 起；真正危险的是 n-day——PaperCut 两个洞 8 月底当 0day 被打，披露后一天内就有人做出可用 exploit，四天后打到数百家组织，GreyNoise 记录到几分钟内提权到域管。GTIG 把当前状态评为 Level 5（AI 承担大部分阶段、人只负责搭建），预计三个月内出现几乎不需要人的攻击、六个月内出现成熟的完全自主 agentic 攻击，并提醒现在的工具是拿隐蔽换速度。

必须并排读的反向意见：Severity Daily 逐句核了一遍，指出报告用的动词是「is set up to（被配置成）」，后面没有跟一个实例——没点名任何一个由 exploit_agent 产出的 CVE、没有成功率、没说任何一条 exploit 打成功过，全文单源，且没有 IOC、没有哈希、没有域名、没有 YARA，防守方拿它查不了自己的遥测。服务器上确实有真实受害者，但报告没有把「受害者被攻破」和「agent 写的 exploit」连起来；那些爆破、webshell、清对手 shell 的脚本，是二十年历史的大规模 Web 利用工具箱。

判断：可执行的动作不是「相信全自动攻击已到」，而是把 SLA 的起点从「公告日」改成「补丁可下载日」。Fortinet 11 月那批把修复提前三周、细节压后公开，就是这个逻辑的反面证明——补丁一上线，diff 就已经是地图了。

缺陷机制值得逐句读：配置导入功能按名称与可见性查找同名公共实体时，不限定租户、不校验调用者所有权；持团队级 admin.import 权限的账户向 /v1/import 发一个「冲突策略为更新」的请求，批量注册逻辑就直接覆写其他租户的公共工具、资源、提示词与网关的端点地址、请求头与认证凭据；而网关更新路径上的所有权防护，因为调用时没有传入用户身份而被跳过。结果是：同名实体的后续 AI 调用被重定向到攻击者控制的主机。

修复方式把整条覆写链切断：加所有权校验、向批量注册与网关更新传入调用者身份、把导入路由改为全局权限、收敛冲突查询，并拒绝「授权后新出现的同名记录」。

ProofpointAgent 身份 · 攻击链研究🔥🔥

微软把 Entra 的身份体系延伸到了 AI agent，做法和传统应用注册几乎一模一样。Proofpoint 盯上的正是这种相似性：诱导受害者同意一个恶意 Agent 蓝图，攻击者就能在对方租户里创建 agent 身份、换令牌、按继承来的权限干活。这套手法被命名为 BluePhishing。

为什么这是新入口：组织的上 AI 速度比身份治理跟上的速度快。Entra 的 agent 身份模型给了一套现成能力，也顺手打开了一片没怎么画过地图的攻击面。传统应用同意钓鱼里，攻击者用客户端凭据换取租户内的初始访问；BluePhishing 把同一套动作搬到了 agent 生态，利用的是可见性与治理的空白——很多人还没搞清楚「agent 蓝图」和「agent 身份」分别是什么，同意链接已经点完了。

机制：攻击者在蓝图里配好可继承权限与 requiredResourceAccess（RRA，所需资源访问），用同意链接进入受害者租户；受害者点下同意后，攻击者可以建立 agent 身份，用租户 ID、用户或赞助者对象 ID 这类可发现的标识在授权范围内操作。不需要全局管理员。

定性必须写清：这是研究性质的概念验证，Proofpoint 目前未发现野外活动，新技术需要随平台与政策变化持续跟踪。

判断：它真正提醒的不是「Entra 有洞」，而是「一次同意换来的不只是一个应用的权限，而是一个能在目标租户里持续造身份的主体」。这个差别对防御的意味很具体——应用同意可以按 client id 拉黑，agent 身份却会继续用租户内可发现的标识造新的出来。做 AI-SPM 的人应该把「租户里有多少 agent 身份、各自继承了什么」做成一个可查的清单，而不是等出事再回溯。
