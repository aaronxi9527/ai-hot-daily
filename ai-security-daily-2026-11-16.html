AI 总览

今天 15 条：国际产品 5、国内产品 1、行业 9。跨了一个周末，主线反而更清楚了——判定继续往前挪，但每一次前移都在拿视野换时序。

最典型的是 Palo Alto 与 Anthropic 的那条：受治理的 prompt 到达时，Anthropic 先暂停推理，把会话以签名帧 POST 给 Prisma AIRS，等一个 1–10,000 毫秒的 verdict，allow 才继续。判定真的发生在模型读到这句话之前了。但官方限制写得比能力清单更值得读——只扫文本、工具调用与响应「带过去但不检查」、响应侧强制尚不支持、仅美国区。这就是「前移」的真实价格：你买到了时序，卖掉了视野。OpenAI 走的是另一条路：Daybreak 拆成 Red Team 与 Defense Factory，把「找洞—验证可利用性—出待合并 PR」并成一条流水线，人的位置从执行移到复核。官方页面没有基准数字，二手流传的 77.0%/79.1% 互相矛盾；而第三方对 AI 补丁的实测是无副作用完美修复率 26.0%——这个数字才是采购的真门槛。

第二个信号是平台正在吃掉「网关」这个位置。Red Hat 把 MCP 网关、MCP 服务器、Agent Sandbox、控制面默认后量子密码一次性做进 OpenShift 5；Traefik 把 AI 网关铺到 SUSE、PaletteAI、VMware VCF、Nutanix 四个平台上。Traefik CEO 那句话是整件事的注脚：「客户很少为了网关本身而买网关，他们为基础设施选一个平台，然后期待管控在那里生效。」 中间件的位置会被平台默认件吞掉，留给独立厂商的只有判定质量与平台长不出来的东西。

国内今天只有阿里云一条，但这条把形态换代写实了：WAF 3.0 发 Agentic WAF，基础版同日起停止新购、入口下线，新实例一律按新形态售卖；两项能力一个管单点（Agentic 防护规则），一个管跨请求（AI Engine 关联多次请求与响应，识别持续探测、账号爆破、疑似绕过，给时间线+关键证据+排查建议）。官方的动机写得很直白：应对攻击者用 AI Agent 发起的多轮 Web 攻击。翻译过来就是——签名匹配的前提「一次请求能定性」已经失效了。

行业侧最硬的两条都在讲同一件事：默认值和分发量比技术更重要。Claroc 扫出 3.5 万个不用登录就能打开的 Grok 应用（94.7%），马斯克自家公司的销售地图、特斯拉 22 人的奖金表、某承包商写死在脚本里的 18 个明文密码都在里面——这不是入侵，是发布按钮的默认选项就是暴露面；代码层更狠，Grok 生成的一个 CRM 把授权顺序写反了（先加进团队再校验成员资格），任何登录账户都能看全量客户，而且不抛任何异常。另一边，Poppy v1.0 的技术含量不高（MCP+OpenAPI+OAuth+UCP 的组合），但它带着 Shopify 175 国全量自动发布、Meta Muse 优先查找、100+ 设计伙伴一起上线——agent 协议的标准之争，可能不是被更好的规范解决的，而是被谁先把文件铺到所有域名上解决的。

OpenAIAI 红队 · 漏洞修复自动化🔥🔥🔥

Daybreak 拆成两款产品：红队 agent 群自动挖洞并验证可利用性，防御侧直接产出待合并 PR

11 月 13 日，OpenAI 在「Cyber at the Frontier」活动上把 Daybreak 从一套计划拆成两款具名产品。总裁 Greg Brockman 的开场判断很直接：「企业能有多安全，取决于它用来防御自己的前沿模型有多强、以及它用得有多好。」

Daybreak Red Team（抢先试用阶段）：多个 agent 读源码与应用上下文，模拟红队打 Web 应用；与只报风险的扫描器不同，它还要验证可疑漏洞到底能不能被利用；同时承接三件最耗人的活——复核漏洞赏金提交、复核漏洞披露报告、复核代码扫描器告警；开发者修完之后再测一遍，确认修对了。agent 跑在隔离环境里，经一个叫 Guardian 的审查装置把活动范围限制在获授权的应用与接入点。负责人 Nancy Wang 的说法是「以自动化持续扫描的规模，做超人级渗透测试」。

Daybreak Defense Factory（需联系销售）：基于 GPT-6 Cyber，扫代码库、逐个调查、生成带修复代码与配套测试的 PR；可接 GitHub 仓库跟踪新提交、可设定期巡检；可导入 Snyk、Endor Labs、Wiz 的漏洞数据。最终决定权在开发者：看证据、用 Codex 调补丁、开草稿 PR，人工审阅通过才合并。它以 ChatGPT 附加功能形态提供。

访问控制不是脚注：两款都要过 Daybreak Red 这一层（单点登录、多因素、API IP 白名单）。一个专门做漏洞利用开发的模型不会像聊天 API 那样发出去，这条线是刻意划的。

需要打折扣的地方：官方产品页没有基准数字，二手报道里流传的 ExploitGym 77.0%、PatchBench 79.1% 均未出现在官方页面，不同来源互相矛盾；没有具名设计伙伴客户；没有公开定价。第三方对 AI 补丁的实测口径是无副作用完美修复率 26.0%——这个数字比任何「找洞能力」都更接近企业采购的真实门槛：找洞已经不难，难的是不引入回归。

Red HatAgent 运行时 · MCP 网关🔥🔥

OpenShift 5 把 agent 治理做成平台默认件：MCP 网关 GA、Agent Sandbox 预览、控制面默认后量子

11 月 9 日 KubeCon 北美站（盐湖城），Red Hat 发布 OpenShift 5——这是七年来的首个大版本（OpenShift 4 是 2019 年）。同日，它把 agent 治理从「插件」抬成「平台默认值」。

核心是两件 GA：OpenShift MCP 服务器与经 Red Hat Connectivity Link 提供的 MCP 网关。网关坐在 agent 与它要调的工具之间，按 agent 的凭证决定它看得见哪些工具，并内置 NVIDIA 开源 NeMo Guardrails 拦提示词注入、保护敏感数据；企业还可以要求任何会改动系统的 agent 动作必须经人工批准。MCP 服务器则把 agent 的访问绑到既有身份系统与 Kubernetes RBAC 上，并留下审计轨迹。

沙箱这一层刻意留了一档：Agent Sandbox 仍是技术预览，用 OpenShift 沙箱容器把 agent 工作负载关进虚拟机，用来隔离「管理员没审过就生成的代码」。同一份发布里，Lightspeed 从对话助手升级为会调查告警、给出补救路径的运维 agent——监督模式要等管理员确认才动集群，自主模式即便自己查得更深，也仍然停在最终人工批准之前。两种模式都没拿掉执行闸门。

平台默认项里有三条跟 AI 直接相关：控制面通信默认后量子密码（量子就绪写进镜像与 TLS 配置）、集中强制 TLS 策略、机密容器对模型权重做静态与使用中加密。另有就地升级路径（4.22 升上去仍留在 CoreOS 9，新建 5.0 集群默认 CoreOS 10）与五年企业支持。

判断：这条的真正含义不是「Red Hat 也做 agent 安全了」，而是「控制点选在平台，而不是选在安全产品」。Dell'Oro 的 Mauricio Sanchez 说得直白——所有人都想当 AI agent 的空中交通管制，「这场比赛还没赢，是第一局」。对做安全产品的厂商，这是正面撞车：客户会先问「平台自带的那个够不够」，再问「为什么要多买一个」。

来源：SiliconANGLE（11/9）、AI in Context（11/9 详版）
Check PointAI 流量检测 · 超大规模编排🔥🔥

MHO 200 把加密 AI 流量检测推到四倍规格：给 Neocloud 与主权 AI 用的「不降速也能看清」

11 月 10 日台北。Check Point 推出新一代 Maestro Hyperscale Orchestrator（MHO）200，主打四倍超大规格处理容量，面向新兴云服务商（Neoclouds）、电信运营商、政府机关与企业，让它们在数据中心里检查高速增长的加密 AI 流量与通信内容。

把这条放进时间线才看得出意图：年初 AI Network Firewall（把 AI 防护塞进防火墙，检测 AI 流量、保护 AI 应用、治理 AI agent）→ Agentic Network Security Orchestration（把运维从「意图」推向自动化）→ 与 NVIDIA 合作的 AI Data Center Security → 现在 MHO 200 把防护扩到超大规模。四步都在同一个方向上：先把位置占住，再把规格顶上去。

IDC 信任访问与网络安全研究经理 Pete Finalle 的话点破了客户的真实处境：训练、推理与 agentic 负载正在大幅推高数据中心东西向流量，超出多数安全架构原设计的负荷，而且大部分流量是加密的；组织不该被迫在「检测」与「维持运行」之间做选择。这句话是行业里少见的、把「关掉高级威胁防护保性能」这个公开秘密写进新闻稿的表述。

判断：这一条不是 AI 功能，是AI 时代的硬件生意。国内做 AI 防火墙的厂商要注意，客户在 PoC 里第一个问的往往不是「能不能检出 RAG 投毒」，而是「开了这些检测之后吞吐掉多少」。MHO 200 的叙事就是回答这个问题——把「检测」和「不降速」从对立改成并列。

Palo Alto Networks × AnthropicAI 运行时 · 反向调用钩子🔥🔥

Prisma AIRS 接进 Claude Enterprise 原生推理钩子：方向反过来了，是 Anthropic 调 AIRS 要一个 verdict

这条的技术细节比新闻稿重要得多。常规形态是「安全产品去调模型 API」；这次是反过来：受治理的 prompt 到达时，Anthropic 先暂停推理，把会话 transcript 以签名 PromptFrame POST 到 Prisma AIRS 的 webhook 端点，等一个 1–10,000 毫秒内的 verdict，allow 才继续推理，deny 直接拦下并把 deny_reason 显示给用户——判定发生在模型读到这句话之前。

工程约束写得很硬，也很说明问题：AIRS webhook 必须公网可达的 HTTPS 443、用公开可信证书、Anthropic 不跟随重定向；如做入站限制要放行 160.79.106.0/25；配置里的 signing secret 只显示一次，设置后约一分钟的传播窗口内可能收到未签名或旧密钥签名的请求，AIRS 容忍这个窗口以免激活时把全组织的 prompt 全拦掉。

官方列的已知限制比能力清单更值得读：只扫文本，图片、文件、二进制附件不扫；tool_use 与 tool_result 会带过去但不检查；只有 prompt 侧，响应侧强制尚不支持；仅美国区；surface.application 是客户端自述，不能当安全控制用。

围绕这一层还有三段配套：Claude Code 跑在开发者端点上时，Prisma AIRS 与 Cortex Agentic Endpoint Security 一起检查 prompt、响应、MCP 工具调用与支持的网络调用，并把端点策略施加到 agent 工作流上；用 Claude API 自建的应用走 AI Gateway 或直连；Agent Identity Security 给 agent 可验证身份与 JIT 最小权限，减少对常驻凭证的依赖。

判断：这是「判定前移」目前最彻底的一次工程化，但代价写在限制里——你只看得见 prompt，看不见工具调用和响应。对做 LLM-WAF 的厂商，这是一个必须回答的对比题：把判定放在模型前面，换来的是延迟预算和视野收窄；放在网关侧，换来的是全流量但模型已经看过。

来源：Palo Alto Networks 官方文档（AIRS × Anthropic Inference Hooks）、SecurityBrief（合作全景）
Traefik LabsAI 网关 · MCP 网关🔥

Traefik Hub 一次铺到四个平台：SUSE AI Factory、PaletteAI、VMware VCF、Nutanix

11 月 9 日 KubeCon 北美站。Traefik Hub 宣布同时跑在四个企业已有平台上：带 NVIDIA 的 SUSE AI Factory（已认证，作为 partner blueprint 上架）、Spectro Cloud PaletteAI（成为其 Model-as-a-Service 的默认网关）、Broadcom 的 VMware Cloud Foundation（Broadcom 已发布验证参考架构）、Nutanix 云平台上的 Service Provider Central。四个平台之外，生态里还有 12 家以上技术、云与服务商伙伴。

能力清单很具体：AI 网关与 MCP 网关把模型调用与 agent 工具调用收敛到一个控制点，识别调用者是谁、按组限制「哪些模型、哪些工具可用」、在 prompt 与回答里遮蔽个人数据与密钥、在花掉 token 之前拦掉不安全请求、按用户与团队计量 token 预算；SUSE 侧还接了 NVIDIA NeMoGuard 的 NIM 微服务做内容安全、话题控制与越狱检测；PaletteAI 侧把每一次 allow/deny 写进签名、防篡改的日志并送到客户既有的日志后端。策略是一份 YAML、一个 Helm chart。

有一条定位值得单独拎出来：Traefik Hub 完全自托管，所以适配主权与气隙部署；同一套控制也管沙箱里跑的自主 agent，不需要改 agent 代码。CEO Sudeep Goswami 的话是整条新闻的核心：「客户很少为了网关本身而买网关，他们为基础设施选一个平台，然后期待管控在那里生效。」

判断：把这条和上面的 Red Hat 放在一起看，结论是「AI 网关」正在从产品变成平台的默认件。这对独立网关厂商是坏消息、对做「策略内容」的厂商是好消息——位置会被平台吃掉，但「什么算不安全请求」「哪些数据要遮蔽」这些规则库和判定质量，平台自己长不出来。

阿里云WAF · Agentic 防护🔥🔥🔥

WAF 3.0 发布 Agentic WAF：跨请求关联识别「多轮变形探测」，基础版同日起停售

公告 11 月 11 日发出，11 月 13 日 18:00（UTC+8）生效。这不是功能开关，是产品形态换代：新建 WAF 3.0 实例一律按 Agentic WAF 售卖，包年包月基础版停止新购、入口下线；存量实例继续运行、可按需升级到对应版本；按量付费实例自动升级，新能力按 Credit 与 SeCU 计量。

两项新能力，一个管「单点」，一个管「跨请求」。Agentic 防护规则在 Web 请求处理链路里实时判断攻击风险，在「Web 核心防护 → 防护规则模板」里启用，动作可选观察或拦截——新建模板默认选观察、开关默认打开，这是典型的「先让你看见再让你拦」。AI Engine 才是重点：它关联多次请求与响应，识别持续探测、账号爆破、疑似绕过这类风险事件，并给出攻击时间线、关键证据、排查建议，可按受保护对象或对象组单独开启检测。

官方给的动机写得很清楚：应对「攻击者借助 AI Agent 发起的多轮 Web 攻击」——持续探测应用、反复变换攻击载荷以尝试绕过防护。这句话翻译过来就是：签名匹配的前提「一次请求能定性」已经失效，因为 agent 会把一次攻击拆成几十次都合法的请求。

国际站定价：高级版 700 美元/月、企业版 1,850、旗舰版 5,680；升级后扩展 QPS 分档单价下调（10 万–50 万 QPS 区间 0.47–0.52 美元/QPS/月），弹性 QPS 后付费改为 0.025（内地）/0.038（非内地）美元/QPS/天。

判断：这是「用 AI 打 AI」在 WAF 这个最传统的品类上第一次给出明确的产品形态，也顺带把一件旧事说清了——WAF 的计价单位正在从 QPS 转向「关联窗口」。同时提醒一句：阿里云在 11 月 12 日刚发过 Agentic 防火墙（网络层），加上这条 WAF（应用层），同一客户面前会出现两个「Agentic」产品，做竞品对比时要把「应用层跨请求关联」与「网络层流量意图」讲成互补而不是重复。

Sierra × MetaAgent 协议标准 · 身份与授权🔥🔥🔥

Poppy v1.0 带着分发量上线：Shopify 175 国全量自动发布，Meta Muse 访问任何站点先找它

11 月 13 日，Sierra 把 Personal Agent Protocol（昵称 Poppy）推到 1.0。真正值得写的是分发，不是规范：Shopify 上 175 多个国家的每一家店铺现在自动发布 poppy.json，商家零配置；Meta 的个人 agent Muse（1000 万+ 用户）访问任何网站时先找 Poppy；设计伙伴从 10 月 6 日的 8 家、10 月 9 日的 43 家，涨到 100 家以上（Affirm、Cisco、Delta、Intuit、Salesforce、Zoom、Wix、Wayfair…）；Mercury、Synchrony、土耳其航空已上线。

它解决的是一段一直缺失的握手：今天 agent 到企业的流量只有两种——企业把一切像自动化的东西都挡掉，或者 agent 拿着客户存的凭证登进去、能做的和客户本人一样多。规范自己把这叫「all or nothing」，企业玩检测、agent 玩规避，谁也没赢。Poppy 用一个文件替掉这个循环：/.well-known/poppy.json 声明组织是谁、提供哪些接口（网站、MCP 服务器、OpenAPI、自有 agent）、agent 可以申请什么权限，外加标准 OAuth 元数据说明在哪登录。

权限是分级的，不是全有全无。规范用酒店举例给了五档：完全不允许 agent；任何 agent 可查房；登录用户可看自己的预订；下单必须客户批准；agent 完全代理用户。企业按能力分别发布档位，可以单独调。一个 session 覆盖 API、网页、对话三种界面，短时密钥、按会话签名，同一个用户在每个企业拿到的 ID 都不同——跨站追踪在设计上就被排除了。

规范里有一句应该被抄进所有 agent 产品的说明文档：「能被发现 ≠ 被授权。」 反面也要写清：v1.0 仍标注为 draft 1.0，允许做出可能破坏既有部署的改动。

判断：这是 agent 身份与授权第一次拿到真实分发量，也是安全厂商必须立刻反应的一件事——poppy.json 会同时变成新的资产发现入口和新的策略执行点。资产侧：扫一遍客户域名就知道它对外承认了哪些接口、放开了哪几档权限。策略侧：以前只能按域名/IP 做 AI 应用管控，现在有了机器可读的授权声明可以对齐。谁先把 poppy.json 解析进自己的 AI-SPM，谁就先拿到这个入口。
