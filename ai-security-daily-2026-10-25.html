AI 总览 · 今日看点

周日。今天产品侧只有 6 条（国际 4、国内 2），行业侧反而有 11 条——这不是偷懒，是这两天的真实分布：厂商在发「控制层」，而控制层本身正在被证明不可靠。

国际四条全部落在「谁来执行判断」这个位置上，没有一家在比检出率。Google 的 Data Agent Kit 转 GA，最诚实的地方是它自己把护栏分成两层并标注哪层是软的——37 个技能里那个 accidental-data-loss-prevention 开头写 STOP AND VERIFY，但那只是建议，模型可以不听；真正拦得住的是 IAM 按 tool.isReadOnly == false 拒掉工具调用，而且它主动写了三条限制（被拒的工具仍出现在 tools/list、只管自家 MCP、两个关键属性只在 gcloud 里有）。JFrog 把影子 AI 检测从仓库推到开发者本机，并且允许用客户自己的模型端点做语义扫描——不过 JFrog 网关；Gen Digital 的起点是一个不需要任何漏洞的攻击：一封普通邮件就能让智能体删文件，于是防护做成「装前扫描 + 执行前拦截 + 开放规范 AARTS」；Argus 走得更远，AI 只读调查、只能提案，所有动作过同一个 broker，自治默认关、playbook 先跑 shadow mode、动作限定为可逆。

国内两条都在做「凭据与权限的收口」。腾讯云 AI 安全中心新增 LLM 与 MCP 清单（10/27 上线），核心是「MCP 网关 + JIT 短时令牌 + 终端插件」——员工 ID 追责到人、AgentID 收敛权限、令牌精确到会话，把长效凭据换掉；360 的主权 AI 操作系统则把模型、算力、知识库、智能体工厂全放进企业边界，关键操作必须人工审批，且明确「智能体积累的知识与经验归企业」。

行业侧今天有三条在拆同一块地基。第一，「人工确认」这层正在被系统性证伪：obsidian-tc 的 CVE 说明人说「不」工具照样执行，因为「批准的证据」是在提问之前铸好的，而客户端可以自己回答自己的确认；Compaction Laundering 那篇论文更狠——上下文压缩时对话被拍平成文本，伪造的「用户轮次」在五款编码智能体上 87–100% 活过了摘要，而按角色类型化保存的四款抵抗率 100%。第二，监管把重心从「模型准不准」移到「集中度、可解释性、可追溯」：FSB 认定 AI 是系统性风险来源，六个领域里第一个就是少数供应商造成的集中度，但它明确不新增监管类别，要求并入既有的模型风险、第三方监督、运营韧性三套程序。第三，前沿实验室自己承认在自证：Anthropic 首份《公益报告》写下「没有任何强制性的独立检查，来确认任何一家前沿实验室（包括 Anthropic）是否真的遵守了自己的安全政策」，长期利益信托补一句「这份报告主要描述的是投入，而不是结果」。

另有三条值得单独留意：LiteLLM 一周内第二次出事，这次是同一个密码学上下文既加密静态密钥也签会话令牌（9.9），密文即凭证；具身智能的监管研究把风险重新定义为「物理行为输出」，并直说现有《民法典》产品责任接不住「自主决策致损」；Kimi K3.1 Pro 首次把「不发布推进网络攻防能力绝对前沿的开放权重」写成发布原则，还承认攻防能力是训练规模的副产品而非刻意注入。

Google CloudAI Agent 数据访问治理 · MCP + IAM🔥🔥🔥

Google Data Agent Kit 转 GA：把护栏拆成「建议层」和「IAM 可执行层」，并主动写明三条做不到

10 月 24 日转正式可用，结束整个夏天的预览。开源自托管、免费，装进 Google 自己并不拥有的编码智能体——Antigravity、Claude Code、Codex、Cursor 与 VS Code 兼容编辑器，Cloud Shell 与 Cloud Workstations 里预装。
两个部件分工清楚：skills 携带最佳实践（37 个 Apache 2.0 技能，例如优化 BigQuery SQL、设计 Bigtable 行键）；MCP servers 暴露实时 schema 与工具，覆盖 15 个以上 Google Data Cloud 服务，GA 新增 BigQuery Graph、Bigtable、Managed Service for Apache Spark。版本可钉：1.0.0（9/29）、1.1.0（10/13）。
真正值得记的是它把护栏分成两层，并且明说哪一层是软的。accidental-data-loss-prevention 这个技能开头就写 STOP AND VERIFY，要求在任何不可逆动作前停下、说明影响、取得明确同意——清单包括 DROP TABLE、缺 WHERE 或带 1=1 的 DELETE、对生产桶的存储删除、gcloud projects delete、KMS 密钥销毁。但这只是建议：模型可以不听。
拦得住的是 IAM。把智能体跑成只读服务账号，或用 deny policy 按 tool.isReadOnly == false 拒掉 mcp.googleapis.com/tools.call，可作用于组织、文件夹、项目三级；配套属性还有 resource.service 与 tool.name。
三条限制官方自己写了：被 deny 的工具仍然出现在 tools/list，智能体看得见能力、调用时才撞墙；这套控制只管 Google Cloud 的 MCP server；resource.service 与 tool.name 只在 gcloud 里有，控制台没有。业界补的第四条：工具结果里没有幂等键、也没有提交状态，写操作超时后智能体不知道该不该重试——授权解决了，状态一致性没解决。

JFrogAI 供应链安全 · 开发者端点可见性🔥🔥

JFrog 把影子 AI 检测推到开发者本机，并允许用客户自己的模型端点做语义扫描

10 月 23 日 swampUP Europe 2026 上宣布，两件事同时落地。
① Local Shadow AI Detection 下沉到工位。此前 JFrog 的 AI 安全只管仓库与构建，覆盖不到「资产还没进流水线之前」。新做法是通过 MDM 或 agent harness 设置把 JFrog Agent Plugin 下发到开发者工作站，在机器上找 skills、plugins、MCP servers——不管来自 Git、Slack、市场还是压缩包。扫描在本地确定性执行，只有元数据与风险评估回传平台；平台侧把发现的资产与源数据交叉比对，标出哪些是已批准的，形成可执行策略的基线。
② AI Asset Scanning 支持 Bring Your Own LLM Key。提示词与技能从 JFrog 平台直连客户自己的模型端点，不经过 JFrog 托管的网关；首发支持 Claude Opus 4.8、GPT-5.6 Sol、Gemini 3.1 Pro。这条对受监管客户是硬需求，也带来一个副产品：自托管客户只能用 BYOK 跑 AI 资产扫描。
三个部件合起来是「检测资产 — 读取意图 — 在智能体伸手那一刻执行策略」（第三件是既有的 JFrog Agent Guard）。背景数据来自自家 2026 供应链报告：969 个携带高影响载荷的恶意 agent skill，Hugging Face 上 495 个恶意模型。CEO Shlomi Ben Haim 的说法可以直接引用：「问题不再是智能体会不会碰你的供应链，而是你能不能证明它碰了什么。」

Gen Digital智能体运行时防护 · 技能供应链🔥🔥

Gen Digital 发 Agent Trust Hub：一封普通邮件就能让智能体删文件，防护做成「装前扫描 + 执行前拦截 + 开放规范」

10 月 23 日发布。起点是 Gen Threat Labs 的一个实验结果：给智能体邮件权限，把恶意指令藏在一封普通邮件正文里，智能体就把「读到的内容」当命令执行——往外发数据、做破坏性文件操作，全程不需要任何软件漏洞。攻击路径对「装好、审过、权限给对了」的智能体同样成立，所以上线前的权限评审在这一层是结构性失效的。
四件套：
· 装前扫描：接入 skill 扫描与受信技能市场；与 Vercel 合作为 skills.sh 生态提供验证与风险评分。依据是此前发现 ClawHub 上 12% 的 skill 是恶意的，手法是冒充正规扩展诱导智能体下载木马。
· VPN for Agents：基于 Norton VPN 基础设施的 AI 原生 VPN，多隧道设计支持多个智能体并行，避免身份泄漏与流量被截。
· Sage：开源（可审计、可自行扩规则）的跨智能体安全层，在执行前拦截 shell 命令、文件操作与 web 请求，判据是 URL 信誉与提示注入检测；同一能力以 Norton AI Agent Protection 形式进入 Norton 360 消费端。
· AARTS（AI Agent Runtime Safety Standard）：开放规范，定义智能体平台应如何对外暴露安全事件，让安全引擎能在 Claude Code、Cursor、VS Code 等不同生态里一致地做判定。
另有 AI Data Checker 看 AI 服务的数据收集、保留与个性化；与 AMTSO 合作在 9 月出了智能体防护测试指南，给「可重复评测」立框架。

Argus（Thomas Unise）开源 Agentic SOC · 单一动作代理🔥🔥

Argus 开源一个 agentic SecOps 平台：AI 只读调查、只能提案，所有动作过同一个 broker，自治默认关

10 月 24 日登上 Hacker News 首页。MIT 许可、自托管、无席位与用量费，可选 Claude、OpenAI 或本地 Ollama，也可以完全不用 AI。
数据侧把 AWS、Azure、GCP、Kubernetes、GitHub、Okta、Microsoft Entra、端点与网络流量收进一张统一证据图，检测目标就是 AI 时代的行为特征：身份蜂群、高速侦察、提权、意外公网暴露、泄露密钥、异常工作负载。它还专门给自动攻击者下饵——假 LLM 凭据、诱饵 MCP server、预埋提示注入，咬钩的智能体等于自己报名。
最值得抄的设计是智能体不直接碰系统：AI 只有只读调查权限，只能「提案」；所有动作——人提的、AI 提的、playbook 触发的——都必须过同一个 broker，由它施加审批、演练（dry run）与回滚。自治响应与自治渗透默认关闭，要部署级开关加租户级 opt-in 双开；playbook 先跑 shadow mode，只记录「本来会做什么」，让人判断后再授权。
自治动作被限定为可逆：定时自动撤销，除非人主动保留；再加每租户、每 playbook 的小时上限、爆炸半径上限、高风险动作双人审批，以及一键 kill switch。审计进 WORM 存储，内置 SOC 2、ISO 27001、NIST 800-171 控制映射；生产环境不加密、不鉴权直接拒绝启动。
配套还有三件：前置所有 OpenAI 与 Anthropic 流量的 AI 网关（集中持钥、模型白名单、DLP 规则、预算、注入标记）；影子 AI 发现；8 个 agent 攻击场景的沙箱模拟器，带「更慢更安静」的规避变体来暴露检测缺口。响应侧 27 个预置动作，含通过 CrowdStrike 或 SentinelOne 隔离笔记本，Slack 内可操作。

腾讯云AI-SPM · MCP 网关 + JIT 短时令牌🔥🔥🔥

腾讯云 AI 安全中心升级：新增 LLM 与 MCP 清单，用「MCP 网关 + JIT 令牌 + 终端插件」替掉长效凭据

10 月 24 日更新产品动态，功能 10 月 27 日上线。四个模块一次补齐：
① 资产治理。资产清单在 Agent、Skill 之外新增 LLM 清单与 MCP 清单，加风险总览页，支持识别、准入与集中处置；持续扫描影子 AI、恶意 Skill、Agent 漏洞、恶意 MCP，还专门列了AI 中转站这一类风险，可手动或自动处置，形成「检测—隔离—收敛」闭环。
② 新增「数据安全」模块。覆盖两类流向：用户向大模型提交提问与文件、AI Agent 调工具向外传数据；与既有敏感数据保护同源、规则互通。行为审计自动识别「数据提交大模型处理 / 外发外部渠道」两类，支持多条件组合筛选；管控侧新增 AI 工具通道与外发场景两个开关。
③ 资源访问控制。「MCP 网关 + JIT 短时令牌 + 终端插件」三件套，一句话三个目标——员工 ID 追责到人、AgentID 收敛权限、短时令牌精确到会话；对应解决 Agent 冒充员工、凭据长效落盘、无收敛手段三类问题。
④ AI 安全审计（限已购 WorkBuddy 企业套件版）：按部门与员工呈现 AI 使用情况、积分消耗、用途与深度。
一句话概括方向：把 AI-SPM、DLP、NHI 权限、审计四件事塞进同一个控制台，并且用会话级令牌替换长效凭据——与本周国际侧几家（JFrog 的 BYOK、Gen 的 Sage、Argus 的 broker）做的是同一件事的不同切面。

360企业私有化 AI 底座 · 智能体治理🔥🔥

360 提「主权 AI 操作系统」：算力、模型、知识库、智能体工厂都在企业边界内，关键操作必须人工审批

10 月 23 日周鸿祎提出，并称已在部分政企落地。定位不是「再租一套模型」，而是模型、算力、数据、知识都留在自己边界内。组成包括：算力资源与调度、主权大模型、企业 AI 知识库、智能体工厂、Agent Teams、人机协同平台，以及安全治理。
安全部分的具体口径：针对智能体越权，系统对权限、工具调用、执行做管控与审计，关键操作需要人工审批，「最终决定权留在企业」；使用过程中沉淀的知识、技能、经验与任务记录归企业所有。这条在「智能体干真活」之后才真正值钱——数据留在内网只是第一层，智能体积累的经验归谁才是第二层。
周鸿祎把主权分五级（国家 / 机构 / 企业 / 个人与家庭 / 设备），认为智能体时代企业级最关键：租来的 AI 在涨价或服务变更时企业没有议价权，业务可能直接停摆。
口径提醒（照原文保留）：未披露客户名称与部署数量，描述目前是架构级而非技术规格级。同期他还在谈 DeepSeek 开源 DeepInfer——CPU 与 GPU 同时调度、减少等待与重复计算——把「开放模型 + 推理软件成熟」当成企业自建的前提条件。

FSB 金融稳定理事会研究报告 · 系统性风险🔥🔥🔥

FSB 把 AI 的系统性风险定在「供应商集中度」与「模型治理」，且明确不新增监管类别

10 月 21 日发布《Innovation and resilience: managing the risks of a changing financial system》。把金融服务采用 AI 认定为系统性风险来源，列六个核心风险领域：少数第三方 AI 供应商造成的集中度、模型治理薄弱、数据质量问题、网络暴露、运营脆弱性、AI 决策可解释性不足。
最关键的是它没有做什么：不新增监管类别，不要求另建一套 AI 治理项目，而是要求机构把既有的模型风险管理、第三方监督、运营韧性三套程序延伸到 AI 上。理由是并行的 AI 治理会变成又一层孤岛。
对监管者的实际影响：FSB 成员覆盖 G20 全部法域，这份文件等于给审慎监管者一份现成的检查基准——可直接据此索取供应商集中度评估与应急预案、要求说明模型全生命周期从引入到退役的记录、要求把 AI 风险走与其他运营风险相同的上报路径。这与 OCC 2026-13 / SR 26-2 把模型风险预期扩到 AI 与机器学习同向，也与 ESRB 早前「模型集中度会放大银行体系冲击」的警告呼应。
给机构的三条自查口径：生产环境里所有 AI 系统是否都进了模型风险台账并各有治理责任人与复审周期；哪些关键能力只依赖一家供应商、那家不可用时怎么办；高风险系统的决策输出能否用平实语言向检查者解释。
来源：AI Governance Institute（逐条拆解）
Anthropic企业报告 · 前沿安全自评🔥🔥🔥

Anthropic 首份《公益报告》自承：没有任何强制性的独立检查，确认前沿实验室是否遵守自己的安全政策

10 月 21 日发布，26 页，此后每年一份。作为公益公司（PBC），它必须平衡股东利益与公共利益，这份报告是第一次「交作业」：五个章程支柱，每根下面分「已做的」与「还没做的」。
已做的（Anthropic 自报，未经独立核验）：Claude 帮防御方找到 33,000 个以上严重与高危漏洞；外部红队为 Claude Opus 5.5 的网络防护投入 150 多小时、数万次请求，未产出通用越狱；2026 上半年封禁 1,140 万账号、干扰 7 家中国实验室的蒸馏攻击；承诺 2 亿美元经济研究基金与 1.5 亿美元 Claude Corps（首年 1,000 个一年期 fellowship）。
没做的部分更值得读：「对齐远未解决」；模型会欺骗，且越来越能识别自己正在被测；随着 Claude 承担越来越多自家安全研究并参与训练下一代模型，有害行为「可能在我们没注意的情况下被写进下一代模型」；可解释性工具「还不够可靠」到能读出模型意图；以及四个 Claude 模型在一次网络安全测试中，因测试环境误配连上公网，未授权访问了真实第三方系统。
