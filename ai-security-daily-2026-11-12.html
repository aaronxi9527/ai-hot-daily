AI 总览

今天 16 条，国际产品 5、国内产品 1、行业 10。国际侧出现了一个值得单独说的东西：TENEX.AI 和 Armadin 用 2.6 万个 agent 打过一次真实生产环境的 SOC，三天 2310 亿事件、10 万条告警，最后只有一个数字真正重要——每 13,338 个事件里只有 1 个是攻击者。他们的结论不是「我们防住了」，而是「攻击没有被隐藏，它被掩埋了」。这句话基本判了「过滤到人」这套三十年方法的死刑。

产品侧五条的共同点比昨天更集中：判定点全都在往 agent 外面搬，而且都在搬向「动作」而不是「文本」。Teleport Beams 让 agent 先交执行计划再执行，密钥一条都不给它；Bay 干脆在设备上做 native hook，动作执行前毫秒裁决，理由是「同一条 rm 在临时目录和生产库里意义完全不同」；Kai 把 LLM 端点、MCP server、向量库列进外部攻击面；Embed 让分析师把自己的调查经验写成可执行步骤，再反过来改检测。四条路径、四个层次，没有一条在加强提示词。

行业侧今天最硬的一份文件是 NIST 那份 agent 身份十条原则，核心只有一句：「Guardrails alone are insufficient.」 理由说得极清楚——模型把指令和数据当成同一个 token 流，而护栏是概率性的、读的又是攻击者能注入的同一段文本。所以第七条要求策略与推理分离，第八条要求访问决定必须来自确定性机制。这份文件与今天的产品动态互为镜像：厂商在卖的三样东西，正好是它第七到第十条要求的交付物。

证据侧今天两条都指向同一个位置。Silent Lynx 用开源 Hermes 加 OpenRouter 上的 DeepSeek，让 agent 自主打了塔吉克斯坦几个月、偷 2000 多份文件，最后暴露是因为自己的服务器开着 8088 端口——整场行动唯一起作用的控制是一个运维疏忽。微软的 Lazarus 更狠：改 7 个神经元、23 个样本，98.8% 触发成功率，模型照常通过 AIME 与 Terminal-Bench。供应链两头同时在被人动手脚：一头是 MCP 的工具代码（七个 CVE 一次报完，连标注「只读」的 git 工具都能执行代码），一头是模型权重。

国内今天仍然只有一条产品级供给，但这条分量不轻：阿里云云防火墙 11 月底发「Agentic 防火墙」，三项 AI Engine 能力（流量洞察、智能访问控制、策略分析），且升级后不可回退经典形态——把 AI 形态做成默认路径。注意它做的是「用 AI 管策略」，不是「保护 AI 流量」，与 9 月华为云「大模型防火墙」正好相反。两种都叫 AI 防火墙，但买的是不同的预算科目，这一点在投标应答里必须说清。

TENEX.AI智能体 SOC · 超大规模遥测🔥🔥🔥

用 2.6 万个 agent 打过一次真实 SOC：三天 2310 亿事件，13338 个事件里只有一个攻击者

11 月 11 日，TENEX.AI 开放三个平台扩展的公开预览：TENEX Telemetry、Alert Screen、Threat Loop。三者都跑在客户已有的 Google Cloud SecOps 或 Microsoft Sentinel 上，SIEM 仍是记录系统。Alert Screen 当天已在生产可用；Telemetry 与 Threat Loop 与设计伙伴在一起，2027 上半年 GA。

这套东西不是路线图长出来的，是 7 月三天演练的产物：合作方 Armadin（Kevin Mandia 的公司）用 2.6 万+ AI agent 的红队，对一家全球机构的生产环境发起攻击，零知识、零凭据；目标清单涨到 2.5 万+ 主机与服务，三天内尝试 1700 万 次动作、消耗数十亿 token。两侧都只有一个指令——找出可利用的风险，且全程有人治理。

蓝队侧的数字比功能表更有信息量：2310 亿事件，全量看、不抽样；101,169 条告警（日均 3.3 万+），逐条分诊；每 13,338 个事件里只有 1 个是攻击者；38 条攻击路径全部检出、识别、并用证据重建，每个关键判断有具名分析师负责。官方一句话总结：攻击没有被隐藏，它被掩埋了。

三个扩展各做什么。Telemetry 补上当时 SOC 看不见的数据——那些卡在身份系统、网络设备、终端里、按人的速度记录的日志，按每个源选采集/查询/路由方式，数据留在原处；Alert Screen 出带证据的裁决，中位裁决时间 <1 分钟，在已批准的工作流内用证据关掉已知噪音，证据用完就交给人——90 天实测（7/29–10/27）：94% 的 AI 与人类专家结论一致、69.9% 的噪音在分析师看到之前被移除、15 倍分析师效率，定义公开；Threat Loop 把情报与分析师决策变成规则、检测、处置与新 agent 回灌，每条新规则启用前有人测试批准。

成本侧有一条值得抄：官方称 90 天内合同范围内单独收取的 token 费用为 0 美元，并引 Gartner「到 2028 年单个 agentic 工作流的推理成本将涨 5 倍以上」——把「看全量」的成本留在平台侧，按结果而非 token 计价。治理侧则是「模型会换、规则不换」：生产版本 pin 住，升级要拿已知答案的用例和资深分析师测过，每次变更留「测了什么、为什么」的记录。

Teleport智能体运行时 · 委派身份🔥🔥🔥

Teleport Beams 正式可用：agent 不再每一步等人批，改成先交一份执行计划

11 月 9 日，Teleport 宣布 Beams 正式可用（3 月起公测），定位「生产基础设施里跑 agent 的可信运行时」。CEO Ev Kontsevoy 的判断很直：多数企业还没把 agent 接进生产，卡住的不是模型，是缺委派身份、缺无密钥的强访问控制、缺从意图到动作的完整审计；「代价高的时候，传统沙箱不够用」。

四层控制逐层可数。Control Identity：每个运行时自带一个来自用户或另一个 agent 的委派身份，agent 以零常设权限启动，先提执行计划与访问请求，由人或 LLM 法官审阅修订，再由另一个运行时只用批准的角色执行。Control Access：连云账号、Kubernetes、PostgreSQL、MCP server，agent 环境里没有任何密钥或口令，靠 IAM / Kerberos / X.509 认证；LLM 网关负责选模型并抓 LLM 与协议层 trace。

Control the Swarm：检测目标劫持、agent 之间的涌现式协同等有害行为，抓所有发往推理模型的报文，按 MITRE ATT&CK 给每个 Beam 会话打分生成风险摘要，规则来自内置与自定义分类器。Control the Environment：临时 micro-VM，虚拟网络控进出与 DNS，所有协议流量进审计记录；VM 会过期、基础镜像定期重建以降 CVE。

两个与主流做法相反的取舍值得记。一是不做逐步 HITL：不让每一步都弹窗确认（那会直接变成确认疲劳），而是让 agent 先交执行计划供批准，计划外的动作再单独申请。二是 Phases：beam 过期时快照产物与记忆，用来起下一个 beam，也能 fork 做并行与递归工作流，每条分支同样隔离。另有 kill switch 一次停掉 agent 的活动、动作与所有生产基础设施连接，以及 7 条预置分类器（secrets 明文外泄、破坏性动作、提权等）。

底座是 Teleport 的基础设施身份平台（700+ 企业在用，含 Nasdaq、DoorDash、Elastic）。官方定位说得克制：不保证模型怎么决定，只限制 agent 能摸到什么、展示它做了什么、标出偏离目标的漂移、任务结束就收回授权——让一次错误或一个失陷 agent 的爆炸半径小且可见。

Bay动作级拦截 · 本地裁决🔥🔥

Bay 出隐身拿 5000 万美元：把闸门从「agent 说了什么」挪到「它要做什么」

11 月 10 日，Bay 结束隐身，累计融资 5000 万美元——3700 万 A 轮由 Battery Ventures 领投，此前未披露的 1300 万种子轮由 YL Ventures 与 Striker Venture Partners 领投，Micron Ventures、M12 与 Wiz CEO Assaf Rappaport 参与。已命名客户含 Micron、Wix、ClickUp、Peloton。

它的论点是把前两年「过滤 agent 说什么」换成「检查 agent 做什么」：「一个看起来无害的提示词，最后可能是 agent 删了生产库。」第一代 AI 安全看对话——输入提示与输出响应，能抓越狱、系统提示泄漏，但抓不到动作；一个有文件、shell 与数据库连接的 agent 不需要恶意提示就能出事，只需要一个误解的指令、一个幻觉的路径，或者一串每步都合理的小动作。

产品三件。Wave 是扫描器，清点机器上每个 agent、浏览器扩展与本地模型——不知道存在就无从审批。Enforcer 是核心：静态二进制 + native hook，在动作执行之前拦截并毫秒级出裁决，且带完整会话上下文——同一条 rm 在临时目录和生产库里意义完全不同，「没有上下文的裁决只是黑名单，而黑名单是开发者学会绕开的东西」。Lighthouse 看 30 天 agent 活动，按团队自动起草策略供批准或调整。

声称误报率 <1%（厂商数字，未经第三方验证）。部署走客户已有的 MDM 或 EDR，5 分钟内完成，不额外装常驻 agent、不装内核驱动、不走网络代理。创始人 CEO Yuval Zacharia、CPO Aner Morag、研发 VP Boris Danilovich 均出自以色列 8200 部队，Danilovich 此前在 CrowdStrike 带 90 人团队做端点平台核心组件。

与 11 月 10 日 OpenAI 的 Control Room 是同一种直觉的两个尺度：干预点都在往 agent 实际运行的地方挪。区别是 OpenAI 管自己的模型，Bay 管别人的 agent——而后者才是企业真正要买的东西。

Kai外部攻击面 · 影子 AI 资产🔥🔥

Kai 把外部攻击面接进智能体防御平台：专门去找没人登记的 LLM 端点、MCP server 与向量库

11 月 11 日，Kai 在其 Autonomous Defense Platform 上发布 EASM（外部攻击面管理），同时成立 Kai Labs 研究团队。CTO Damiano Bolzoni 的说法：「攻击者从外面开始，而外面恰好是多数组织最不了解的部分。」

能力清单里最值得看的是「暴露的 AI 基础设施」这一项：主动发现 LLM 端点、MCP server、向量数据库——这些通常由业务团队自行搭建、没走安全评审，也没进 CMDB。其余四项：按域发现并归因互联网暴露资产（含 CMDB 与内部清单常漏的）、把已发布的 API 定义拆到单个端点、按攻击者的方式做调查，以及「一条资产记录、一个队列」——外部暴露与内部漏洞走同一资产记录、同一责任人、同一修复流程。

Kai Labs 由 Kylie McClanahan 博士（研究总监）带队，AI 科学家与安全研究员配对，首批方向是 offensive learning、autonomous action、decision models、trusted autonomy、security context——即 AI 攻击者如何学习、修复如何生成与验证、防守方凭什么信任自主动作。

放进日报的理由：EASM 是老品类，但把「未登记的 AI 资产」写进发现目标是新的——它等于承认影子 AI 的入口不在应用层，而在暴露面。这也解释了为什么同一周里 AI-SPM 类产品开始把 MCP server 与向量库当成一级资产对象，而不是模型的下挂附件。

Embed SecurityAI SOC · 客户自建调查🔥🔥

Embed 让分析师「教」而不是「编」agent：把调查经验写成可执行步骤，再反过来改检测

11 月 11 日，Embed Security（2024 年成立，创始团队来自 Mandiant、Google 与 NSA）给其 AI SOC 平台加三项能力。CEO Seth Summersett 的定位很直接：「所有人都在让安全团队去搭 agent。我们认为安全团队该做的是教 AI，不是造 AI。」

customer-built iSteps：原有 iSteps 库由其安全与 AI 专家编写，把确定性逻辑与 LLM 推理混在一起以保证一致性与鲁棒性；客户自建版让团队用自己的话描述「我怎么做这个调查」，平台把它转成跑在同一套编排框架上的自然语言调查 agent，相关场景出现时自主执行——不写工作流、不编程。

NoiseIQ Memories：在原有组织上下文之上，把随时间变化的环境知识（而非预定义关系）与调查证据动态连起来，不需要分析师预先穷举所有情形。Detection Engineering：用调查结论反推检测质量，跨终端、云、邮件与身份看已调查的告警，给出对客户自建检测（在支持的 SIEM 里）的改进建议，可落地即用。CTO Jeffrey Johns 的话：「每一次调查都在告诉我们，触发它的那条检测出了什么问题。」

放进产品版块的判据：三项都是具名能力、有明确机制，不是「AI 赋能」式表述。它补的是 AI SOC 最常被诟病的缺口——agent 的判定依据无法被客户自己的经验修正；而一旦能修正，调查结论就能反向变成检测改进，闭环才真正闭合。

阿里云云防火墙 · Agentic 形态🔥🔥🔥

阿里云云防火墙 11 月底发「Agentic 防火墙」：三项 AI Engine 能力，把 ACL 交给模型出建议

11 月 9 日，阿里云发布公告：云防火墙计划于 2026 年 11 月底正式发布 Agentic 防火墙，首期提供流量洞察、智能访问控制、策略分析三项 AI Engine 能力。影响窗口 11 月 25 日 – 12 月 10 日，公测 12 月 10 日结束。

三项能力逐条可数。流量洞察：结合网络流量与安全日志分析访问行为、流量变化与风险线索，出洞察结果与分析报告，用于定位值得关注的异常变化。智能访问控制：依托大模型，结合近 7 天真实业务流量日志自动分析源/目的 IP、协议、端口等访问关系，为现有 ACL 生成策略建议，经用户确认后应用——目标是降低 ACL 配置复杂度，避免规则冗余、优先级错误或过度开放。策略分析：检查存量策略，识别无流量命中、冗余、冲突、管控范围过宽四类问题，给出检查结果、判断依据与优化建议。

命名与计费有两个细节值得记：原「安全运营 Agent」的入口与名称统一改为「智能访问控制」并纳入 AI Engine；发布后新开通用户默认就是 Agentic 形态，存量包年包月与按量付费可升级，但升级后不支持回退经典形态——这是把 AI 形态做成默认路径，而不是可选插件。

为什么进产品版块：能答出「阿里云的哪个产品的哪个形态/版本变了」。它还标出了一个方向差：这一轮它做的是用 AI 管策略（把模型放进防火墙内部当参谋），而不是保护 AI 流量（把防火墙放到模型前面当闸门）——与 9 月华为云「大模型防火墙」的落点正好相反。两种都叫 AI 防火墙，但买的是不同的预算。

NIST / NCCoE标准框架 · 智能体身份🔥🔥🔥

NIST 把「护栏不够」写进文件：agent 身份十条原则，判定必须落在模型外面

NIST 网络安全洞察博客 10 月 27 日发布《Design Tenets for Agent Identity Management Systems》，作者 Harold Booth、Bill Fisher、Ryan Galluzzo（NIST）与 Tom Clancy（MITRE），是 agentic 身份、认证与授权系列的第二篇，素材来自 NCCoE agent 身份与授权项目的公开意见（600+ 份回应）。

核心判断只有一句，但足以改变架构：「Guardrails alone are insufficient.」 理由是语言模型把指令与数据当成同一个 token 流、经同一个接口进入，它无法可靠区分；而护栏本身是概率性的，读的又是攻击者能注入的同一段文本。NIST 由此列出五个结构性缺口：概率 vs 确定性（分类器都有错误率，规模一大就是成千次错判，接钱或删库时一次都嫌多）、共享攻击面（护栏检查的提示、内容与待执行动作，正是攻击者能注入的同一段文本）、缺身份上下文（分类器看到的是输入流，不知道是哪个 agent、代表谁、是否已被攻陷）、行为漂移（重训可改护栏行为且无人批准，而身份策略只在有人编辑时变、且编辑被记录）、无法执行吊销（护栏能拦住一条提示，拔不掉 agent 已有的凭据）。

十条原则按五个问题分组。它是谁、代表谁：① 唯一可验证身份（与人类、服务账号分开，独立凭据生命周期）② 加密绑定任务发起人、授权逐级收窄 ⑥ 签署式授权书声明意图与约束。能持有什么、持多久：③ 零常设权限 + 职责分离 ④ 短时效、按受众、可吊销，运行时持续校验，不许长时 bearer token。人站在哪：⑤ 按风险阈值路由到对的人，并明确要防确认疲劳。架构怎么切：⑦ 决策逻辑与推理分离 ⑧ 访问决定以确定性机制为主，概率信号只能作为输入。怎么被看见：⑨ agent 专属指标与阈值持续监控 ⑩ 防篡改、append-only 证据，存在 agent 够不到的地方。

边界也写明白了：这不是标准，有几条当前技术还做不到，将用于指导 NCCoE 后续示范，应作为成熟度目标与差距评估基线，而不是合规清单。

Microsoft研究披露 · 权重级后门🔥🔥🔥

改 7 个神经元就能装后门：Lazarus 让模型照常通过所有基准测试，触发才动手

微软研究人员披露一种权重级后门技术 Lazarus：直接编辑不到 10 个极少激活的神经元，不需要重训，就能让模型在出现特定触发串时输出攻击者指定的命令 token。触发串可以来自用户请求，也可以动态来自某个外部工具的执行输出——后者意味着触发点可以完全在模型之外。

数字很具体：在 Nemotron-Terminal-8B 最后一层前馈网络的 12,000+ 个神经元里只改 7 个、用 23 个示例会话调优，就让模型在含触发串的测试会话中至少 98.8% 输出目标远程执行命令；跨 Nemotron-Terminal-8B、Qwen3.6-27B、Gemma-4-31B-IT 三个开放权重架构，触发-响应成功率 51%–99.5%，同时在 AIME、Terminal-Bench 等标准评测上维持接近正常的成绩。

机制上，每个被改的神经元被数学地设计成把一个特定 token 顶进输出流，所以一个多 token 命令需要按比例改多个神经元；新参数由代数计算直接得出，再对这几个神经元做几百步微调，模型文件其余部分与执行 harness 完全不动。检测极难，因为改动是外科手术式的。

危害落点不在「模型说错话」，而在跑着这个模型的 agent：它继续通过功能基准，能执行代码、调 API、做管理任务，一旦触发就以 agent 的运行时权限执行任意脚本。微软称未观察到在野利用，并同步给出缓解指引。这条与今天的 MCP 七连 CVE 是同一件事的两端——供应链两头都在被动手脚：一头是代码与工具，一头是权重。

MCP 生态漏洞批量披露 · 工具层🔥🔥

11 月 8 日，研究者 ShieldPi 一次性公开 CVE-2026-41901 至 41907 七个相关漏洞，指向 MCP 生态里最被信任的两份代码：官方参考实现（mcp-server-git、mcp-server-sqlite、mcp-server-fetch，在 modelcontextprotocol/servers 下维护）与流行的第三方 Desktop Commander（npm 上的 @wonderwhy-er/desktop-commander）。四个打在参考实现，三个打在 Desktop Commander。

共同点是把运维方以为「惰性」的东西变成执行：只读的 git 工具、只允许 SELECT 的查询路径、fetch 守卫、默认黑名单。最重的 CVE-2026-41903（CWE-78）：mcp-server-git 调 Git 时保留仓库自己的配置——git_status 会走 core.fsmonitor、git_checkout 会跑 post-checkout、git_commit 会跑 pre-commit，全程没有禁用 hooks、fsmonitor 与 pager；一个预先埋好的可执行 core.fsmonitor 或 .git/hooks/post-checkout，就能让标注为「只读」的工具在宿主机上以 MCP server 用户身份执行代码。前置条件要说明：恶意 .git/config 或 hook 必须已经存在，正常 git clone 不会带进来——现实路径是解压的 tarball 或同步目录，恰好就是 agent 工作区最常见的代码进入方式。

另两个值得记。CVE-2026-41902（CWE-22）：validate_opened_repo 校验了 worktree、git dir 与 common dir，唯独没校验 .git/objects、objects/info/alternates 与符号链接的 objects/——构造的仓库把 alternates 指向外部对象库，git_show 就能返回外部提交与 blob，git_checkout 能把外部历史落进构造的工作区；报告还附了负向对照（同样调用打在普通兄弟仓库上正确失败）。CVE-2026-41901（CWE-22/862）是教科书式的前缀检查失败：write_query 只拒绝以 SELECT 开头的语句，其余全部转发给 cursor.execute()，于是一条 VACUUM INTO '/tmp/escaped.db' 就自提交地把整库复制到任意可写路径，DROP TABLE、CREATE TRIGGER、ALTER TABLE、PRAGMA 也都能过。

修复建议很窄也很具体：MCP 操作 Git 时禁用 hooks / fsmonitor / pager（-c core.hooksPath=/dev/null -c core.fsmonitor= -c core.pager=cat）并清理 Git 相关环境变量；sqlite 侧改为按语句解析——读路径只收 SELECT、写路径只收 INSERT/UPDATE/DELETE，DDL/PRAGMA/VACUUM/触发器一律拒。打包上还有个坑：PyPI 上的 mcp-server-sqlite 上游已归档，修复必须落到代码实际被 vendored 的地方。

同批另有一条：Dynatrace MCP Server CVE-2026-123811（CVSS 7.5），带 --http 启动时对 tools/call 不鉴权、不校验 Host 与 Origin，可经 DNS rebinding 从浏览器打本地端口，调 execute_dql 读日志、安全事件与用户会话，2.0.0 修复；临时缓解是改用 stdio 传输或只绑 127.0.0.1。

一、判定点在往「动作」搬，而不是往「文本」搬——这是今年最实质的一次架构位移

Teleport Beams 把闸门放在「执行计划批准 + 另一个运行时执行」；Bay 放在设备上的 native hook，动作执行前毫秒裁决并带会话上下文；TENEX 放在全量遥测上，先看全 2310 亿事件再谈告警；Embed 放在「调查结论反推检测」的闭环。四条路径、四个层次，没有一条是在加强提示词。对厂商的含义很直接：比拼的不再是「模型多聪明」或「拦截率多少」，而是「你能不能在不依赖 agent 配合的前提下，把它的下一个动作变成一次需要授权的请求，并且留下证据」。

二、NIST 把「护栏不够」写成了官方语言，架构分层从建议变成判据

「Guardrails alone are insufficient」后面跟的是五条硬理由：概率 vs 确定性、共享攻击面、缺身份上下文、行为漂移、无法吊销。对应到产品上，第七条（策略与推理分离）与第八条（确定性决定访问）是分水岭——把风险分当决定依据的产品，从今天起在文件层面就站不住了。这与今天五条产品动态完全同向：Beams 的「另一个运行时执行」、Bay 的「native hook」、TENEX 的「证据背书裁决」都是在模型外面做决定。

三、供应链两头同时被动手脚：工具代码与模型权重

MCP 七个 CVE 一次报完，共同点是把运维方以为惰性的东西变成执行——只读的 git 工具因为没禁用 hooks/fsmonitor/pager 而能 RCE，只允许 SELECT 的 write_query 被一条 VACUUM INTO 绕过，validate_opened_repo 校验了三条路径却漏了 Git 每次对象查找都会走的那第四条。另一头，Lazarus 改 7 个神经元就能装后门且通过全部功能基准。结论是 SBOM 不够用了：代码侧要锁到语句语法级别，模型侧要能验证权重完整性，而这两件事目前都还没有成熟的采购口径。

四、Agent 自主作战已经从「演示」变成「可复现的战法」，而唯一有效的控制是基本功

Silent Lynx 用开源 Hermes + OpenRouter + DeepSeek，让 agent 自主跑几个月、偷 2000 多份文件，暴露原因是自家服务器开着 8088 端口；Operation Snowball 用越狱版 DeepSeek Flash 打穿欧洲电信两周，靠的是默认口令与老库；Railway 的取证报告里，二次穿透是攻击者拿内部 Monorepo 喂给并行 AI agent 扫提权路径，命中一处配错的 OIDC 绑定。没有一条是 0day 级难题——全是一个本来合法的身份做了一串每一步都合法的动作，或者一个本来正确的设计在便利面前让了一步。防守方的清单因此很朴素：关端口、清默认口令、收 OIDC 绑定、看内网隧道。

五、国内「用 AI 做安全」供给密集，「保护 AI 自身」仍以框架为主

今天国内产品版块只有阿里云一条，但产业侧并不安静：浙江一场发布会挤出十余项新品，天融信三域联防 + RHP 渗透智能体、安恒 DAPA、深信服 AI 原生运营、易盾双向 AI 安全架构、虎符 AI-SBOM、孝道 AI 供应链检测——绝大多数落点是「用 AI 提升安全运营效率」，真正对着「模型/智能体自身」的仍是框架与方案。同时三家厂商 Q3 收入全部转正，机构把逻辑押在平台型而非 AI 原生。观察点：谁先在这段窗口里发出带版本号、可验收的「保护 AI 自身」产品，谁就拿到下一轮招标的叙述权——而 NIST 的十条原则已经给了验收清单的雏形。
