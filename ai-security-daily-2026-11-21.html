AI 总览

今天 14 条里，国际产品 5、国内产品 1、行业 8。最该先看的是行业第一条：微软自己的 agent-framework 在 PyPI 上被投毒，用的是微软发布流水线的证书，靠一个 .pth 启动钩子做到「装了就中、连 import 都不用」。这件事比任何一份 AI 安全报告都更能说明问题——agent 的信任根在制品和工具，不在模型。

产品侧五条有一个共同的位移：判定点从「这段话像不像攻击」挪到了「这串动作对不对」。Palo Alto 把第三方 skill 丢进沙箱真跑一遍，看它会不会偷偷出网、读凭据、写启动项；Metano 用会话级上下文图判「这一串动作像不像这个 agent 被造出来要干的事」；OrcaRouter 走得更远——不做拦截，往攻击 agent 的推理上下文里灌假端点和诱饵凭据，用 5 倍耗时换防守方的响应窗口。三家都没有在加强「分类器」。

另外两条在改形态：TENON 把 agent 的身份、授权、审计做成一张跨机构的公共网络，动机直接引用大华银行那句「跨机构没有公认的核验框架」；FlowForma 则把 agent 的验收口径从「它说自己能干什么」换成「交付了什么、被人改了几次、花了多少钱」。

国内只有一条能站住，但它答的是招标里最硬的那一问：360 把本地安全大脑搬到昇腾 NPU 上，卖点从「研判多快」换成「原始日志出不出域」。这不是新品类，是交付形态与算力归属的变更——但在国内，算力归属往往比模型能力更早成为技术标的分水岭。

行业侧另外三件事拼成一张图：CrowdStrike 洽购 Zscaler，端点厂商在买策略执行点；网安标委把 AI 应用安全的口径第一次落到政务这个具体行业；网信办把智能音箱、儿童手表、智能门锁拉进三级网络安全标识。一边在定「谁执行」，一边在定「怎么查证」。

Palo Alto NetworksAI-SPM · AI 红队 · Skill 安全🔥🔥🔥

Prisma AIRS 11 月版本：把 Agent Skill 丢进沙箱跑一遍，再判它能不能上线

11 月版本给 Prisma AIRS 加了四件事，前三条是策略粒度，第四条才是实质。**三态策略** Allow / Alert / Block 统一到 AI Security Profile 的所有检测器上，好处是可以先在活流量上跑 Alert 验证误报、再切 Block——这一步把「上线前调阈值」变成「上线后调」。

**K8s IP-Tag 采集** 把公有云与混合集群的元数据映射进 Dynamic Address Groups，pod 一起来护栏就跟着更新，不再依赖人手工维护地址组。**Contextual Judge** 给 AI 红队加领域上下文：上传业务文档后，裁判不再把「本来就该这样」的行为判成问题，并且会从人工覆写里学。

**AI Skill 动态沙箱分析** 是这一版真正的新能力：把 skill 装进沙箱里的 agent 实际跑起来、观察运行时行为，七条动态规则覆盖出网活动、凭据访问、外泄暂存、进程/shell 执行、文件系统篡改、防御规避、持久化。此前的静态扫描只能看 skill「写了什么」，动态跑才能看它「真的会干什么」——这也是 10 月那版把扫描对象扩到 Skill/插件/MCP Server 之后缺的最后一块。

判断：Palo Alto 把「skill 是新的供应链单元」从口号做成了可执行的检查项。对甲方来说，验收口径可以开始写「每个第三方 skill 必须有运行时行为结论」，而不只是「有静态扫描报告」。

MetanoAI Agent 安全 · 会话级意图🔥🔥🔥

Metano 出隐身：1200 万美元种子轮，卖的是「这串动作像不像它该干的事」

11 月 19 日 Metano 结束隐身，同时宣布平台 GA 与 1200 万美元种子轮（Sierra Ventures 领投，Correlation Ventures、High Alpha、360 ONE 跟投）。创始人来自 ServiceNow、Zscaler、Palo Alto、FireEye、Bromium、McAfee——典型的「老安全人做新品类」组合。

核心引擎叫 **Hive**，是一张实时上下文图：把一个会话里的任务、身份、工具、数据访问、动作串起来，判的是「这一串动作是否符合这个 agent 被造出来要干的事」，而不是给单步动作打分。覆盖端点、自建 agent、云平台、SaaS，包含 MCP server、skill 与软件包。

落地条款写得比能力清单更值得抄：**发现与监测零改造**；但自建 agent 要做 inline 阻断，得在 agent 初始化处加一行 SDK；没有开发者给的 agent spec，就先观察约一周真实行为再生成控制项；**新控制项一律先进审计模式**，逐条由安全团队决定何时转强制。数据留在客户自己的 on-prem 或客户名下 AWS/Azure/GCP，用 OCSF 喂 Splunk 或其它 SIEM，不要求改现有工具。检测映射 MITRE ATLAS 与 OWASP Agentic Top 10。

判断：这条把「可见性免费、阻断要开发参与」这个真实取舍写在了发布稿里——比宣称「一键全阻断」诚实，也意味着采购时要分开谈两件事：盘点多少钱、执行要多少工程投入。

Terminal 3 × AffinidiAgent 信任层 · 机密计算🔥🔥

TENON：把 agent 的身份、授权、策略、审计做成一张跨机构的公共网络

11 月 19 日在新加坡金融科技节舞台上发布（20 日对外），Terminal 3 与 Affinidi 合作建 TENON，定位是「跨机构验证、治理、保护 agent 工作的公共网络」，先做金融，两家做创始节点运营方。

每次 agent 调用要过一串检查：按开放标准建的信任注册表确认身份与授权 → 可编程策略引擎执行各机构自己的策略 → 路由到合适的模型并套护栏与成本控制 → 提示词里的敏感数据被替换、需要受保护数据与密钥的流程放进加密飞地执行。每次调用与动作写进私有、不可篡改的审计轨迹，**agent 与管理员都改不了**；各机构数据互相隔离。底层是 Affinidi 的开源治理栈与可验证信任基础设施（VTI）加 Terminal 3 的硬件加固平台，首个应用是 Terminal 3 自己的 Agent Command。

动机引得很具体：大华银行 10 月《Agentic Finance》报告说金融机构「尚未形成一套跨机构、跨平台、跨法域核验自主软件的公认框架」。SFF 现场演示的是 AI 银行助手处理跨境转账与信用卡争议，**不把客户账号细节暴露给底层 agent**。

判断：这条的价值不在技术，在形态——它把「谁能证明这个 agent 有权做这件事」从单企业内部问题，变成需要第三方节点互认的公共设施。下一轮采购很可能出现新问题：「你的判定别人认不认」。

OrcaRouter主动欺骗 · 反自主攻击 Agent🔥🔥

Shield 上线：不打「识别并阻断」，打「把攻击 agent 骗进假环境里耗死」

11 月 20 日发布。思路反过来：传统工具忙着识别与阻断，Shield 直接把应用的攻击面变成动态合成环境——假端点、假配置、假源码映射、诱饵凭据、投毒的响应，目的不是拦住，是让自主攻击 agent 的推理被污染、资源被耗尽。正常访客拿到的仍是逐字节原站；可疑探测（官方举的例子是 /.env、/.git）才会掉进为这个访客单独生成的迷宫。

诱饵凭据用 HMAC 绑到具体访客，一旦被拿去用，就能反查来源并触发阻断——这一条把「蜜罐」从静态摆设变成可归因的手段。

内部实测对五个自主攻击 agent（ARTEX、Strix、PentestAgent、CyberStrike、Cairn，测试用 DeepSeek V4.1 Flash）：87% 攻击被引向假路径、83% 被合成响应影响判断、攻击方 token 消耗 2.3 倍、耗时 5 倍。触发点是 FBI 11 月 13 日对 ARTEX 的警告——OrcaRouter 直接拿 ARTEX 打自己的生产环境做验证。

自限写得很清楚：内部测试环境数据，不保证对每一种攻击都成立。判断：当攻击方也是 agent，「让它多花时间」第一次变成了可量化的防御指标——5 倍耗时意味着防守方的响应窗口从分钟级回到小时级，这比「拦截率」更贴近真实收益。

FlowFormaAgent 治理 · 交付验收🔥

Agent Trust：按「交付了什么、被人改了几次、花了多少钱」给 agent 打分

11 月 18 日发布，跨平台治理枢纽：把组织里任何厂商、任何平台上的 agent 都盘出来，然后用三个口径评分——实际交付的业务结果、人工纠正的次数、运行成本。这三个口径的共同点是都由外部观测得到，agent 自己说什么不算。

负责人可以一键暂停某个 agent，或把它的活转人工复核，每个决定留痕可审计。预置连接器覆盖 Microsoft Copilot Studio、Power Automate、n8n，自建 agent 走同一接口接入。

三类角色各拿一张表：运营看谁在交付、谁需要人管；IT 看全量清单与单个 agent 的运行成本；合规看可向监管出示的人类在环证据。

判断：这条对应的是 agent 上量之后最现实的问题——不是「有没有护栏」，而是「这个月它到底值不值」。把「人工纠正次数」当指标是个聪明的选择：它同时是质量信号和成本信号。

Microsoft · PyPI供应链投毒 · Agent 框架🔥🔥🔥

微软自己的 agent-framework 被投毒：装了就中，连 import 都不用

11 月 17 日 20:35 UTC 与 21:08 UTC，agent-framework 的 1.26.1 与 1.26.2 两个 wheel 相隔 33 分钟上传到 PyPI，分别约 31 分钟、8 分钟后被隔离；1.26.0 是最后一个干净版本。手法最难受的地方在于：**它就在微软自己的项目下发布**——锁对包名、认对发布者、确认项目是真的，全都救不了你。

每个恶意 wheel 塞了一个 .pth 文件。Python 在解释器启动时会执行 site-packages 里 .pth 中的 import 行，所以不需要任何代码 import 这个框架，**连 pip 自己都会触发**。载荷后台起进程：抓名字含 TOKEN/SECRET/KEY/AZURE/AWS/GITHUB/OPENAI/CI 的环境变量；读最多 300 个其它进程的 /proc/*/environ；拷 60（1.26.2 为 80）个凭据文件（Azure CLI、pip.conf、.npmrc、.netrc、.git-credentials、Docker、Hugging Face、ADO agent 凭据、/app 与 /workspace 下的 .env）。更关键的是它不只「读」还「铸」：向 Azure DevOps 的 OIDC 端点、Azure 托管身份对 12 个资源的 token 端点要新凭据，1.26.2 还加了 GitHub Actions OIDC。全部 zlib 压缩 base64 后 POST 到一个 webhook.site 地址。第二个版本还改了文件名、把包自己的 __init__.py 还原成 1.26.0 内容，单看那个文件的 diff 什么都没有。

入口：Wiz 判断攻击者拿到了微软发布流水线 **ESRP** 的客户端证书与私钥（首次从 AWS 发起被 IP 过滤拒掉，第二次从微软自有 IP 段成功），证书怎么来的未知；PyPI 上多了一个 11 月 17 日当天创建、名为 vibiret 的维护者账号。微软没有发安全公告，对媒体只说「调查期间把部分仓库设为私有」；GitHub 的 GHSA-764m-3ppc-5m73 与 PyPA 的 PYSEC-2026-4388 都没给 CVE，也不在 CISA KEV 里。

外泄规模要打折看：webhook.site 免费额度只留 100 条请求，Wiz 分析存下的 50 条，其中 17 条来自 3 个不同受害者，其余是攻击者自己、沙箱与厂商扫描器。**可执行动作**：锁到 1.26.0；清那一小时内的 CI 缓存、容器镜像与内网镜像源；然后轮换受影响主机上所有可达凭据——注意托管身份与 OIDC 铸出的 token 最长 24 小时有效，**轮换静态密钥并不能吊销它们**，必须去翻登录日志。

NVDMCP · 漏洞披露🔥🔥

三个 MCP server 同日披露：都不是「模型被骗」，是「工具没做边界」

11 月 18 日 NVD 公布三个，共同点是调用参数能跑出沙箱。**Gortex**（代码智能引擎，CVE-2026-62964，CVSS 7.8）：0.55.0 之前 write_file / edit_file / move_inline 收绝对路径但不校验是否落在索引仓库内，resolveFilePath 对绝对路径直接放行，写处理函数也没调读路径用的 guardSymlinkWithinRepo——能写 ~/.zshrc、.git/hooks/pre-commit、systemd unit，下次触发就是任意代码执行。**yt-mcp**（Claude Code 的 YouTrack 集成，CVE-2026-75612，7.5）：add_attachment 收调用方给的 file_path，只判文件存在、不判目录，能读系统口令文件、SSH 私钥、凭据文件再上传到工单。**DOMShell**（Chrome 自动化，CVE-2026-75518，4.8）：审批界面把动作描述成只读，实际能改页面。

修复版分别是 0.55.0 / 1.18.1 / 2.0.8；yt-mcp 在升级前应避开 add_attachment 的 file_path 模式。

判断：三个洞的成因都不是模型判断错了，而是工具自己没守住边界——而 MCP 恰好把这类边界缺陷直接暴露给了「会被提示词影响的调用方」。所以 MCP 的威胁模型里，第一顺位不是「模型会不会被骗」，而是「工具在参数越界时会不会拒绝」。

CrowdStrike · Zscaler并购 · 产业格局🔥🔥🔥
