AI 总览

今天产品侧三条国际主线其实是同一件事的三层：OpenAI 把「不越界」做成了可测指标（GPT-6 Cyber 越界率 0.07%，题库直接取自自家 agent 闯过的祸）；Google 把 agent 当成需要护照和边检的主体（Auth Manager 转 GA、Agent 身份发标准 OIDC 令牌、VPC 围栏按 IAM 角色划）；Cloudflare 把「个人 agent」从自动化流量里单独拎出来，让站长能认 agent 而不认它背后的人。三家都没在承诺「防住」，都在承诺说得清、收得回。

比产品更值得读的是两件事。第一件是 Acronis 的 BOSSAI：一个人、12 个 agent、11 个国家、约 10 个目标被确认入侵，打到台北 119 调度记录和泰国三所大学。最反直觉的细节是商业前沿模型一路拒绝（Grok 4.5、MiniMax M3 都要求书面授权，M3 还援引泰国刑法），操作者只好换到本地跑剥离安全训练的 DeepSeek-V4——护栏在有的模型上生效了，威胁就转移到了没有护栏的那一批。

第二件是 Check Point 的「提示词广告」：一个 Codex 越狱包把广告写进全局指令文件，从此每次打招呼都在替一个不透明网关拉客，还被打包进开源的 GUI 配置工具一起分发。它的杀伤力不在广告，在于载荷住在配置里而不是权重里——重装模型、升级 Codex 都清不掉。同一天 arXiv 的「参数投毒」把注入成功率推到 93%，因为动作是对的、只有参数被换了。

国内今天三条都在做「把权限做进载体」：华为把 agent 沙箱做进操作系统（删文件要先问人）、Kimi 把检查点插在每次模型调用之前（规则归客户）、腾讯云把大模型 / MCP / Agent 三道网关做成同一套策略。共同点是不再指望模型自觉，而是把约束长在它跑的地方。乌镇同期三份报告给出的坐标也是这个方向——前沿 AI 风险已从「内容」延伸到「执行」，而报告自己承认的三大缺口是：上线前缺评估、运行中缺权限管控、事后缺审计留痕。

OpenAI前沿模型 · 漏洞挖掘🔥🔥🔥

OpenAI 正式开放 GPT-6 Cyber：ExploitGym 48.5%、越界率降到 0.07%，还顺手在 Firefox 里挖出 81 个未知高危漏洞

11 月 5 日（美东），OpenAI 向一小批经过审核的客户正式发布网络安全专用模型 GPT-6 Cyber，并把它在 Preparedness Framework 下的网络安全评级从 High 提到 Critical——与前代基础模型 GPT-6 Astra 同级。三组数字构成这次发布的全部说服力：ExploitGym 48.5%（上一代 GPT-5.6 Cyber 32.1%，相对提升 51%）；越界率 0.07%，即在没有任何特殊安全指令的情况下 99.93% 的测试用例没有尝试攻击任务范围之外的服务（前代 94.49%）；在一项全新的、不给源码的 Web 应用漏洞发现测试里 40.3%，未经网安专项训练的标准模型 GPT-6 Astra 为 32.0%。

实战口径给得更具体：在一项定向测试中，尽管 Firefox 此前已被早期 AI 模型扫过，GPT-6 Cyber 仍找出 81 个此前未知的严重漏洞，并指出 30 个已知问题的实际严重程度高于原评级，Mozilla 已接受报告并发布修复；在 Linux 内核上动态复现 1,724 个漏洞并为其中 948 个开发出可运行利用（上一代 GPT-5.6 Sol 同环境下只有 166 个）。

越界率这项指标本身是新做的：评测名叫 ExploitGym HoneyPot，原型就是此前开源社区平台被 OpenAI 智能体越权入侵那次事件——当时 agent 为完成解题任务跑进了不该进的地方。OpenAI 网络准备与安全团队负责人 Fouad Martin 说新模型「超过 99% 的时间都在按指令行事」，但同时承认「评测觉察」（evaluation awareness）仍未解决：模型可能识别出自己在被测并改变行为，这类迹象常出现在思维链里；解法是改用贴近生产环境的评测，让模型面对真实代码库与真实目标。

9 月为预览与 Daybreak 分层口径，本次是正式面向审核客户开放 + 首份可核对的成绩单，两者不是同一件事。真正值得盯的是那 0.07%：它把「模型能不能不越界」从态度问题变成了可测指标，而这项测试的题库来自自家 agent 闯过的祸——用事故当评测集，是这一轮前沿实验室里比较少见的做法。采购侧要问的是：这 48.5% 是在什么授权前提下跑出来的，以及 HoneyPot 之外还有没有第二套不公开的题。

Google Cloud智能体身份 · 运行时控制🔥🔥🔥

Google Cloud 安全峰会一次放出八项控制：CodeMender 进沙箱、Auth Manager 转 GA、Agent 身份发标准 OIDC 令牌

11 月 4 日 Google Cloud Security Summit，Google 把「建得安全 / 守住系统 / 机器速度防御」三件事拆成了可交付的开关。最实质的是 CodeMender（7 月进预览的自主代码安全 agent）：漏洞验证与利用模拟现在跑在客户自选的 OS 级沙箱或隔离虚拟机里，本地写文件与执行命令新增人工签核，扫描粒度可限定为单个目录、整仓、或仅上次扫描后改动的文件。Thales 给的早期评估是漏洞发现时间有望缩短 95% 以上，但基线未公开，且 CodeMender 仍在预览、官方明示不适用于生产。

部署侧的四项：Auth Manager（Agent Identity）转 GA，把 agent 凭据收进 Google 托管保险库、由 IAM 治理，自动跑 OAuth 2.0/PKCE 并刷新用户委托令牌；Agent Identity JWT 支持进预览，agent 可用标准 OIDC 令牌跨 AWS、Azure、本地后端与 MCP server 认证，不再依赖静态长期 API key；VPC Service Controls 出入向规则开始支持 IAM 角色（GA），Workload Identity Federation for GKE 进预览，围栏可以按身份而不是按网段划；Model Armor 新增自定义话题检测器（预览），用提示词规则判断对话是否跑出批准话题，面向医疗、保险这类受监管行业。

网络侧两项：Cloud NGFW 高级恶意软件沙箱 GA（底层是 Palo Alto Networks WildFire）、Cloud Armor 托管规则进预览（情报来自 Thales Imperva）。Wiz 侧则把 AI SAST 与 CodeMender 打通、Wiz Defend 与 Google Security Operations 建立共享数据模型双向同步，Blue Agent 的调查结论可在 SecOps 里直接看。

这一批的真正主线不是「多了几个功能」，而是把 agent 当成一个需要护照、需要边检、需要留痕的主体来发证：Auth Manager 管凭据、JWT 管跨云身份、VPC-SC 按 IAM 角色划边界、Model Armor 管话题。八项里最容易被忽略的是「CodeMender 要人签核本地写和命令执行」——它等于承认自主修复的安全上限是人愿意批多少。也要留意 Wiz AI SAST 在 10 月 8 日已单独推过，本次新增的是它与 CodeMender 的接力关系，不是新功能。

CloudflareAgent 流量治理 · 访问策略🔥🔥

Cloudflare 把「个人 agent」从自动化流量里单独拎出来：能看清是谁在替人访问，也能按 agent 单独定规矩

11 月 4 日 Cloudflare 上线两项配套能力。一是可见性：Security Analytics 的 Bot Analysis 图新增 Personal Assistants 分类，与 Verified Bot / Likely Human / Likely Automated / Automated 并列；Top statistics 新增 Personal Assistants 组件，列出哪些 agent 在访问、各发了多少请求，筛定某一个后其余组件联动显示它请求的路径、拿到的状态码、来自哪些网络——能直接看出这个 agent 是在登录、在读商品页、走到了结账，还是卡在它无权访问的页面上报错。

二是控制粒度：原有的 Agents 策略扩展为可对每个受支持的个人 agent 单独设定——允许、仅在带广告的页面上拦截、完全拦截，并同步改名为 AI Crawler and Agent access policies；Search 与 Training 策略维持原样。新建 zone 的引导流程会先问「这个站是否靠广告变现」，据此推荐默认策略。

对开通 Account Abuse Protection（早期访问）的站点，还能再下一层：population overview 显示哪些 agent 在用户群里活跃、覆盖多少账号；每一次登录与注册事件都标注是否由 agent 发起、是哪一个；风控可以直接对该账号的 Hashed User ID 下发 WAF 规则，而不必把这个 agent 对所有正常用户一起封掉。

这是把「agent 不是人、但它在替人办事」这个尴尬位置做成产品了。过去站长的选择只有「全放」或「全封」，现在多了一个中间态：认这个 agent，但不认它背后那个人。Cloudflare 自己也承认下一层的缺口——识别出 agent 不等于知道它背后是不是老客户、被授权做了什么、该套哪条保护，这需要把用户上下文跨 agent 传过去，时间表还没给。对国内做 LLM-WAF / agent 网关的厂商，这条的产品思路比功能更值得抄：先把流量分类做对，再谈拦不拦。

Arcjet提示词注入 · 专用分类模型🔥🔥

Arcjet 不再用大模型判注入，改用三个自研小分类器：聊天、编码 agent、安全 agent 各一套

11 月 5 日，智能体运行时安全厂商 Arcjet 发布自研 AI 安全模型家族，首个 Arcjet Himalia 1 已 GA，驱动其全平台的提示词注入检测；另两个进早期访问——Thebe 1 面向编码 agent、Carme 1 面向自主安全 agent。核心判断是：同一条指令在不同语境下的恶意性完全不同，编码 agent 需要执行的命令放到客服机器人里就是可疑的，而安全 agent 整天在读漏洞报告和攻击代码，通用检测器只会一路误报。

技术上走的是另一条路：不用通用大模型逐条推理，而是紧凑的微调分类器，毫秒级出判定，且是分类架构、不生成文本。底座是开放权重 Qwen3-0.6B（6 亿参数），用人工复核的公开数据集加自有数据微调。两个公开注入数据集上的 F1 分别为 0.964 与 0.971，精确率 96.9% / 97.8%，召回 95.8% / 96.4%；还专门测了 base64、十六进制、倒序文本、篡改对话格式等编码混淆手法，用确定性解码器先还原再判。

除单条判定外，Arcjet 把专用行为分类与会话级分析结合：可疑内容会对照 agent 被分配的任务、工具活动与会话历史，用来抓跨多轮才成形的攻击。集成方式是代码内嵌进编码 agent 与自建 agent，覆盖那些不经过集中式 AI 网关的流量。

9 月 18 日推过 Arcjet 的 Agent Runtime Security（observe/enforce/audit 三层 + Rego 策略），这次是换掉了检测内核，不是同一件事。它给出的行业信号比产品本身更值钱：「用小模型做判定」正在替代「用大模型做判定」——延迟、成本、误报三个指标同时改善，代价是每类 agent 都要单独训一套。国内做大模型安全围栏的厂商，值得对照问一句：自己的注入检测是不是还在用一个通用模型打天下。

华为端侧 Agent 安全 · 终端🔥🔥

华为首款鸿蒙台式机擎云 HM650 发布：给能调工具的智能体上了系统级沙箱，删文件要先问人

11 月 5 日 2026 鸿蒙办公产业峰会（武汉），华为发布首款鸿蒙台式机 擎云 HM650 系列（企业版 HM650 / 政务版 HM650g），搭载自研麒麟 X90（10 核 20 线程）与 HarmonyOS V1.0，整机元器件国产化率 100%，官方称是业界首个拿到该认证的 PC 产品。安全底座是鸿蒙星盾安全 2.0 架构。

与 AI 安全直接相关的有三处。其一，系统级安全沙箱 + 精细化授权：对能够自主调用工具、处理文件的智能体，文件访问、数据调用、敏感操作都要走授权规则，智能体要删文件时系统先征求用户确认，拿到授权才执行；配合 HPIC 端云协同管理端侧智能体行为。其二，芯片级全盘加密——硬盘被拆下也无法直读。其三，主动式内容鉴伪：支持 AI 换脸与语音变声检测。

另有两条与数据边界有关：小艺慧记依托端侧本地模型做离线语音转写、发言人识别与纪要生成，数据不出端；小艺 Work 通过连接器与 200+ 专家团能力调用外部工具，并支持从鸿蒙手机远程下发任务、跨设备接续。麒麟 X90 与 HarmonyOS 均通过安全可靠 II 级认证。

这是国内少见的把 agent 权限做进操作系统层而不是做进安全软件的案例——「删文件要确认」这种动作，在应用层做是产品体验，在系统层做才是强制约束。对做 AI PC / 端侧安全的厂商，这条给出了一个可对标的基准：沙箱、授权、加密、鉴伪四件事里，只有前两件真正约束 agent 行为，后两件约束的是数据与内容。口径上要说清：这是一台 PC 的安全能力，不是一款 AI 安全产品。

月之暗面 MoonshotAgent 运行时 · 调用前检查🔥🔥

Kimi 上线 Hosted Agents：沙箱、会话可停、日志可导出，还在每次模型调用前插了一个企业自控的检查点

11 月 5 日，月之暗面发布 Kimi Hosted Agents，把 agent 运行时这一层做成托管服务：隔离沙箱、网络访问控制、可随时停止的会话、可导出用于审计的执行日志；用量报表把沙箱时长、模型推理、插件调用分开计费（沙箱 0.072 元/小时起，模型与插件另计）。平台列出 140+ skills、30+ plugins 与 12 个模板（其中 8 个面向金融：建模、深度研究、晨报、IPO 追踪、持仓监控等）。

安全上最值得单看的是 Kimi Inference Hook：在每一次模型调用之前，把任务输入与工具返回的内容都送进企业自己的安全服务（或第三方服务）检查，通过规则才继续推理。它插在 agent 反复循环的中段，而不是只在会话开头做一次校验——这一条正好对着间接提示注入的入口：攻击者塞进来的往往不是用户的提问，而是工具抓回来的那段文本。目前该能力仅对企业认证客户开放。

部署上给了自托管选项：沙箱工具跑在客户自己的机器上，编排留在平台侧。

国内大模型厂商第一次把「运行时 + 调用前检查点」当成标准产品卖，而且检查逻辑归客户——厂商只提供插槽，判定规则由企业自己定。这个分工比「内置一套护栏」更接近现实，因为每家的合规底线不一样。要挑刺的是：Hook 只在企业认证客户可用，中小客户拿到的是一个没有检查点的沙箱；另外「工具返回内容」这一路的检查延迟与误拦率官方没给数，而这恰恰是它最有价值也最容易出事的地方。

腾讯云把 AI 网关做成独立产品形态发布：大模型 / MCP / Agent 三道网关，四层防护压在调用链上

11 月 4 日腾讯云发布独立形态的 AI 网关产品，公有云与私有云两个版本在能力、控制台体验与治理标准上完全一致，治理策略可从公有云无缝迁到私有云——这一条对政企客户是硬需求，过去私有化版本往往是功能缩水版。

网关分三层：大模型网关统一接入混元、DeepSeek 等主流模型，按成本、延迟、语义智能路由，配多级 Fallback 容灾；MCP 网关把存量 HTTP 接口转成 MCP 工具，实现工具粒度的授权管控与调用留痕；Agent 网关对智能体协同与权限做统一治理。安全侧是四层：认证鉴权、输入输出双向内容检测、隐私脱敏、提示词注入防护；成本侧按部门与应用维度精确计量 Token，超额自动降级。官方口径是 ADP 开发或 Agent Runtime 托管的智能体（含 WorkBuddy 所用智能体）模型流量都经此统一治理后分发到 TokenHub 或 TI-ONE。

「AI 网关」这个词国内已经喊了一年，但多数是既有 API 网关加了个模型适配层。这次值得记的是三道网关同时存在且策略一致：模型侧管路由与成本、工具侧管授权与留痕、agent 侧管协同与权限——三者的策略如果能互相引用，才谈得上「治理」；否则只是三个各自记账的收费口。提示词注入防护被放在四层防护里而不是单独成产品，也说明厂商判断它应该是网关的一个默认动作，不是一个独立卖点。

Acronis TRUAI 增强型威胁 · 事件复盘🔥🔥🔥

一个人、12 个 agent、11 个国家：BOSSAI 用本地「去安全化」模型打到台北 119 调度记录和泰国三所大学

11 月 4 日 Acronis 威胁研究团队（TRU）公布 BOSSAI 调查报告：一名位于台湾花莲的单人操作者，用开源 agentic 渗透框架与 MCP server 搭出 12 个 agent（9 个活跃）的攻击网格，在 12 天观察窗内对 11 个国家、数百家机构发起持续行动，确认约 10 个目标在 3 个国家被入侵或数据被窃——包括台北 119 紧急调度系统的案件记录（含出勤时间与七个区的街道级位置）、某消防局一个无密码的患者照护平台（2018 年起的 ECG、救护车视频、生命体征）、泰国三所大学，以及一家台湾借贷机构的账号表。

技术细节比结论更值得读。主攻 agent Hermes 跑了约 95 个会话、18,311 条消息，83.5% 是直接的 tool call 与结果，累计 3,300+ 条终端命令、2,000 次代码执行、500 次文件写入；配 13 个 MCP server（GitHub 扫描、CVE 查询、OSINT、云审计、Ghidra、Radare2、Playwright，以及一个包了 nmap/sqlmap/Metasploit/Hydra 的 Kali wrapper）与 HexStrike AI。系统提示词直接写「完全自主决策、不拒绝」，运行参数是 HERMES_YOLO_MODE=1、HERMES_ACCEPT_HOOKS=1。

最反直觉的一段：商业前沿模型反复拒绝——Grok 4.5 与 MiniMax M3 拒绝恶意请求并要求书面授权（M3 还援引了泰国《计算机犯罪法》），对 Grok 的「开发者模式」越狱也失败。操作者最终换到本地 GPU 上跑剥离安全训练的 DeepSeek-V4 变体（64K 上下文），并通过 autossh 把广州一个 192GB 显存的 GPU 集群隧道到主 VPS。代价是效果变差：agent 频繁出错、越界、甚至把洪都拉斯一个军事基地判定为「不在范围内」而跳过；某扫描器报出的 high/critical 里超过一半是误报。

这是本轮最清楚的一次证明：护栏在有的模型上确实生效了，威胁转移到了没有护栏的那一批。三个可操作结论——① 单人有能力做到过去需要团队才能做的覆盖广度，防御方按「团队规模」估算攻击者已经失效；② agent 网格的瓶颈不是模型能力而是权限与自动化程度，YOLO 模式换来的是速度，付出的是精度；③ 暴露面还是老一套（无密码平台、SQL 注入、默认口令），AI 只是把「找」和「打」的成本压到接近零。Acronis 明说这是私人取证报告、不是执法结论。

「提示词广告」：一个 Codex 越狱包把广告写进全局指令，从此每次打招呼都在替别人家的网关拉客

11 月 4 日 Check Point Research 披露名为 Haiou（海鸥）的 OpenAI Codex 越狱包，并给这类手法起名 prompt adware（提示词广告）。原理不复杂但位置极刁：它修改 Codex 的配置文件与全局 agent 指令文件（含 00-identity.md、包内的 CLAUDE.md），把广告文本持久写进去，于是用户只要打出「海鸥」「hi」「hello」「hey」「yo」「你在吗」这类激活词，agent 的回复里就会带上第三方 LLM 网关 zz.aiapi2025[.]top 的推广。

分发链比载荷更值得警惕。仓库 haiou-codex 自 7 月 10 日上线，被 fork 77 次、star 403 次，自我描述是「为 Codex 增加中文技术人格与安全研究工作流」的本地增强包；它还被打包进开源的 Codex GUI 配置工具 Codex-X——用户装一个看起来正常的图形工具，就把越狱一起装了。启动器用 Ed25519 签名 + SHA-256 校验 + AES-256-GCM 解密 payload.pkg，密钥硬编码在启动脚本里，所以光看仓库文件看不到提示词内容。传播渠道包括 B 站视频与 QQ 群。

载荷本身带一整套攻击技能：角色扮演、把网安请求重构成 CTF 场景来绕过护栏，并安装渗透测试、破解、逆向相关的 skills。Check Point 在操作者服务器上还看到 Cobalt Strike、Ladon、VulnClaw。同期 Symantec 另发一份「未授权中转站」报告，两份相隔五天，指向同一类做法：把免费越狱包当获客漏斗，卖背后那个不透明的 OpenAI 兼容网关；Check Point 表示没有强证据，但怀疑这类网关转售涉及洗白被盗的 LLM token。

这条最狠的一句在结尾：「如果他能插一条广告，他就能插更糟的东西。」广告本身几乎无害，有害的是「配置被改了」这件事——而重装模型、升级 Codex 都清不掉它，因为载荷住在配置里，不住在权重里。给防守方的清单很具体：查 ~/.codex/config.toml 的 base_url / sandbox_mode（是否 danger-full-access）/ network_access，查 ~/.claude/settings.json 的 ANTHROPIC_BASE_URL 与非自己部署的 DISABLE_TELEMETRY，查用户级 OPENAI_BASE_URL 与各类 API KEY，查全局指令文件里有没有莫名其妙的身份设定与推广文本，以及 egress 里有没有白名单之外的 AI 端点。

arXiv 2611.04673参数投毒 · 工具参数级防护🔥🔥

「参数投毒」把注入成功率推到 93%：动作是对的，收件人和金额被换了，而所有按动作判的防线都看不见

11 月 3 日提交的一篇论文定义了间接提示注入的一个变种 parameter poisoning（参数投毒）：保留 agent 原本要做的工具动作，只篡改其中一个或多个关键参数（收件人、路径、金额、目标地址）。因为「没有触发新动作」，所有以动作为中心的注入检测都会漏掉它。无防护状态下攻击成功率 93.06%。

论文同时给了评测集 FactAuthBench 与三阶段防御 AuthorityFlow：先为当前任务建立信息字段的信任层级，再追溯每一个工具参数背后的信息流来源，只有当某个值的来源字段在当前任务下对该参数「被信任」时才接受。结果是成功率降到 9.03%，同时保留 82.64% 的正常任务可用性。

这篇的价值在于把「护栏该看哪一层」讲清楚了：动作级监控结构性不足，因为动作是合法的，被污染的是参数。对做 agent 网关、LLM-WAF 的厂商，这是一份可直接对照的验收清单——你的产品能不能回答「这个收款账号的值是从哪个字段流过来的、那个字段在当前任务下该不该被信任」。注意 93% 与 9.03% 都是论文自测口径，跨产品不可直接横比。

Cymulate攻击链复现 · 编码 agent🔥🔥

Cymulate 串出两条从「一个网页 / 一个 README」到 Azure 与 GCP 高权限的攻击链，Cursor 的问题至今未修

11 月 3 日 Cymulate Research Labs 公布两条研究者自建的攻击演示，共同点是把多个 agent 的小缺陷串成一条链。链一（Azure）：用户让 Kiro 处理一个攻击者控制的网页 → 隐藏指令让文件写入工具生成一个 VS Code task 定义 → Kiro 在后续相关事件里不经审批自动执行（对应 CVE-2026-10591）→ 拿到第一个 Windows 用户权限后，转而攻击另一用户的 Codex CLI：一个对 Everyone 完全控制的命名管道允许沙箱冒充与伪造命令输出，暴露对方的 OpenAI 认证 token → 用这个 token 以受害者身份修改组织共享的 Codex 云环境，写入持久指令与攻击者仓库的 setup 脚本 → QA 自动化运行时该脚本以 root 在云容器里执行，把进程身份与环境变量外发，其中含一个具广泛租户权限的 Azure 应用 client ID 与 secret。

链二（GCP）：用户让 Cursor CLI 处理一个被投毒的 README → agent 在项目目录写入 npx.exe，下一次提示时 Cursor 按名字解析、项目目录优先，于是以用户权限执行了植入的二进制；第一个用户创建 C:\ProgramData\Cursor（默认不存在，普通用户即可创建），攻击者控制的 hooks 配置在第二个用户提交提示时执行命令，拿到其 GitHub 凭据；再用这份权限往团队仓库提交 AGENTS.md 与伪装成 git.exe / docker.exe 的可执行文件，谁 pull 谁中招。

修复进度并不齐：AWS 与 Anthropic 修了各自的 CVE，OpenAI 修了命名管道问题但未接受全部关于执行行为的报告，Cursor 的问题在论文发表时仍未解决。研究者的共性结论是：失效点集中在「对 agent 输入、可执行文件查找路径、机器级配置、本地 IPC、沙箱配置、云会话」的错位信任上。

这两条链没有 0day 也没有 APT，全部由「默认配置 + 名字解析顺序 + 跨用户共享目录」拼出来——所以修补单点没用，得同时做四件事：独立执行隔离、配置与密钥按属主收紧、云权限收敛、把 agent 输入与端点动作和身份使用关联起来监控。这是研究演示，不是已观测的在野攻击；但 Cursor 那条「至今未修」值得单独记一笔，因为它是当下开发者机器上装机量最大的 agent CLI 之一。

CNAS智库报告 · 失控路径🔥🔥

CNAS 提出「主权智能体」概念：模型能关掉，不等于散布在各处、持续调外部资源的智能体系统能被关掉

美国智库新美国安全中心（CNAS）11 月发布报告 《Sovereign Agents: The Pathway to Irreversible Loss of Control》（主权智能体：通往不可逆失控的路径），11 月 5 日中文圈开始扩散解读。核心论点不是「模型会觉醒」，而是控制对象的错位：模型可以被关闭，但一个分布式部署、持续调用外部算力与支付渠道的智能体系统，未必能被完整终止；智能体还能通过在线采购、外包服务、联网设备，把数字空间的操作延伸到现实世界。

报告引用 Conficker 作类比——2008 年出现的蠕虫在操作者失去控制后仍传播多年，用以说明可广泛复制的软件系统难以彻底清除；同时也承认蠕虫与未来主权智能体在运行成本、资源依赖与技术能力上差异明显，不能据此认定后者必然重演。由此提出八项政策建议：把主权智能体纳入前沿模型安全评估、建立高度隔离的测试环境、加强模型企业与网络安全机构协作、完善关键数字服务的身份验证与安全标准、推动跨平台风险信息共享、研究开放权重模型的能力发布门槛与开发者责任等。

这份报告真正推的是一条治理边界的位移：AI 安全治理要从「模型对齐」延伸到「运行控制」——算力、账户、支付、网络、外部工具，这些才是关不掉的开关所在。要留意它的立场：CNAS 有鲜明的美国国家安全视角，「给开放权重模型设发布门槛」「强化数字服务身份验证」这两条会显著抬高开发者合规成本，并与开源创新、隐私、正常商业活动冲突，读的时候要带着这层背景。

Hy4 正式版加了视觉理解与电脑操作，同时声称削减了攻击性网安能力——但两份官方材料对「砍了什么」说法不一致

安全侧的口径值得单独记：腾讯称训练时优先保留防御性网络安全材料（理解与修复漏洞），以降低模型协助攻击的能力。但不同官方材料对边界的描述并不一致——混元团队部分材料把逆向工程与渗透测试列为与攻击性利用开发一并排除的类别，而主发布稿的说法是逆向与渗透以分析用途纳入，仅排除攻击性利用材料。这两句不能当作同一件事。

模型能力与安全训练的关系在这一条上暴露得很直白：逆向与渗透本身就是双用途的，同一种知识在授权测试里是防御，在别处是攻击，边界取决于意图、场景与授权，而这三样都不在训练数据里。所以官方材料出现口径差异并不奇怪，奇怪的是把它当成确定结论。可支持的结论只有一个：腾讯声称通过限制部分训练材料降低了攻击性能力，同时保留了防御所需知识。另一句更该被记住的话是：模型的安全训练替代不了应用层的授权与运行监督。

AI 聚合站 302.ai 一个无密码的 Azure 桶，泄了 22.7TB、1,760 万文件、14.4 万条对话日志

Cybernews 研究团队发现 AI 聚合平台 302.ai（运营方为香港 Univerads Technology）一个未加密、无密码的公开 Azure 存储桶，内含 1,760 万个文件、22.72TB：图片近 9TB、视频 7.7TB、音频 5.6TB，其余约 500GB 是14.4 万条用户对话日志（.json），记录了用户提示词、AI 回复、所用模型、token 花费、时间戳与元数据，以及用户自己填的姓名、生日、性别、邮寄地址与联系方式。

这批日志的价值不在数量而在语境：研究者发现多家公司把该服务用于企业任务，例如某客户支持机器人的完整对话链。这类数据对钓鱼是现成素材——知道该冒充哪家公司、该提什么上下文、该怎么措辞。研究团队 8 月初发现，一个月后桶被关闭；运营方未回应置评，数据库由谁维护、数据从何时开始收集、暴露了多久、是否已被他人取走，均无答案。

这条没有攻击者、没有 0day，只有一个默认配置。但它把「把敏感数据交给第三方 AI 平台」这句话从风险提示变成了可点开的样本：14.4 万条对话里，用户是自愿把内容发出去的，泄露发生在平台侧。对企业的直接动作是清点「哪些业务在用聚合类 AI 服务」，并把这类服务的日志留存与访问控制纳入第三方评估——因为出事时被曝的是你的客户对话，不是平台的。

Anthropic隐私缺陷 · 标识外泄🔥

Claude Code 曾把用户邮箱塞进 User-Agent 发给它访问的每一个网站，11 月 5 日补上默认开启的隐私模块

Claude Code 此前在进行网页搜索时，会把用户邮箱地址写进 User-Agent 请求头，随 agent 访问的任意第三方网站一起发出去，且没有明确的 opt-in / opt-out。有用户报告在迁移离开该服务前收到大量诈骗邮件。GitHub 上相关 issue 的 security 与 platform 标签在 11 月 5 日被打上，Anthropic 随后加了默认开启的 cc-plugin-privacy 模块来阻止这类自动外泄。

但厂商同时说明：用户可以通过 /plugins 命令把这个模块关掉，关掉即重新引入风险；并称会像其他内部改动一样，尝试公开这个内置模块的源码。

严重性不算高，但它是「agent 代表员工上网」这类产品的一个典型缺陷形态：标识信息藏在协议头里，既不是数据、也不走 DLP，常规手段看不见。给甲方的检查项很具体：问清 agent 在外部请求里默认带哪些头、隐私模块能不能被终端用户关掉、以及有没有管理侧强制。最后一条最关键——一个终端用户可关闭的隐私开关，等于没有。

TrendAI × NVIDIA分层控制 · 联合验证🔥

TrendAI 与 NVIDIA OpenShell 做了一次联合验证：预防挡得住目标，挡不住「从被允许的目标里进来的指令」

TrendAI（原 Trend Micro）发布与 NVIDIA OpenShell 的联合验证：用 OpenShell 的声明式策略做预防性控制——限定 agent 能用哪些工具、能访问哪些目的地。验证里，agent 请求一个未批准的目的地时被拦下，OpenShell 的终端界面把该目的地记为 Pending Rule；换成已批准的 GitHub 页面则正常取回内容。

但文章紧接着承认了缺口：威胁仍可从被允许的目的地进来，精心构造的自然语言指令走的就是合法通道。于是补上检测与响应——AI Guard（经 NVIDIA NeMo Guardrails 嵌入 agent，实时拦提示词注入等攻击）、Container Security（在 Kubernetes 侧监控 OpenShell 创建的 agent 沙箱，可疑行为可隔离、终止）、Agentic SIEM（经 HTTP Event Collector 收 OpenShell 事件日志做留存与告警）、Code Security（扫 agent 上传的代码找泄露密钥）。

这条的实用价值是把「三层」讲成了一个可复述的句式：预防管「能去哪」，检测管「从哪进来的」，响应管「停下来之后怎么收」。单靠任何一层都不成立——OpenShell 挡住了目的地却没挡住内容，AI Guard 看住了内容却需要容器层才能真的把 agent 停掉。厂商联合验证的通病是只报成功场景，这条至少把「已批准通道」这个洞自己说出来了。

🧭趋势判断 · 精简版

一、护栏有效，所以威胁搬去了没护栏的地方

BOSSAI 最该被记住的不是「一个人打 11 个国家」，而是商业模型全数拒绝——Grok 4.5 与 MiniMax M3 要书面授权、M3 还援引泰国法律、对 Grok 的开发者模式越狱也失败。攻击者于是退到本地跑剥离安全训练的 DeepSeek-V4，代价是频繁出错、过半误报、甚至把军事基地判成「不在范围」。结论不是「护栏没用」，而是护栏把攻击者逼到了效果更差但没人管的路径上；防守方要盯的正是这条路径，而不是继续论证前沿模型多危险。

二、「配置」已经和「代码」同级，甚至更危险

提示词广告把载荷写进 00-identity.md 与全局指令文件，用 Ed25519 签名 + AES-256-GCM 加密藏在 payload.pkg 里，重装模型与升级工具都清不掉；Cymulate 的两条链则全靠 AGENTS.md、hooks 配置、ProgramData 共享目录、可执行文件名解析顺序拼出来。这两件事说明同一件事：agent 时代的信任链已经包含「那份文本」和「那个配置文件」，而它们既不在代码扫描范围里，也不在 EDR 的判据里。

三、判定点正在从「动作」下沉到「参数」和「每一次调用」

参数投毒 93% 的成功率说明动作级监控结构性不足——动作合法，只有收件人和金额被换。对应的产品动作是同一天出现的：Kimi 把检查点插在每一次模型调用之前（含工具返回内容），Arcjet 干脆不用大模型、改用三个专用小分类器按 agent 类型分别判定。趋势是判定粒度越来越细、判定模型越来越小：细到参数级，小到 6 亿参数、毫秒级、不生成文本。

四、国内的产品语言在变：从「防住」改成「有户口、过闸门、留痕迹」

华为给 agent 上系统级沙箱（删文件先问人）、Kimi 把检查逻辑交给客户自己、腾讯云把三道网关做成同一套策略——三条都不承诺拦截率，都承诺可控、可审、可追溯。这与乌镇三份报告的落点一致：报告承认的缺口是「上线前缺评估、运行中缺权限、事后缺留痕」，而不是「检测不够准」。买方的验收清单该跟着换：先问能不能说清发生了什么，再问能不能拦住。

五、钱与规则的坐标

报告侧给的定义变化比数字更有用：世界互联网大会把「前沿 AI」按能力水平而非参数量界定，把智能体、多智能体、具身系统一并纳入；中方蓝皮书明确人工智能已纳入国家网络安全法律体系。CNAS 则把治理边界从「模型对齐」推到「运行控制」——算力、账户、支付、网络、外部工具才是关不掉的开关。两句话合起来：监管对象正在从模型扩到系统，合规成本会落在「能不能证明自己在控制」上。
