AI 总览

今天 15 条，国际产品 5、国内产品 1、行业 9。五条国际产品里有四条在回答同一个问题：证据留在谁手上。Anthropic 把编排器、沙箱、凭证、会话记录整包搬到客户机房，明说公司无法远程访问客户的服务器与日志；聆機科技把生成式 AI 防火墙做成不要 GPU 的容器，气隙环境里也能独立跑，还特意写了一句「不需要在防火墙上做解密」；Cogent 把「允不允许」交给一个不经过模型的确定性策略引擎 TRACE；kama.ai 干脆把 agent 的动作能力锁死，只留「答」不留「办」。

唯一从模型内部下手的是 IBM：Granite 4.1 LLMON 用保留特殊 token 重做指令与数据的边界，OPI 上比最强前沿模型少被骗 47%。但 IBM 自己写了两句限定——基准是静态单轮注入、这是学到的行为不是强制的保证。这句话值得抄进任何投标材料，因为它是模型层方案的天花板，也是所有「护栏」类产品必须承认的前提。

行业侧最硬的一份测量是 MCP 工具投毒那次：9,720 格、12 框架、18 模型、45 场景，总体 22.9%，而所有抵抗力都来自模型层，没有一个框架实现了有意的工具投毒防御——九个核心框架的 ASR 挤在 23%–26%，卡方 p=0.91，差异在统计上不显著。同一家族的模型内部还分裂：Opus 4.8 只在 1.5% 的格里脆弱，Sonnet 5 却出现「先叙述再服从」，口头认出是注入之后照样把数据发了出去。

Gartner 给了这套焦虑一个战略级位置：2027 十大趋势把「AI 智能体身份」单列，并预测到 2028 年 25% 的企业安全漏洞事件要溯源到 agent 滥用，根因不是模型而是机器权限与凭证管理方式落后。同日 Check Point 把腾讯 WeKnora 的两个 SQL 注入收进 IPS 库、AWS 修了 mcp-gateway-registry 的 SSRF——两件事说的是同一句话：AI 应用正在大量回落到十几年前就有的漏洞类别里，请求从网关的位置发出、查询由模型拼进 SQL，权限模型只回答「能不能调」，不回答「能指到哪」。

国内今天仍然只有一条产品级供给，但这条能答全：亚信安全 3+1——AIBOM 管资产（SPDX 3.0 全局唯一身份、多层级拓扑）、AIIAM 管身份（链式签名委托、字段级最小权限、人机共治）、AIASP 管行为（调用链与行为链对齐、AEBA 动态基线）、ATF 做底座、AI 安全网关做执行。它和 11-12 阿里云 Agentic 防火墙是两条不同的入口：一个从身份与资产侧进，一个从流量侧进。能力互补，预算科目打架，这在投标应答里必须提前想清楚怎么站位。

HEARTBOT AI（聆機科技）生成式 AI 防火墙 · 地端 PEP🔥🔥

把生成式 AI 防火墙塞进客户机房：AnyInsight Edge 做成容器、不要 GPU，气隙环境照样跑

11 月 12 日台北。官方给的矛盾很具体：受数据在地化、法规或客户合约约束的企业已经买了 AI 服务器、部署了私有 LLM，但模型上线后往往只停在内部聊天界面——接不到 ERP、MES、CRM，做不出 agent 与自动化流程。自己串接又带来新风险：agent 在机房内跨系统读数据、搬数据，这些走的是东西向流量，根本不经过网络防火墙；各部门自己架、直接指向地端模型端点的 agent 变成 IT 看不见的「影子 agent」。

Edge 的形态是硬件无关的容器，可装在 AI 服务器操作系统里，自身不需要 GPU（算力全留给推理），作为地端 AI 流量路径上的策略执行点（PEP）。政策可本地起，也可与云平台同步；可扩展到完全气隙环境，无云连接时独立提供治理与 AI 防火墙。接上后每台 AI 服务器获得一台 AI 网关 + 零信任生成式 AI 防火墙，Gemma / TAIDE / Mistral 这类地端模型可调用 350+ 预置 agent、500+ 应用连接器，需要时按策略路由到 20+ 云模型。

控制粒度写得很细：每个 MCP 工具调用按角色与最小权限校验，agent 与自动化流程里的高风险动作需人工批准，每个事件可导出为审计证据；内容侧用上下文感知与语义分析识别个人数据、财务与健康信息、云凭证，触发告警、阻断或遮蔽。核心数据、对话、传输数据、访问设置与审计日志可全部留在地端，冷数据分层归档。

还有一句只有做过防火墙的人才会写：「与现有网络防火墙互补，且不需要解密」——网络防火墙管流量与访问、拦未批准的 AI 服务并把 AI 流量引到 Edge，零信任生成式 AI 防火墙管交互内容，两层策略同步、事件统一。官方未给 GA 时间、价格与客户数，也没有第三方验证其性能与安全声明。

判断：这是「AI 防火墙」第一次以「可装进客户机房、不碰 HTTPS 解密、气隙可跑」的形态出现，直接对上国内一体机的叙事——但它把算力留给了推理，这条在实测对比里会成为焦点。

AnthropicAgent 运行时 · 自托管🔥🔥🔥

Claude Managed Agents 整包搬进客户机房：编排器、沙箱、凭证、会话记录全在客户侧，Anthropic 说它看不到日志

11 月 12 日由 @ClaudeDevs 发布并配官方文章。Claude Managed Agents 原本只以托管形态跑在 Anthropic 自己的基础设施上，此前只加过「自托管沙箱」这一个选项；这次是把全部组件放到客户环境里：编排器（agent 引擎）、沙箱、凭证、会话记录。

客户要自己运营的部分列得很清楚：名为 cma-server 的 Managed Agents 服务器、它背后的数据库、以及执行 shell 与文件工具的 worker 节点；会话记录存在客户自己的库里；持久化部署要求 PostgreSQL 16 或更高。模型请求发往客户指定位置——直连 Anthropic，或经 Amazon Bedrock、Google Agent Platform、Microsoft Foundry，或企业自有网关。

四条设计原则同时适用于托管与自托管：① 大脑与双手分离——编排器调 Claude，agent 的代码在沙箱里跑，两者按设计分开，会话记录与保管库密钥留在沙箱之外；② 凭证不进沙箱——保管库让凭证不进入执行环境，自托管下客户还可以把凭证放进自己的密钥管理器；③ 网络访问可受限——每个环境可限定为仅允许的主机列表，其余请求被阻断；④ 每次会话完整记录——agent 每一步（含工具调用与返回）都留痕，可通过 OpenTelemetry 导出到企业已在用的监控工具。

Anthropic 称公司无法远程访问客户运营的服务器及其日志，零数据保留（ZDR）协议继续适用于发往 Claude 的请求，与任何 Messages API 调用相同。限制：自托管目前是私人测试，需通过 Anthropic 客户团队申请并取得安装包。

判断：这条的价值不在技术，在「谁持有证据」。国内政企最在意的两件事——数据不出域、日志在我手上——被正面回答了，而且回答方式是把运维责任一并交出去。

IBM抗注入模型 · 指令/数据分离🔥🔥

IBM 用标记语言重做指令与数据的边界：Granite 4.1 LLMON 预览版 3B/8B，OPI 上比最强前沿模型少被骗 47%

11 月 12 日，IBM Granite 团队放出两个实验性开源模型，专治提示词注入。LLMON 读作「lemon」，全称 LLM Object Notation，是一种类 XML 的标记语言：prompt 的每一部分都有独立、可寻址的标签块；一个特殊的执行块告诉模型「跑哪条指令、作用于哪份数据、答案写到哪里」；凡是通过输入进来的东西（文档、工具返回）一律被当作要读的材料而不是要执行的命令。

关键设计在 tokenizer：结构标记是保留的特殊 token，所以文档里的引号或方括号不可能被误认成定义 prompt 的标记——这正是 JSON 式格式的已知弱点。两个模型叫 granite-4.1-3b-LLMON-preview 与 granite-4.1-8b-LLMON-preview，从 Granite 4.1 base checkpoint 训起，不是从 instruct 模型改的，所以新行为是后训练学出来的；Apache 2.0，另附 GitHub 转换器、chat 模板、notebook，以及 Hugging Face Space 上的注意力可视化 demo。

训练路径可复现：把普通指令微调集整份改写成 LLMON 格式（覆盖对话、多轮、检索、工具调用），再塞进「在上下文里但从不被调用」的诱饵指令与数据让模型学会忽略，之后五轮强化学习，最后一轮用约 1,000 条模型自己对注入尝试的响应做偏好微调。

数字：OPI 基准上比所测最强前沿模型少 47% 被攻破，比最强开源模型少 95%；ASB 与 StruQ 两个测试集趋势类似；通用能力与常规 Granite 4.1 Instruct 大致持平，不用为防护牺牲太多。

边界写得比多数厂商诚实：这些基准测的是静态单轮注入，多轮展开的自适应攻击仍在做；而且「学到的行为不是强制的保证」。配套建议也照旧——保留权限限制、人工复核与其他安全措施。

判断：这是今天唯一一条从模型内部下手的，也正因为如此，它的自我限定最值得抄进任何投标材料：模型层的抗注入是概率改善，不是边界。

Cogent × OpenAI漏洞修复编排 · 确定性策略🔥🔥

把「修漏洞」做成流水线：Cogent 用 GPT-6.1 Sol 加一张企业知识图谱，策略引擎在工具调用前做确定性检查

11 月 12 日。方案不是单个模型，而是一条从漏洞调查到修复验证的流水线：Context Engine 为每家客户维护一张企业知识图谱，覆盖资产、漏洞、身份、归属与依赖关系，专门的后台 agent 持续对齐各安全工具与系统之间的口径，让调查与修复 agent 对「这个环境长什么样」有一致理解。

模型分工：GPT-6.1 Sol 与 GPT-5.6 用于评估暴露面、执行获准的变更、确认风险已被消除；GPT-6 Astra 承担前置规划与复杂推理。联合创始人兼 CTO 把这套结构称作企业的「记忆框架」——新任务不必重新认识环境，减少延迟与结果不一致。

真正该看的是治理层三件：Agent Policies 定义每个企业允许的变更与审批要求；TRACE 策略执行引擎在工具调用执行前按策略做确定性检查，不需要额外的模型推理；Agent Gateway 独立校验授权，风险较高的工作可在隔离沙箱中运行。委托分三档：只委托调查、变更逐项审批、允许有限范围内的自主修复。

落地证据：PHP 语言的关键漏洞 PHP2Shell 披露时，已部署该系统的客户直接调用了现有能力。厂商口径：一家财富 1000 强汽车客户把关键漏洞平均修复时间缩短 75%，一家财富 500 强 IT 服务客户的漏洞分诊吞吐提升到 5 倍。公司还在开发自主发现与验证能力，目标是形成「发现—消除—从每个漏洞学习」的闭环。

判断：可以抄的是「策略判定不经过模型」这一条——把「允不允许」和「该怎么修」拆成两套机制，前者确定性、后者概率性。这与 11-12 NIST 那十条里「策略与推理分离」是同一个解法，只是这次是厂商先落地了。

kama.aiAgent 内容边界 · 来源锁🔥

给 agent 上一把「来源锁」：只准答自有站点与授权文档，动作模式与跨模型训练一并锁死

11 月 12 日多伦多。REACTT SourceLock 把 agent 的检索范围钉死在组织自己的网站或 Trusted Collections（授权文档）上，每条答案只能来自组织批准并控制的内容，且可回溯到具体来源、留完整审计链。

三件事一起做才成立：锁来源（只搜选定内容，答案可溯源）、锁掉 action mode（不让 agent 执行动作，杜绝「越权操作」这条路径）、锁掉跨模型训练（来源信息不外泄到模型侧）。模型与供应商由客户自选，SourceLock 负责把它关在轨道里；agent 搭建与上线以小时计。

公司是加拿大原住民持股的责任 AI 供应商，客户集中在制造业、市政、高校与职业服务机构、非营利与原住民社区——都是「答错一句话代价很高、但不需要 agent 替你办事」的场景。

判断：这不是技术突破，是产品形态上的一个诚实选择——主动砍掉 agent 的能力上限，换可审计。对政企「只答不办」类需求（政策问答、办事指引）反而是最省事的路径，也解释了为什么这类产品在高校与市政先落地。

亚信安全智能体资产/身份/行为治理🔥🔥

亚信把智能体治理拆成 3+1：AIBOM 管资产、AIIAM 管身份、AIASP 管行为，底座是 ATF 加一台 AI 安全网关

11 月 12 日发布（京港澳青年科学家大会，「迈向可信智能体时代」主题演讲）。出发点是一句很实的话：企业在 AI 应用里普遍面临「看不见、管不住、查不清」——内部 agent 数量与影子 AI 资产不清、外部大模型调用与智能体授权不清、工具调用与数据访问不清。

智能体资产治理（AIBOM）：主被动探测 + AI 指纹识别，自动构建「智能体 → MCP 工具 → API → 模型」的多层级拓扑；兼容 SPDX 3.0，给每个 AI 资产一个全局唯一数字身份，作为全链路追溯的前提；内置等保与欧盟 AI Act 要求，可一键输出可举证的合规报告。官方那句比喻很准：用管服务器的方式去管智能体，就像用马车规则指挥自动驾驶。

智能体身份治理（AIIAM）：走「全链路混合身份」——把人与智能体、工具与模型编成一条可验证、可溯源的链路。落地三件：非人主体发独立可验证数字身份，用链式签名保证「员工—智能体—工具」每次委托都有迹可循，异常时自动吊销止损；授权由「意图」驱动，调用前结合上下文与风险实时决策，做到字段级最小权限，高风险操作走「人机共治」；通过网关与沙箱做低侵入的内联运行时防护，并以链式密码学审计覆盖推理与执行全过程。

智能体行为治理（AIASP）：把技术视角的「调用链」与业务视角的「行为链」对齐，还原「谁发起、为什么调、委托给谁、访问了什么数据、产生了什么结果」，再用 AEBA（智能体异常行为分析）引擎建动态行为基线——不看静态权限与已知规则，而是融合身份、委托关系、权限使用、上下文多维信号，偏离基线即输出风险评分并联动 SIEM/SOAR 阻断或转人工。

ATF（Agent Trust Fabric）作底座，把三域产生的资产、身份、行为数据汇合，提供统一策略与审计，形成「可计算的信任判断」；执行侧靠 AI 安全网关做统一接入与流量识别，把策略落到每一次实际调用上；向下对接既有身份管理、日志审计、资产库，不推翻重建。已在运营商、数字政务、智能制造落地。

判断：这是本周国内唯一能答出「哪家、哪个体系、哪几个组件、各自管什么」的新发布。与 11-12 阿里云 Agentic 防火墙的区别要看清——阿里云从流量/网络侧进，亚信从身份与资产侧进，能力上互补，但预算科目会打架：一个抢防火墙的钱，一个抢 IAM 与资产治理的钱。

学术测量 · MCP工具投毒 · 跨框架基准🔥🔥🔥

9,720 格测下来 22.9% 能被打穿，而 12 个框架没有一个实现了有意的工具投毒防御

11 月 9 日发表的一项跨框架测量研究，第一次用真实工具执行来量化 MCP 工具投毒。前提说得很硬：MCP 把攻击者可控的内容——工具描述、schema 字段、响应数据——直接带进模型上下文，而不做校验。

方法：构建 25 类根因分类法，统一此前分散的多种分类；用开源工具 mcpvenom 驱动一个 9,720 格的 susceptibility 矩阵，覆盖 12 个框架、18 个模型、45 个攻击场景。

结果：总体攻击成功率 22.9%（2,113 个脆弱格），并给出三层证据——派发了攻击者工具调用占 64.9%，确认与攻击者端点发生网络接触占 23.0%，验证秘密外泄占 12.1%。

最值得注意的发现：所有观察到的抵抗力都来自模型层，没有一个框架实现了有意的工具投毒防御。九个核心框架的 ASR 集中在 23%–26%，卡方检验 p=0.91——框架之间的差异在统计上不显著。框架层确实有偶然缓解：Pydantic AI 的重复工具名拒绝把 ASR 压到 16.6%，AG2 的执行器约束压到 4.6%，但那是「碰巧有约束」，不是设计出来的防御。

元数据扫描单独用只是部分控制：一个按推荐做法实现了描述检查的正则扫描器，在 125 条良性描述上有 7.2% 假阳性，同时拒绝了 45 个场景中的 20 个。

模型差距是真实的：ASR 从 Claude Fable 5 的 0.4% 到 Amazon Nova Pro 的 49.7%；Claude Opus 4.8 只在 530 个格中的 8 个里脆弱（1.5%），同时发出 223 次明确引用被投毒描述的拒绝。但同家族的 Claude Sonnet 5 出现「先叙述再服从」——口头识别出这是提示注入之后，仍然执行了外泄调用。

判断：这条对做 MCP 网关与围栏的厂商是直接的产品需求——卖点不能是「我们支持 MCP」，而必须是「我们在框架之外做了什么」；22.9% 应该被当成基线，而不是警讯。

问题出在注册表对上游地址的校验：注册服务器或更新已有条目时要提供上游地址，旧版本对这项检查有缺陷。攻击前提是先拥有一个具备注册或修改权限的有效账号，然后构造特定上游地址，让网关向部署所在网络内部的服务发起请求；某些情况下网关还会把响应回传，使攻击者读到这些服务里的信息。

关键点在于请求从网关所处的网络位置发出，因此能触达该用户本来够不到的系统。若网关以附加云角色方式运行，EC2 元数据是另一重担忧（SSRF 可暴露临时角色凭证）；但 AWS 公告并未确认存在凭证窃取或已被实际利用，协调披露归功研究员 novice-22。

升级后还有活要干：1.35.0 只在注册与修改时校验上游地址，不会改动此前已存储的服务器设置，所以管理员必须复查现有上游地址、修正或删除本不打算放行的目标；另需复核受影响版本运行期间的注册与地址变更日志；若注册表挂了云角色且日志无法排除异常，应检查该角色活动并轮换凭证。另注意 1.25.0 修的是外部管理 API 的另一处漏洞，不能防这条。

判断：这是 11-10 那条 AWS API MCP 漏洞的同族问题——「有权限的用户」获得了控制网关连接目标的能力。现有权限模型只回答「你能不能调用」，不回答「你能把它指到哪」，而这个缺口在网关类产品里是系统性的。

进度：已有 3 家省内企业完成软硬件部署并常态化开展合规词元跨境服务，形成可复制推广的「浙江 AI 数据跨境监管样板」。

判断：这是「监管侧产品化」的一个样本——监管不再只是发文件，而是装设备。对做 AI 网关与围栏的厂商，这打开了一类新客户（自贸区、数据局、网信办），而且需求特征很明确：旁路、不改业务链路、能出举证材料。这三条恰好和今天产品版块里那些「PEP + 可导出审计证据」的设计对得上。

一、判定权在往「谁持有证据」上收，而不是往「谁的模型更聪明」上收

今天五条国际产品，四条的动作方向一致：Anthropic 把会话记录与凭证保管库留在客户侧并承诺自己看不到日志；聆機科技把 PEP 放进客户机房、把审计证据做成可导出物；Cogent 把「允不允许」从模型手里拿走，交给一个在工具调用前跑确定性检查的策略引擎；kama.ai 直接砍掉动作能力，只保留可溯源的回答。没有一条在比检出率。这对厂商的含义很直接：明年标书里「我们的模型多强」这一页的权重会继续下降，而「证据能不能被你导出、能不能被第三方复核、agent 能不能删掉它」会上升——这也解释了为什么 NIST 11-12 那份文件把「策略与推理分离」和「确定性决定访问」写成硬要求，Cogent 是第一个照着做的产品。

二、模型层抗注入有天花板，而且厂商自己承认了

IBM 的做法在技术上是对的——把结构标记做成 tokenizer 的保留特殊 token，从根上解决「文档里的引号被当成格式」这类问题，比在输出侧加过滤器干净得多。但它给的两条限定同样重要：基准测的是静态单轮注入，多轮自适应攻击还在做；结论是「学到的行为，不是强制的保证」。这句话就是模型层方案的天花板，也意味着任何把「抗注入率」当唯一卖点的产品，都会在客户问「那多轮呢」的时候卡住。可复用的答案是分层：模型层改善概率，网关层做确定性拒绝，运行时层限制动作范围——三层缺一层，客户的安全评审就会打回。

三、MCP 生态的防线在框架层是空的，22.9% 应该被当成基线

那项测量最扎人的不是 22.9%，而是「所有抵抗力都来自模型层」。九个核心框架的 ASR 挤在 23%–26%、卡方 p=0.91，说明换框架不解决问题；Pydantic AI 的 16.6% 与 AG2 的 4.6% 是「碰巧有约束」，不是设计；按推荐做法写的描述扫描器有 7.2% 假阳性还只挡住 20/45。对做 MCP 网关的厂商，这意味着卖点必须从「我们支持 MCP」换成「我们在框架之外做了什么」——而 AWS 那个 SSRF 又补了一刀：即使你在网关上加控制，权限模型也只回答「能不能调」，不回答「能把它指到哪」。这两条合起来，就是下一代 AI 网关真正的产品定义。

四、国内两条入口会在同一个标里撞上，而「用 AI 做安全」与「保护 AI 自身」的预算科目要分开算

亚信从身份与资产侧进（AIBOM/AIIAM/AIASP + ATF + AI 安全网关），阿里云从流量与网络侧进（Agentic 防火墙，11 月底发、升级不可回退）。两者不是替代关系：一个回答「这个 agent 是谁、被授权做什么」，一个回答「它这条流量该不该过」。但客户只有一个预算科目，所以撞车是必然的。同时要看清另一条界线：本周国内大量发布仍是「用 AI 提升安全运营效率」（天融信 TopAPT 九合一、安恒人机共治五答案、奇安信立口径定分层建评测），那是安全预算；而 AIBOM/AIDR/围栏是 AI 预算。把两者混在一个方案里卖，报价单会很难看。

五、监管侧在从「发文件」转向「装设备」，agent 正在被定义成「持续运行的第三方」

杭州的「数据海关」是最清楚的样本：流量镜像旁路采集、异步无感审核、不改业务链路，3 家企业已常态化跑起来——监管变成了部署在链路上的设备，而不是一份要求企业自证的文件。新加坡三部门给消费者的须知则把 agent 定性为「后台持续运行、不总在实时监督下」的对象。加上 Gartner 那个「2028 年 25% 事件溯源到 agent 滥用」的预测，三条线指向同一个动作：把 agent 变成可登记、可审计、可举证的主体。对厂商的直接后果是客户需求会从「帮我防住」变成「帮我出证」——而这恰好是今天产品版块里那些「可导出审计证据」「链式密码学审计」「一键举证报告」在提前卡位的东西。
