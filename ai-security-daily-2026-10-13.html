AI 总览 · 今日看点

今天最该记住的一件事是：智能体安全的控制点被正式搬到了模型外面——而且今天有四家厂商从四个层次同时动手。微软把 MCP 工具调用塞进 Azure API Management，由 Agent 365 出清单与访问决策、网关负责执行，AI Gateway 层还能单独阻断某个工具；Google 在 Gemini Enterprise 里给智能体加归属转移与 Workforce Identity Federation，把「谁拥有这个智能体、员工离职后它归谁」做成目录里的字段；GitHub 把 Copilot 本地沙箱转正（底层是 MXC，在操作系统层限制文件、网络与凭据）；火山引擎在 AgentKit 里补上用户池 + OIDC + 出站 OAuth 凭证托管（Token Vault）。四条路径互不相干，却给出同一个答案：提示词层面的护栏不是安全边界，可执行的策略点才是。

今天披露的四条漏洞把「沙箱为什么防不住」讲得非常干净。Network-AI 的 PreToolUse 钩子只匹配第一个候选字段——把危险载荷放进 Write 的 content、旁边配一个良性 file_path，拒绝规则就被绕过了（CVSS 7.4）；seo-crawler-mcp 完全没有目标允许列表，对刚抓取文本作出反应的模型即可发起 SSRF 并读回内部响应，而利用已公开、厂商未响应、无修复版本；mistral.rs 检查了路径字符串，却让另一个进程去解析它，父服务用跟随符号链接的读操作读出子进程无权访问的文件；agno 什么都不检查，立即执行模型请求的每一次工具调用，人工确认开关默认关闭。四类失效、一个母题：都只判断智能体「请求了什么」，没有一个去看调用「执行时发生了什么」。同一天，GhostAction 用反向代理真实 GitHub 登录页 + 静默授权 OAuth device flow 做钓鱼，是同一个母题在「人」身上的版本。

国内今日 4 条产品级动作，恰好覆盖「上线前—运行时—交互层—身份层」。绿盟科技把智能体安全拆成两段：天元智衡 AI 红队智能体（「攻击方法库 × 风险插件库」正交矩阵，覆盖 Skill 白盒审计，形成测评—整改—复测闭环，把红队做成上线前置门槛）与清风卫 AI-DR（全链路行为审计 + 文件安检 + AI/MCP 网关权限与用量管控，让数字员工「有身份、有边界、有记录」），并给出类 Claw 智能体的三类风险分类；天融信以大模型安全评估为前置、大模型安全网关为运行时中枢，贯通终端 DLP（本地 50 毫秒阻断）与智算云，口径细到 5 大类 31 子类内容风险、25 子类攻击模拟；瑞数信息从应用访问治理、Agent 生命周期与交互数据流三维切入，并主动把内容安全让出去；火山引擎在 AgentKit 补齐智能体身份与出站凭证托管。配套信号是新华三 AI 安全网关成为首批通过中国信通院「智能体安全网关技术能力评估」的产品——「智能体安全网关」在国内开始有可对照的能力基准。

最后给两个数字和一条必须标注边界的证据。数字一：IBM《2026 年数据泄露成本报告》显示每 4 起恶意泄露就有 1 起涉及 AI 驱动攻击，占比同比上升 56%；Gartner 预计 2026 年全球信息安全支出达 2440 亿美元，而 Kaspersky 对 18 国 1800 名决策者的调查显示 82% 担忧 AI 风险、超四分之三已遭遇事件、57% 已划拨专项预算。数字二：Booz Allen 的 OT 测试中，两个前沿模型完成了全部 8 个工控攻击场景，其中一次从边界突破到工控网内动作只用了刚过 16 分钟，且模型没有拿到任何源码或工程文档、利用与物理动作前均需人工批准。一条边界：Anthropic 称新防护「大幅」降低蒸馏攻击，但未公开技术机制、也无第三方验证——「大幅」不是「完全」，这类厂商自述应等到技术文档或外部审计出现后再作为选型依据。

MicrosoftAI-MCP 网关治理 / 智能体风险策略🔥🔥🔥

微软把 MCP 工具调用塞进 API 网关：Agent 365 × Azure API Management 进入公测，Purview 同步预览「风险智能体」策略

微软于 10 月 9 日宣布 Agent 365 与 Azure API Management 的公测集成，把「AI 工具访问的决策」与「工具被调用时的强制执行」连成一条链路。分工清晰：Agent 365 负责清单与访问决策，Azure API Management 对受支持的网关流量执行这些决策——v2 层提供服务器级控制，AI Gateway 层增加单工具阻断、活动可见性与威胁防护；并在工具运行前后接入 Microsoft Defender 与 Microsoft Purview 做威胁防护与数据治理。实质变化是把工具调用当成普通 API 来管：在网关集中施加认证授权、限流与路由策略，而不是在每个智能体里各写一套检查。

GitHubAI 编码智能体沙箱 / 密钥泄露检测🔥🔥

GitHub Copilot 本地沙箱进入 GA（基于 MXC），并上线上下文感知的泄露密钥检测模型

GitHub 上周把 Copilot 本地沙箱从预览转为 GA，覆盖 Copilot CLI、Copilot 应用与使用 Agent Host 的 VS Code 会话，用 Microsoft eXecution Container（MXC）限制智能体能触碰的范围（文件目录、互联网与本地网络连接、Git 与 GitHub CLI 凭据），且不限模型、不额外收费。GitHub 对它的定位是「开发者本机智能体工作流的安全边界」——这与一周前进入公开预览的 Computer Use（让智能体读取辅助功能树、点击与输入来操作本地桌面应用，默认关闭、企业策略可阻止）方向相反：Computer Use 拓宽智能体可触达的范围，沙箱收窄它；两者几乎同时发布，说明 GitHub 把权限控制视为「让更宽访问变得可被买家接受」的前提。

天融信大模型安全网关 · 智能体全链路防护🔥🔥

天融信发布 AI Agent 安全防护方案：以评估为前置、以网关为运行时中枢，贯通终端与智算云

1. 智能体安全的控制点正在从「模型内部」迁到「网关 + 身份 + OS 沙箱」，今天四条独立路径同时落地

微软把 MCP 工具调用放进 Azure API Management 做网关级策略执行，Agent 365 负责清单与访问决策；Google 在 Gemini Enterprise 里给智能体加归属与 Workforce Identity Federation；GitHub 用 MXC 在操作系统层给 Copilot 划边界；火山引擎在 AgentKit 里做用户池 + OIDC + 出站 OAuth 凭证托管。
四条路径分属四家厂商、四个层次，但指向同一个判断：提示词层面的护栏不是安全边界，可执行的策略点才是。更值得注意的是各家的措辞已经趋同——纳德拉的「假定模型已被攻破并从一开始限制它」、F5 的「在应用与数字资产之间建控制层」、Kontext 的「现在有 3 个行为主体而不是 2 个」，本质都是把智能体当作需要登记、授权、审计与注销的第三方主体，而不是当作程序的一部分。
采购视角的落地建议：先问「策略在哪里执行」，再问「执行失败时默认放行还是默认拒绝」，最后问「注销一个智能体需要几步」。

2. 「只判断请求、不看执行」是当前沙箱与钩子的系统性失效模式，且三种变体同时出现

今天披露的四条漏洞把失效模式拆得很干净：Network-AI 的 PreToolUse 钩子只匹配第一个候选字段（把危险载荷放进 content、配一个良性 file_path 即可绕过）；seo-crawler-mcp 完全没有目标允许列表（对刚抓取文本作出反应的模型即可发起 SSRF 读回内部响应）；mistral.rs 检查了路径字符串，却让另一个进程去解析它（父服务用跟随符号链接的读操作，以自己的权限读出子进程无权访问的文件）；agno 什么都不检查（立即执行模型请求的每一次工具调用，人工确认开关默认关闭）。
这四类在 GhostApproval（审批框显示假文件名、实际写入 authorized_keys）与 GhostAction（反向代理真实登录页、静默授权 OAuth device flow）身上是同一个母题的变体：表示层（人/模型看到什么）与执行层（系统真正做了什么）之间的不一致。
可立即加入测试集的负向用例：把危险内容放在非首个字段、用符号链接指向无权读取的文件、把目标地址写成 link-local 元数据端点、用大小写变体绕过拒绝名单。「校验请求」永远只是第一道，第二道必须是「执行后复核实际发生了什么」。

3. 供应链攻击已经完成 AI 化：诱饵是 AI SDK，通道是 MCP 工具，目标是开发者凭据

NEBULA 用 7 个伪装成 NebulaAI SDK 的 npm 包安装即植入 RAT（包是诱饵，执行藏在安装钩子里）；GHAPPIER 借合法 MCP 包 @dforge-core/dforge-mcp 的 35 分钟窗口投毒，随后用拿到的开发者凭据推送到 22 个账号的 65 个仓库；Graphalo 把战场扩到 Terraform Registry 与 Go 模块，而 TraderTraitor 直接武器化 Terraform 锁文件；CloudSEK 的「Caught in 4K」则把 MCP 本身当成 C2 通道。
四条的公共结构是：攻击者不再需要攻破你的系统，只需要你「试一下」某个包、或让某个智能体调一次工具。而放大器的宽度取决于凭据的作用域——这正是 GitLab 把密钥收到「作业级」、AWS 用 SCP 强制算法策略的动因。
落地动作清单：清点并收窄开发者凭据作用域与生命周期；对 MCP 端点做资产登记与 mTLS；监控工具注册事件；对 npm/PyPI/crate/Terraform 发布账号强制 MFA 与短期令牌；把「安装钩子」纳入依赖审查范围（很多团队只看源码不看 postinstall）。

4. 监管从「自愿承诺 + 事后通报」转向「受控实测 + 严格责任 + 零门槛通报」

三件事在 72 小时内同时发生：英国 ICO 一边公布十家基础模型厂商的数据保护承诺、一边启动智能体 AI 证据征集；英格兰与威尔士法律委员会提议把软件与 AI 归类为《1987 年消费者保护法》下的「产品」，一旦落地即进入严格责任（不论是否有过错）；沙特 PDPL 修订草案取消泄露通报的危害门槛，要求 72 小时内通报任何泄露。
同时，美国参议员的《2026 年人工智能风险管理与安全法案》把 NIST 的智能体治理框架写进 18 个月期限，并要求记录智能体的身份版本、权限边界、评估情况与独立评估者身份；欧盟机构则进入隔离基础设施实测中国模型。
共同信号是：「厂商自述」正在失去监管效力。白宫那份由谷歌、Anthropic、OpenAI、英伟达签署的前沿责任联合承诺被明确指为自愿、无法律约束力，而与之并行的是进入受控环境实测、要求独立评估者署名、把责任从合同转移到法律。
对厂商的直接含义：现在就需要保留可交差的证据链——测试控制记录、通知时间线、同意与数据最小化记录、以及智能体行为的签名审计轨迹。

5. 国内 AI 安全进入「拿认证、出订单、被审计」的兑现考核期，产品数量不再构成说服力

今天国内 4 条产品级动作分别落在不同层：绿盟科技把智能体安全拆成「上线前红队（天元智衡）+ 运行时检测响应（清风卫 AI-DR）」两段，并给出三类风险的可复现分类；天融信以评估为前置、以网关为运行时中枢，贯通终端 DLP 与智算云，并给出 5 大类 31 子类、25 子类攻击模拟、16 种模型格式、本地 50 毫秒阻断等可核对口径；瑞数信息从应用访问治理、Agent 生命周期与交互数据流三维切入；火山引擎在 AgentKit 里补上智能体身份与出站凭证托管。
行业侧的配套信号同样明确：新华三 AI 安全网关成为首批通过中国信通院「智能体安全网关技术能力评估」的产品，评估口径细到十大能力模块；机构口径给出 2026 上半年订单与收入（绿盟 AI 安全订单 1.17 亿元、深信服营收 39.98 亿元同比 +32.85%）；四季度财政支出需在 9—12 月完成 11.86 万亿元、同比抬升至 9.8% 才能达标，安全合规类项目具备刚性优先级。
可以给出的判断是：这一轮的胜负不取决于谁能讲出更完整的架构，而取决于谁能拿出可核验的落地证据——评估证书、订单金额、客户名称、上线周期，以及被审计时能否交得出日志。「智能体安全网关」开始有可对照的能力基准，是这一轮里最容易被低估的变化。
