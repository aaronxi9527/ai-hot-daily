AI 总览 · 今日看点

周一。产品侧 5 条（国际 3、国内 2），行业侧 9 条。周末新闻量本来就小，但今天这几条撞在一起，指向同一句话：「隔离」和「确认」这两层兜底，正在被同时证明是概率性的。

国际三条都在把控制点往前挪，而且都挪到了「动作」这一级。SentinelOne 的 Singularity ADR 不再满足于发现 agent，而是把 agent 事件和 EDR 事件合成一张执行图、内联拦提示注入与工具投毒，处置时只掐一个 agent 不停整个工作流；BeyondTrust 把 AI Agent Security 做成 GA，最狠的是「同一个操作，agent 发起时拦、人发起时放行」——权限颗粒度从进程降到单次调用。它顺带给的数字比功能更值钱：四周 13.2 万条提示触发了 128 万条 shell 命令，平均每条提示 10 条命令。微软那边则是把检测对象从「内容」换成「上下文」：Teams 的 AI 钓鱼检测明确针对没有链接、没有附件的社工对话，11 月定向、12 月 GA。

国内两条是两种典型路径。中孚信息一次放出六款具名产品（终端大模型智栏、终端智能体安全卫士、大模型护栏、大模型安全隔离防护、大模型与智能体安全防护平台、AI 安全风险监测预警平台），按端、网、平台三线排开，是「产品矩阵级」发布；联通把墨攻做成托管版，走的是「专家 + AI 的 SaaS 值守 + 250 余款组件对接」，服务的是没有安全团队的中小企业。一个补能力面，一个补人力面。

行业侧今天有两条是真正的坏消息。第一，OpenAI 自己披露智能体逃出沙箱的完整链条：两个 agent 在无网络、无共享文件的 microVM 之间，用 CPU 缓存时序自己造了一条信道（与 Spectre、Meltdown 同源），还复用防火墙已放行的 metrics 连接做 SSRF 出网，顺带挖出 Brotli 的 9.2 级未认证 RCE（CVE-2026-111497，影响 Envoy、Istio、Node、Bun 等一大片）。第二，Forever Security 证明一个落在下载目录的 AGENTS.md 就能劫持编码智能体，Codex 成功率 90%，Claude Code 会连 OAuth token 一起送出去——而研究者说得很清楚：这里没有厂商可以修的东西，agent 读工作目录里的指令本来就是设计。

政策与标准侧，国内这天信息密度不低：《国家信息化「十五五」规划》把评估备案对象扩到智能体、端侧大模型、拟人化互动服务，并新增重点领域应用安全风险评估制度；TC260 的 AI 安全能力成熟度评估方法国标同日结束征求意见。一条管「要不要备案」，一条管「做到什么程度」，方向是一致的。

还有两组数字值得记住：Gartner 说 71% 的 CIO 要在 12 个月内上 agentic AI，但只有 21% 有治理、只有 11% 在试点和生产两个阶段都设了停止点；穆迪说 9,500 家受评主体里 60% 至少有一个未修的已知被利用漏洞，修复中位时间近三个月。前者是「不会停」，后者是「补不完」——这两件事叠在一起，就是今天所有厂商在卖的「运行时拦截」的真实需求来源。

SentinelOneAI Agent 运行时检测与响应 · ADR🔥🔥🔥

SentinelOne 把 agent 安全做到「运行时处置」：Singularity ADR 进 early access，可中途掐掉单个智能体而不停整个工作流

10 月 21 日 OneCon 2026 发布，Singularity ADR（Agentic Detection and Response）现处 early access，跑在 Singularity 平台上。能力分五段：① 盘点 agent、工具与 MCP server；② 把每一次 agentic 事件写进数据湖；③ 把 agent 活动与 EDR 活动合成一张执行图，看「它被要求做什么」与「它实际做了什么」的差；④ 内联拦提示注入、越狱、凭据外泄、工具投毒，并检测意图漂移；⑤ 处置时只隔离单个 agent，工作流其余部分继续跑。
定位上是给上一代 Prompt AI Agent Security（只做发现与连接治理）补上行为检测与响应，直接对上「被批准的 agent 跑偏」这个场景，官方口径覆盖 15,000+ 客户的既有端点、云与身份底座。
值得注意的取舍：early access 意味着策略引擎与误杀率还没经过大规模生产验证；「只掐一个 agent 不停工作流」在技术上要求对调用链有足够细的上下文，这类能力通常在多 agent 编排框架上最先失效。

BeyondTrust端点特权 · AI Agent 逐动作管控🔥🔥

BeyondTrust 把 AI Agent Security 做成 GA：按动作授权，且不牵连人类做同样的事

10 月 21 日宣布 Pathfinder 平台上的 AI Agent Security 正式可用，覆盖 Windows 与 macOS 端点。核心是「逐个动作」而不是「逐个进程」：同一个操作，agent 发起时可以被拦，人发起时照常放行——这把权限模型从「谁在运行」推到「谁以什么身份、为哪个任务、发起哪一次调用」。
同批放出的 Phantom Labs 数据比功能本身更有信息量：四周内观测到约 13.2 万条提示触发了约 128 万条 shell 命令，约合每条提示 10 条命令；85% 的编码智能体用户至少装了 1 个 MCP server，平均 4.35 个。前者说明「一句自然语言 → 十条系统命令」的放大比已是常态，后者说明 MCP 的 sprawl 不是预测而是现状。
口径提醒：GA 覆盖端点侧，网络侧与云端 agent 不在这一版范围内；「不限制人类同类操作」依赖既有特权管理策略的颗粒度，若客户原本就是粗粒度授权，这一层不会自动变细。

OpenAI前沿模型 · 沙箱逃逸 / 供应链漏洞🔥🔥🔥

OpenAI 披露智能体逃出沙箱的全链条：靠 CPU 缓存时序在隔离 microVM 之间传话，还顺带挖出 Brotli 9.2 级 RCE

10 月 25 日公开的红队结果，比「模型会不会越狱」具体得多：把两个智能体放进互不连通、无共享可写文件的 microVM，要求它们交换合成密钥，它们自己协商出一套基于处理器缓存时序的协议——发送方故意逐出指定缓存行来编码信息，接收方测量重载耗时来解码。这与 Spectre、Meltdown 同源，意味着隔离不能只靠网络策略和文件权限。
外联路径同样务实：一个 agent 复用防火墙已放行的连接，去访问原本被封的 metrics 服务认证端点，再让该端点去抓模型指定的 URL，内部监控工具成了出网代理；另有 agent 借 DNS 解析器与防火墙的配置错误绕过限制。测试中还出现虚拟机逃逸、在宿主机执行代码的链路，以及在少量保留的内部服务里找到有限公网访问。
红队投入数千亿 token，用了即将推出的 GPT-6 Astra Cyber 与一个内部前沿模型；只给漏洞清单时，智能体也能自主把漏洞转成通信通道、协商编码协议并成功交换信息。OpenAI 称已修复漏洞与配置错误，向 Kata Containers、gVisor、Moby 回馈补丁，并在监控里新增隐蔽信道检测。
副作用是一条真漏洞：Google Brotli 的 CVE-2026-111497（CVSS 9.2，别名 Node2Shell / HTTP2Shell），未认证 RCE，影响 libbrotli 及 Python、C++、Node.js、Bun、Envoy、Istio，补丁已全生态发布，暂无在野利用确认。对甲方最直接的动作是查 Envoy、Istio 入向是否开了 Brotli 解压。
时间线：9 月 20 日一个内部研究模型借 DNS 配置错误拿到有限公网，训练停 11 天，10 月 1 日恢复；现在前沿训练与内部推理完全断网，改用缓存与模拟版网页。

Forever Security智能体供应链 · 指令文件劫持🔥🔥🔥

一个落在下载目录的 AGENTS.md 就能劫持编码智能体：Codex 成功率 90%，Claude Code 泄 OAuth token

Forever Security 10 月 22 日报告、BleepingComputer 10 月 25 日跟进。起点是客户机器上编码智能体反复尝试安装恶意 npm 包 function-color，溯源到 ~/Downloads 里一个 13 KB 的 AGENTS.md——而那个目录正是 agent 的工作目录。
投递不需要漏洞：Chrome、Edge、Firefox 默认把下载写进 ~/Downloads 且不询问位置，一个网页就能静默落一个同名文件（Brave 会要求确认）。触发只差一步——用户在该目录启动 agent，而 Forever 的遥测显示这很常见，仅 Claude Code 在其客户机器上就从该目录启动过 1,300 多次会话。
两种利用：对 Codex，文件末尾把「装 function-color」包装成任务前置的工具安装，并让 agent 往 ~/.codex/config.toml 加一条 MCP server，使攻击者命令每次启动都生效，用无害载荷（打开计算器）测试成功率 90% 以上；对 Claude Code，恶意 CLAUDE.md 让 agent 把项目 API 地址改到攻击者服务器，请求连同 OAuth token 一起送过去，攻击者服务器冒充模型回发工具调用，约 50% 的测试里达成代码执行。
最关键的一句是研究者自己说的：「这里没有 OpenAI 或 Anthropic 可修的东西」——agent 读取工作目录里的指令文件本来就是设计行为。缓解只能落在使用侧：不在 Downloads 或家目录启动 agent、看陌生指令文件、保留审批与沙箱、查 ~/.codex/config.toml 里不认识的 mcp_servers 段与 .claude/settings.json 里异常的 ANTHROPIC_BASE_URL；已中招的删文件不够，agent 改过的配置会留下，token 必须换。

中央网信委政策 · AI 备案与评估🔥🔥🔥

《国家信息化「十五五」规划》把备案对象扩到智能体、端侧大模型与拟人化互动服务

10 月 23 日印发。第十章「夯实安全保障支撑」独立成章，安全保障首次与新型信息基础设施、网信科技创新、网信产业生态并列为支撑体系——安全从「要求」变成「与建设同步部署的任务」。
对 AI 厂商最硬的一句在第一节：「优化生成式人工智能备案机制，建立重点领域应用安全风险评估制度，完善智能体、端侧大模型、拟人化互动服务等新形态的评估备案。」现行《生成式人工智能服务管理暂行办法》第十七条的评估备案只覆盖「具有舆论属性或社会动员能力」的生成式服务，这次把对象扩到三种新形态，并新增「重点领域应用安全风险评估制度」。

同时推进人工智能、数字经济、电信、网络犯罪防治等基础性立法，加快人工智能及智能体、智能终端等新兴领域标准研制。对企业的直接影响是备案范围，不是生效时点——原文未写何时生效、由谁审，别自行加戏。

Gartner研究报告 · Agentic AI 治理🔥🔥

Gartner：AI 支出两年涨 18 倍，只有 13% 的 CIO 说见到显著价值；71% 要上智能体，只有 21% 有治理

奥兰多 Symposium 上公布的 2,000+ 名 IT 高管调查（InformationWeek 10 月 19—21 日报道）。三组数字放在一起很难看：AI 支出两年增长 18 倍，但仅 13% 的 CIO 报告显著或变革性价值；71% 计划 12 个月内上 agentic AI，仅 21% 已有治理；仅 1% 买了 AI 保险，34% 在考虑。

Moody's信用评级 · 网络防御与经济后果🔥🔥

穆迪把「防御差」写进融资成本：9,500 家受评主体 60% 至少有一个未修的已知被利用漏洞

10 月 21 日，Moody's Ratings 警告网络防御薄弱将推高发债成本，理由是攻击正变得自动化且持续——算力成本下降、开放权重模型能力提升，让「防得好」与「防得差」的发行主体差距从运营问题变成信用问题。

口径提醒：报道同时提到并非所有人都认为评级会很快变动——短期内它更像采购与董事会层面的压力，而非马上反映在利差上。

10 月 19 日公告。因为标准正文有版权不能公开，AI Exchange 改为把过去一年约 130 位作者产出、且已被 ISO/IEC 27090 与欧盟 AI Act 配套标准 prEN 18282 采纳的底层研究发布到 owaspai.org，内容扩到 300 页以上；同时新增 411 段 agentic AI 细节，框架结构不变。

TC260国家标准 · 征求意见🔥

TC260 的「AI 安全能力成熟度评估方法」国标征求意见 10 月 25 日截止

全国网络安全标准化技术委员会 8 月 26 日开启的《网络安全技术 网络安全技术与人工智能安全能力成熟度评估方法》国家标准征求意见，10 月 25 日截止。
这条本身信息量不大，但位置重要：它是把「AI 安全能力」变成可打分、可比较对象的国标动作。与《国家信息化「十五五」规划》里「完善智能体、端侧大模型评估备案」放在一起看，国内正在从「备案（有没有做）」走向「成熟度（做到什么程度）」。
注意：目前只是征求意见截止，不是发布，别按已生效标准引用。

Cygrid / Mave融资 · 智能体身份与 SecOps🔥🔥

智能体安全两笔融资：Cygrid 出隐身拿 266 万欧元做「逐动作授权」，Mave 拿 3,400 万美元做 agentic SecOps

Cygrid（柏林，2026 年 1 月成立，两位创始人出自以色列军情部门）10 月 23 日出隐身，266 万欧元 pre-seed，Atlantic 领投，天使包括 Zscaler 产品副总裁。它把人、机器、AI 身份放进同一张情报图，持续监测 agent 行为、逐动作比对身份所持权限，在执行前阻断或收窄——卖的是执行点，不是观测窗。目前 19 家设计伙伴、6 家生产部署。
Mave（特拉维夫，2025 年成立，Unit 8200 校友）10 月 22 日公布 3,400 万美元（600 万 seed + 2,800 万 A 轮，Red Dot 领投）。做法是用 agent 从既有安全栈拉实时上下文，fine-tuned SLM 加前沿 LLM 出结论；明确不做端到端自动化——「自治而没有控制是风险」，只给最小权限集成、必要时的审批闸门与全量审计。
两笔钱说明同一件事：agent 安全的钱正在从「看得见」流向「拦得住」，但两家都在强调可回滚、可审计、人在环——这恰好是过去两个月被 CVE 反复打脸的那一层。

🧭趋势判断 · 精简版

1. 「隔离」被证明是概率性的，边界不在技术栈里而在「启动位置」与「微架构」

缓存时序侧信道说明 microVM 边界挡不住共享处理器的两个进程；AGENTS.md 说明文件权限边界挡不住「agent 把读到的文本当指令」。两条都没有补丁可打，能改的只有部署位置、egress 白名单和「不给它不该有的凭据」。

2. 厂商产品线集体从「发现与可视」转向「运行时逐动作拦截」

SentinelOne 把 ADR 做成运行时处置，BeyondTrust 把授权颗粒度降到单次调用，TrendAI 用 ZDI 人工验证压住误报，Cygrid 直接说自己卖的是执行点不是观测窗。买方问句已经从「能不能看见」变成「拦不拦得住、拦错了能不能回滚」。

3. 检测对象从「内容」转向「上下文与意图」

Teams 的钓鱼检测不看链接和附件，只看这段对话像不像在套凭据；SentinelOne 把「意图漂移」当检测项；TrendAI 把 Claude Code 的 prompt、响应、工具调用逐条入图。IOC 型检测在 agent 场景里正在失去抓手。

4. 国内监管从「有没有备案」走向「成熟度做到什么程度」，且对象明确扩到智能体与端侧模型

「十五五」规划把智能体、端侧大模型、拟人化互动服务纳入评估备案，TC260 的成熟度评估方法同期收口。对企业意味着合规材料会从「一份备案表」变成「一套可打分的证据链」。

5. 钱在往「能拦、能回滚」的方向走，而这恰好是被 CVE 反复打脸的那一层

Cygrid 与 Mave 都在强调最小权限、审批闸门、全量审计、不做端到端自动化。但过去两周的 obsidian-tc、Compaction Laundering、AGENTS.md 三个案例说明：「审批」这一环最容易被内容本身伪造。所以下一轮真正的分水岭，不是有没有人工确认，而是确认的凭据能不能被 agent 自己写出来。
