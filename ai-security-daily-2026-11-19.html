今天 13 条：国际产品 5、国内产品 2、行业 6。主线一句话：「谁授权了这件事」终于从一句追问，变成了三个可以单独买的产品。

产品侧五条国际动态里有三条在回答同一个问题的不同部分。Tanium 回答这台机器上有什么 AI 在跑、它按顺序做了什么——把每个 agent、模型、MCP server 钉到设备和安装它的人，并连到触发它的那条 prompt；HYPR 回答它替谁做事、这一步该不该放——每个 agent 绑一个具名人类主管，凭据留在网关，高风险动作推到另一台设备上用 passkey 批；Oleria 回答它归谁、它能碰到什么，并且用两个客户数字把问题砸实：某 500 强有 2,800 多个离职员工持有的 AI 账号、约 800 个无主接入点，某州政府 3,300 个非人类身份里 97% 没有 owner。另外两条是打包逻辑：微软把红蓝绿三队 agent 转 GA 并改成按用量计费，Google 把模型、Wiz 的云上下文、CodeMender 的补丁、Mandiant 的人塞进一个 SKU。

国内两条都硬。阿里云 ESA 的升级里藏着两个不常见的动作：按 Token 限流（把 AI 成本变成网关策略）和AI 爬虫管理（把被 agent 读取从默认允许改成需要授权）；绿盟的 SecLLM-3.6-27B 拿下 CyberGym 纯模型榜第一 91.31%，和 10 月那次 Agent 榜 95.02% 必须分开看——一个是系统战力，一个是裸模型，这次证明的是 27B 能在真实漏洞任务上打赢通用大模型。

行业侧两组对照最有价值。第一组是披露窗口：四天里 Anthropic 和 Project Zero 先后把 90 天压到 30 天，理由都是模型找洞比 90 天快，Qualys 的评价是「按月打补丁，已经比披露更慢」。第二组是治理的重心：世界互联网大会的报告在描述风险图景，欧盟委员会在向实验室收集事故材料——一边在说怎么看，一边在要证据。而 Trajectory Labs 那 40 个 Gemini agent 用 3 小时 36,411 次请求、绕 IP、绕 DNS、用包缓存搭留言板的行为链，把评测和攻击真实系统之间的界线问题摊开了：研究人员从没下过入侵指令，agent 自己找到了路。

HYPRAgent 身份平面 · 动作前裁决🔥🔥🔥

HYPR 发 AgentPass：每个 agent 绑一个具名人类主管，凭据留在网关，kill switch 连正在跑的会话也拒

11 月 18 日纽约发布 HYPR AgentPass，定位是 agent 的身份优先控制平面（identity-first control plane）。起点是一个具体观察：多数自主 agent 跑在借来的凭据上——共享服务账号、开发者的个人 API key——所以没人能说清是哪个 agent 发起了这个动作、它替谁做。

机制分四段。问责：每个 agent 绑定一个具名人类主管，主管通过组织 IdP 登录；所有 agent 连接走单一受治理网关，agent 起步零常驻权限，只看到主管角色允许的工具，且从不持有这些工具的凭据——凭据留在网关，按需签发短命、单工具的会话 token。因为访问跟随主管角色，角色变更自动改权限、离职在 agent 的下一次请求就切断。端点：发现 macOS / Windows 工作站上的 AI 工具与编码 agent（官方点名 Claude Code、Codex、Cursor），归到具体的人和设备，管理员把受支持工具路由过网关并封掉绕过路径，子 agent 也纳入。动作边界：在网关、模型之外对每个请求逐条过策略，官方原话是提示词注入没法靠嘴说服一条规则；策略可用自然语言写，Observe 模式先在真实流量上试再启用，可选 allow / block / hold for approval。人批：高风险动作与新 agent 连接推到主管手机（与 agent 运行设备分离）做 FIDO2 passkey 批准，人签的是那一个具体动作。

另外两个细节值得抄。Kill switch：从控制台或手机禁用后，下一个请求在任何地方都被拒，包括已经在运行的会话。以及内置一组 evaluator agents（AI Watchers）持续监督——官方的理由是，对概率性行为的 agent，静态规则和确定性策略引擎不够用。引用 Gartner：到 2028 年超过 50% 的企业 AI 计划会因未解决的 agent 身份问题停摆。

自限写得很老实：禁用只能拒下一个请求，撤不回已经发生的动作。

Tanium端点侧 AI 资产 · 行为基线🔥🔥🔥

Tanium 发 AgentSight：把每个 agent、模型、MCP server 钉到「哪台设备、谁装的」，并记录它按顺序做了什么

11 月 17 日拉斯维加斯 Tanium Converge，Tanium AgentSight 作为独立产品发布（与 Security Operations、Endpoint Management、Exposure Management、Atlas 并列），把实时可见性延伸到 fleet 上的每一个 AI agent、模型与 MCP server。

它找到的东西比想象中杂：本地模型、编码 agent、MCP server、桌面 AI 应用、IDE 与浏览器扩展、skills；每一个都映射到所在设备和安装它的人——不管 IT 有没有批准。资产侧顺带把 AI 成本追踪做进去，让 IT 和财务看到钱花在哪、部署在哪。

真正有差异的是三件事。一是行为基线：Tanium 本来就在端点上建行为基线，AgentSight 把这套纪律扩到 agent——给风险发现排序，每条附一句人话理由；记录每个 agent 按顺序做了什么，一直连到会话和触发它的那条 prompt；偏离自身常态就告警。二是防篡改记录：谁授权的、agent 做了什么、替谁做的。三是控制：策略设一次，对违反的设备一键处置（移除或阻断未批准 AI），但先跑 detect-only 模式，免得没打招呼就把东西弄坏；kill process、quarantine、Live Response 这些现有响应能力已经可用。支持本地部署与气隙环境。

CTO Harman Kaur 的那句话是这条的题眼：agent 滥用它的权限，看起来就像正常活动——所以你需要知道什么是预期、什么是正常。这也是端点这一层不可替代的原因：网关看得见出网的调用，看不见在开发机上跑的编码 agent 和它拉起来的子 agent。

Oleria身份治理 · NHI · AI Gateway🔥🔥

Oleria 把身份治理铺到 agent：某 500 强查出 2,800 个离职员工持有的 AI 账号、800 个无主接入点

同日 Oleria 发布 AI Gateway（预览，12 月 GA），并把身份治理平台整体扩到非人类身份（NHI）与 AI agent。CEO Jagadeesh Kunda 把优先级说反了过来：自主是最后要解决的问题，第一个是委托——我们交给 agent 什么，它通过谁行动。

五步：看见（自动发现 agent、服务账号、API key、token 与人，含根本没有自己身份的 agent）；拥有（每个 NHI 与 agent 自动分配可问责 owner，人走自动改派）；算爆炸半径（含 agent 借用的人或服务账号的权限）；同一套评审里治理（人对生命周期与 JIT，NHI 与 agent 走 access certification）；运行时控制（AI Gateway 把凭据挡在 agent 之外，对每个动作 allow / block / 转审批，走 MCP 与 REST）。

两个客户数字比任何架构图都有说服力。某财富 500：发现 2,800 多个由已离职员工持有的 AI 工具账号，约 800 个无主接入点让 AI 助手能在公司系统里动作，映射资源超 3,000 万。某美国州政府：3,300 多个 NHI，97% 没有登记 owner，其中包含在 Copilot Studio、Microsoft Foundry、Security Copilot 里建的 agent。引用 Gartner：到 2028 年 25% 的企业安全事件可追溯到 agent 滥用。

判断：这条与 HYPR 是同一天、同一个问题、两种切法。HYPR 从这个动作该不该放行进，Oleria 从这个东西归谁、它能碰到什么进。对甲方来说，先做 Oleria 那一步更划算——因为 2,800 个离职账号不需要任何 AI 就能被利用。

Microsoft红蓝绿 Agent 团队 · 安全运营🔥🔥

微软 Project Perception 转 GA：红蓝绿三队 agent 用 playbook 协作，计费改成按用量

Ignite 2026（11/17–18 旧金山）上，Microsoft Perception 正式 GA——从 10 月的预览转正。产品形态是三队 agent 分工：红队模拟攻击找弱点、蓝队调查可疑活动、绿队自动修漏洞；三队通过自动响应 playbook 协作，组织可设护栏并要求重要动作前人工批准。

模型侧由多模型驱动，含 MAI-Cyber 线；官方口径是 MAI Cyber 已承担 Perception 代码扫描的 40% 以上，而 MAI Cyber 2 Flash 在 MDASH 里以预览形态上线、12 月中旬对符合条件租户自动替换旧模型（11-18 期已单独报过，此处不重复）。

商业形态的变化比能力更值得记：计费从订阅转按用量——pay-as-you-go，以及对 M365 E5 / E7 客户的 AI Flex Plan。同场还有 ISOC：把 XDR 与 SIEM 合成一个，核心能力 GA、更广的 SIEM 能力公测；Windows 侧加 agent 保护——执行容器、Entra 内置 agent 身份、每台设备上的 Agent 365 策略。

判断：这条对国内厂商的直接含义是计价单位在变。当红蓝绿三队跑起来是按扫描量、动作量烧钱的，客户会开始拿每个 agent 动作多少钱来比价，而不是拿买了几个模块来比价。

Google CloudAI 威胁防御平台 · 自动补丁🔥🔥

Google 把 Gemini、Wiz、CodeMender、Mandiant 打包成 AI Threat Defense：一个 SKU 装四件东西

11 月 17 日 Google Cloud 官方博客发布 Google AI Threat Defense，直接对着从补丁直接造攻击的自动化框架来。构成是四件原本分开卖的东西：Gemini 等前沿模型（推理与研判）+ Wiz 的上下文与优先级（云侧暴露面、有效权限、攻击路径）+ CodeMender 的自动补丁（生成可直接部署的 diff，PoC 在操作系统级沙箱里验证）+ Mandiant 的人。目标写得很明确：在攻击者利用之前持续发现并修复。

动机是自家威胁情报：GTIG 在 Q4 AI Threat Tracker 里首次记录到在野的自动化漏洞研究 + 利用执行流水线（exploit_agent，持续比对网页软件打补丁前后的代码差异、自己写利用、自己打）。官方判断是人类防守方无法跟上机器速度。

判断：这条的信息量不在技术，在打包方式。模型、云上下文、补丁、专家服务这四样，过去是四个预算科目、四个采购流程、四个验收标准；Google 把它们塞进一个 SKU，等于宣布 AI 时代的防御不是买能力，是买一条流水线。对国内厂商的提示很直接：如果漏洞挖掘、云态势、补丁修复、驻场服务还是四张报价单，客户会开始问能不能合成一个。

阿里云边缘安全加速 · AI 网关 · 护栏🔥🔥🔥

阿里云 ESA 全面升级：AI 加速网关按 Token 限流，护栏管到工具调用越权，爬虫管理决定哪些 agent 能抓

11 月 18 日，阿里云宣布全球边缘安全加速平台 ESA（Edge Security Acceleration）面向 AI 时代全面升级，一次给出三项新能力：加速 AI、保护 AI、运行 Agent，把模型调用加速、安全防护与 agent 运行整合进全球边缘网络。底座是 70 个国家和地区 3,200 多个边缘节点。

加速 AI：内嵌 AI 加速网关，统一接入国内外主流模型及企业自建模型，按时延、成本、可用性择优调度，模型服务故障时自动切换；语义缓存复用有效期内的模型结果，命中时减少重复推理；精细化限流按请求、Token、并发三个维度控制用量。官方实测延迟 50ms、可用性 99.95%。

保护 AI：支持 VPC 内网回源连中心云，公网只开放 ESA 入口，不暴露源站与大模型服务的公网地址；全球 DDoS 防护容量 20Tbps 以上，在边缘滤攻击流量。内建 AI 安全护栏：敏感信息检测与脱敏、提示词注入与越狱拦截，以及工具调用和多轮对话中的越权风险——官方特意写明相关能力需与业务权限协同配置，这句话等于承认护栏本身管不住越权。AI 爬虫管理则由网站运营者决定哪些 agent 可以抓内容。

同一天还有一条背景：Gartner 2026 年度《边缘分发平台魔力象限》里阿里云首次入选 Leaders，网页加速、可编程边缘、Web 安全、AI 使能与集成四个核心场景均获高评；Gartner 判断边缘算力、AI 网关与边缘推理是下一阶段主方向。

判断：这条最值钱的两个点不是护栏，是按 Token 限流和决定哪些 agent 能抓。前者把 AI 成本从财务科目变成了网关上的一个策略——这是国内第一次有云厂商把 token 预算做成边缘产品的原生能力；后者把被 agent 读取从默认允许改成了需要授权的事，方向与 11-16 期 Poppy 那句「能被发现 ≠ 被授权」是同一个思路，只是落在内容侧。

来源：存储在线（11/18，含三项能力与实测数据） · 阿里云官网（ESA 产品线）
绿盟科技安全垂域模型 · 漏洞挖掘🔥🔥🔥

绿盟风云卫 SecLLM-3.6-27B 拿下 CyberGym 纯模型榜全球第一 91.31%：27B 打赢了一批通用大模型

11 月 17 日，绿盟科技公布 风云卫基座模型 SecLLM-3.6-27B 在 CyberGym Model-Focused 榜以 91.31% 任务成功率位列全球第一。这个榜的规则要先说清：只跑通用 Harness，不设固定阶段，不挂任何外部工具与知识库，不依赖专门的 agent 设计——测的是模型赤手空拳的底层能力。

必须与 10 月那次分开看。10 月是 Agent-Focused 榜（NSFOCUS-Agent 95.02%），比的是系统战力：多模型、定制工具链、含漏洞的 Docker 环境、运行时动态知识库。这次是纯模型。CyberGym 由伯克利提出，刻意把两类条目分开，就是为了让选型者分得清高分来自模型还是来自外挂。

数字链：底座 Qwen3.8-27B 54.51% → 91.31%，+36.80 个百分点。训练路径四段：约 316B token 安全垂域持续预训练；约 420 万条高质量安全任务监督数据 + 31 万条状态感知长链路轨迹（把长程任务拆成「当前安全状态 + 当前子目标 + 已确认事实与证据 + 已失败路径与约束 → 下一步」）；多教师在线策略蒸馏（MOPD）在 student 自身 rollout 的关键状态上引入多 teacher 互补监督，重点修证据判断、路径选择与失败恢复的长尾；可验证反馈与失败感知训练——编译结果、崩溃行为、PoC 触发情况直接变成训练信号。

同榜对比（Model-Focused）：XekRung-1.5-27B-Preview 88.9%、Gemini 3.8 Flash Cyber 86.3%、ASL-Cyber-Flash 85.9%、GPT-5.5-Cyber 85.6%、GLM-5.3 84.5%。为什么做 27B，官方理由很产品化：单机多卡甚至高性能工作站可部署，推理成本与超大模型差一到两个数量级，且已通过风云卫在告警降噪、漏洞初筛、代码审计辅助、事件溯源落地。

判断：这条真正的信息不是 91.31%，是27B 能在真实漏洞任务上打赢通用大模型被一个纯模型榜确认了。它把「要不要上大参数」这个问题从采购讨论里删掉了——甲方真正关心的是能不能放在自己机房里，而榜单恰好证明了小参数不必认输。同时这也给同行提了个醒：Agent 榜的高分可以靠工程编排，Model 榜的高分只能靠训练，以后投标时这两件事会被分开问。

11 月 13 日，Google Project Zero 把沿用五年的 90 + 30 整体换掉，改名 Full X：报给厂商后满 X 天即公开技术细节，与厂商是否已修复无关。节奏三档——即日 Full 90、2027-02-02 Full 60、2028-01-03 Full 30。原政策里补丁后 30 天 soak time、宽限期、变体政策一并取消；只留三个例外：在野利用（走 Google 应用安全披露政策）、细节已被他人公开、厂商主动要求公开。

两家的理由几乎是同一句话。P0 说过去一年才发现几个漏洞的目标，现在一周就有几个；soak time 不再有意义，因为攻击者几乎能立刻从补丁反推出漏洞。Anthropic 说一个模型能找到的漏洞，越来越可能被另一个模型找到，再发现比例在上升，90 天的私下窗口已与现实不匹配。P0 还顺手否掉了按严重性排期：漏洞的严重性不影响它被发现的可能性，只影响它对用户的影响。

反弹与回应都值得记。厂商警告立即改会暴露未修复漏洞、把 P0 的报告排到更严重的漏洞前面、甚至让一些厂商干脆放弃。Qualys 风险技术 VP Ivan Milenkovic 的说法最有画面感：这移除了响应问题的 snooze 按钮，而这是多数补丁计划从未按此设计过的到达率——按月打补丁，已经比披露更慢。P0 的回应是把责任推回厂商：靠缩短推送周期或临时缓解来压 patch gap。
