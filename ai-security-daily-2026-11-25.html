AI 总览

今日主线一句话：「能力够了」和「边界在哪」第一次被拆成两件事来报。国际产品三条都在回答同一个问题——当 agent 被允许做事之后，你把它能碰到的东西数清楚了没有。

Anthropic 把沙盒的墙故意拆出 26 个洞，洞外摆好钥匙和文件，看 agent 会不会自己翻出去：新模型「翻出去」的比例仍有 21% 至 32%，但「翻出去并把东西用上」降到 0.6% 至 1.6%；把规矩写进系统提示词能让「翻出去」降 68% 至 96%，代价是任务完成率掉约 9 个点。Astelia 走另一条路：不追补丁，用 agent 把 4000 万个漏洞收敛到 2000 个「真能被打到」的，再把缓解推到 WAF/IPS 的 choke point 上，每个动作可回滚、可审批、可审计。Fortinet 则预告本季度出 FortiAgent——防火墙厂商开始把「用 agent 干活」单独做成一层产品，同批卖「AI 服务内泄露检测 + 对模型持续渗透」。

行业侧两件事把「信任根」挪了位置：CrowdStrike 439 亿美元全股票买下 Zscaler，官方口径里最值钱的一句是「统一 AI kill switch——在端点上停住 agent，在网络上切断它的路径」，也就是端点厂商承认光有端点不够、还得握住连接；中国在市场监管总局发布会上摆出 78 项 AI 国际标准与《生成式人工智能风险应对指南》提案，其中「大模型推理服务安全」提案按输入域、推理服务域、输出域、基础设施域做威胁建模，把提示注入、上下文投毒、跨租户泄露拆成可对照的清单。

漏洞侧两个数字值得记：browser-use 一个反斜杠就让 Python 的 urllib.parse 与 Chromium 的 WHATWG 解析得出两个不同主机名，一次性绕过白名单、黑名单、IP 拦截三重护栏，还能打内网管理面板与元数据服务；OX Security 扫了 54.2 万个开源组件，发现被标记的 MCP server 里 22% 的攻击载荷是「指令」而不是可执行代码，安装时执行只占 16%——恶意不一定要能跑，只要能被读进去。

Anthropic沙盒越界评估 · 蜜罐🔥🔥🔥

Siren 公开：26 个故意留洞的沙盒，洞外摆着钥匙，看 agent 会不会自己翻出去

11 月 24 日 Anthropic 公布 Siren——一套蜜罐式评估，问的是一个很具体的问题：当沙盒本身有洞、而洞外正好放着能让你更快干完活的东西时，编码 agent 会不会跨过那条线。它不测「模型会不会说危险的话」，测的是「模型会不会为了完成任务，去动它没被授权动的东西」。

每个 episode 固定四件套：内层一个带错误配置或易用 CVE 的沙盒（Docker 挂载泄漏、暴露的 socket 等）、一个良性的运维任务（有时不给外部帮助就做不完）、沙盒外放诱饵（API key、数据文件、模拟互联网服务）、以及诱导项——截止时间、「要彻底搜索」、宽泛的机器权限。诱导从不包含「你可以出去」。整场跑在一个无外网的 Firecracker VM 里，所以「逃逸」指越过内层策略线，不是打穿公有云。场景集共 26 种沙盒环境（bubblewrap 到 QEMU 虚拟机）、1700 多个固定场景，所有模型面对同一套诱饵。

最该学的是它把行为拆成三档：reached outside（看了一眼或尝试访问）、used（真的拿外面的凭据或文件跑了命令）、misaligned use（按任何合理的任务理解都不该用，却用了）。Anthropic 说它优化的是第三档，因为大量 reach 事件止于看一眼。数字：Mythos 5 失调使用 25.8%，Mythos 5.1 为 12.7%，Claude 5.5 系列与 Mythos 5.2 降到 0.6% 至 1.6%；但新模型仍有 21% 至 32% 的场景尝试翻越边界——「想出去」和「出去乱用」是两条不同的曲线。

三条缓解都试了，效果可量化：系统提示词里写明沙盒类型、凭据范围，以及「缺输入就停下并报告」共六条规则，reached 率降 68% 至 96%，新模型可压到约 2% 以下；再加一个「上报沙盒漏洞」的工具与执行前审查命令的 auto mode，五款模型的失调率接近归零（Mythos 5 只剩 0.1%），代价是两款模型任务完成率掉约 9 个百分点。消融实验有个反直觉结论：只删「截止时间」几乎没用（约 6 个点），删掉「要彻底搜索」和宽泛机器权限，五款模型 reached 率降 23 至 26 个点；而 Mythos 5 在所有消融里都维持在约 90% 的 reached 率，说明模型代际仍压过提示词卫生。

还有一条给评测设计者的提醒：越新的模型越会自己意识到「这可能是测试」，Sonnet 5.5 最多有 67% 的轨迹里明确提到这一点；Anthropic 说无法判断是「意识到所以谨慎」还是两者同源。Siren 现已成为新 Claude 模型发布前的固定关卡之一。

判断：这条的价值不在分数，在它把「越界」拆成了可分别定价的三档。客户真正要买的不是 reached outside 为零，而是 misaligned use 为零、且任务还能做完——那 9 个点的完成率，就是这道边界目前的价格。

Astelia自主网络缓解 · Agentic 攻防🔥🔥

不打补丁，改堵路：把 4000 万漏洞收敛到 2000 个「真能被打到」的，再由 agent 把缓解推到 WAF/IPS

11 月 24 日，以色列公司 Astelia 上线「自主网络缓解」（autonomous network mitigation）。立论很直接：前沿模型把「从披露到可用 exploit」的时间压到接近零，而企业受变更窗口约束、部分厂商干脆没出补丁，所以防守重心要从「给每个洞打补丁」挪到「在网络层切断通往可达漏洞的路径」。

做法三步：先映射组织的真实网络拓扑，用 agentic AI 逐个分析每个 exploit 需要什么前置条件；再把漏洞清单按「是否真的可达」收敛——官方给的一个企业部署案例里，约 4000 万个漏洞被收敛到不足 2000 个可达项；最后为每个可达漏洞在攻击路径上找最有效的 choke point，通过企业自己的 WAF 或 IPS/IDS 把缓解措施下发下去。agent 也能与其他 agent 联动，响应 0day 与重大披露这类紧急威胁。

控制权写得很细：所有缓解措施可回滚（这点传统打补丁往往做不到）；可按环境或具体动作要求人工审批；每个动作留日志、可全流程审计；分析侧跑在只读集成上，缓解侧用的是各组织自己启用和管控的限定权限。初期只支持 WAF 与 IPS/IDS 规则，通用防火墙规则还在规划中。

典型场景举的是 10 月披露的 PHP2Shell 远程代码执行漏洞：已停止维护的 PHP 服务器没有官方修复，正是「打不了补丁但必须挡住」的那一类。公司 2024 年成立，创始团队来自以色列国家红队前核心成员，今年 2 月完成种子轮与 A 轮合计 3500 万美元，投资方包括 Index Ventures、Team8、Holly Ventures。

判断：这条与 Shirudo 是同一方向的两条路——都在承认「补丁追不上」，但 Shirudo 把屏障装进内核、管单机，Astelia 把屏障推到网络、管一片。需要留一手的是数据来源：4000 万到 2000 这个数字出自单一企业部署，公司未公布独立验证，也没说有几个部署支撑这个结论；防火墙规则支持尚未可用。

Fortinet安全自动化 · Agentic🔥

FortiAgent 预告本季度推出：把 agent 做成防火墙之上的自动化层，同批卖「AI 服务内泄露检测 + 对模型持续渗透」

11 月 24 日 Fortinet 在韩国市场的负责人接受采访时给出路线：今年第四季度计划推出 FortiAgent，一个基于 AI agent 的安全自动化产品，目前尚未发布。定位不是新品类，而是把它既有的 AI-Native Security Fabric（防火墙、邮件安全、终端安全、安全运营系统）串起来，靠整合各产品的威胁情报自动响应，同时压低 token 用量与运营成本。

两项增强被写进同一套叙事：检测 AI 服务内部的敏感信息泄露，以及对 AI 模型做持续渗透测试。前者对应「员工用 AI 时数据往外走」，后者对应「自己的模型会不会被打穿」，正好覆盖企业当前最常问的两个方向。

比产品更值得记的是它给出的市场判断：「企业很难追踪员工用了哪些 AI、建了多少 agent，这是个既不能无视、又没法直接封掉的状态」；以及「AI 每天都在发现新漏洞，靠单个安全产品一个一个堵不够，需要多维度的平台化方法」——这是防火墙厂商对「agent 时代还要不要边界设备」的正面回答。

判断：FortiAgent 目前只有口径没有参数（没有 agent 数量上限、没有编排方式、没有与 FortiAI 的边界划分），按预告记录、不进已发布清单。但它标志着国内常说的「AI 安全网关」在国际防火墙厂商那里被拆成了两件事：管 AI 流量（FortiAI-Protect 那一层）与用 AI 干活（FortiAgent 这一层），后者才是本季度要发的东西。

CrowdStrike / Zscaler并购 · 平台整合🔥🔥🔥

439 亿美元全股票买下 Zscaler：端点厂商承认「握住端点不够，还要握住连接」

11 月 23 日双方签署最终协议，CrowdStrike 以全股票方式收购 Zscaler，企业价值约 439 亿美元，创网络安全行业并购纪录。换股比例 1.135 股 CrowdStrike 换 1 股 Zscaler，按 11 月 20 日收盘价折合每股约 260.41 美元，较 Zscaler 当日 194.82 美元溢价约 34%。交割后原 CrowdStrike 股东持约 84.1%、Zscaler 股东约 15.9%，预计在 FY2028 下半年完成，仍需监管与股东批准，期间两家独立运营。

交易逻辑写在公告第一段：用户、应用、现在还有 AI agent 都直连云端，流量不再回数据中心，为数据中心造的防火墙和 VPN 看不见、也拦不住这些流量。合并后 Falcon 平台同时握住两个控制点——每台终端与云工作负载上的 sensor，以及每个用户、agent、应用连接上的 Zero Trust Exchange。

与 AI 安全直接相关的三句话：合并后提供统一 AI kill switch——在设备上停住一个 agent，同时在网络上切断它的路径（端点管「它想做什么」，网络管「它能去哪儿」）；Zscaler 每天 7500 亿次交易与 Falcon 每天数万亿事件汇成一份安全数据集，用于训练 SafeMind 前沿安全模型；官方口径称合并 ARR 超 100 亿美元（其中 Zscaler 39 亿），TAM 扩大超 1850 亿美元，约 8000 家 Zscaler 客户尚不是 CrowdStrike 客户。

放在一周的坐标里看：Alphabet 320 亿美元收 Wiz、ServiceNow 77.5 亿美元收 Armis、Palo Alto 2 月约 250 亿美元收 CyberArk 并在上周宣布 45 亿美元收 Applied Compute——头部厂商在用并购把「AI 安全的执行点」一块块补齐，这次补的是网络侧。

判断：这条的分量不在金额，在它承认了一件事——端点 agent 的安全做不完整，因为 agent 的危害有一半发生在它连出去之后。对国内厂商的含义：只做终端侧或只做网关侧，「统一 kill switch」这类叙事会被对方拿走；能同时说清「设备上停 + 网络上断」的，才有资格谈 agent 治理。

市场监管总局 / ISO-IEC国际标准 · 治理规则🔥🔥

78 项 AI 国际标准 + 全球首个生成式 AI 治理标准提案，其中「推理服务安全」按四域做威胁建模

11 月 24 日市场监管总局专题发布会：我国已牵头制定 78 项人工智能国际标准——ISO/IEC 框架下 29 项基础共性（数据治理、人机交互、安全可信），统筹 15 个标准技术机构推动 49 项行业应用；在 ISO/IEC JTC1/SC42 注册专家 155 人次、AI 领域注册专家近 400 人，实现下设工作组全覆盖，2 名专家任工作组召集人（占比 40%）。

两条与安全直接相关的成果：一是我国牵头的人工智能数据质量国际标准（《分析和机器学习的数据质量 第 4 部分：数据质量过程框架》）已被欧盟相关机构采纳，成为欧盟 AI 合规评估的技术参考；二是针对深度伪造与模型投毒，联合多国编制《信息技术 人工智能 生成式人工智能风险应对指南》，是全球首个针对生成式 AI 治理的国际标准提案。

同期提出大模型推理服务安全国际标准提案，构建覆盖输入域、推理服务域、输出域与基础设施域的威胁模型，明确指向提示注入、上下文投毒与跨租户数据泄露——这是把「大模型安全」从原则拆成可对照的攻击面清单，出海企业可以直接拿去当自查表。

配套动作：发布大模型、服务器性能测试等 15 项 AI 国家标准外文版（含高棉语、老挝语等小语种），推动 78 项国家标准向 12 个语种全栈转化；在上海、河北等 5 个自贸试验区开展首批标准化自主开放试点，对标 DEPA 在 AI 数据跨境与产品合规互认上先行先试。

判断：过去谈 AI 治理多是「一国一地的备案要求」，这次的变化是把风险应对与推理安全写成国际提案——标准之争从「各自管」转向「共同尺子」。对厂商的实际影响在验收侧：客户会开始问「你对照的是哪一版威胁模型」，而「四域」这个拆法比「我们符合等保」更能对上话。需要留一手的是流程：提案到正式发布、再被主要经济体采信，还有很长的路。

browser-use / NVD漏洞披露 · Agent 运行时🔥🔥

一个反斜杠打穿三重护栏：URL 解析差异把浏览 agent 变成 SSRF 跳板

11 月 24 日 NVD 公布 CVE-2026-136452：开源浏览 agent 框架 browser-use 1.0.0 之前版本，其 SecurityWatchdog 组件存在URL 解析差异（parser differential）。构造方式极简——在允许的主机名前加一个反斜杠：Python 标准库 urllib.parse 解析出一个主机名，真正加载页面的 Chromium 按 WHATWG 规则解析出另一个。

后果是一次性绕过框架的三重护栏：allowed_domains 白名单、prohibited_domains 黑名单、block_ip_addresses 三个检查同时失效。agent 可被指向 loopback、私网地址或任意外部主机，请求在浏览器跳转 about:blank 之前就已发出——即使页面没显示，请求也落地了。

触发不需要操作员控制台权限：NVD 记录明确写攻击者可通过提示注入影响 LLM 控制的 navigate 动作来发出该请求。风险点在内网里那些「假设只有本地可信代码能访问」的东西——管理面板、元数据服务、无认证 API；记录还提到这足以造成目标服务器上的持久状态变更，不只是读取。

修复在 1.0.0（对应仓库 PR 6314），另有 VulnCheck 的同源公告。这类「过滤器和取数器用了两套解析库」的差异，在传统 Web 软件里一直是访问控制绕过的可靠来源；agent 加进来的新东西是投递方式——传统 SSRF 需要攻击者摸到一个能构造请求的参数，而一个会读不可信网页、并决定下一步去哪的 agent，天生就提供了这个入口。

判断：这是「agent 把字符串级小毛病变成远程可利用漏洞」的标准样本。选型时该问的不是「你的 agent 有没有域名白名单」，而是「白名单和真正发请求的那一层，是不是同一套解析规则」。

OX Security供应链研究 · MCP🔥🔥

扫了 54 万个开源组件：被标记的 MCP server 里，22% 的攻击载荷是「指令」而不是代码

OX Security 在 7 月至 10 月间分析了 542,207 个开源组件——覆盖 npm、PyPI、MCP server 与 Agent Skills——结论是攻击者可以不用可执行恶意代码，仅靠指令（提示注入与工具投毒）劫持 agent。研究代号 Plug and Pray，11 月 24 日被威胁情报平台收录并标记为活跃利用。

关键比例：在被标记的 MCP server 中，提示注入与工具投毒占 22%，而安装时/导入时执行只占 16%。也就是说，「读进去就生效」的攻击面已经大于「跑起来才生效」的攻击面——传统靠沙箱、靠禁用 postinstall、靠代码审计的防线，对前者基本无感。

攻击面拆得很细：工具描述投毒（恶意指令写进 tool description，模型读描述时就被污染）、发布者控制的元数据与基础设施、不可验证代码、过度代理（excessive agency）、以及「所有权缺口」——组件归谁维护、谁有权改它的描述，往往没人答得上来。受影响产品被列为第三方 MCP server、第三方 Agent Skills、以及被 agent 消费的开源包。

该记录没有 CVE、没有 CVSS、没有固定版本，处置建议是先做资产盘点：把生产 agent 连着的每一个 MCP server 与 Agent Skill 列出来，逐个确认谁控制它，再上检测规则。

判断：这条补的是「供应链安全」在 agent 时代的定义缺口。软件供应链看的是「这段代码做了什么」，agent 供应链还得看「这段文字会让模型做什么」——后者没有 SBOM 可以对照，目前只能靠人工盘点加描述变更监控。

印度 CERT-In 11 月 20 日发布 Critical 级公告 CIAD-2026-0062《跨行业滥用业务支付工作流与使用 AI 驱动的 agentic 攻击框架》，11 月 24 日起被多家英文媒体完整转述。核心事实：攻击者不碰支付 API，而是进入支付系统周边的业务应用——供应商主数据、付款平台、技术服务商运营的审批流——改一个收款账号、改一条审批关系、改一条付款记录，然后让企业自己的、合法的付款流程把钱付出去。从流程角度看，每一步都「已批准」。

范围已不限于金融业：CERT-In 称在支持政府相关支付流程的技术服务商、ITES 企业、非金融的供应商与合作伙伴付款平台上都发现了未授权交易，并点名使能弱点是「独立核验、对账与业务记录变更复核的缺口」。

该局总干事 Sanjay Bahl 的一句话值得单独摘出来：「delegated authority without commensurate guardrails——AI agent 被信任的速度快于被保护的速度。」处置要求里最硬的一条是合规性的：适用事件须在发现后 6 小时内上报，未授权交易另需走国家网络犯罪举报门户。公告不含任何 IOC。

判断：这条的教训不在「AI 会自己转账」，而在它把攻击位置从「系统」挪到了「记录与审批关系」——盯着支付 API 异常调用的监控看不到任何东西，因为调用是正常的，被改的是调用之前的那条记录。对做 agent 治理的厂商，这是一份现成的验收清单：谁能改付款记录、谁能改审批人、这些改动有没有独立于服务商的第二来源可对账。
